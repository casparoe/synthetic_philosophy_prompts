I was covering a small workshop a few months ago on AI agents that negotiate on your behalf -- think "your assistant haggles with the airline's assistant" -- and during the Q&A two of the panelists got into it over something called "program equilibrium." The basic idea, which I gather goes back to a game theorist named Tennenholtz sometime in the early 2000s (don't hold me to the date), is that instead of picking moves in a game directly, players submit whole programs that can read each other's source code before acting. Everyone in the room kept circling back to a one-shot Prisoner's Dilemma where both sides submit a program that basically says "cooperate only if I can first prove you cooperate with me" -- people called it "FairBot," apparently from a later paper that uses Löb's theorem to make that self-reference actually go through -- and the punchline is that two FairBots facing each other provably cooperate, and that this mutual cooperation is itself a stable equilibrium: no repeated rounds, no outside enforcer, nothing exchanged but code.

Here's the exchange as best I could reconstruct it walking out, between two panelists I'll call R and L since I don't want to misquote anyone on the record:
(1) R said this is a genuinely big deal philosophically -- it shows mutual transparency, not repetition or punishment, can ground cooperation between purely self-interested rational agents, which classical game theory treats as flatly impossible in a one-shot dilemma.
(2) L shot back that it's a shell game: DefectBot paired with DefectBot is every bit as much a program equilibrium as FairBot paired with FairBot, so nothing has actually been settled about which equilibrium rational agents land on. The cooperation was smuggled in through the choice of which programs get submitted, not derived from anything.
(3) R answered that just expanding the menu to include mutual cooperation as a reachable, individually rational option is the achievement -- in the ordinary one-shot game cooperation isn't reachable by rational play at all, full stop, and "but which equilibrium" is the same boring problem every game with multiple equilibria has, so it's not a special mark against this one.
(4) L said fine, maybe that's true in the idealized case, but the idealized case is exactly what's in dispute: the whole trick only works because Löb's theorem lets FairBot "prove," inside one specific formal system with a bounded search, that the other side cooperates -- and it falls apart the moment you add resource limits, noisy source code, or an opponent too complicated to verify, since checking whether two arbitrary programs behave the same is undecidable in general. So it's not an escape route from anything real, just a cute fact about two specially-chosen self-referential programs.
(5) R's closing shot was that brittleness is a totally fair complaint if you're trying to ship this as an actual product, but it doesn't touch the conceptual claim, which was never "this is robust to noise" but "rational cooperation without external enforcement is possible even in principle" -- and far as R was concerned, that claim is still standing.

Neither of them budged before the moderator moved on to the next question, so it never really got resolved. I did one philosophy class in college, which is not gonna cut it here -- could you go through moves (1) through (5) and say who's actually right at each step, seperately for each move, rather than just tallying up an overall winner? And is there some real crux underneath this whole thing that R and L never quite put their finger on?
