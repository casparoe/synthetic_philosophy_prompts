At work, two people on my team got into a genuine argument over what began as a joke during a code review, and it ended up running through a Slack thread for the rest of the day. The premise, meant as a joke, was a hypothetical twist on the autoscaling script we were reviewing: it flips a fair coin exactly once. Heads, it spins up exactly one instance. Tails, it spins up three identical instances in parallel, from the same image, with no networking between them and nothing in their environment — no hostname, no index, no peer count, no timestamp — that would let an instance tell how many siblings it has, or which one of them it is. Every instance that boots runs identical code whose only job is to compute and report one number: its own best-guess probability that the coin landed heads.

(1) Marcus said the answer is 1/2. His reasoning: the coin is fair, and nothing about "being an instance that just booted" tells you anything about how many siblings you have, so there's no new information to update on.

(2) Dana said it's 1/4. Her reasoning: imagine the pipeline runs a huge number of times. Heads-runs and tails-runs happen equally often, but each heads-run produces one report and each tails-run produces three, so across all runs, only one in four reports comes from a heads-run. Since no instance can tell which kind of run it's in, each one should reason as if randomly drawn from that pool of reports, giving 1/4.

(3) Marcus objected that "reason as if randomly drawn from the pool of all reports" isn't forced by the setup — it's an extra assumption. An instance isn't sampled from anything; it's produced deterministically by the coin flip. He said you could just as easily say "reason as if randomly drawn from the pool of all coin flips," which gives 1/2 — so why prefer Dana's pool over his?

(4) Dana answered with a betting argument. Suppose every instance, in addition to reporting a number, places a $1 bet at 1-to-1 odds on heads (win $1 if heads, lose $1 if tails), settled individually per instance. Run the pipeline many times: three-quarters of all individual bets get placed by instances that exist in a tails-run, so an instance betting as if the probability is 1/2 loses money on average. Betting at 1/4 (which requires 3-to-1 odds to be worth taking) is the only break-even strategy, which shows Marcus's argument must be missing something.

(5) Marcus granted the arithmetic but said it's an artifact of scoring each instance's bet separately. If the three siblings in a tails-run had to agree on and place one shared $1 bet instead of three separate ones, a tails-run would risk exactly as much total money as a heads-run, and betting that shared dollar at 1/2 would break even again. So which scheme is "fair" depends on how you pool outcomes across instances, not on the coin — meaning the betting argument can't actually settle what any one instance should believe.

(6) Dana replied that this only shows betting behavior is sensitive to how payoffs get pooled across correlated instances, which is a fact about decision-making, not about belief. The question "how likely is it that the coin came up heads, from this instance's point of view" never mentions wallets, and on that question, untouched by Marcus's reply, her argument from (2) still stands.
