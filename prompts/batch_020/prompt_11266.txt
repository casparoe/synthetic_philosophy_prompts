I've spent the past few months in an informal AI-safety reading group that a couple of us started after school, and this week we got stuck on the idea of "program equilibrium" — the result that if two agents can commit to source code and read each other's code before playing a one-shot Prisoner's Dilemma, mutual cooperation can be sustained as an equilibrium without repeated play or any external enforcement. Everyone in the group can recite the punchline that agents like FairBot and PrudentBot pull this off by searching for formal proofs about each other rather than by simulating each other, and that the mutual-cooperation result for two copies of FairBot is proved using Löb's theorem from provability logic. What nobody in the group could explain to my satisfaction, including our club's faculty sponsor, is why that machinery is actually necessary rather than merely traditional within this literature.

Specifically, I'd like to understand two things in more depth than the one-paragraph gloss that shows up in most introductions to this topic. First, when people say the naive strategy of "simulate the other program, then cooperate if and only if it cooperates" fails, is that strictly a halting-problem obstruction — the simulation might never terminate — or is there a subtler issue with the very definition of such an agent, something closer to a circularity in self-reference that would persist even if each agent had access to a halting oracle? Second, why does the actual fix specifically require reasoning about what is provable in some fixed formal system, rather than about what is simply true, given that both notions seem like they should support some kind of fixed-point argument? I'd like to see concretely where an attempted proof of mutual cooperation would break down if "provable" were replaced by "true" throughout, and why that breakdown is connected to Löb's theorem having no valid analogue for a truth predicate.
