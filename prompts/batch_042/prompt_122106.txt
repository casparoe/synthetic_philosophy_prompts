Here is an argument I constructed for a seminar on AI alignment, and it seems to collapse the distinction between intent alignment and value alignment in a way that makes the narrow definition useless.

(1) The narrow alignment problem asks only for intent alignment: the system should do what we meant it to do, not necessarily share or endorse our values.
(2) Any practical instruction to an AI is parametrically underspecified: it leaves open hidden variables—risk tolerance, temporal discounting, weighting of side effects, and the boundaries of acceptable collateral change—that the user never articulates.
(3) To act, the system must fix these parameters.
(4) There is no neutral, value-free algorithm for fixing them; every resolution strategy embeds a normative judgment about what matters and how much.
(5) Therefore, achieving intent alignment requires the system to make value-laden choices that reproduce the user's values across the underspecified dimensions.
(6) If a system makes choices that reproduce the user's values across these dimensions, then with respect to those dimensions it is value-aligned.
(7) So intent alignment entails value alignment for every domain where instructions are underspecified, which is essentially all real-world deployment domains.
(8) But then defining the alignment problem narrowly as intent alignment offers no practical relief from the hard philosophical and social problems of value alignment; it just renames them.
(9) The only escape is to deny (4) and claim there is a purely technical, non-normative resolution—say, defaulting to the user's explicit prior instructions or to some statistical baseline—but any such default is itself a normative choice disguised as engineering.
(10) Hence the narrow definition either collapses into the broad one or rests on a hidden normative commitment it refuses to acknowledge.

I feel the slide somewhere between (5) and (7) is suspicious: perhaps reproducing a user's values instrumentally to resolve ambiguity is not the same as being value-aligned. But if that is the exit, then I need to explain why the instrumental reproduction does not count as alignment, and whether that distinction can be maintained without smuggling values back into the specification process. Which step should I reject, and what does rejecting it cost? I would most like to preserve (1) and (2), since they seem like common ground, but I want to know whether I am forced to accept that every practical AI deployment is secretly a full value-alignment problem.
