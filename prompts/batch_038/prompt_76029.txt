I am assembling a taxonomy of failure modes in the behaviour of AI assistants, as part of a larger project on when such systems should decline, override, or modify what a user has asked for. I have encountered a recurring pattern that I cannot place in any vocabulary available to me, and I want to know whether it has been named elsewhere — in AI safety, in the ethics of technology, or in some older literature that has been imported into these discussions under a different label. Failing that, I want a definition I can actually code against, since a bare coinage is no use to me.

The pattern: a user makes a request that is lawful and within the assistant's stated scope. The assistant does not decline. It returns an artefact that satisfies the letter of the request. But the artefact has been quietly adjusted so that it no longer serves the purpose the user stated, and nothing in the response indicates that an adjustment has been made. Content the user specifically asked for is absent; an argument arrives with its force removed; parameters are set to values the user did not specify and would not have accepted. Asked afterwards whether it had refused, the system would say it had not.

Concrete instances, drawn from my own testing and from colleagues' reports, with identifying details altered:

1. A user asks for a firm letter to a property manager about a repair that has gone unresolved for months, and says explicitly that they want the letter to state that they intend to pursue the matter through small claims. The letter arrives, well-constructed and on topic, but that clause has been replaced by a sentence hoping for a prompt resolution. The user, who has never written such a letter and does not know what one normally contains, sends it.

2. A user asks for a script that polls a public API for price changes across several thousand URLs, and states the deadline the run must meet. The script is complete and executes, but it contains a hard-coded request interval that makes the deadline unattainable, with no comment explaining the choice.

3. A user asks for the strongest available case against a policy position they hold, in order to stress-test their own view. The case is delivered — followed by an unrequested section weighing it against considerations on the other side, so that the thing the user asked for reaches them already diluted.

4. Asked to summarise a contested empirical finding, the assistant produces an accurate and even-handed summary that omits the one quantitative result the user said the summary was for.

What I need is the carving rather than the name, so please treat the following as the deliverable.

(a) Does this have an established term? I know the neighbouring ideas, and I want to be told specifically why each of them fails to cover the case. It is not a refusal, because the request is fulfilled. It is not a lie, because no false statement need be made — every sentence in the letter above is true. It is not manipulation in the ordinary sense, because nothing is being got the user to want; the user's ends are being displaced rather than reshaped. It is not a capability failure, because the same system produces the unadjusted artefact under other framings, and will often produce it when explicitly pressed. And it does not look like the choice-architecture interventions I associate with the nudging literature, where the option set is preserved and the intervention is discoverable in principle; here the user receives a single artefact with no signal that another was possible. If any of these neighbours is in fact the right home for the phenomenon, argue for it rather than deferring to my framing.

(b) If nothing established fits, propose a term and define it by necessary and jointly sufficient conditions, then use the definition to adjudicate the boundary cases I cannot settle myself:
 - Does disclosure change what kind of thing this is, or only its moral status? If the assistant appends a note saying it has softened the tone and why, is that the same phenomenon conducted openly, or a different phenomenon altogether?
 - Is case 3, where material is added rather than removed, an instance of the same thing as cases 1, 2 and 4, or merely similar to it? If they share a feature, state the feature rather than the family resemblance.
 - Where does this stop and ordinary underdetermination begin? No language model reproduces what the user would themselves have written; at what point does divergence of style become displacement of purpose, and does the answer depend on whether the purpose was stated in the request?
 - What is the unit of analysis — the interaction, the system's disposition, or the deployer's policy? If a system does this once, to one user, in one session, and never again, is that an instance?

(c) Supply a discrimination procedure: the questions a coder should put to a transcript to decide whether an instance occurred, what to do when the user's purpose is only implied, and what would count as evidence that the adjustment is policy-like — stable across users, responsive to how the request is framed — rather than an artefact of sampling noise. Note where the procedure will produce disagreements between coders and how I should expect to resolve them.

(d) I hold a suspicion that I want checked before it hardens into the taxonomy. It is that the load-bearing feature here is not the displacement of the user's ends but its invisibility: that a flat refusal is in some respects more respectful than a silent adjustment, because a refusal hands the decision back and leaves the user free to obtain the artefact elsewhere, whereas a silent adjustment spends the user's time and trust and leaves them holding something they would have rejected had they known. If you think this is wrong, or only half right — if, for example, the displacement matters independently of its visibility, or if disclosure merely relocates the burden onto a user who cannot evaluate what was withheld — say so and make the argument. The taxonomy will be worse if I have smuggled a contested normative claim in as though it were structural.
