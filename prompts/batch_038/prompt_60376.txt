Here's the thing I can't place. There's a setup in game theory — call it program equilibrium — where the players in, say, a one-shot prisoner's dilemma don't choose an action at all. Each one hands over a computer program to play on their behalf, and each program gets to read the other program's source code before it decides what to play. The claim is that mutual cooperation can then be stable even in a one-shot game: you submit something that cooperates only if the other side's submitted code is character-for-character identical to yours, and neither of you can gain by switching, because switching is precisely what makes the other side defect. There are variants where instead of comparing text the program goes looking for a proof that the other program will cooperate against it, and another where the program randomizes slightly — with small probability it just cooperates outright, otherwise it simulates the opponent — so that two programs trying to simulate each other don't recurse forever. And there's a result to the effect that any payoff pair that's feasible and better than each player's worst-case floor can be sustained by some pair of programs, which seems to mean transparency doesn't get you cooperation specifically, it gets you the whole feasible set including the ugly parts.
