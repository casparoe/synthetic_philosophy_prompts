I'm a software engineer with no formal philosophy background, so please flag anything I've described below that already has a standard name in the literature — I'd rather learn the name than have it assumed.

I'm building a router that maps free-text support tickets onto a fixed list of canonical issue categories. I got pulled into Hofstadter's Copycat work and the surrounding literature on fluid concepts and analogy-making because I want the router to handle tickets that don't match any category on a literal reading, and I've now tried to write down what I actually believe before I commit to an architecture. I'd like an audit of whether the set hangs together.

1. A category isn't a definition. Its boundary moves with context, and I want the system to be able to see a ticket as an instance of a category that shares no feature with it on the surface — the way people can see the same thing under two different descriptions, or see two things as the same despite no overlap.
2. What I find most convincing in that literature is the claim that there is no clean seam between perception and cognition: what you notice in the input depends on what you're currently looking for, so bottom-up and top-down pressure have to operate simultaneously rather than in stages.
3. My pipeline is an off-the-shelf embedding model, frozen and never fine-tuned in production for cost and reproducibility reasons, which turns a ticket into a vector; a separate layer above it does the analogical work over those vectors.
4. Similarity in my system is cosine distance in that space. I want it to be a genuine metric — symmetric, with near-enough-ness behaving transitively — because otherwise my nearest-neighbour index can't be exact and I can't reason about the scores.
5. I want an analogue of the temperature mechanism: many weak candidate interpretations explored at once, with a global measure of how much coherence has been reached so far deciding how much randomness to tolerate.
6. I don't think a system needs a body or sensorimotor coupling for its concepts to be genuinely fluid; text statistics plus the right control mechanism is enough.
7. The inventory of categories and the relations between them is fixed by me, in code, versioned, so that I can write regression tests against it.
8. Some conceptual distances are just true independently of my application — successor and predecessor are close in a way that successor and leftmost are not — and the system should get those right rather than infer them from my ticket data.

Which of these pull against each other, and how badly? Please rank the tensions by severity rather than listing them all as equally serious, and for each one say what specifically would have to be weakened or given up and what that costs me. Then tell me which single revision would clean up the most. I also suspect I'm carrying at least one pair that only looks contradictory, so please say explicitly which apparent problems dissolve on inspection and why, rather than flagging everything.
