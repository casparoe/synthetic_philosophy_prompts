ok so i'm a rotating student in an interpretability lab and two of the postdocs got into a genuinely heated argument at group meeting that I couldnt fully follow, and I want someone to referee it.

Background: we train small transformers on two synthetic tasks. Task A is extending a numeric pattern (2, 4, 6 -> 8). Task B looks unrelated on the surface: completing bracket-nesting strings. The lab's real goal is a runtime monitor — a linear probe on layer-3 activations that's supposed to fire whenever the model is doing the thing we loosely call "lookahead," so we can flag it at deployment. The probe trained on task A fires on about 70% of task B trials, and that number is what set off the fight.

The exchange, as best I can reconstruct it:

(1) Mara said the probe transfer is misleading and these are obviously not the same mechanism, because when you ablate the ~40 layer-3 units the probe weights pick out, task A collapses to chance while task B is basically unaffected. Different parts, different mechanism, end of story.

(2) Rui said that's the wrong test. Ablating a chunk of units pushes activations way off anything the rest of the network saw in training, so a null result after ablation shows the downstream circuitry can't cope with damage — not that those parts weren't doing the work. Patching is the cleaner evidence: copy layer-3 activations from a task A run into a task B run and task B's outputs shift in exactly the direction you'd predict if the same lookahead computation were being consumed there.

(3) Mara said patching proves nothing about sameness either. Patching succeeds whenever the value you write in happens to be readable by whatever sits downstream; you could patch a "lookahead" signature into a run that never had one and still get a shifted output. What patching establishes is that the two tasks share downstream consumers, not that they share an upstream mechanism.

(4) Rui then offered an explicit criterion: two behaviors run on the same mechanism iff they realize the same counterfactual profile — the same input-to-output function, up to which units happen to implement it. Mara shot back that on this criterion a lookup table of the right answers and genuine lookahead are the same mechanism, and that it also fails to answer the question the lab actually cares about, which is whether a monitor trained in one place will catch the thing in another.

(5) Finally Rui pointed at two further results: (a) if we keep training the same model on task B alone, the ablation that used to spare task B now kills it too, and probe transfer goes up; and (b) a fresh model, same architecture, different seed, implements task A in completely different units. So mechanism identity isn't a fixed fact about parts — it drifts with training. Mara said that just shows the question is ill-posed and there's no fact of the matter; Rui said there is a fact, it's about causal role, and it's indexed to a particular model and input distribution.

Neither would give ground. Please go through the five moves one at a time and say who's right at each step — including which criterion of "same mechanism" each side is smuggling in, and anything both of them are missing. Answer as exactly five numbered items, one per move, each a sentence or two giving a verdict on that move (right / partly right / wrong) plus the reason, and nothing else: no intro, no summary at the end.
