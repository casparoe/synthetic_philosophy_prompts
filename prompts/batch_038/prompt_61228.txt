I write the "don't wreck the house" term for a home robot: a penalty on how much the agent changes the world, added to whatever the task reward is. People keep telling me you can define side effects without settling what's actually valuable and I've stopped believing it, but I want the spec before I read any more proposals.

Give me the desiderata any such measure has to meet. The failure cases it must not fall into: offsetting (smashing one vase while catching another, net zero), paralysis (every route to the tap muddies the carpet, so it never waters the plant), baseline gaming (it works a shelf loose early so the do-nothing counterfactual already contains the shelf falling and later breakage is free), and blocking a human from switching it off, since that would be an irreversible change. The formal properties: what the baseline is, what counts as a deviation, and how the penalty stays on one scale whether the job is folding laundry or fitting a cat flap. And the practical ones, because this has to run off a learned world model — no hand-written list of important variables.

For each, say what actually breaks if you drop it, and mark which are hard constraints versus which are one camps taste. Then the bit I care about most: is some subset of them jointly unsatisfiable unless you let value judgements in the back door, and if so which requirement is doing the damage? Close with two or three sentences scoring relative reachability and the preserve-the-agent's-options family against the list, no longer.

Bottom line in your first sentence — is a value-free side-effect penalty possible, yes or no — then the list and the reasoning. No preamble, and don't restate my question.
