Question: "In the program-equilibrium framework for a one-shot two-player game, each player submits a program that takes the opponent's program as input and outputs an action in the underlying game. Define program equilibrium, explain how the notion relates to Nash equilibrium, say what it lets players achieve that Nash equilibrium doesn't, and describe the computational difficulties the framework runs into. Illustrate with the one-shot prisoner's dilemma."

Student's answer:

"A program equilibrium is a pair of programs (P1, P2) such that neither player can improve by submitting some other program Q instead of their own. The payoff of a pair is found by running P1 on P2's code and P2 on P1's code and plugging the two actions into the usual payoff matrix. Because the action a program picks can depend on the opponent's code, the strategy space is much bigger than the original one — the constant programs that ignore their input reproduce the original strategies, so program equilibrium is a refinement of Nash equilibrium that knocks out the equilibria that only survived because players couldn't see each other's plans.

In the one-shot PD mutual defection is the only Nash equilibrium, but not the only program equilibrium. Consider Open Book: 'output C if the opponent's program would output C when handed my code, otherwise D.' If both submit Open Book they get (C,C); if one switches to always-D the other's program answers D, so the deviator gets (D,D), which is worse. So cooperation is sustainable in a single-shot game, and the same idea supports plenty of other feasible payoffs that Nash would rule out. This is essentially Hofstadter's superrationality made rigorous: since each program can read the other's source, each one knows the other is reasoning the same way, and that symmetry of reasoning is what produces the cooperation.

Computationally the worry is the halting problem — if each program runs the other, the simulation never ends. The standard fix is to admit only programs that halt, which makes the whole thing decidable: to check a candidate equilibrium you just run the two programs and compare payoffs. Self-reference is then only an implementation detail."
