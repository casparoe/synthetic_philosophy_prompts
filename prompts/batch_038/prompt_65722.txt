Our team builds an internal-activation anomaly detector for a deployed language model, and after a bad month of false positives I have come to see that the arguments in our postmortems are not engineering arguments at all: whether a suspect forward pass counts as anomalous turns on whether the circuit producing it is the same mechanism we characterized on the clean baseline. Please write a decision tree that carries an engineer from a single starting commitment — that we can record activations and perform causal interventions such as patching and ablation in both the baseline and the suspect run — to a named account of what makes a mechanism in the suspect run identical to one in the baseline.

Each branch node must be a question an engineer could answer from an experimental result or an intuition about a case, without knowing which position that answer leads toward. Please build the nodes around cases like these: the suspect run realizes the same input–output function in a disjoint set of neurons; a sparse autoencoder trained on the suspect run splits one baseline feature into three; a fine-tuned successor reproduces the circuit with drifted weights; ablation of the baseline circuit is compensated by an unrelated backup pathway; the same computation appears in a different layer with different wiring.

The leaves should include at minimum a causal-role account, a substrate or implementation account, an algorithmic account, an etiological account appealing to how the circuit came to be there, and a deflationary account on which sameness of mechanism is a choice of description rather than a fact — plus any leaf you think the space demands and I have missed. Close with the answer combinations that no position actually occupies, saying of each whether it is incoherent, unattractive, or merely unexplored, and flag any pair of leaves that our interventions could not in practice separate.
