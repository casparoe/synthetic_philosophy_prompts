I maintain the scheduling layer for a service that runs as a pool of interchangeable container replicas: the orchestrator can start N identical copies of a process, kill one, and later restart it from a checkpoint with its memory of the interval wiped. I want to write a module that lets each replica carry calibrated degrees of belief in propositions involving its own identity and time — what fraction of currently running replicas are on the new build, whether this is the first or second time I have been started since the deploy — and update those beliefs as evidence arrives. Before I choose between the competing accounts, I want the specification they will be judged against.

Write the desiderata any update rule for self-locating belief must meet to be usable in this setting. At minimum, cover: what the rule must reduce to when there is no self-locating uncertainty at all; how it must behave in a case where a coin flip determines whether one replica or two indistinguishable replicas are started, including whether a replica that comes up should revise its credence about the coin purely from the fact that it has come up, and by how much; what it owes the constraint that a replica's credences not expose the pool to sure-loss bets placed against any or all of its copies; how it distinguishes learning which copy you are, from an external marker such as a hostname, from learning something about where you sit without learning anything new about the world; how the set of copies among which the agent locates itself gets fixed, and whether that can be done from information the replica actually has rather than by stipulation; whether the rule must be dynamically consistent, so that a replica does not now commit to a course of action its own memory-wiped future instance will reverse; and whether the rule has to be computable without enumerating every possible instantiation.

For each item, give the concrete case that motivates it, and say plainly whether it is non-negotiable or is a preference of one camp. Then tell me which single desideratum knocks out the most candidate rules, and whether any subset of them is jointly unsatisfiable. I suspect the no-sure-loss constraint and dynamic consistency collide in the checkpoint case, where the same belief state is entered twice by copies that will bet differently; if that is so, I want it stated as a result rather than papered over as a design choice. I am not asking for a survey of the literature, though a line or two on how the two standard answers to the coin case fare against the list would help me choose where to start.
