For my alignment seminar I had to build a toy "low-impact" agent and I've since talked myself into an argument that the whole project is incoherent. My groupmates can't find the hole, and I can't either, so I figured I'd write it out cold.

Setup, since it might matter. Gridworld, one task: carry a package to a square on the far side of the map. I scored states with an impact number. I fixed a basket of 200 auxiliary goals sampled ahead of time (reach this square, push that block onto that tile, get the lamp on, hold three keys at once, etc.). For each goal I computed how much of it is still achievable from the state the agent is now in versus from the start state, and summed the shortfalls. The pitch is that you're penalizing the agent for making the world worse-for-arbitrary-purposes, so you never have to say which purposes are the good ones.

Argument:

(1) An impact measure has to say how much each change the agent makes matters, or it can't rank trajectories.
(2) How much a change matters is never a property of the change itself. A smashed pot matters to somebody or it matters to nothing.
(3) So any impact measure has to be covertly consulting somebody's values.
(4) There are only two candidates for the somebody. If it's the designer, then the designer already had to decide which features of the world were worth preserving, which is a chunk of the value function we were trying to avoid writing down. If it's humanity collectively, the measure has to aggregate over all our values, which is the whole value function.
(5) My 200-goal basket looks like it escapes this, but it doesn't: I chose the basket. Random sampling doesn't launder it, because it's random over a space of goals I chose, and the choice of that space is exactly the claim about what's worth preserving.
(6) The other horn: try to make the basket genuinely goal-neutral, e.g. all computable functions of the state. Then nearly every action destroys attainable value for something in the basket — turning the lamp on makes "keep the room dark" unattainable — so the penalty is large and roughly flat across everything, and the minimum-impact policy is to never move.
(7) Therefore an impact measure is either a smuggled value function or a paralysis device.
(8) The only reason anyone wanted low-impact design was to get protection without the value function.
(9) So there is no such protection. You solve alignment first, or you get a statue.

I'd rather keep (2) than anything else here, because if (2) goes I owe an account of what it is for a change to matter that doesn't bottom out in somebody caring, and I don't have one. And (6) doesn't feel like the weak link either — that's literally what my own toy run did, the agent that stood still beat every agent that tried to deliver the package, and it beat them by a lot. So don't just tell me (6) is an implementation artifact unless you can say why the artifact is avoidable in principle rather than by luck.

Which step is actually broken, and why did it look fine? And for the steps I'd have to reject instead, what do I have to swallow? I especially want an answer on (5), because "you picked the goals" feels like a gotcha that would also kill every evaluation metric and every proxy reward anyone has ever written, and I don't believe that's fatal, but I can't articulate why not.
