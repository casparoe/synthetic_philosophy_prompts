I'm a backend engineer, no ML research background, and I got volunteered to build a drift monitor for the models we fine-tune in-house.

Design: after every fine-tune I run the old and new checkpoint over the same fixed probe set, pull the residual stream at layers 6, 14 and 22, and take cosine similarity per token, then average. If it drops below a threshold I page whoever's on call, on the theory that if the outputs are still right but the internals moved a lot, the model has probably found some new route to the right answer — the same-behavior-different-mechanism case that mechanistic anomaly detection is supposed to catch.

Two questions. (1) What threshold? I'm at 0.9. Weird datapoint: as a control I retrained the exact same config with a different seed and it scored 0.72 againt the original, so I've been treating 0.72 as my noise floor and anything under that as a genuine change. Is 0.9 too twitchy or not twitchy enough? (2) The one I actually can't work out — when my number moves, what is it that moved? What would have to be true for two models to count as running the same mechanism, such that a similarity score like mine could be evidence about it in either direction?
