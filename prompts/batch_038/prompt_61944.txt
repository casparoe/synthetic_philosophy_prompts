Two game theorists have been arguing for a year about program equilibrium in the one-shot prisoner's dilemma. The first holds that letting each player submit source code, which the other's code may then inspect, produces genuinely cooperative equilibria where the ordinary one-shot game has none, and that this is a substantive solution to one-shot cooperation. The second holds that nothing has been solved: the construction replaces the original game with a different one, its cooperative results rest on assumptions about the programming language and on unbounded computation, and the requirement that both programs be executed by a trusted common interpreter already supplies the very assurance the account claims to generate.

To pin the dispute down, they have agreed to study a bounded variant: each player submits a program that may run the opponent's program for at most N steps and must otherwise return a pre-specified default action, where that default is a free parameter of the construction rather than a fixed rule.
