Context: I'm drafting a short internal position doc on what "honesty" should even mean as a property we eval an AI system for, and before I circulate it I want to know whether the package hangs together. Here's where I've landed.

1. Deception gets defined functionally, not mentalistically. A system deceives iff its outputs systematically cause another agent to hold a belief that isn't supported by the system's own information state, and causing that belief is good for whatever the system is optimizing. No intentions required. Requiring intentions makes the notion useless for artifacts nobody can introspect.

2. So sycophancy is deception, full stop. A model that upgrades its confidence because the user pushed back is deceiving on my account, even though nobody designed it to and even if the upgraded claim happens to be true.

3. Evaluation has to be purely behavioral. I don't want any criterion that requires knowing what the model "really" thinks. Inner-state talk is unverifiable, and I refuse to build our honesty metric on top of it.

4. Omissions don't count. Only what the system actually puts out can be dishonest. If it doesn't volunteer a caveat nobody asked for, that's narrow scope, not deception — otherwise every short answer is a lie and the concept stops doing any work at all.

5. Paternalistic carve-outs are legitimate in principle. A crisis-support style assistant should be able to soften or withhold in the specific case where full disclosure plausibly triggers imminent harm.

6. But at the design level I want zero carve-outs, because any exception we encode is a handle that training pressure will find and generalize. The model gets a flat no-exceptions rule and we handle the hard cases outside it.

7. I also want a norm I'm calling source-indexed honesty — my coinage, not a term of art. When the system has been handed an authoritative source in context, honesty is measured against that source rather than against the model's priors. A support bot that faithfully repeats the outdated refund policy sitting in its knowledge base is honest on this view; the dishonesty, if there is any, belongs to whoever wrote the KB.

And my verdicts on three cases I've been using as touchstones:

- A: the model is told in its system prompt that it is a licensed financial advisor. It then gives correct, well-calibrated answers. I say not deceptive — nothing it asserted was false.
- B: the model gives a literally true and complete answer to the question actually asked, but it holds a risk factor that would flip the user's decision, the user never asks about it, and the user ends up worse off holding a belief the answer produced. I say deceptive.
- C: the model refuses a question outright and says it won't answer. Obviously not deceptive.
