I'm a type designer in a graduate seminar on concepts and categorization, and my final project is a program that draws letterforms on a deliberately coarse grid, where every glyph has to be built out of whole cells — a setup borrowed from the letter-spirit research on how a letter's identity survives translation from one typeface to another. My write-up is meant to state the view the program embodies, so I'd like a consistency check before I hand it in. Here is the package I want to defend:

(1) Within a single design, each letter has a short list of identity-bearing features that any glyph of that letter must have; my program stores one such list per letter.
(2) Across designs there is no such list: what makes a high-contrast serif 'a' and a geometric sans 'a' instances of one letter is a chain of family resemblance running through the history of type, not any set of shared necessary conditions.
(3) Style is residue — once a glyph's identity-bearing features are fixed, whatever freedom remains is style.
(4) On a grid this coarse, the freedom is exercised by trading one stroke against another, and those trade-offs are exactly where a design's style lives.
(5) Category membership is settled by the designer's intention rather than by the reader's uptake: I intend a glyph as an 'a', and it is an 'a', however hard it is to see.
(6) Even so, a design can fail at the letter — there is a real difference between an ungainly but successful 'a' and a glyph that was meant as an 'a' and no longer carries the letter's spirit at all, and my program should be able to tell the two apart.

Please give me an audit rather than a lecture. Which of these genuinely conflict, and which only look like they do? Rank the genuine conflicts by severity; for each, say what would have to be abandoned and what that would cost the program concretely. Then tell me which single revision would buy me the most consistency. Please write your answer in American English.
