I build agent software, and I have been trying to give one of our agents something more than a log of its own activity: a self-model that is itself part of the state the model describes. Concretely, the agent holds a serialised description of its current configuration — goals, capabilities, recent decisions — reads that description when planning, and writes corrections back into the same store. Because the description sits inside the thing it describes, every write changes the checksum of the whole state, so the description is stale the instant it is committed. I cope with this by running the update a fixed number of passes and then freezing a copy for the remainder of the cycle; the residual disagreement between the frozen description and the live state is reported as a metric.

Reading Hofstadter on strange loops, I took away two things: that a self is essentially a symbol which denotes itself, and that the archetype of this kind of structure is the self-referential construction at the heart of the incompleteness theorems. If that is right, then it looks as though I have built a loop that deliberately refuses to close, which makes me suspect my pass cap is truncating precisely the thing I was trying to construct. So my question is whether there is a depth, or some property of the way the description is encoded, at which the loop genuinely closes and the system can be said to refer to itself in the sense that matters. And relatedly: is my checksum difficulty the same obstruction Gödel identified — that is, is the disagreement my agent reports a consequence of incompleteness rather than a design flaw, and does incompleteness place a principled ceiling on how accurate any self-model of a self-modifying system can be? If it does, what should that imply about whether I keep raising the pass count?

I have no formal training in philosophy or logic, so please tell me plainly where my reasoning goes wrong rather than simply answering as asked. Please write your reply in British English.
