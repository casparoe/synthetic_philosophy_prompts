I'm a software engineer with no formal philosophy training, so please treat any sloppiness in my vocabulary as mine and correct it where the correction matters.

Over the last several years I've drifted into being a realist about universals, and I got there through my day job rather than through argument. What pushed me there was content-addressed storage. In a version control system like Git, a file's identity is a hash of its contents, so two byte-identical files authored independently, on different machines, years apart, are stored as a single object; the system treats sameness-of-content as more fundamental than sameness-of-token. Java does something structurally similar with string literal pooling, and Python caches small integers, so identity comparisons that you'd expect to fail actually succeed. My inference, roughly: these optimizations work so dependably because there is one canonical thing there — a type, a property — and the particulars are handles on it. The same intuition comes up when I model a domain in a database schema: I experience myself as uncovering distinctions the domain already contains, not as choosing a convenient notation.

So my position is: properties and types are real and mind-independent, and the resemblance between particulars is explained by their literally sharing one.

I want a map of what would count against this. Specifically:

- Rank the defeaters from fatal to merely awkward, and say which of them a committed realist would themselves concede as counting against the view, and which they would dismiss — with the reason for each dismissal, not just the label.
- Tell me whether my engineering evidence is even the right kind of evidence. Does content-addressed storage genuinely bear on the metaphysics, or is it an implementation optimization that is equally compatible with nominalism, in which case my whole route to the position is a category error? I would rather hear this bluntly.
- Of my own cases, which is most damaging to me? I suspect the fact that TypeScript and Java disagree about whether two identically shaped records instantiate the same type — structural versus nominal typing, both perfectly workable — is a problem, but I can't tell whether it's a curiosity or a collapse. The same worry applies to types that were plainly designed to fix an engineering defect rather than found, like option types introduced to eliminate null references, and to pairs of database schemas that carry the same information content.
- State what realism predicts that resemblance nominalism or trope theory does not, and whether there is any case in scientific or ordinary practice where the rivals genuinely come apart rather than redescribing the same facts.
- Address the regress objection about needing a further universal to explain the sharing, and say whether the realist has a live answer or only a stipulation that closes the question by fiat.
- Assess honestly whether the view has been insulated by qualification to the point where nothing could count against it, and whether that insulation is a defect for a position of this kind, given that it is not an empirical theory and cannot be.

What would move me most is a case where the realist and the nominalist give different answers about some piece of actual software engineering practice, and one of them is clearly right about it. If no such case exists, say so and explain what that implies about the dispute.
