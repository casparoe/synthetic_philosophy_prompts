**Q3 (25 marks).** In a *program game*, each player of a normal-form base game submits a computer program rather than an action. Each program is run with the other player's program supplied to it as input, and returns an action of the base game; payoffs are the base-game payoffs of the pair of actions that result.
(a) Define a program equilibrium and explain how it is related to a Nash equilibrium of the base game.
(b) Give an example showing that a one-shot prisoner's dilemma can have a program equilibrium in which both players cooperate.
(c) What assumptions does your example depend on, and how much weight should the result carry for actual one-shot strategic interaction between people or firms?

The candidate's answer:

> (a) A program game is built on top of an ordinary normal-form game. Instead of choosing an action, each player chooses a program, and each player's program is run with the other player's program handed to it as input, so that a program can inspect its opponent's code before settling on what to return. What comes out is a pair of actions of the base game, and the payoffs are just the base-game payoffs of that pair. A program equilibrium is a pair of programs such that neither player can get a higher payoff by unilaterally swapping their own program for a different one — in other words a Nash equilibrium of the program game rather than of the base game.
>
> It matters how this sits relative to ordinary Nash equilibrium. Since a program equilibrium is a Nash equilibrium computed over a strategy space that contains the original one, program equilibrium is a refinement of Nash: it imposes the same best-response requirement plus an additional one, namely that your plan has to survive being read by your opponent. Refinements work by eliminating, so the interpretive content of the concept is that some profiles we would happily have called equilibria in the base game turn out not to be stable once the players can condition on one another's code.
>
> (b) Take the standard prisoner's dilemma and consider the program I'll call M: read the opponent's source code; if it is character-for-character identical to M itself, cooperate; otherwise defect. If both players submit M, then each one's if-clause is satisfied, because each is looking at a copy of M, and the outcome is (C, C), which both prefer to (D, D).
>
> Is it an equilibrium? Suppose player 1 replaces M with some other program X. X is by hypothesis not M, so player 2's copy of M reads X's code, sees that it is not identical to itself, and defects. The best player 1 can now manage is to defect as well, for the mutual-defection payoff, and anything else yields the sucker's payoff. Either way the deviation is worse than staying put, and the same goes for player 2. So (M, M) is a program equilibrium with a cooperative outcome, in a one-shot game, with no repetition and no reputations doing any work.
>
> It is worth being clear about what is doing the work here. M is not responding to what its opponent will *do*, it is responding to how its opponent is *written*. A program that behaves exactly like M but carries one extra comment or an extra space is not identical to M and gets defected against, so the two end up in mutual defection despite being behaviourally indistinguishable. The cooperation is therefore not a matter of trusting the other's conduct at all; it is a matter of both parties having happened to write down the very same string. That seems to me the real weakness of the example, though I'd want to say it is a weakness in this way of achieving the equilibrium rather than in the idea of program equilibrium as such.
>
> (c) That fragility is what the proof-based agents were introduced to repair. Rather than comparing code, an agent like FairBot searches for a proof that its opponent will cooperate against it and cooperates if it finds one; PrudentBot is the more cautious variant, cooperating only with opponents it can prove to be proof-based cooperators of that kind. The philosophical significance of this move tends to be understated. Such agents no longer need the opponent's code at all, because what they need is a proof about the opponent's *behaviour*, and a proof of that can in principle be had from evidence about behaviour falling short of the source code. If so, the assumption that each player can read the other's program — plainly the least realistic feature of the whole set-up — drops out, and what remains is a claim about reasoning rather than about information. That is why I think the result does carry weight for actual one-shot interactions: people and firms cannot inspect one another's decision procedures, but they can form expectations about one another's behaviour, and the argument only needs the second. PrudentBot also does better than FairBot against an opponent that cooperates unconditionally, where FairBot simply lets itself be exploited.
>
> This is also, I think, what the line of work is reaching for: a rigorous version of Hofstadter's superrationality. Both locate the source of cooperation in the fact that the players reason in the same way, so that each can take it that whatever it settles on the other settles on too; program equilibrium merely makes that symmetry explicit by letting each program look at the other.
