I work on causal inference tooling at a software company — experimentation platforms, uplift models, the occasional do-calculus argument in code review — so I have enough exposure to Pearl to be dangerous and no formal philosophy at all. I'd like a decision tree that sorts a technically fluent reader into a named position on what causation *is*, built entirely out of software-engineering scenarios rather than out of the philosophers' usual repertoire.

Ten questions or fewer, each a concrete case answerable on intuition alone: two deploys ship, either of which alone would have caused the outage; the missing null check that "caused" the crash; a retry that gets removed and lets a downstream failure propagate; a feature flag that cannot be randomized without changing what the system is; a flaky test whose flakiness has no single source. Phrase every node so that answering it does not require knowing which view it leads toward.

Then tell me, explicitly, which of these cases are reskins of the standard preemption, overdetermination, and absence-causation puzzles, and which put genuinely new pressure on the theories.

The leaves should be named positions, and must include whatever view holds that causal claims are made true by nothing over and above the pattern of particular events, and whatever view denies there is causation at all. Flag any pair of leaves my cases cannot actually separate. Mark any combination of answers that no one occupies, with a one-line diagnosis of whether the gap is incoherence, unattractiveness, or mere neglect. Finally, note where an engineer's working habits — assuming modularity, demanding randomization, treating reproducibility as proof — quietly commit them to a leaf they would reject if they saw it named.
