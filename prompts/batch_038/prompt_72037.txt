Mechanistic anomaly detection aims to flag a deployed model whose internals contain something — a scheming routine, a suppressed refusal, an instrumental subgoal — that was absent from the benign activations against which the monitor was calibrated. Every such program presupposes a sameness relation for mechanisms, and it is rarely stated which one. Before committing to a criterion, I want the specification: what must a relation of "the same mechanism" deliver for a monitor built on it to be worth trusting? Give each requirement together with the case that motivates it — a paraphrased prompt, a fine-tuned checkpoint, an anomaly elicited in the lab versus one arising unprompted, a benign circuit that happens to fire the same features, two distinct routes realizing one function — and mark which requirements are non-negotiable for any monitor and which are artifacts of a particular interpretability methodology. Then assess joint satisfiability. My worry is that making the relation abstract enough to survive paraphrase and multiple realizability drives it toward a functional criterion, and that a functional criterion is fixed by what a mechanism does, which collapses the monitor back into a behavioral test and forfeits its main advantage. Say whether that is right, or where it misdescribes the trade-off.
