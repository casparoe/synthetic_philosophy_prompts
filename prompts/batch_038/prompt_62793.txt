For a project on fluid concepts in the Copycat tradition, I'm coding written answers to an analogy puzzle, and I need a decision tree that sorts each answer by the conceptual move behind it rather than by whether it looks correct. The microdomain is deliberately not the familiar alphabet-string one, so please don't simply carry that puzzle's answer families across.

Solvers see two worked examples — Mon Tue Wed → Mon Tue Thu, and Thu Fri Sat → Thu Fri Sun — and are then asked: Fri Sat Sun → ?

Build the instrument in three layers. First, lay out the answer space: the outputs reachable by stepping one or more positions forward or backward by a day, together with the whole-string moves (rotation, reversal, no change at all), marking which of these break the no-repeat pattern the examples display. Second, give the tree itself, five to eight branch nodes, each phrased as a question a coder could settle from the output plus at most one sentence of justification, and none phrased in terms of the leaf labels. The leaves should name the concept that bent or refused to bend: taking the week to be cyclic rather than treating "successor" as a partial function that fails at Sunday; shifting which positions are in scope (last only, first only, all of them); reversing the direction of the step; treating the three days as a single unit instead of three elements; and any further moves the space turns up. State the output string each leaf produces. Third, flag every collision — distinct moves landing on the identical string — that your tree cannot resolve from the output alone, and name the cheapest additional evidence that would separate them.

Close by listing the unoccupied cells of the answer space, saying for each whether nobody lands there because it breaks an implicit constraint, because the move is unmotivated at this particular cliff, or because it is simply unexplored.
