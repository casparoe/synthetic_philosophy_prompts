I'm a backend engineer with no formal philosophy background. I've been reading about two-dimensional semantics on my own time, mostly because the split between primary and secondary intensions looks like something a type system could exploit. I'd like you to write the parody of the language-design RFC that idea produces: a proposal to add a modal reference layer to a strongly typed language so the compiler can check whether an identifier still picks out the same thing when the world changes.

Form: a realistic RFC with numbered sections — Motivation, Proposed Syntax, Type-Checking Rules, Alternatives Considered, Migration Notes, Open Questions — plus at least one short code block and a reviewer comment thread at the end. Around 900 to 1,100 words. Voice: earnest, mildly bureaucratic, and completely serious about the philosophy; nobody in the document should be aware that anything is funny.

The humor needs to come from the semantics being correct rather than garbled, so please keep the machinery straight: the primary intension as what a term picks out across scenarios taken as actual, the secondary intension as what it picks out across worlds taken as counterfactual once reference has been fixed in our world, the fact that a natural-kind term and its chemical formula can share a secondary intension while differing in primary intension, and hence the room this leaves for the necessary a posteriori and the contingent a priori. Include, at minimum:

1. A type-class distinction between terms whose reference is settled by an internal description and terms whose reference depends on a causal-historical link to the environment, together with a lint rule that fires when a module rebinds the second kind without declaring an environment dependency.
2. An integration-test section in which CI is instantiated in a scenario whose clear, drinkable lake liquid is not the substance our production term was fixed on: a test that passes locally fails there, and a reviewer insists the failure is the feature rather than the bug.
3. A proposal to recover the lost apriority by diagonalizing, and a reviewer's objection that this makes the type checker's own assumption context part of the program's meaning, with the consequence that no caller can know what the checker assumed when it accepted their code.
4. Under Alternatives Considered, a conformance suite for a physically identical build that passes every behavioral test while instantiating none of the phenomenally typed values. The author should concede that nothing in the suite distinguishes the two builds, acknowledge that on this framework's own premises a coherently describable scenario is supposed to be a genuine possibility, and then decline to draw any conclusion about physicalism, marking it out of scope for a compiler RFC. A reviewer objects that the author cannot invoke the bridge from conceivability to possibility when it delivers the semantics and disown it when it delivers the metaphysics.
5. A Migration Notes section informing teams that code written on the assumption that reference is settled by what is in the head will not compile unchanged, with one concrete before-and-after snippet.

Target the impulse to formalize meaning into a type system, and more gently the conventions of the RFC genre — never two-dimensional semantics itself. Someone who knows the literature should recognize real arguments being exaggerated and find the piece fair; someone who doesn't should still get a coherent, funny document. No winking, no explaining the jokes, and no closing paragraph about what it all means.
