Last term I audited a reading group on commitment devices in game theory, and two of the regulars had a running argument about the program-equilibrium setup: both players in a one-shot prisoner's dilemma must submit source code before play, each program receives the other player's code as input, and a pair of programs counts as an equilibrium if neither player could get a higher payoff by substituting different code while the other's stays fixed.

Their exchange went as follows.

(1) Marcus: This dissolves the dilemma. Each player submits code that cooperates exactly when the opponent's code is identical to its own and defects otherwise. Substitute anything else and the opponent's program defects, so at best you fall back to the mutual-defection payoff. Mutual cooperation is therefore an equilibrium.

(2) Priya: Nothing is dissolved. Two constant-defect programs are also an equilibrium on your own test, so the concept doesn't select cooperation — it just stacks further equilibria on top of the one we already had. And your mechanism only works if both players happen to write byte-identical code; one extra space and both defect.

(3) Marcus: Identity was only the crudest instance. Let each program cooperate whenever it can verify that the opponent's program will cooperate against its own code. Cooperation is then supported by a wide family of programs, and a solution concept that makes Pareto-superior outcomes attainable has done something real even if it doesn't single one out.

(4) Priya: That version isn't well-defined. Your program must settle what an arbitrary program does when fed its own source, which is undecidable in general, and if each program tries to simulate the other you get an infinite regress. So the equilibrium exists only on some hand-picked decidable subclass, and you've given no account of how a player is to know they belong to it.

(5) Marcus: That's an objection to implementations, not to the concept. Restrict the admissible programs and the definition goes through unchanged. What survives is the substantive claim: full mutual transparency yields folk-theorem payoffs in a one-shot game.

(6) Priya: And what survives of that is a claim about a trusted interpreter, not about players. The result is purchased entirely by assuming the code you publish is the code that runs, and that both sides read it correctly.

I was only taking notes and never worked out who won. Could you adjudicate this move by move — for each of the six, say whether it is right, wrong, or partly so, and why — and then say what, if anything, both of them are missing about what this setup does and does not establish?
