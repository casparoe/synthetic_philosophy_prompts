I'm working on a chapter about games where the players don't just pick strategies, they pick *programs*: each player submits code to a referee, each program gets to read the other player's program (sometimes as a printed listing, sometimes as an oracle it can query), and then outputs an action, and payoffs come from the outputs. That's the program equilibrium idea Tennenholtz set up, plus the later resource-bounded stuff from Halpern, Pass and Seeman where you're only allowed to introspect so much before you time out. Before I sort through the pile of variants, I want to know what I should even be asking of one.

So: write the desiderata. What does any theory in this family have to deliver before it counts as an answer rather than a rebranding? Give me each requirement, then the concrete case behind it — the little 2x2, the two-line code snippet, the specific pair of programs that makes you see why you can't skip it.

Here's what I already suspect belongs on the list; handle these and add your own:

- termination. two programs that each read the other can mutually recurse forever. what fixes the output when that happens, and is a default-output rule part of the theory or a fudge?
- syntax vs semantics. suppose my strategy is "cooperate iff the opponent's source is byte-identical to mine." now somebody rewrites their program to be extensionally identical but spelled differently, and we both defect. is stability under benign re-coding a real requirement or a luxury? and if it is real, does the theory have to say what counts as the same program?
- findability. can the players actually compute the equilibrium themselves, given that they're subject to the same bounds as the code they submit? if not, in what sense is it an equilibrium of anything they could play?
- reduction. when code is opaque, does the theory fall back on Nash? does it have to?
- the neighbors. what distinction does it have to preserve against superrationality, against a mediator generating correlated outcomes, against cheap talk, against an ordinary commitment device? if a variant can't say how it differs from those, is that fatal?
- predictive bite. Tennenholtz's own result is that the program-equilibrium payoff set of a game coincides with its feasible and individually rational payoffs, which sounds like the concept predicts almost anything. is narrowing the outcome set a genuine desideratum here or just Nash-envy?
- asymmetry and lying. partial transparency — one player's code is legible, the other's isn't — and players who refuse to reveal, or reveal something that isn't what gets run.

Then tell me which of these are non-negotiable and which are really one camp's aesthetic dressed up as a requirement. And the part I want most: whether any subset is jointly unsatisfiable. If demanding computability-by-the-players plus full mutual introspection plus stability under re-coding is impossible together, say it as a theorem-shaped claim and sketch the argument, don't wave at it.

Close with a very short scorecard of three flavors — (a) unbounded introspection with a default rule for nontermination, (b) bounded or forgetful introspection where you only get a capped/noisy view of the opponent's code, (c) a trusted compiler that takes both programs and reveals nothing but the outputs. Brief is fine, the list is the deliverable.
