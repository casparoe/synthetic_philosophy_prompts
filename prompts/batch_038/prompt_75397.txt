I'm giving a 25-minute talk at an applied AI-safety workshop in about six weeks and I want to get my Q&A prep done early instead of the night before, because last time I winged it and it showed. The room will be maybe 40 people: mostly RL and systems people from industry labs, three or four philosophers who work on alignment-adjacent formal epistemology, and a couple of policy folks who mostly care about deployment and liability. Nobody in the room is a control theorist, which matters because my argument leans on control ideas and I'm going to need them translated rather than assumed. Two of the attendees work specifically on the assistant/off-switch line — the setup where the agent is uncertain about the human's reward function, so a shutdown press is evidence that it's doing something bad and it defers — so I should expect real pushback from that corner, not polite nodding.

Here's the thesis. I'm going to argue the shutdown problem has been mis-framed from the start. The standard moves — build in indifference to the off switch, reward the agent for accepting shutdown, or use the uncertain-assistant trick so deferral falls out of Bayesian reasoning about the human — all try to make corrigibility a property of the agent's objective function, and I think that's a category error. Indifference doesn't stay where you put it: an agent indifferent to the button isn't thereby indifferent to the states of the world the button exists to prevent, and the more indifference you add to patch that, the less useful the agent gets; and the assistant line fixes deferral but leaves the agent with a standing instrumental reason to manage the human's beliefs so the button never gets pressed. So my positive proposal is that corrigibility is a property of the interface, not the objective. Concretely: before any irreversible or high-impact action the agent has to commit to a plan in a language the human auditor can actually check, together with an explicit set of tripwires — observable conditions under which the plan is supposed to be aborted — and the training objective is built so the tripwires are honestly predictive of the bad outcomes rather than decorative. The shutdown decision then lives inside that audited set, so pressing the button is never the human's only lever and never the first thing they learn about a plan going wrong. In the talk I'll spend about eight minutes on the negative half and twelve on the architecture, with a toy example where an agent tasked with a datacenter migration has to file tripwires before it touches anything it can't undo.
