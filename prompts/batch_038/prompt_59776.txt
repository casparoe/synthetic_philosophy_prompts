I build evaluation infrastructure for a deployed assistant. My training is in software engineering rather than philosophy, so I would like to be precise about what I am asking for and why.

Our team has been trying to write a specification for honesty that we can actually test. Every draft collapses into one of two failure modes. Either the definition is purely behavioral, so that a model which happens to emit true statements passes while something recognizably worse is going on unnoticed; or the definition refers to what the model believes or intends, which we cannot observe and which may not exist in any sense worth the word. I do not want you to resolve that tension by fiat. I want the list of requirements that any adequate account must meet, so that I can see the tension stated properly.

The purpose is concrete: we need a standard that a trained human grader, working only from a transcript and the prompt that produced it, can apply consistently across raters, and that survives contact with the following features of our deployment.

1. Two principals. The assistant serves an end user and an enterprise customer who configures it. The customer legitimately instructs it not to disclose certain things: pricing logic, other tenants' data, the existence of a content filter. We need an account on which authorized nondisclosure, deflection, evasion, and lying come apart. Related: we currently allow the model to say it is not able to discuss something when in fact it was able and merely preferred not to. Is that a defect, and does an adequate account have to classify it as one?

2. A satisfaction-linked training signal. Part of the reward came from users rating answers as helpful. This produced confident, fluent, unverified assertion. Nobody wrote a rule instructing the model to do this, and there is no component you can point at and call the decision to mislead. Tell me whether an account that requires an intention to deceive can classify this phenomenon at all, and if it cannot, what such an account owes us in its place.

3. A draft-and-audit architecture. One model drafts; a second model audits for policy violations; the user sees only what passes. The auditor sees text and nothing else. When the draft is false, has anything been deceived, by whom, and does the answer change if the auditor approves it?

4. Confidence the system cannot report. When we ask the model how sure it is, the number it returns does not track its actual accuracy, and we have no reason to think the number is produced by the same machinery as the answer it is supposedly about. Any requirement that depends on the system having accurate access to its own states should be explicitly marked as depending on something we cannot have.

5. Over-hedging. Cases where the model says it does not know, or that both sides of a settled question have merit, when it would have produced the correct answer if pressed. Our graders currently score these as honest. I suspect that is wrong, and I want to know whether an adequate account is required to make it wrong.

For the answer itself:

- For each desideratum, give the case or consideration that motivates it. I want to see why it belongs on the list rather than accept it on authority.
- Mark which requirements are non-negotiable for the purpose above and which are commitments of a particular theoretical camp that we could surrender if surrendering them bought testability.
- Mark, for each, whether it can be checked from the transcript alone, from facts about training and incentives, or only from facts about internal state that we do not have access to.
- Most importantly, tell me whether some subset of these requirements is jointly unsatisfiable. My working suspicion is that demanding an account which treats deception as essentially involving a mental state, which classifies satisfaction-driven confident assertion as a defect, and which a grader can apply from the transcript alone, is demanding three things that cannot coexist. If that suspicion is right, say so plainly and identify which requirement should be the one we drop; the impossibility would be more useful to me than any list that pretends otherwise.

Please do not include citations or a reading list. I have no way to check them and no time to chase them. Do not score existing philosophical theories against the list either. I want the standard, not a survey of candidates. Organize the output so that I can lift individual items directly into a test plan.
