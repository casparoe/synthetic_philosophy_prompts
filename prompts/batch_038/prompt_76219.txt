I am a first-year graduate student in a seminar on the foundations of decision and game theory. Last week's session was on program equilibrium, that is, the family of setups in which the players in a one-shot game do not submit moves but instead submit source code: each program receives the other program's code as its input, each outputs an action, and payoffs are assigned from the pair of actions. Afterwards two other students in the seminar, whom I will call Mira and Owen, argued about the framework for close to an hour. I was sitting beside them and kept notes. I am deliberately not telling you which of them I found more convincing, because I do not know; I would like a referee's report.

The setup they were both working with, so that you can check their claims independently: the underlying game is the ordinary one-shot prisoner's dilemma with (C,C) = (3,3), (D,D) = (1,1), (D,C) = (5,0), (C,D) = (0,5). The program at the centre of the dispute, which Mira called Twin, is: inspect the opponent's source code, determine what that program would output if it were run against Twin, and output C if that answer is C and D otherwise.

1. Mira. The standard claim that rational players must defect in a one-shot prisoner's dilemma is an artifact of assuming players submit moves rather than programs. Once they submit programs, (Twin, Twin) is a Nash equilibrium paying (3,3). If I deviate unilaterally to any other program p, then either p defects against Twin, in which case Twin defects and I receive 1, or p cooperates against Twin, in which case Twin cooperates and I receive 3, no better than what Twin receives. So there is a stable profile of one-shot play that is not mutual defection, and the familiar moral about the inevitability of defection is not delivered by rationality at all.

2. Owen. You have assumed away the only thing that makes the dilemma hard. Twin works because each program can read the other's code. Actual agents do not publish their decision procedures, and they have a positive reason not to: an agent whose code is visible can be studied and then beaten. Remove the transparency premise and (Twin, Twin) is not an equilibrium of anything, it is a description of a situation that cannot arise.

3. Mira. Transparency is carrying less weight than you think, and your reason for concealing code is backwards. Publishing Twin is a deterrent rather than an invitation: anyone who reads Twin can see that defecting against it yields 1 and not 5. It is opacity that invites exploitation, since Twin facing an unreadable opponent must assume the worst and defect. In any case full disclosure is not required. What Twin needs is the ability to determine its opponent's behaviour towards it, and there are realistic settings in which that is available without handing over everything: an audited contract, a public commitment device, an inspector, or a long record of play that pins a strategy down.

4. Owen. Grant partial verifiability. The more serious problem is that Twin is not well defined even under full transparency. Suppose I submit Liar: inspect the opponent's code, determine whether it outputs C against me, and output D if it does and C if it does not. Now run Twin against Liar. Twin outputs C only if Liar outputs C against Twin, and Liar outputs C against Twin only if Twin does not output C against Liar. There is no consistent assignment of outputs at all, so your subroutine that determines what the opponent would do returns nothing. The profile you call an equilibrium is not even an element of the game, and the concept has no defined domain precisely in the adversarial cases, which are the only cases where the concept was supposed to earn its keep.

5. Mira. That is a bug in the implementation, not a defect in the concept. Define Twin proof-theoretically instead: cooperate only if you can prove, in some fixed sound system, that the opponent's program cooperates against you. Against Liar, nothing is provable in either direction, so neither program can establish the other's cooperation, both defect, and the paradox disappears. You have inflated a technicality into a refutation.

6. Owen. It is not a technicality, it is a change of subject. On the proof-theoretic version, what Twin does depends on which proof system you fixed. Strengthen the system and more programs become provably cooperative; weaken it and fewer do. So the equilibrium is not a fact about the prisoner's dilemma or about the players' interests but a fact about a logic. Two agents with identical interests and identical information about one another can fail to cooperate for no other reason than that one of them is running a weaker deductive system. That is not a solution concept.

7. Mira. Then let me state the objection you should have made, because everything so far leaves open the possibility that the framework is coherent but uninteresting. (Twin, Twin) is a fixed point that was stipulated rather than discovered: Twin is just the instruction to cooperate with one's own kind, and two such instructions are trivially stable. The set of program equilibria also contains (always defect, always defect), which is Pareto-dominated, and Twin is only a weak best response, since any other program that cooperates against Twin does exactly as well. So the framework does not predict cooperation, it multiplies equilibria in the way that cheap talk multiplies equilibria, and the interesting question, why anyone would submit Twin in the first place, is pushed outside the model and left unanswered.

8. Owen. I accept the credit, but it does not rescue your position, and the regress is worse than you described it. In an ordinary game a Nash equilibrium is self-enforcing because each player's action is best given the action the other actually performs, and each player can confirm this by inspection. In the program game, whether my program is a best response to yours may require settling what your program does to mine, and you have already conceded that this can fail to be decidable in general. If best-responsehood is not computable, no agent can reason its way into the equilibrium, and the equilibrium cannot function as a recommendation to anyone. What you have established is that logically omniscient agents who have already agreed to publish their source code cooperate with one another. Both of the hard parts of the original problem, the one-shot structure and the information structure, were assumed away.

Please adjudicate this exchange move by move. For each of the eight numbered moves, state whether it is right, partly right, or mistaken, and identify the specific claim that carries its weight and whether that claim survives scrutiny. In particular I want you to check: Mira's best-response computation in move 1 and whether it establishes what she says it establishes; her claim in move 3 that publishing Twin deters rather than invites exploitation; whether the Liar construction in move 4 really leaves the outcome undefined; whether move 5's repair works, and if not, what actually happens when the proof-theoretic Twin meets Liar; how much force move 6's proof-system-dependence charge has; whether move 7's concession is correct about multiplicity and about Twin being only a weak best response; and whether move 8's claim that best-responsehood is uncomputable follows from what was conceded earlier or overstates it. Then say which of the two is more right overall and why. Finally, set out separately what neither of them raised: I am fairly confident that at least two substantial points about this framework, one of them concerning the very profile Mira defends, went unmentioned by both of them.
