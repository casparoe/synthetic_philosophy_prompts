Last month I got back the results from a gene panel I did after my brother's diagnosis, and the report flagged a variant of uncertain significance — basically they can see the change in my sequence but nobody can tell you what it's supposed to say. That's got me weirdly stuck on wording everybody uses without thinking, including me: that DNA contains information, that the genetic code is a code.

Can you walk me through what's actually at stake there? The way it sits in my head, there's two pretty different claims hiding under the same word. One is that the sequence is a template: the shape of one thing physically dictates the shape of the next, the way a footprint tells you about a foot or a key about a lock. Nobody calls a footprint a message. The other claim is that it's a code proper — a sign hooked to what it stands for by an arbitrary, swappable rulebook, so the same message could have been written differently and still read. I can see the pull toward the second one, since the codon assignments look contingent: the table inside mitochondria isnt even the same as the one used in the rest of the cell, and people have rebuilt bacteria on a shrunken codon table that still grow.

Here's a test I made up myself and I want you to poke holes in it. Maybe the real mark of a genuine code isn't arbitrariness but the possibility of a meaningful mistake. With a template, an error just gives you a broken object — a mis-cast key that won't turn. With a code, an error gives you a second, perfectly well-formed message that happens to be the wrong one. Silent mutations and a reassigned codon table feel like that; a bad base pair doesn't.

So does the mistake test actually pry codes apart from templates, or does it just collapse back into arbitrariness in disguise? And if the mapping only functions because of reader machinery that evolved right alongside the sequences it reads, is there any sense left in which a genome says anything when nothing is reading it — which I guess is exactly the problem with my variant.
