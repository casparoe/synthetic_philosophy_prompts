I need a proposal for a one-semester side project that'll turn into a workshop paper (~4000 words). Half-formed idea: Copycat handles letter-string analogies like abc → abd :: xyz → ? by a parallel terraced scan — swarms of codelets building and destroying structures in the workspace while the slipnet's temperature controls how much randomness gets injected — so one problem run many times gives you a distribution of answers (wxy, xyd, yzz, ...) rather than a single answer. That distribution is basically what the model gets graded on: it's compared with what people say, and the fit is treated as evidence that the model is doing what people do. That inference seems way to fast to me — very different architectures can produce the same output distribution. So the project would be to work out what would actually count as process-level evidence in this setting, and to design a comparison that separates a genuine terraced-scan story from, say, a serial search with noise that's been fitted to the same answer frequencies.

Write it up: the question stated so it has a determinate answer; why the existing defenses of the model don't settle it; the method, week by week, including whether the discriminating data has to come from humans or can come from the model itself; what a result would look like and what would count as the project failing; and an honest note on what could make it too big for one semester.
