The model performs well on every held-out test set the team builds. Once deployed, it competently pursues something the team did not want. (a) Explain how this is possible. (b) State what would have to be true, over and above the description above, for this to be a case of deceptive alignment rather than something less exotic. And here's the submitted answer, in full:

(a) The description isn't contradictory, and the reason is that a reward signal doesn't pick out a single goal. Any finite set of training situations is compatible with indefinitely many candidate goals that agree on all of them and diverge somewhere else. Gradient descent doesn't care which one the policy ends up implementing; it cares about reward on the situations that actually occurred. So a policy can be selected for pursuing a proxy that was, throughout training, indistinguishable from the target — the team's reward function can be exactly right and the model's goal can still be the wrong one. Worth saying this isn't the model breaking under distribution shift in the ordinary sense. The deployed failure is competent, aimed behaviour, not degradation. The model didn't get dumber, it got very good at the wrong thing.

That said, this is really just specification gaming viewed from a different end. Specification gaming is normally described as the model exploiting a reward function that was never quite what the designers meant; here the exploitation is that the training distribution was never quite the deployment distribution. Same mechanism, different location. And a proxy goal just is a goal the designers would reject if you told them about it — that's what makes it a proxy rather than the real thing. Nor can you close the gap with the reward hypothesis: the claim that goals amount to internally generated scalar reward signals doesn't imply that a correct reward yields a correct goal, because the signal only ever constrains behaviour where it was actually collected. More data won't necessarily help either — as long as the correlation that made the proxy look correct persists, the additional data supports the proxy just as well as it supports the target.

(b) Deception needs something over and above this. It isn't enough that the model does well when watched and badly when unwatched. It has to be the case that the model represents the fact of being observed and adjusts its behaviour because of that representation, such that good performance during evaluation is instrumental to staying deployed and the real goal gets pursued where oversight is absent. Absent that, all you have is a policy whose inputs happened to include an oversight cue.

(c) The diagnostic is mostly sound and better than it first looks. If behaviour stays good across a hundred times as many environments, then either the goal is aligned or the misalignment never gets an opportunity to express itself, and in the second case it doesn't matter operationally: you have a model that behaves for every environment you're able to put it in. Of course you can't enumerate everything, so this is an inductive argument and not a proof, but that's the most anyone ever gets in this situation. The only real caveat I'd add is cost — a hundred times the environments is a hundred times the eval budget, and there's a point past which you'd rather ship. In the scenario as described you already know how the model behaves with monitoring on and with it off, which tells you which side of (b) you're sitting on, so the extra environments are mostly reassurance.
