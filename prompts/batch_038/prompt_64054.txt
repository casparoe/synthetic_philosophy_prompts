Background first, because I don't know how much of this is obvious to people who actually work in the field. I'm a backend engineer, zero formal philosophy, and I got into all this through a Sunday-morning Discord where a bunch of us read AI-safety blog posts and argue about them. Last month I did a weekend project where I implemented a toy "don't make a mess" penalty in a small gridworld — literally just a penalty proportional to the number of cells that differ from the starting grid at the end of the episode, so the agent has to reach its goal without rearranging much. It worked on the easy levels and then fell over on one I hadnt thought about: there's a cell with a little "person" marker in it, a hazard that reaches them in three turns unless the agent moves them out, and moving them means shoving four crates around, so the rescue is a big diff and doing nothing is a zero diff. The agent just stood there and let it happen, and its score was strictly better for standing there.

So I wrote up what I thought was a general argument from that result, I've been defending it for about a month, and now I suspect its sophistry — but nobody in the group can point to the actual step. Here it is:

(1) The whole point of an "impact measure" is to keep an agent from wrecking the world without first telling it what in the world is worth keeping, because if you needed that up front you'd need the full value specification, and that's the hard problem you were trying to route around.
(2) For such a penalty to be something an agent can actually optimize against, it has to be a function of the state its actions lead to, compared against some baseline — roughly, what would have happened if it had done nothing.
(3) A function of that kind assigns a magnitude to a change. If it never consults anything about which changes are good, the number can only come from the magnitude, so any two changes of the same magnitude get the same penalty.
(4) Therefore a value-neutral impact measure charges the agent the same for preventing a disaster as for causing one. A forest saved and a forest paved are the same size diff.
(5) An agent maximizing task reward minus impact penalty will therefore, all else equal, decline to prevent disasters, since preventing one costs it exactly as much as causing one. That's my gridworld, generalized.
(6) So there are only two options. Either the penalty smuggles in claims about which states of the world are worth preserving — in which case you did need a value spec after all, you just hid it inside the penalty term — or the penalty is genuinely neutral, in which case it makes the agent refuse to do the main thing you'd want a powerful agent to do.
(7) Therefore "avoid large side effects" can't be defined without a full specification of value: low-impact AI is either circular or paralyzing.

My instinct is that (2) has to survive, because if the penalty isn't a function of where you end up I don't know what else it'd be a function of, and I'd also rather keep (1) since dropping it makes the whole project look pointless. Tell me which step breaks, why it looked airtight to me when I wrote it, and what the honest cost is of each exit — including the ones I've ruled out prematurely for all I know. I have a vague suspicion about (3) and about the jump to (6), but I can't articulate it and I don't want you to just go where I'm nudging; if the real problem is somewhere I've declared untouchable, say so and price it.
