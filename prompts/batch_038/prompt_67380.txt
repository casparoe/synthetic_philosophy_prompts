I've been reading about the Lucas–Penrose "consciousness can't be a computer program" argument off and on for a couple months — mostly blog posts, no philosophy training on my end, I just write backend services for a living. The thing bugging me is that every version I run into is basically the same three lines: any program has a Gödel sentence it can't prove, we can see ours is true, so we're not programs. Meanwhile the rebuttals I find are all over the place and each one seems to knock out a slightly different argument, and I can't tell which knockouts are real and which are people arguing past each other.

So before I read one more take, I want the spec, not another argument. Write out the requirements any Gödel-based case for "the mind isn't a machine" has to satisfy to actually count as succeeding — treat it like you're writing the acceptance criteria for a design doc that keeps getting rejected in review.

For each requirement give the failure case behind it: what specifically goes wrong for arguments that don't meet it. I want the distinction-type requirements in particular, e.g. what a system can prove versus what's true of it, consistency versus soundness, the idealized unbounded reasoner versus an actual brain with a finite skull, a heat-death deadline, and a memory that's lossy and noisy, "no single program can do this" versus "no program at all can do this," and whatever else you think is load-bearing.

Also, and this is the part I actually want: label each one as either non-negotiable (any serious version, from any camp, has to clear it) or a preference of one side that's been smuggled in as if it were a requirement. I have a strong suspicion a couple of the things people insist on — some flavor of "the argument has to be constructive," or "it has to work even if we grant the machine can prove its own consistency" — belong in the second bucket. Tell me where I'm wrong.

Then: is any subset of the non-negotiable ones jointly unsatisfiable? If it's literally impossible to hit all of them at once, that's the actual result and the whole project is dead, and I'd rather hear that up front than after ten pages. Relatedly, name the single requirement that kills the most existing versions.

Last, score the main contenders against the list, briefly: Lucas's original, Penrose's version that leans on the machine not being able to know it's sound, and the hedged "well maybe humans are inconsistent" line. Pass / fail / untested per requirement is plenty, a table is fine. I don't need a bibliography or a reading list — I can't look things up right now anyway, and made-up citations are worse than none. Just make sure the requirement list comes first and stands on its own, since the scoring is only as good as the list.

American English, please.
