Talk for my reading group in two weeks, working title something like "does no free lunch finally settle Hume", and before I build slides I want to know whether the package I'm going to defend actually hangs together. Here's what I'm committed to, roughly in the order I'd present it:

1. Hume's problem is live and unsolved. Going from "it's held every time so far" to "it'll hold next time" needs a bridge principle, and any argument for the bridge is either deductive (and then the conclusion isn't in the premises) or inductive (and then it presupposes the very reliability it was meant to establish).

2. The no free lunch results are that same point made rigorous instead of rhetorical. For any two learners, whatever one gains on some set of target functions it pays back on the complement, so averaged across all possible targets everything ties. Same on the optimization side: averaged across all fitness landscapes, no search procedure beats blind search. Its a theorem, and I want to lean on the fact that it's a theorem rather than a vibe.

3. So I don't buy that a universal prior solves induction. Solomonoff weighting, Occam's razor dressed up in Kolmogorov complexity, whatever — a bias with a better marketing department, and (2) says the bill gets paid somewhere else in function space.

4. But I also think the dominance result is a genuinely big deal: the universal prior dominates every enumerable measure up to a multiplicative constant, so its cumulative excess loss stays bounded no matter what the world turns out to be like. I take that to be an internal justification for using it, one that doesn't smuggle in any assumption about which world we happen to be in. I don't see 3 and 4 as conflicting — 3 is about the philosophical question, 4 is about what you should actually run.

5. You can't bootstrap out of this. Inferring "induction is reliable" from induction's track record is vicious circularity, not the harmless rule-circular sort that people sometimes say is fine.

6. I want the problem of induction to be a substantive problem. If a way of stating it amounts to nothing more than "you can't get out what you didn't put in", I find that uninteresting and I'd rather not spend forty minutes on it.

7. And on the practical side I'm perfectly happy asserting both that NFL holds for search and optimization, and that genetic algorithms and Bayesian optimization really do work on real engineering problems.

Audit these as a set. Which pairs genuinely pull against each other and which only look like they do? Rank the real ones by severity instead of handing me a flat list where everything is equally bad, and for each say the cheapest revision that repairs it and what I give up by making that revision. Where a pair only looks bad, name the distinction that dissolves it, since I need to be able to say that out loud when someone in the group pounces. And if I can only keep five of the seven and still give a coherent talk, tell me which five and which two get cut.
