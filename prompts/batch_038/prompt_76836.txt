Ok so I'm stuck in the middle of an argument at my lab that has been running for about a year and its gone nowhere, and I want the document the two sides should have produced instead of another 40-message thread.

The two camps, roughly:

- **The guarantors.** They think alignment work should target worst-case guarantees: no reachable state of the deployed system in which the catastrophic thing happens, established by proof, verification, or hard architectural constraint rather than by measurement. Their complaint about evals is arithmetic — a system that misbehaves on 1 in 10^5 episodes will get there eventually if you run enough episodes, so a measured failure rate isn't a safety property, it's a countdown.
- **The empiricists.** They think worst-case guarantees over learned systems are unobtainable in practice, and that acting like they are produces false comfort, because the proof always ends up being about an idealized model of the harness while the real risk walks in through a channel the model never covered. What you can actually do is drive failure probability down, measure it honestly without gaming the benchmark, and build detection and correction so that a single failure isn't catastrophic.

The concrete thing they're fighting over: we want to ship an agent that can spend money up to a cap and edit part of its own scaffolding. The guarantors want a machine-checked argument that no reachable state lets it blow the cap or rewrite the limiter. The empiricists say that even if we got such an argument, it would cover the code and not the fact that the agent can write to a human operator who can raise the cap — so the guarantee sits inside a boundary that the system's most dangerous capability sits outside of.

There's one claim I keep reaching for and I want to know whether both sides can sign it: expected number of catastrophic failures is roughly per-episode failure probability times number of episodes, so an average-case bound is a genuine safety property only if you also bound exposure — either you cap how much the thing is used, or you cap how bad any single failure can be. If that's signable, a lot of the heat goes out of the argument. If it isn't, I want to see exactly why not.
