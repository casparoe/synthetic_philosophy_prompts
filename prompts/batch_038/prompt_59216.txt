The question as it was given:

> In the program-game version of a one-shot prisoner's dilemma, each player chooses a computer program rather than an action; each player's program is run with the other player's program as input, and the action it outputs determines the payoffs in the ordinary PD. Programs may also access their own source code. Define program equilibrium. What does code transparency change about the dilemma, and what does it leave intact — is mutual cooperation sustainable, and is mutual defection? What do the standard cooperative constructions assume?

The student's answer:

> Program equilibrium is Tennenholtz's solution concept for games where the players don't pick actions but pick programs, and each program is run with the opponent's program as input and outputs an action; the payoffs are then just the base game's payoffs applied to the two outputs. A program equilibrium is a Nash equilibrium of this derived game: given the other's program, no player can do better by submitting a different one. Programs are allowed to read their own source, which is what makes the interesting constructions possible, and where they can't you can get self-reference by quining.
>
> What this changes is the one-shot PD. In the ordinary game defection is the only equilibrium, because it's dominant. In the program game a player can submit a program that cooperates only if it can establish that the opponent will cooperate against it, and mutual cooperation becomes sustainable. The simplest version cooperates if and only if the opponent's code is character-for-character identical to its own: if both submit it, both cooperate, and any deviation makes the codes no longer match, so the deviator gets mutual defection at best. That's obviously brittle — one extra space and it collapses — so better versions have each program search for a proof that the opponent's program, run on its own code, outputs C, and cooperate if it finds one; Lob's theorem is what makes the two searches succeed at each other. A third version just runs the opponent's program on itself, with a small probability of cooperating unconditionally so the mutual recursion terminates. Nothing forces the programs to be friendly, either: a player could submit one that defects specifically when its opponent turns out to be a code-inspector.
>
> I'd say the whole thing is really Hofstadter's super-rationality made formal — the players can see each other's reasoning, so the symmetry that makes defection self-defeating is now explicit instead of assumed.
>
> Note that mutual defection is no longer an equilibrium. Any program that defects gets recognized as a defector by the code-inspecting programs and met with defection, so there's nothing to gain from it. Transparency dissolves the dilemma rather than just adding options to it.
>
> One limitation: deciding what an arbitrary program outputs is undecidable, so a computable agent can't in general condition its move on what its opponent will do. Program equilibrium therefore presupposes agents with halting oracles, which is why it models idealized agents rather than anything implementable.
