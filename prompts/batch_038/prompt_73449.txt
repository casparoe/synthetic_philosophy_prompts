Here's the problem as I assigned it (the setup is from the seminar handout, which is basically Tennenholtz's program equilibrium stuff):

"A program game works as follows. Each player i chooses a program p_i from a fixed set P. Every program in P halts on every input. A program takes as input the source code of the opponent's program (and may assume it has access to its own source code) and outputs an action in {C, D}. Programs may inspect the code handed to them but may not execute it — that restriction is what keeps the halting guarantee from collapsing. Both programs are then run on each other's source, and each player receives the payoff of the resulting action pair in the usual one-shot prisoner's dilemma, T=5, R=3, P=1, S=0. A profile (p_1, p_2) is a program equilibrium if neither player can get a strictly higher payoff by swapping in some other program from P while the opponent's program is held fixed.

(a) Show that (AD, AD) is a program equilibrium, where AD ignores its input and outputs D.
(b) Give a pair of programs in P that both output C when run against each other, and show that the resulting profile is a program equilibrium. Be careful about whether your programs are actually in P.
(c) Must the action pair produced by a program equilibrium be a Nash equilibrium of the underlying one-shot game? Argue for your answer.
(d) People sometimes describe the construction in (b) as showing that fully transparent agents can get mutual cooperation in a one-shot prisoner's dilemma. What is that claim leaning on?"

And here's the student's answer:

"(a) AD outputs D no matter what it gets as input, so if player 1 swaps in some other program p, player 2's AD is still going to output D. Against a D, the best p can do is output D itself, for a payoff of 1, which is what AD was already getting. So there's no profitable deviation and (AD, AD) is a program equilibrium. Worth noting this shows program games can have inefficient equilibria too, so transparency doesn't just dissolve the PD on its own.

(b) Let m be the following program: on input x, run x with m's own source code as x's input; if x outputs C, output C, otherwise output D. Now m against m: each one runs the other, each sees C coming back, so both output C and each gets 3. Suppose player 1 deviates to some program p. Player 2's program is still m, and m is now inspecting p. If p isn't the kind of program that cooperates with m, m outputs D and player 1 gets at most 1, which is worse than 3. So (m, m) is a program equilibrium.

(c) Yes. Suppose the action pair coming out of a program equilibrium weren't a Nash equilibrium of the one-shot game. Then one of the players has a better reply to the action the opponent actually plays, and that player can just submit the constant program that plays that better reply. The opponent's program was already fixed before anything ran and can't change mid-execution, so the deviator is guaranteed the payoff from the better reply. That contradicts the profile being a program equilibrium.

(d) It's leaning on each player really seeing the other's source code, and on what they see being what gets run. Also on the payoff matrix and the program set being common knowledge. So it's not cooperation built on trust — the transparency is doing the work."
