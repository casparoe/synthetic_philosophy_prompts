I work as a software engineer and have no formal philosophy training, but I have been reading Wittgenstein's late notes on certainty — the ones written in the last months of his life, published posthumously, in which he takes up Moore's claim to know such things as that he has two hands and that the earth existed long before his birth. A senior colleague of mine has been using an analogy drawn from our own line of work to close down arguments, and I want to know how much weight it can bear before I either accept or reject it.

The analogy: hinge propositions are like the configuration of a running system — the base image, the constants in the config file, the axioms the code is compiled against. You cannot test them from inside the system they configure, because any test you run already presupposes them; when a test fails you cannot tell whether the code is wrong or the config is wrong without assuming something further, and that assumption is itself config. Different teams run different configs, and there is no neutral vantage point from which to compare them, since the only way to evaluate a config is to boot a system with it, which changes the very thing under evaluation. My colleague draws a conclusion from this: where two people's hinge propositions differ — about whether the external world persists unobserved, say, or about which kinds of evidence count as evidence — the disagreement is not resolvable but only negotiable. Neither party is making an error; they are running different base images. The right response is a live-and-let-live relativism, and any attempt to argue one config out of the other is just one system trying to assert itself over another.

I would like an audit of this analogy rather than a summary of hinge epistemology. Specifically:

1. Lay out the correspondence explicitly. What plays the role of the config file, the boot process, the test suite, the version history, the failure log, and the engineer who is able to edit the config? Where an element of the source has no honest counterpart in the target, say so rather than forcing a mapping, since I suspect at least one of these is unmappable and that this is not a trivial point.

2. Separate the disanalogies that actually threaten the intended conclusion from the ones that are merely decorative. Four candidates I have come up with, which I would like you to take seriously rather than list: config files are written down and can be read off and diffed, whereas hinge propositions do not seem to be things anyone asserts or could recite; a config can be swapped by a deliberate act with a rollback plan, whereas Wittgenstein appears to deny that hinges are adopted or abandoned by decision; a bad config typically produces malfunctions that show up in the system's behavior, whereas it is unclear what a malfunctioning hinge would look like from inside; and the impossibility of testing a config from inside is a fact about one particular architecture, not a necessary truth, so the analogy may be importing a contingent engineering limitation and presenting it as an epistemic one.

3. Say what the source domain quietly imports that the target lacks. I have in mind especially the presumption that there is someone outside the system — a deployer, a maintainer — for whom the config is an object of choice, and the presumption that config is separable from code, so that the same program could in principle run under several different configurations. Tell me whether those imports are doing the real work in my colleague's argument.

4. Give me a verdict, and commit to it. Does the relativist conclusion survive once the disanalogies are on the table, or was the analogy carrying it the whole way? If it does not survive, say what weaker claim about unresolvable disagreement does survive, if any, and what would have to be true for a hinge-level disagreement to be genuinely non-negotiable rather than merely difficult.

5. If the analogy is a poor one, propose a better one and state what it buys and what it still cannot carry. I gather Wittgenstein himself reached for a physical image of a hinge on which a door turns, and for something like a riverbed that the water of inquiry both depends on and gradually shifts. I would like to know whether either does the job better than the config file, what each leaves out, and whether a third image drawn from software practice — rather than from carpentry or hydrology — would serve better.

Please take a definite position and give your reasons for it, rather than laying out the interpretive options and leaving me to choose among them. At the end, flag anything in your reading that is contested among commentators, since from the reading I have done I cannot tell which parts of this are settled and which are one school's interpretation being passed off as the text.
