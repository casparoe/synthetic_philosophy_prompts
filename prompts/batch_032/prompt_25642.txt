I'm a backend engineer working on a product that helps small teams make group decisions — prioritizing features, picking conference venues, that sort of thing. Users rank options, and the system produces a group ranking. It sounded straightforward when I took the ticket, but I've now spent two weeks trying to get the aggregation logic to behave, and I keep running into the same class of problem no matter what approach I try.

Here's the pattern. I start with a method that seems reasonable — say, pairwise majority vote. But then I find a case where a majority prefers A over B, a majority prefers B over C, and yet a majority also prefers C over A, so there's no winner at all. Fine, so I switch to a points system: each user's top choice gets N points, second gets N minus one, and so on. That fixes the cycle, but then I notice something else: the relative order of A and B in the final output can flip depending on whether some third option C is even included on the ballot, even when nobody changes their mind about A versus B. That feels wrong — why should the system's verdict on A versus B depend on whether I remembered to put C in the poll? So I try to fix that by using only pairwise information, but then I'm back to cycles. I've also tried methods where you eliminate the option with the fewest first-place votes each round, but then I get cases where an option that would beat every other option head-to-head gets eliminated early because it's nobody's passionate first choice.

I've now seen enough of these failure modes to suspect I'm not just bad at designing algorithms. It's starting to feel like I'm trying to do something impossible — like there's a general result that says you can't have all the properties you'd intuitively want in a fair ranking system at the same time. Is there a name for this phenomenon, or a formal result that captures it? And if so, what exactly are its boundaries? Does it apply only to ranked voting, or does it show up in other kinds of aggregation too — like rating systems, or budget allocation? I'm less interested in a label than in understanding what the actual constraints are: which combinations of desirable properties are mutually compatible, and where the tradeoffs really lie.
