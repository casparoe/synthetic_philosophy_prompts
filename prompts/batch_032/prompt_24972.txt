I've been reading about the philosophy of probability lately, and I keep running into something called the reference class problem, but I haven't found a discussion that really makes it click for me. I understand the basic idea: when you want to assign a probability to a single event — say, the probability that a particular bridge will collapse in the next decade, or that a given startup will fail — you need to sort that event into some class of similar events and look at the base rate. But the same event belongs to indefinitely many classes (this bridge is a steel truss bridge, a bridge in a seismic zone, a bridge built before 1970, a bridge inspected last year, etc.), and the frequencies differ across them. So it seems like you can get wildly different probabilities depending on which reference class you pick, and there's no obvious rule for which one is correct.

What I'm struggling with is whether this is a merely practical problem — we just need better statistical methods or more data — or whether it points to something deeper about the concept of single-case probability itself. Some authors seem to treat it as a devastating objection to frequentism, but I've also seen it raised as a problem for subjective Bayesianism (since your prior still has to be informed by some reference class reasoning, even if informally). And then there's the question of whether the problem shows up differently for different kinds of probability claims: the probability that this coin lands heads, the probability that this defendant is guilty, the probability that this medical treatment will work for this patient. Are these all the same problem, or does the reference class problem fracture into different issues in different domains?

I'd appreciate an explanation that walks through why this isn't just a "pick the narrowest class" issue — because I can see that the narrowest class might have n=1 and be useless — and that also touches on what the reference class problem implies about what we're even doing when we talk about the probability of a single event. I'm less interested in the technical details of specific proposed solutions than in getting clear on what makes the problem so stubborn in the first place.
