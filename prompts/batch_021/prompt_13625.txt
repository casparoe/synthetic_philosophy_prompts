So this happened after my seminar on decision theory last week and I haven't been able to stop turning it over. We'd just covered program equilibrium -- Tennenholtz's old move where instead of choosing an action directly, players submit programs, and those programs get to see each other's code before playing. The classic trick: submit a program that checks whether the other program is a literal copy of itself, cooperating only if so and defecting otherwise. Since neither side wants to unilaterally swap out its program while the other one stays put, mutual cooperation on a one-shot prisoner's dilemma turns out to be a genuine Nash equilibrium -- no repeated play, no reputation, no third party enforcing anything. Two of my grad students, Marco and Ines, got into it walking out of the room afterwards.

(1) Marco said this basically vindicates rational cooperation: two purely self-interested agents can escape the dilemma just by being transparent with each other, full stop.

(2) Ines said that's overselling it -- pair "AlwaysDefect" with itself and that's also an equilibrium, for the exact same structural reason. So transparency doesn't select cooperation, it just adds cooperation to the menu of equilibria alongside defection. Same old multiplicity problem, now wearing a disguise.

(3) Marco granted the multiplicity but said that's true of every equilibrium concept -- we don't stop caring about the efficient equilibrium in a coordination game just because inefficient ones exist too. Once you're transparent, an agent who wants to be read as trustworthy has an actual reason to submit the nice program, so cooperation should be focal in a way defection isn't.

(4) Ines said "wants to be read as trustworthy" is exactly the disposition that was supposed to be derived from rationality, not smuggled in as a preexisting preference. And the whole setup assumes you can verify you're looking at the code that will actually run, which is the hard part of trust to begin with -- nothing stops AlwaysDefect from being wrapped in packaging that looks cooperative on inspection.

(5) Marco said there's a fix for exactly that: instead of checking for a literal copy, define the program to cooperate only if it can prove the other program cooperates with it -- which can't be gamed by cosmetic repackaging the way a text check can -- and a Löb's-theorem trick lets two such programs mutually establish this without the infinite regress you'd expect from each having to simulate the other simulating it.

(6) Ines said that fix just relocates the idealization instead of removing it -- now you need common knowledge that both sides are sound proof-searchers of the relevant kind, with no real bound on search length, which might be a worse idealization than plain transparency, and it still says nothing about what bounded, possibly adversarial real agents (including actual AI systems that might someday trade source code) should do.
