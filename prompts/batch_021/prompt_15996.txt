Me and my friend got into a whole thing last night about that "does a rock implement every computer program" argument against functionalism -- Putnam's old proof that you can map basically any physical system onto any finite-state machine if your mapping is gerrymandered enough, plus the Searle bit about the wall behind him "running" WordStar. My friend's really into Scott Aaronson and kept arguing that computational complexity is what actually rescues computationalism here: sure, you can cook up some crazy mapping from a waterfall's molecules onto the states of a mind-program after the fact, but decoding that mapping back into anything usable would take as much computation as just running the mind-program yourself, so the waterfall isn't doing any real work, and only mappings that are cheap to compute should count as genuine implementations. I dont buy it -- "cheap to compute" is only cheap relative to some choice of which physical variables count as the basic states in the first place, and you get to pick that basis after the fact too, so it just feels like the same arbitrariness got moved down one level. We argued about it for like an hour and got nowhere. Can you make the strongest possible case for my side -- that bringing complexity theory into the trivial-realization debate doesn't actually save functionalism from Putnam and Searle, it just relocates the same problem?
