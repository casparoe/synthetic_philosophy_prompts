So I fell down a rabbit hole on the Liar paradox ("this sentence is false") and ended up reading about Kripke's fixed-point theory of truth. The three-valued "gappy" construction he uses is basically the same trick as computing the semantics of a recursive function via a least fixed point (start with everything undefined and keep iterating the evaluation step til nothing changes), which, as someone who writes code for a living, I thought was a pretty delightful parallel. But then I read that this approach has a "revenge" problem: a sentence like "this sentence is not true at the fixed point" apparently cant even be stated in his object language, and it blows the same hole open one level up, using resources that only exist in a stronger metalanguage. That smells to me like he hasn't actually fixed the paradox, just moved it somewhere he doesn't have to look at it directly - which seems like basically the same move Tarski makes with his object-language/metalanguage hierarchy, the thing Kripke's whole project was supposed to be an improvement on. Can you make the case that Kripke's fixed-point construction doesn't actually give a real solution to the Liar, it just relocates the same problem, and so isn't really an advance over Tarski's hierarchy?
