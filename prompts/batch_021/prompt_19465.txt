And here's the answer one of the members sent in:

"(a) The folk theorem for program equilibrium says that more or less any payoff profile that's at least as good for each player as their minmax/safety payoff in the underlying game can be supported as a Nash equilibrium once players submit programs instead of choosing actions directly, even when the stage game itself is only played once. The classic example is the 'twin' program, sometimes called CliqueBot: 'cooperate if and only if the other program's source code is textually identical to mine, otherwise defect.' If both players submit this program, each one sees that the other is identical, so both cooperate; and no one-sided deviation pays, because switching to any other program just gets read as 'not identical' and punished with defection, so a deviator ends up at the mutual-defection/safety payoff rather than getting away with the temptation payoff they were hoping for. Since neither side can do better by deviating given what the other submitted, mutual cooperation is a Nash equilibrium of the program game, not just of some repeated version of the game.

(b) The catch is that this equilibrium runs entirely on exact syntactic matching rather than anything about what the other program would actually do in general. Two programs that are functionally identical but written differently -- different variable names, an extra comment, compiled from a different language -- fail to recognize each other and lock into mutual defection even though 'really' they're the same disposition. And the strategy has no way to extend any trust to a program it's never seen before, even one that would clearly cooperate for principled reasons, since all it can check is bit-for-bit sameness. So it solves cooperation only inside a clique of literally identical code, which is closer to a password check than an account of when trust is warranted.

(c) FairBot replaces the identity check with a proof search: it cooperates with an opponent X exactly when it can find a proof, within some fixed bounded proof system, that X cooperates against FairBot, and it defects otherwise. The obvious worry is circularity -- to know if the other FairBot cooperates you'd seem to need to already know what you yourself do, and so on forever. What actually blocks the regress is Gödel's incompleteness theorem: because a consistent formal system can't prove its own consistency, the 'easy' proof that would justify mutual defection can't go through, and this is what allows two FairBots facing each other to both end up successfully proving mutual cooperation rather than the reasoning collapsing into contradiction. Where FairBot still falls short is that it can be exploited by DefectBot: because FairBot is occupied looking for proofs of cooperation rather than first ruling out guaranteed defectors, DefectBot is able to draw the sucker's payoff out of FairBot in a way a more careful agent would have avoided. PrudentBot patches this by adding a second requirement: it only cooperates with X if it can also prove that X defects against a DefectBot, so PrudentBot can no longer be talked into cooperation by an opponent that just defects unconditionally."
