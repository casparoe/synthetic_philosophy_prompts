For my decision theory seminar this semester (its cross-listed with the CS department, so it's basically turned into "game theory for AI agents") we just spent a lecture on program equilibrium: the setup where instead of picking an action directly, each player in a game submits a program that gets to read the other player's source code before it outputs a move. The classic toy example the professor put up, going back to a 2004 paper by Tennenholtz, is a program for the one-shot Prisoner's Dilemma that cooperates only if the other program's source code is literally, character-for-character identical to its own, and defects otherwise -- if both players submit this program, mutual cooperation turns out to be a Nash equilibrium of the "which program do I submit" game. For next week we've got a follow-up reading on a fancier version called FairBot, from some MIRI-adjacent logicians, which cooperates with any program it can formally prove will cooperate with it, using Löb's theorem (something about provability logic) to avoid having to simulate the other program forever.

We were procrastinating on the actual problem set and two people in my study group, Leah and Marcus, ended up arguing about how impressed we're supposed to be by any of this. (1) Leah's opening move was that the identical-source-code program is a cheap trick: rename one variable and it defects, so it's not a real solution to cooperation, just a sameness-detector wearing a game theory costume. (2) Marcus said that's beside the point, since a Nash equilibrium only requires that nobody benefits from unilaterally switching programs given the other's is fixed, and that holds here no matter how brittle the matching rule is. (3) Leah shot back that "always defect" is trivially a Nash equilibrium by that exact same standard, so pointing out that something is a Nash equilibrium doesn't yet show it's a good one -- you still need a reason to expect this equilibrium over mutual defection. (4) Marcus brought up FairBot at that point, saying that's exactly why people moved past source-code-matching: FairBot cooperates with anything it can prove cooperates with it, not just literal copies of itself, so Leah's "rename a variable" complaint doesn't touch it, and the Löb's theorem trick makes two FairBots provably cooperate with each other, which is real progress and not just a relabeled coincidence. (5) Leah wasn't having it: she said this just relocates the knife-edge instead of removing it, since now instead of needing byte-identical code, both sides need to share a common formal system and be transparent to each other's proof search, which is just as special a condition and basically never holds between two independently written real-world agents, so FairBot is a cute existence proof and nothing more. (6) Marcus's comeback was that literally every equilibrium concept in game theory leans on some idealization that never exactly holds either, like common knowledge of rationality, so that's not a fair complaint specifically about FairBot, and the actual contribution is the in-principle result that mutual transparency can turn a bad equilibrium into a good one without repeated play or outside enforcement.
