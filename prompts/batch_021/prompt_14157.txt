I've been down a rabbit hole reading old Alignment Forum posts on the AI shutdown problem, and I keep going back and forth on which of the two 'serious' proposals actually holds up. First there's the classic MIRI corrigibility paper (Soares, Fallenstein, Armstrong, Yudkowsky) -- the fix there is utility indifference: you bolt a correction term onto the agent's utility function so its exactly indifferent, in expectation, to whether the shutdown button gets pressed, which is supposed to kill any incentive to mess with the button either way. Then theres the newer Thornley approach, which instead just drops completeness -- the agent has no preference at all between trajectories of different lengths, and picks actions via timestep dominance (never choosing an action when some alternative guarantees at least as good an outcome at every timestep, and a strictly better one at some timestep) rather than by maximizing expected utility.

Both are aimed at the same failure mode -- an agent that manipulates the odds of getting shut down -- but the mechanisms are pretty different. Can you actually compare these two properly? Specifically, does dropping completeness fix the thing that made utility indifference fragile in the first place (that it's a hack which doesn't obviously survive the agent self-modifying or building subagents), or does incompleteness just hide the same instability somewhere else? And if you had to actually bet on one of these for a real optimizer, which would it be?
