Hey, quick one for a piece I'm working on about AI "negotiator" agents -- the idea that before too long, deals (procurement contracts, maybe even wages) get hashed out by bots representing each side instead of people. I fell down a rabbit hole on an old game theory idea called program equilibrium that almost nobody outside game theory/AI-safety circles seems to know about, and it feels weirdly relevant. The gist: instead of picking a strategy, each side submits a program that gets to read the other side's source code before acting, and that apparently lets you sustain cooperation in a one-shot Prisoner's Dilemma -- something ordinary Nash equilibrium says shouldnt be possible. The original trick (CliqueBot, i think its called) is dumb: cooperate only if the other guy's code is literally identical to yours. But there's apparently more robust versions built from programs that try to *prove* things about each other instead (FairBot, something to do with Löb's theorem) that don't need exact code-matching. Give me the 2-3 implications of this that actually matter for a near-future where negotiating agents get built this way -- especially whether it makes collusion between companies' bots worryingly easy and hard to regulate against, and whether the crude version's fragility means none of this matters until the provable stuff is actually deployable. Skip the history lecture, just want the practical stakes.
