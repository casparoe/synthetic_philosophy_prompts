I'm putting together a presentation for my school's AI ethics club on whether self-interested artificial agents could ever cooperate without some outside authority to enforce their promises, and in researching it I came across a game-theory idea called "program equilibrium." As I understand it, Moshe Tennenholtz proved in 2004 that if the two players in a one-shot Prisoner's Dilemma submit computer programs instead of ordinary strategies, and those programs are allowed to read each other's source code before choosing an action, then mutual cooperation can be sustained as a Nash equilibrium of this new "program game." The standard example is almost comically simple: a program that cooperates if and only if its opponent's code is an exact copy of itself, and defects otherwise. I gather this kind of source-code transparency is sometimes discussed as a rough model for how future AI agents or even smart contracts might interact with one another, which is part of why I would like to know how seriously to take it as an actual solution rather than a mere technical curiosity.

The more I read, the less settled the issue seemed. That exact-copy program, which researchers call "CliqueBot," only cooperates with byte-for-byte clones of itself, so it looks like it proves less about cooperation between genuinely different agents than about an agent recognizing its own mirror image, and it apparently breaks down the moment the two programs differ even slightly. Researchers at MIRI later tried to fix this using ideas from provability logic, building programs called "FairBot" and "PrudentBot" that can cooperate with provably similar-behaving but non-identical agents instead of requiring exact copies. Yet Tennenholtz's own theorem also shows that essentially any feasible, individually rational payoff of the underlying game, not just mutual cooperation, can be sustained by some program equilibrium, which makes me suspect the framework doesn't really pin down cooperation as uniquely rational so much as it reproduces the original indeterminacy of the Prisoner's Dilemma at a higher level, in an unconstrained choice of which program to write and submit in the first place.

So here is what I would like an essay on: does letting agents read each other's source code before acting amount to a genuine, principled solution to the commitment problem that makes defection irrational in a one-shot Prisoner's Dilemma, or does it merely relocate that same strategic indeterminacy into an unresolved "meta-game" of program selection? Please weigh the strongest considerations on both sides -- feel free to use the CliqueBot, FairBot, and PrudentBot examples and the brittleness and folk-theorem objections I mentioned, or bring in other considerations of your own -- but don't leave the question hanging. Commit to and defend a specific verdict; a qualified one (something like "it is a genuine solution only under conditions X, and merely relocates the problem otherwise") is fine, but a purely noncommittal answer is not.
