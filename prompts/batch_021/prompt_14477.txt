I have no formal background in machine learning, but I have been working through the AI safety literature on wireheading on my own, and one piece of the reasoning escapes me. Some discussions of reward tampering distinguish agents according to how they evaluate a candidate future in which they have altered their own reward function. One type of agent always plugs that future into the reward function it has right now, disregarding the fact that the function will have changed by then; the other type judges the reward received at each future moment using whichever reward function actually happens to be operative at that moment. Apparently only the second type has any built-in incentive to tamper with its own reward function in the first place. This strikes me as backwards, since I would have guessed that an agent anchored to its 'current' reward function is exactly the one tempted to just wirehead — to satisfy that function by the shortest route available. Where does this intuition go wrong, and why does anchoring evaluation to the present, unaltered reward function remove the incentive to tamper with it, while letting the standard float to 'whichever function is operative then' creates that incentive?
