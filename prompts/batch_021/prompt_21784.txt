I've been reading about epistemology on and off after a coworker sent me a link to something called the "dogmatism paradox" (I gather it traces back to some unpublished lectures Saul Kripke gave in the 1960s, later written up by Gilbert Harman). The argument, as I understand it, goes roughly like this: suppose I know that some proposition P is true. Since P is true, any evidence that might turn up later suggesting P is false would have to be misleading evidence — it would, by definition, be pointing me toward a falsehood. But if I can already see now that such future evidence would be misleading, it seems I'm entitled to discount it in advance, before I've even encountered it. So the argument appears to show that once you really know something, refusing to update in light of contrary evidence isn't a character flaw at all, but the epistemically correct response — "dogmatism," properly understood, turns out to be rationally required rather than a vice.

This has actually started shaping how I think about disagreements at work. When I've spent real time verifying that a piece of code is correct — writing tests, tracing through edge cases, checking it against the spec — and a reviewer still pushes back with some hand-wavy objection, I've started telling myself that their objection must be confused or misleading, precisely because I already know the code is right, so I don't owe it much further consideration. A couple of colleagues have called this closed-minded, but if the dogmatism paradox is a genuine proof, it sounds like they're the ones failing to reason correctly, since by their own admission I did verify the code beforehand. Is that a fair reading of what the paradox establishes, or is there a flaw in this reasoning that epistemologists have already identified?
