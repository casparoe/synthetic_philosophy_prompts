As a software engineer, I've always found the standard case for functionalism about the mind intuitive: what makes two implementations count as "the same algorithm" -- whether it runs on a silicon chip, an abacus, or, in principle, some elaborate arrangement of pipes and gears -- is their shared causal-functional organization, not the stuff they're built from, so the same should hold for mental states realized in different kinds of physical systems. A philosopher friend sent me the following passage, from Leibniz's Monadology (1714), section 17, and told me it's still treated as a genuine problem for exactly this way of thinking, centuries before anyone had the word "functionalism":

"Moreover, it must be confessed that perception, and that which depends upon it, is inexplicable by mechanical causes, that is to say, by figures and motions. And, supposing there were a machine so constructed as to think, feel, and have perception, we might enlarge it while preserving the same proportions, so that we might be able to enter it as into a mill. Now, on going into it, we should find only pieces which push one against another, and never anything by which to explain a perception. Thus it is in a simple substance, and not in a compound or in a machine, that perception must be sought."

Setting aside Leibniz's own solution -- that perception belongs instead to immaterial, indivisible "monads" -- I'd like help with the argument on its own terms. My first instinct is that Leibniz is simply confused about levels: he goes looking for perception among the mill's individual gears, when a functionalist would locate it in the organization of the whole system, much as you'd never find "digestion" by inspecting one molecule of stomach lining. But I suspect that reply is too quick. Can the argument be restated at the level of the system's organization rather than its parts, so that tracing every functional relation in the mill still turns up nothing that explains why perception should be present rather than absent? And if so, does that make this a live, unresolved problem specifically for multiple realizability, rather than just a historical curiosity about early modern mechanism? I'd like a genuinely critical assessment, not reassurance that functionalism already has this covered.
