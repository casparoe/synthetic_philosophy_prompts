Ok this is a weird hobby project thing thats been bugging me for weeks. I'm building a tiny online co-op that's run by a set of rules baked into code instead of people voting live each time, basically a constitution that's also a program. Every few years the members can adopt a whole new rule-set, and I didn't want that handover to be blind trust, so I added a safety check: before the current rules step aside, they have to verify, using nothing but their own logic, that whatever the new rule-set ends up deciding is something the current rules would also sign off on, no matter what that decision turns out to be. But when I actually try to build that check for real, one of two things happens. Either it's so strict it can never verify anything, so the handover never happens, or I loosen it just a bit and it suddenly "verifies" basically anything, including obviously terrible changes, like the whole safeguard collapses the second it becomes useful at all. I've gone through the logic a bunch of times and don't think its a bug in my code, it feels more like "prove today, using only what you know today, that future-you can be trusted" might just be broken as an idea, not just hard to code. Is that an actual known thing? And if it is, does every system that hands power to a future version of itself, maybe even a person trying to trust their own future judgment, end up stuck taking that on faith eventually, or is there a real trick that gets around it?
