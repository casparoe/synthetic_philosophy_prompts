"Both objections try to trivialize computationalism by quietly allowing unlimited computational resources, and Aaronson's strategy in both cases is to bring resource bounds back into the picture.

Take the lookup-table worry first. Aaronson's giant lookup table stores a canned reply for every possible conversation up to some length, so from outside it behaves just like a real conversational partner, which seems to show that passing a behavioral test doesn't require real understanding. His reply is that such a table isn't just big, it's infeasible to ever construct: to fill in the correct entry for every possible dialogue history, whoever builds the table would already have to solve, in advance, every instance of the very cognitive task the table is meant to replace, and there are exponentially many such instances. So the intelligence hasn't been removed, it's been pushed into an infeasible construction phase. A mind that runs in polynomial time couldn't have been built that way, so the lookup table isn't a real alternative to computation, just a way of hiding it.

The triviality argument gets similar treatment. Putnam and Searle claim a rock or a wall can be mapped onto any finite automaton if you're willing to define the mapping in a sufficiently convoluted way. Aaronson's answer is to insist that the mapping itself has to be efficiently computable and has to go on working if you feed the system different inputs, not just describe the one trajectory it happens to follow. A real computer satisfies this; a rock only "implements" the automaton for the single run you've already fitted it to, and refitting it for a new run costs as much work as just doing the computation directly.

Since both moves show that the apparent trivializations only go through if you help yourself to unbounded computation, and that real minds are complexity-bounded rather than merely Turing-computable, Aaronson's arguments establish that computationalism is correct."
