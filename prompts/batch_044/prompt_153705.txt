I've been working through some constructivist mathematics and its overlap with formal verification, and I've kept running into a particular argumentative move that I can't name. Here are two instances. First: in a discussion of the intermediate value theorem, someone rejects the classical proof that a continuous function crossing zero must have a root somewhere, on the grounds that without an explicit algorithm to approximate the root we haven't actually shown that any particular number is that root. So far, standard constructivism. But then the same person talks about "the root we haven't found yet," treating its absence as a temporary gap in our knowledge rather than as the absence of a constructed object, and suggests that if we eventually compute an approximation, that will have "confirmed" the non-constructive proof rather than replaced it with a genuine construction. Second: in security analysis, a proof shows that some protocol must contain a vulnerability—by contradiction, assuming none exists leads to an impossibility—without exhibiting the actual attack vector. The researcher insists this doesn't establish a real vulnerability, yet in planning mitigations they speak of "the hidden flaw" as if it has a definite location in the code, waiting to be uncovered, and they treat discovery of an exploit as validating the abstract proof rather than supplying the missing constructive content. In both cases, the speaker starts with what sounds like an ontological claim—without explicit construction, the object lacks being—but slides into treating it as an epistemically hidden but fully real entity. Is there an established concept for this specific collapse? How does it differ from ordinary scientific realism about unobserved entities, and how does it differ from the constructivist's own careful distinction between weak existence and explicit knowledge? If the literature doesn't name it, what precise boundaries separate it from adjacent confusions—say, from a straightforward misapplication of intuitionistic logic, or from a pragmatic heuristic in engineering—and what term would capture the slippage exactly?
