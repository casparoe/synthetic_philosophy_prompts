hey, im a software engineer with basically zero formal philosophy training, so sorry if this is a dumb framing. i've been noticing something in my work about how code or models "point to" things outside themselves, and i think there might be a philosophical concept for it, but i don't know the vocabulary.

there are two patterns i see all the time. first: i write a variable called `customer_email`. it refers to an actual email address only because i decided it should. if i renamed it to `x` nothing in the world changes, so the "aboutness" feels borrowed from me. second: in a trained model there's an internal activation that consistently fires for cat images, but nobody designed it for that. it tracks cats because of statistical correlations in the weights, not because anyone assigned it. so it points to cats, but not through anyone's intent.

is this the same split philosophers talk about with "original" vs "derived" intentionality - like searle and dennett's argument about minds vs symbols? or is my shadow register a different axis entirely? maybe there's a name for this "intentionally built but semantically opaque" reference?
