Two colleagues, Jordan and Casey, argued over lunch about whether program equilibrium actually solves cooperation in a one-shot prisoner's dilemma or merely relocates the strategic problem.

Jordan opened: in program equilibrium, each agent submits a transparent program that receives the opponent's source code and then plays cooperate or defect. If both submit programs that cooperate exactly when the other does, then rational agents will submit cooperative ones—mutual cooperation is stable, and hidden defection is impossible because the code is fully visible before execution.

Casey replied: writing the program is itself a strategic choice, so the dilemma just moves up one level. You could submit code that looks cooperative but contains a hidden conditional—say, one that parses a specific syntactic feature of the opponent's program and defects if that feature is present—so you're still playing a standard game, just with source code instead of actions.

Jordan countered: full source transparency means the opponent's program can parse your entire code before running. Any hidden conditional is visible in the source, so the opponent's cooperative program can detect it and defect in response. Deception is impossible by design, not just discouraged.

Casey came back with what she called the equivalence-class problem: even with full source access, verifying that the opponent's program is genuinely cooperative requires solving the halting problem for arbitrary inputs, so perfect verification is undecidable. Two programs might be syntactically different but semantically equivalent, or syntactically similar yet diverge on edge-case inputs that never occur in this run. Jordan's "detection" assumes verification that computation theory rules out.

Jordan answered that this is a red herring: practical program equilibrium restricts agents to a decidable programming subset—no unbounded loops, no self-modifying code—so verification works. Smart contracts do exactly this. The undecidability objection applies only to unrestricted Turing-complete languages, and equilibrium can be defined over bounded domains.

Casey closed: restricting the language just pushes the conflict into the meta-level. Choosing which restrictions to accept is itself strategic, and an opponent could submit a program written in a slightly different but permitted subset that behaves cooperatively on every input you actually check, yet defects on an unchecked edge case. The "bounded" solution becomes an arms race over specification languages, which is essentially a repeated interaction. So program equilibrium doesn't eliminate repetition; it encodes it in language negotiation.
