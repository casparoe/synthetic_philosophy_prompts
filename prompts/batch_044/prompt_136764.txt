I am trying to identify the underlying principle that determines when a strategic interaction genuinely admits a program equilibrium, judging by my reactions to concrete configurations.

Consider a two-player Prisoner's Dilemma in which each agent submits a fully transparent source-code program that takes the other program as direct input. Program A contains the instruction: cooperate if and only if running B's code against A produces cooperation. Program B is symmetric. My verdict: this is a canonical and legitimate program equilibrium, and mutual cooperation is the outcome.

Now change only the visibility condition: the programs are compiled into opaque binaries that can be queried only through a noisy black-box oracle with a non-negligible error rate. The logical structure of the conditional is identical, but the epistemic access is broken. My verdict: cooperative program equilibrium collapses here; the reasoning no longer applies.

Extend the transparent setup to three agents, each program verifying that the other two contain the symmetric cooperative condition. Despite the increased computational burden, my verdict is that this remains a valid program equilibrium.

Here is the case that troubles me. Each player's source code is encrypted with a key embedded inside the other player's code. Thus A can decrypt B only if B is already executing, and vice versa. Intuitively this should function identically to the transparent case—mutual access is structurally guaranteed—yet I am unsure whether this circular dependency renders the cooperative condition undefined, making the configuration fall outside program equilibrium altogether, or whether it is simply a technically complex instance of the same thing.

Next, consider simulation-based strategies: A contains a virtual machine that runs B's code against a copy of A, and B does likewise. The loops converge deterministically to mutual defection, which is then executed in reality. I think this technically qualifies as a program equilibrium, but it feels qualitatively different—more like a computational coincidence than a reasoned conditional commitment.

Finally, imagine a meta-intervention: upon reading B's source, A's program rewrites B's instructions before B executes. Even if B originally contained the cooperative conditional, B now defects. My intuition is that this violates the rules of program equilibrium, though I am not sure whether the failure concerns execution order, alteration of the opponent's strategy space, or breach of a transparency norm.

Is there one precise principle—perhaps centered on well-founded epistemic access, non-interference with the opponent's strategy space, or the absence of circular dependency in the evaluation order—that captures all these verdicts? State it exactly, identify which clause addresses each case above, predict its verdict on an unconsidered scenario—specifically, transparent programs running on asynchronous clocks with non-deterministic message delays that may deliver the opponent's code before or after execution—and say honestly which of my verdicts your principle cannot accommodate without revision.
