In debates over open-source sustainability, a common analogy treats a shared code repository like the classic overgrazed meadow: the code is the grass, deploying firms and users are herders who graze by consuming free libraries without maintaining them, maintainer burnout and security debt are soil erosion, and proprietary licensing or mandatory corporate contribution are the fences. This is used to claim that open source is structurally a commons tragedy and needs enclosure to survive. A rebuttal argues that the mapping collapses because code is non-rivalrous — one firm's use does not reduce another's — so nothing is actually being over-consumed; the real scarcity is maintainer attention, which makes the problem closer to under-provision of a public good with positive network externalities, not overuse of a rival resource. Audit the analogy: give the explicit correspondence table (meadow, herder, grazing, erosion, fence), then identify the disanalogies that matter for the enclosure argument — especially rivalry, excludability, and whether maintainer attention behaves like soil. Does the conclusion that open source needs enclosure survive once these breaks are visible? Then assess the rebuttal's counter-frame: is the public-good analogy more accurate, or does it smuggle in its own misleading features about scalability and free-riding?
