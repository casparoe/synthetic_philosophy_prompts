I'm a software engineer, and this came up at work when we were arguing about whether a simulation we wrote could be replaced by a cheap statistical model. Someone pointed me to Stephen Wolfram's A New Kind of Science, and the section called "Computational Irreducibility" has been bugging me ever since. He writes:

"In traditional science it has usually been assumed that if one can succeed in finding definite underlying rules for a system then this means that ultimately there will always be a fairly easy way to predict how the system will behave. Several decades ago chaos theory pointed out that to have enough information to make complete predictions one must in general know not only the rules for a system but also its complete initial conditions. But now computational irreducibility leads to a much more fundamental problem with prediction. For it implies that even if in principle one has all the information one needs to work out how some particular system will behave, it can still take an irreducible amount of computational work actually to do this. Indeed, whenever computational irreducibility exists in a system it means that in effect there can be no way to predict how the system will behave except by going through almost as many steps of computation as the evolution of the system itself."

I get the computational claim — like, theres no closed-form shortcut, you just have to run the system. But I can't figure out what it actually means for explanation. Some of my coworkers read it as: prediction is hard, sure, but you can still understand a system by knowing its rules and how the parts interact. Others read it as something much stronger, namely that for some systems the only honest explanation is the system's own execution, so explanation itself hits a hard limit.

Can you write out a dialogue between two people who know this stuff cold and disagree about exactly that? One should defend the strong reading — that computational irreducibility puts a real limit on explanation, not just prediction — and the other should argue that explanation and prediction come apart, so we can understand a system even when we can't shortcut its behavior. Make them both sharp, no strawmen, and make them respond to each other's actual points over several back-and-forths. Maybe have them stay grounded in a concrete example, like one of Wolfram's cellular automata, so they dont float off into abstraction.
