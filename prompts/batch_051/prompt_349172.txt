I'm a novelist, not much of a programmer, and I've been building a little Python tool to track the revisions of a manuscript. I keep getting into arguments with myself about what the word "same" is supposed to mean when code runs. If I revert a chapter to an earlier version, and every word is exactly the old words again, did I get the same chapter back? If my editor says the new draft is "the same but tighter," I understand it in life, but I can't figure out what rule a machine should follow. So I want a working definition of 'same thing' in a running program—identity, equality, whatever term you think is the right one.

Here are the cases I need it to sort. (1) `x = 5; y = 5`, two variables assigned the number 5 independently. (2) `x = [1,2]; y = x; y.append(3)`—afterwards x has changed, so I want to say they're the same list. (3) `x = [1,2]; y = [1,2]`—now y is a seperate list with the same contents, and changing one doesn't change the other. (4) `t = ([1,2], 'ch1'); u = tuple(t)`, a copy of a tuple that still holds the same inner list, so mutating `t[0]` leaks into `u`. (5) A mutable `chapter` object whose `text` field I append a new paragraph to—still the same chapter, obviously? (6) `restored = json.loads(json.dumps(chapter))`—same data, newly built object. (7) In git, `checkout HEAD~1` back to a previous commit—same file content, but the old file. Give the definition, run it through all seven, tell me where it gives an answer I didn't expect, and say which verdict is the least secure. Bonus if it explains why mutation makes the word "same" do two or three jobs at once.
