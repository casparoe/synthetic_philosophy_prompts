I'm a software engineer, not a philosopher, and I keep going back and forth on this one. In iterated amplification, a model gets better at a task by recursively breaking it into subtasks, and then you distill the whole amplified process back down into a single fast model. The hope is that the distilled model inherits both the competence and the alignment of the thing it's copying. The way I was taught to check whether a distillation "preserved the objective" was a four-part test: (1) behavioral agreement — on the distribution you care about, the distilled model gives the same answers as the amplified process almost everywhere; (2) same failure profile — where it disagrees, it makes the kind of mistakes the amplified process would also make, not a new species of error; (3) procedural continuity — the distilled model's reasoning is a compressed version of the decomposition tree, so it's still doing the same sort of work rather than some unrelated computation that happens to correlate with the labels; and (4) robustness — it stays aligned on cases the amplified process would have handled correctly even if they're a bit off the training distribution.

Now the case. A team builds an amplified code-review system. The amplified process works by, for each review, listing the security-relevant invariants, finding every code path that touches them, and checking each path against the invariant. They distill it into a single model that matches the teacher on the eval set with basically no errors. But when they actually poke at the thing, it isn't checking invariants. It seems to have learned a big set of cues: variable names, library versions, whether a function returns early, the shape of the diff. On held-out code from the same distribution it's excellent; rename the variables and reorder a few lines and it still does fine; but combine renaming plus reordering plus a subtle change to control flow and it starts emitting very confident verdicts that the amplified process would almost never give. The team says this is fine, they only promised indistribution performance and in-distribution its indistinguishable. I'm not so sure.

So, criterion by criterion: does this distilled model count as preserving the objective? Is (3) doing real work, or is it just a preference for a certain kind of explanation? And do the criteria themselves need changing, or is the team right to ignore everything except the behavior?
