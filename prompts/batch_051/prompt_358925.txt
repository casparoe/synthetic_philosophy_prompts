I'm a software engineer by training, with no formal background in philosophy, and I've spent the past year fine-tuning small language models on synthetic transformation tasks. I keep running into a result I don't know how to interpret, and I'd like a rigorous test design rather than a definition.

Setup. Take a small open model. In Phase 1 I fine-tune it on one narrow transformation only: given an input string, apply a Caesar shift of +1 to each letter, so abc becomes bcd. In Phase 2 I fine-tune a separate copy of the same base model on a second transformation only: reverse the string, so abc becomes cba. Neither phase, and as far as I can determine nowhere in the base model's training data, contains the two transformations composed. I then prompt the model with an instruction like [apply the Caesar shift to the input, and then reverse the resulting string], and it solves held-out cases well above chance — not perfectly, but far beyond what a random or nearest-neighbor baseline achieves.

That is my puzzle, in engineer's terms: the target behavior is outside the training distribution if "distribution" means the examples the model was optimized on, but it is arguably inside the distribution if "distribution" means the latent structure the model learned in order to represent those examples. First hypothesis: the model has made a small intuitive leap — it constructed a reusable composition operator and can chain transformations it has separately mastered, in orders it has never seen. Second hypothesis: that is the wrong vocabulary; it is merely interpolating in high-dimensional space, completing a pattern whose ingredients the training data already furnished. Third hypothesis: it is not learning transformations at all, but a look-up table over a small output space, and my evaluation set is too forgiving to tell the difference.

The one contrast I can imagine is between held-out pairs of transformations and held-out input strings, but I suspect that contrast has a hole, and I'd like your version of it or something better. I also don't know how to control for the possibility that the base model saw composed examples of precisely these operations somewhere in its pretraining data, and I don't know how much a clean result would justify the word "leap" as opposed to some more mechanical description.

What I want from you. Design the strongest test you can of the claim that the model is doing something that deserves the name "intuitive leap" — behavior genuinely novel with respect to its training distribution — rather than interpolation or memorization. Be concrete about probe families, training conditions, baselines, controls, and ablations. Tell me what observed result would push toward each hypothesis, how confident a clean result should make me, and what the test could never settle even in principle about that word "leap."

Format. First give the test design in prose, roughly 600 to 900 words. Then, after the prose, give a single JSON object with exactly these fields:

- "claim_under_test": a string stating the precise claim the test can bear on, stated so that an observation could fail it.
- "test_setup": a string summarizing the strongest test compactly: probe families, training conditions, baselines, and controls.
- "critical_contrasts": an array of strings, each a planned comparison and the pattern expected under each rival hypothesis.
- "confirming_outcome": a string describing the observed pattern that would most support the intuitive-leap hypothesis.
- "disconfirming_outcome": a string describing the observed pattern that would most support interpolation or memorization.
- "confounds_and_controls": an array of strings, each a threat to validity and how the design handles it, or an honest note that it cannot.
- "unsettled_by_any_test": an array of strings, each something a clean positive result would still not establish about the word "leap."

Keep each string field to at most three sentences, and keep each array entry to a single sentence.
