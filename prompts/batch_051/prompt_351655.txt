Consider a one-shot Prisoner's Dilemma between two risk-neutral firms, A and B, who will never interact again. The payoff matrix is the standard one: if both cooperate, each receives 3; if both defect, each receives 1; if one defects while the other cooperates, the defector receives 5 and the cooperator receives 0. Both firms can write and verify computer programs, and both have access to a neutral escrow service.

A proposal is made for the following institution. Before the interaction, each firm submits to the escrow service the complete source code of a deterministic program that will select its move. Each program may accept as input a complete copy of the other firm's submitted program, and may simulate or analyze that program in any way the language permits. The escrow service determines A's move by running A's program on B's source code, and B's move by running B's program on A's source code. Because the two evaluations can recurse into one another, the service imposes a step limit: if a program's top-level evaluation has not terminated within L steps, that firm is recorded as having defected. The service also charges each firm a fee proportional to the number of computational steps spent evaluating that firm's top-level program, including any simulation of the opponent's program that it initiates, with the fee paid regardless of the outcome.

The proposer argues that the scheme allows each firm to make its behavior depend in a binding way on the other firm's behavior, so that a program which cooperates exactly when the opposing program would cooperate against it becomes viable, and mutual cooperation emerges as an equilibrium at modest computational cost.

Analyze how this mechanism would actually behave. Specifically: what programs would we expect to be submitted in equilibrium, and does anything resembling mutual cooperation survive? How can the mechanism be exploited—through the timeout rule, through programs that are deliberately expensive for the opponent to simulate, through collusion with the escrow service, or through other channels? Does the step-based fee improve matters or make them worse? Which failure modes, if any, could be fixed by small amendments such as forbidding certain programming constructs, randomizing the timeout, changing the fee schedule, or requiring cryptographic commitments to the source code rather than full disclosure? Finally, what would you advise the two firms to submit, and what rule would you advise the escrow service to adopt?
