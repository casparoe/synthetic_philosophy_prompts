I keep running into a four-part definition of "learning from experience": (a) new expectations are shaped by earlier cases, (b) on the actual problem it's applied to, it does better than chance, (c) if the training data had been different its predictions would be different, and (d) it doesn't just impose a rule the designer picked in advance — the pattern it follows has to come from the data. Now here's the case bugging me. Picture an algorithm built to be completely assumption-free. It lists every possible mapping from inputs to binary outputs, gives each one equal weight, throws out the ones inconsistent with the data it has seen, and then predicts each new case by majority vote among the survivors. The trouble: for any unseen input, every surviving mapping that outputs 1 has a twin that differs only on that input and outputs 0, so the vote is always exactly 50/50, no matter what the data looked like. This is the old underdetermination problem in machine form: the data by themselves never settle what the next case is. The no-free-lunch result makes it sharper — averaged over all possible target mappings, every algorithm has the same expected error on new cases, so nothing beats coin flips unless it brings some prior bias about which mappings are more plausible. So does this zero-assumption algorithm count as learning from experience under (a)–(d), or not? Go through the criteria one by one, flag where they underdetermine the answer, and then say whether the case shows one of the criteria needs changing — in particular whether (d) should really be "it has the right kind of bias, not no bias at all."
