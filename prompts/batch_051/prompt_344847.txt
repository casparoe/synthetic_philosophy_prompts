I keep turning over a parallel between a doctrine in the Jain tradition and something from database engineering, and I cannot tell whether it is a genuine structural resemblance or a loose metaphor. Anekantavada, the Jain doctrine of non-one-sidedness, says that because any finite thing has indefinitely many qualities and relations, no single unconditioned assertion captures it; every claim is true only relative to a particular standpoint, and syadvada, the accompanying theory of conditionally prefixed predication, accordingly licenses a battery of modes: in some respect the thing is, in some respect it is not, in some respect it both is and is not, and in some respect it is inexpressible, with the complete truth emerging only from the combination of such partial descriptions. This looks to me like the picture a database gives under multiversion concurrency control: each transaction reads from a consistent snapshot of committed data, so two concurrent transactions can each correctly see different values for the same row, and the system answers the question what is the value only after fixing a version or timestamp, treating both snapshots as correct relative to their versions rather than naming one unconditioned state as the truth. Is this a deep identity of structure, or does the analogy turn on the single word perspective? To earn the strong reading, what would have to be true on both sides for results to transfer, for example is there a database counterpart of the inexpressible mode, and does the serializable order that reconciles all snapshots secretly reinstate the single privileged viewpoint anekantavada was designed to deny? I would like the answer as continuous prose, with no headings, bullet points, bold text, or tables, written the way one would write an email.
