I'm a software engineer with basically no formal philosophy background, but I've been going down a rabbit hole on whether human values are many separate things or just one thing in disguise, and I wrote up a rough essay idea. I'd love comments from someone who actually knows the philosophy, because this is probably full of category errors. Below are my notes.

The analogy I keep reaching for is refactoring. In code, you sometimes look at a system and see a pile of special cases—a check for admins here, a check for mobile there, slightly different discount logic for returning users—and then you realize they're all one function with a couple of parameters. One piece of code, many behaviors. But the opposite happens too: someone builds a single abstraction that's supposed to do everything, and it ends up as a god function with forty boolean flags, and everyone agrees the code was really doing several different things that got crammed together.

So my thought is: maybe the monism-vs-pluralism debate in value theory is like asking whether a codebase is 'really' one function or many. I dont mean values are literally code. I mean the one-vs-many question is better treated as a question about which representation compresses a person's actual evaluations better. The 'data' would be all the cross-situational choices, tradeoffs, regrets, and corrections a person makes. If a single value plus a small table of context weights predicts most of that data, that's evidence for one value wearing different hats. If you have to retune the weights ad hoc for every new context and they don't pattern together, that's evidence for genuinely many values.

I also thought about it as lossy compression. A one-value model is like storing one base function plus a table of contexts. A many-values model is like storing several small functions and no base function. There's a tradeoff between model complexity and fit. The one-value model picks up epicycles when the base function has to be deformed for each new context; past some point the 'one value' is doing no unifying work. The many-values model overcounts if some of its 'distinct' values actually move together across contexts. So the substantive question seems to be: which side of that tradeoff curve do real humans live on? And I suspect a lot of monists and pluralists are mostly talking past each other because they're optimizing for different things—one side for elegance, the other for fit.

Where I think this might be original (probably by accident) is the idea that 'how many values do we have' is ill-posed the way 'how many functions does this codebase have' is ill-posed until you fix a compression scheme. But I can't tell if I've actually said something or just reworded the obvious.

Could you comment on this? Specifically: (1) where does the refactoring analogy genuinely track something in value theory, and where does it break? (2) Is the compression framing doing real work, or is it just dressing up an old point in engineer-speak? (3) What's the strongest objection to the 'question is badly posed' move? (4) If you were going to turn this into an actual essay, what's the one idea worth keeping and what should I cut?
