I am taking a course on the philosophy of computation, and we have been studying the Ship of Theseus. I am trying to work out what happens to the puzzle when the ship is implemented as a program. Suppose Theseus is represented as a mutable record holding an array of plank values, where each plank value carries a unique grain pattern so that original and replacement planks are distinguishable by their contents. Each year a plank is removed, the corresponding array element is overwritten with a newly allocated plank, and the removed plank is put into storage. After enough years every element has been overwritten, and the stored planks are assembled into a second record, Rebuilt, whose elements are the original plank values.

In a language with object identity, the runtime seems to settle the puzzle in one direction: the record referred to by Theseus has remained numerically the same object through every mutation, while Rebuilt is a fresh allocation, so the continuously repaired record counts as the original. But that verdict is hostage to the decision to mutate in place. Consider instead a purely functional language without mutable fields or object identity, where each year's repair produces a new value by copying the previous value and changing one element, and the previous value is discarded. No object persists from the first year, since every stage yields a distinct value. Yet where object identity tracked the continuously repaired record, equality by value points the other way: Rebuilt has the same plank values as the initial configuration, whereas the current ship does not. The verdict appears to flip when identity is replaced by value equality. A further complication arises with aliasing in the mutable version. If two names refer to the same plank array and the yearly update is performed through one of them, the change is visible through the other as well; the array behaves as shared state rather than a collection of independently replaceable parts, a non-local effect that the original wooden ship could not exhibit.

What I am trying to understand is how the traditional analyses of the Ship of Theseus — the persistence of the original material parts, spatiotemporal continuity, and functional continuity — map onto these implementation choices. Does the runtime actually settle the philosophical question, or does it merely relocate it into a design decision about allocation, copying, and equality? Which standard answers to the original puzzle are encoded by each implementation strategy, and is aliasing the deeper reason mutation is difficult to reason about?
