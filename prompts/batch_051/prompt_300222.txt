I'm an associate at a seed-stage venture fund, and I want to build a one-page checklist we can use in our Monday partner meeting to decide whether a founder gets a second meeting. The conceptual problem is the reference class problem: any given founder can be sorted into lots of classes (dropouts, ex-FAANG, second-time founders, founders in our city, founders in this exact sector) and every class gives a different base rate, so I never know which reference class to use when I'm estimating the probability that this particular founder will succeed. I need a procedure I can actually run in about fifteen minutes with only a pitch deck and my notes, and it should tell me which reference classes are admissible, which are too gerrymandered, and when we should just admit there isnt a class. The partners have to sign off on whatever I use, so it has to feel legible to people who don't know the theory. Apply the procedure to three cases: a 22-year-old college dropout, a 45-year-old ex-FAANG engineer building the same thing her old manager built, and a founder whose previous startup failed but had real revenue. Make one of the worked examples spit out a pass on someone our partners would probably love. Also mark clearly which steps are judgment calls dressed up as procedure, and say what the whole thing cannot do.
