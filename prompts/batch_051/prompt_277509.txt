I've been going back and forth on a question that came out of a conversation at work, and I suspect the confusion lies with me. A while ago I read a little about what is called the language of thought hypothesis: roughly, the idea that the mind has its own internal code, made up of smaller symbols that combine into larger thoughts, and that thinking consists in mechanically processing those symbols according to rules. But when I program, I appear to be doing something extremely similar. A programming language is also a system of symbols that combine into larger structures, and a machine executes those structures mechanically. That observation led me to a conclusion that seems too neat: if thinking is the mechanical processing of compositional symbols, and programming is the mechanical processing of compositional symbols, then writing a program is just thinking out loud in a language of thought, and the brain's native code is simply the program we have not yet learned to read.

Yet this conclusion sits badly with how programming actually feels. Much of the thinking takes place before any code is written—in ordinary language, rough diagrams, and half-formed hunches—and a programmer can be genuinely surprised by what a piece of code does when it runs. If writing the code already was the thinking, that surprise would be hard to explain. So I imagine the equivalence goes wrong somewhere, but I cannot locate the step. What exactly is the difference between the symbol-processing the mind is supposed to perform and the symbol-processing a computer performs when it executes a program, such that one counts as a language of thought and the other does not? Or is the whole contrast misdrawn?
