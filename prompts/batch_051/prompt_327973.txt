Im a novelist, working on a novel set maybe fifteen years out, where programming has become mostly prompting, with the old languages drifting into something like latin—still read for legacy systems but almost never written fresh. I keep circling back to the old argument that a programming language is not a neutral notation, that it shapes the thoughts you can have while working in it: the language you think in changes which solutions even occur to you. That argument was built when a human was the one doing the thinking in the language. The development I want to test it against is this: for a growing share of software, a human states the problem in English, a model emits working code in whatever language it likes, and the human mostly reviews tests and behavior rather than reading the code itself.

I want a philosophical post-mortem on that argument, not a tech prediction. Does the shapes-thought argument survive when the machine writes the code? Lay out what the argument actually needed to be true in order to work, identify which premise a world of machine-generated code puts pressure on (if any), and say whether there's a repaired version that still gives programming languages a real cognitive or practical role—or whether they've become something else, like a checking or debugging interface, and should stop being talked about in the old way. If you think the original argument survives, show me why machine generation misses the premise that mattered. If you think it dies, tell me what's left of language choice and what we should call the thing that still matters, so I dont smuggle the old idea into the book by accident.
