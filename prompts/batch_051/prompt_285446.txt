I bump into this parallel every time I teach a programming-languages class, and I can't decide if its deep or just a vocabulary coincidence. The usual story is that mutation is hard because it breaks substitutivity: if two names point at the same mutable cell, updating through one changes what reading the other gives you, so you can't just swap equals for equals anymore. The functional programmer's fix is to never mutate — each "update" produces a new value and the old value still exists, so every state is a distinct object and substitutivity comes back. That looks exactly like how perdurantism deals with temporary intrinsics: the bent thing and the straight thing are different temporal parts, not one thing with incompatible properties. Mutating in place, by contrast, is endurantist: there's one object that itself changes, and you need special machinery to reason about it (heap ownership, separation logic, temporal logic) much like an endurantist needs a special account of time-indexed properties. So: is value semantics to perdurantism roughly what reference semantics is to endurantism? Where does the mapping actually break — maybe because pointer identity is stipulated by the runtime while diachronic identity is supposed to be a fact out in the world? And what's something this parallel would predict that turns out false?
