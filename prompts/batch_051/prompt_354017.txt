I work on developer tools at a small company, and our build and deployment topology has gotten weird enough that I keep going back and forth with a colleague about where one program ends and the next one begins. We both half-remember the old Free Software Foundation line about the GPL, the one that made the separate-work/derivative-work question turn on whether two pieces of code form a single program at runtime — whether they share an address space, call each other's functions, are built together, that sort of thing. Under that picture, linking against a GPL library makes the result a derivative and triggers copyleft, while merely talking to a separate program over a pipe or a network was supposed to keep the two works distinct. That always felt a little hand-wavy to me, but it did at least fit the Unix world it came out of.

The problem is that almost nothing I build looks like that anymore. We ship containers that are explicitly different processes but get treated as one application; services run seperately and talk over queues, HTTP, and shared schemas that function like an interface; a user can drop a plugin into a GPL-licensed host even when we never linked anything ourselves; and a chunk of our glue code is generated by models trained on a huge amount of GPL code. So my actual question is whether the old one-program argument survives these developments. Is it still basically right and just in need of updated examples? Does it need a repair — and if so, which premise is actually under pressure (process boundary, human authorship of the connecting code, intent to create a combined work)? Or is it dead enough that we should rebuild the notion of a derivative work from what copyleft was actually trying to protect? If you think there is a repaired version, give me the weaker principle you would actually rely on. And please keep the epistemic bookkeeping explicit: separate what is settled enough to act on from what is genuinely contested among people who know this stuff (a lot of the things engineers repeat about linking are less settled than they sound), and do not present the FSF position as neutral consensus.
