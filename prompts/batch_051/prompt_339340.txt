I'm a PhD student in scientific computing and I keep hitting the same wall when I turn code into specs or review someone else's PR. A routine returns roots, or an eigendecomposition, and the value is fine mathematically but only up to relabeling, sign, or basis choice. I want a reusable checklist — something I can actually run in like fifteen minutes before writing the spec — for deciding when I should (a) refuse to promise an ordering at all, because any deterministic one would be arbitrary or discontinuous, (b) impose some canonical convention anyway because users or downstream code will depend on it, or (c) resolve repeated eigenspaces properly instead of pretending the routine returns 'the' eigenvectors. What tests do I run to tell those apart? It should cover at least: a cubic root finder with two complex-conjugate roots, an SVD that may hand back a sign-flipped singular vector, and a small symmetric eigenvalue routine with a repeated eigenvalue. Be honest about which steps are judgment calls dressed up as procedure, and say what the checklist can't decide. Then apply it to those three cases; make sure at least one verdict is one I'm not going to like (say, that I should tell an user the deterministic output they rely on isn't actually determined).
