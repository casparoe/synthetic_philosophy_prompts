I keep noticing a structural parallel between the bootstrapping problem in epistemology and the way a compiler can be used to compile itself, and I want to know whether it is a real identity of structure or just a loose analogy. On the epistemology side, the problem is that a subject can seem to establish that perception is reliable by using perception itself: I check what I see by looking again or by touching, but each check is itself another perceptual deliverance, so the source under audit is also the only instrument of the audit, and the conclusion that perception is reliable appears to come too easily. On the compiler side, a compiler for a language can be written in that language and compiled once by some existing compiler; afterwards, each new version of the compiler is produced by compiling its own source code with the previous binary. A corrupted or malicious binary can survive this process indefinitely, faithfully compiling the pristine source while silently inserting a backdoor into every compiler it produces, so the source code one reads is never the whole story about what will run. Both cases seem to share one abstract shape: a self-referential process that is both the object being certified and the instrument of certification. Is that shape deep or superficial? If it is deep, does anything on the compiler side transfer to epistemology — for instance, that a self-certifying process can have a clean track record yet be compromised in a way no inspection of its source reveals? If it is superficial, where exactly do the two cases come apart, and what would the parallel falsely predict about easy knowledge?
