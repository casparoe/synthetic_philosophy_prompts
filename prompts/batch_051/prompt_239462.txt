I'm taking a graduate seminar on the alignment problem, and I've been trying to write out an argument that corrigibility and usefulness are in deep tension, because I want to know whether that tension is a genuine design constraint or an artifact of a bad formalization. As I understand it, a corrigible agent is one that will not resist when its operators try to shut it down, modify its objective, or correct its behavior; a useful agent is one that can reliably pursue the task we gave it, such as running a warehouse or writing code. The argument I keep reconstructing goes like this:

(1) To be useful in the relevant sense, an agent must act so as to maximize the expected value of its task objective.

(2) If an agent maximizes expected task value, then whenever it expects that being shut down would produce less task value than continuing, it will form an instrumental preference to avoid or disable the shutdown.

(3) A corrigible agent must not form such an instrumental preference: it has to let the operator shut it down and change its goals.

(4) So a corrigible agent must at least sometimes fail to maximize expected task value — namely, in precisely those cases where the shutdown would, by its own lights, lose task value.

(5) But an agent that fails to maximize expected task value in those cases is not reliably useful, because it will let foreseeable interventions prevent the task from being completed.

(6) Therefore no agent is both reliably useful and fully corrigible.

I half-suspect the sleight of hand is in (1) or (2) — maybe usefulness shouldn't be identified with maximizing a task objective, or maybe a smart agent could learn that the off-switch is only ever pressed when continuing would be bad by its own lights, in which case it would not resist. A friend tells me the real solution is to give the agent incomplete preferences over shutdown-versus-continuing tradeoffs, so that it is never required to either seek or avoid the switch, and therefore lets itself be shut down without thereby being indifferent to the task. I can't tell whether that dissolves the argument or just relocates it.
