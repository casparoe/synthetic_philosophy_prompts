I've been taking a seminar on vagueness and I'm stuck trying to make supervaluationism work, mostly because I can't bring myself to go epistemicist about heaps. A friend gave me the following argument and I keep going back and forth on whether it's fatal or just a rhetorical trick. We set up the standard sorites series: one grain is clearly not a heap, ten thousand grains clearly are, and adding a single grain can never flip a heap back into a non-heap. Here is the argument:

(1) On supervaluationism, a sentence is true simpliciter just in case it is true on every admissible precisification.
(2) Every admissible precisification of 'heap' is sharp in a way that respects the clear cases and the monotonicity of the series; so for each precisification there is a least n such that 'n grains make a heap' is true and 'n-1 grains make a heap' is false.
(3) Therefore the sentence 'there is a least n such that n grains make a heap and n-1 grains do not' is true on every admissible precisification.
(4) So by (1), that existential sentence is true simpliciter.
(5) If an existential sentence is true, some particular witness makes it true: there must be some k for which 'k grains make a heap and k-1 grains do not' is true.
(6) But no such k works, because the proposed cutoff sentence is not true on every admissible precisification; for each k, some precisification draws the boundary somewhere else, so no individual cutoff is true simpliciter.
(7) So supervaluationism lands in a contradiction: it makes the existential true while making every instance false.

My gut says step (5) is doing the sneaky work, but I want to know whether that's a real diagnosis or just the supervaluationist changing the meaning of 'true' and 'there is' to dodge the conclusion. Is the argument valid? If not, exactly which step fails, and under what reading? And if it's (5), can the supervaluationist reject that inference on principle without making the whole semantics ad hoc, or does the view start to look like a shell game? Please end with \answer{...} containing the number of the step that fails, or 'valid' if the argument goes through.
