I run a monthly workshop for rationalist-adjacent folks — mostly programmers and math-adjacent people, a few who've read some philosophy. About 14 people, 75 minutes. I want a session that makes them feel the force of mathematical structuralism, specifically the idea that "is 2 an element of 4?" isnt a real question about numbers: arithmetic only pins down the structure of the naturals (first element, unique successor, ordering, addition, multiplication), and any implementation with the right structure is as good as any other, so membership facts are just artifacts of whichever encoding you picked. I don't want to lecture this; I want them to run into it themselves.

Here's the rough shape I'm imagining, but you should turn it into a runnable activity: split the room into two groups and give each group a different but equally natural-looking build rule for the natural numbers as nested boxes or envelopes. One group uses the rule where each number is a container holding all the previous numbers (0 is the empty container, 1 contains 0, 2 contains 0 and 1, etc.). The other uses the rule where each number is a container holding only the previous number (0 empty, 1 contains 0, 2 contains 1, etc.). Have them build up to 4 and write a short spec for their construction. Then run a role-play where they're rival standards committees and I, the facilitator, am a client who only needs the naturals for arithmetic: ordering, successor, addition, multiplication. Both implementations pass my tests. Then someone asks whether 2 is an element of 4, and the two groups give opposite answers. The reveal is that my acceptance tests never mentioned membership, and both specs still satisfy everything I actually needed.
