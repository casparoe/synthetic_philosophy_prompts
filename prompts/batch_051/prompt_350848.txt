I'm a PhD student working on AI safety, and I've talked myself into a corner with an argument that seems to show the whole 'control' programme is empty, which I refuse to believe — or at least I want a precise reason not to. It came out of our reading group and I might have mangled it, but here it is.

(1) The control approach starts from the idea that we shouldn't assume a powerful model is aligned, so we should treat it as maybe-misaligned and wrap it in safeguards: monitoring its outputs, auditing its code with other models, sandboxing, red-teaming, keeping it away from dangerous tools, and so on.

(2) A safeguard only adds security if the thing doing the checking is itself trustworthy in the relevant way. If the monitor is easily fooled or itself compromised, its sign-off adds nothing.

(3) Any monitor or auditor we actually use is either another AI system or a human (or a human using AI, which just moves the problem one step up).

(4) If it's another AI system, then it may be misaligned too — whatever reason we had to doubt the first model applies equally to the checker. So it can't be the thing that vouches for the first one.

(5) If it's a human, then for the models we're actually worried about, the human often can't tell skilled bad behaviour from innocent-looking competence. A sufficiently capable model can make it's plans read as normal, competent work.

(6) So every safeguard inherits the exact problem it was meant to solve: either it means trusting another system that's untrusted for all the same reasons, or it's too weak to catch the relevant behaviour. The regress never bottoms out in something we can trust.

(7) Therefore control measures can't add security by themselves. Either you've aligned the model (in which case they're redundant) or you haven't (in which case they're just theatre). The only real option is alignment.

The conclusion feels absurd because the same shape of argument would show that no security practice against an intelligent adversary ever works — auditing, locks, code review, juries, all of it. But I can't find the bad step. I'd rather keep (1) and (3) than give up (7), but if (7) has to go I want to know exactly what I'm paying. Which premise or step should I reject, why did it look fine, and what does rejecting it cost? Also, could you write the answer in British English? It's for something I'm co-writing with a UK-based group.
