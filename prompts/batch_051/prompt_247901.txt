Ok so I fell down a rabbit hole on the two-envelope paradox (two envelopes, one has twice the other, you pick one, and the argument that switching has expected value 1.25 times what you hold seems to say you should always switch, even though by symmetry the other envelope is just as good). I'm a software engineer and my probability background is mostly undergrad CS, so I want to make sure I'm not missing something before I write a blog post about why the always-switch argument is broken.

Here's the angles I've already seen, so dont repeat them:
- the setup gives no prior over the smaller amount, and there's no uniform distribution over all positive reals, so the 50/50 double-or-half premise is smuggled in;
- with an improper or heavy-tailed prior the expected values blow up or become undefined, so expected-value maximization stops giving advice;
- for any actual proper prior, the probability that the other envelope has 2x given that yours has x is not 1/2 for every x, so the calculation uses conditional probabilities that can't all be right;
- the x in the two branches is an equivocation: in the 2x branch x is the smaller amount and in the x/2 branch x is the larger amount, so you're summing values from different states as if they were the same;
- the symmetry argument: the same reasoning run from the other envelope says switch back, so the argument is symmetric and can't actually favor either side;
- even taking the 1.25x at face value, that's expected dollars, and better only follows if utility is linear in money; with log utility the expected log-gain of switching is zero, so the always-switch conclusion also smuggles in risk neutrality.

I want one more objection to the always-switch reasoning that isn't a rewording, special case, or combination of those. And be straight with me: is it actually any good, or would I embarass myself if I put it in the post?
