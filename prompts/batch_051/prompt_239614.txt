Been going down a rabbit hole on copyleft and derivative works—where does one program end and another begin, basically—and I keep tripping over the old FSF line on linking. Their argument, as I understand it, was that if two pieces of code get linked together into one address space and call each other's functions, they've been combined into a single program, so the whole thing becomes a derivative work and the GPL applies to all of it. Two processes talking over a pipe or a socket, by contrast, were treated as mere aggregation—two separate programs communicating at arm's length, even if one is GPL'd. So the test sort of rode on process boundaries and address spaces.

What's bugging me is this: the way we ship software now, a "program" is often twenty microservices that are useless without each other. They share schemas, get deployed as a unit, call each other over HTTP, but run in separate processes, usually separate containers. By the old address-space test that's mere aggregation, but in any meaningful sense it's more tightly coupled than a lot of code that gets statically linked into one binary. So does the FSF's argument for where one program ends and another begins actually survive that shift? Or did it secretly depend on a picture of a program as a artifact you compile and ship, and microservices just dissolve that picture? If it survives, what does it need to be true—is there a better boundary than address space? If it doesn't, then is "derivative work" doing any real work here anymore, or is it just a license-enforcement convention?
