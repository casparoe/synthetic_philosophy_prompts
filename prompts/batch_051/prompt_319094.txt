I write novels now, but I spent my twenties writing code, and a parallel has been bugging me for months. Philosophers distinguish vicious infinite regresses from benign ones — the classic vicious case is an explanation that keeps deferring: A is explained by B, B by C, C by D, and the original thing never actually gets explained. The classic benign case is the truth regress: p, it's true that p, it's true that it's true that p, and so on, where nothing seems broken. In programming there's a suspiciously similar split: a recursive function with no base case just spins or blows the stack, but a productive corecursive stream — say an infinite lazily-evaluated list — can be nonterminating and still well-defined, because you only ever consume a finite prefix. It struck me that this might not be an analogy at all: maybe a vicious regress just is nontermination, and a benign regress just is a definition that passes a productivity condition. Wether that's real or I'm pattern-matching is exactly what I can't tell. If it is real, does anything transfer both ways? In CS, productivity isn't free — you need guard conditions, and innocent-looking corecursive definitions can fail them — so does that mean alleged benign regresses in philosophy should all have something guard-like, and if one doesn't we should revisit whether it's vicious? And is there a philosophical benign regress that has no CS counterpart, which would show the mapping breaks? If it's superficial, I'd like to know precisely where the structures come apart.
