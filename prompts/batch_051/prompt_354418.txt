I've been writing code for about fifteen years, and for the last two my team has let an LLM generate a big chunk of the code that actually gets merged, and I keep noticing something about how the programming language has changed its role for me, and I don't have a word for it. It used to be the thing I thought in: I'd pick Python or Go or Rust partly because of the kind of program it made natural to write, and the language felt like my medium. Now I mostly pick a language by how much of it the model has soaked up, because completions in a giant, boring language are just better than completions in a cleaner one with a small corpus. And I write comments that read like instructions to the model, then let it do the syntax, then review the result more or less the way I'd review a junior dev's code. The language hasn't disappeared — it's still what I read — but it isn't quite what I write anymore. It's turned into something between a target the model writes toward and a shared protocol that lets me check whether the model understood what I wanted. Is there an established name for this shift, a programming language going from notation you think in to a coordination device between a person and a generator? I know it brushes up against older ideas like declarative languages, programming by example, and the old executable specification dream, but I don't think any of those quite captures it, because those still assume a person (or at least a language) doing the expressing. If there's no standard term, I'd want a precise one, with clear boundaries: at what point does a language stop being the medium and become the protocol, and does this mean programming languages end up mattering less, or mattering more?
