So at work we've got this rule in the engineering handbook, been there since like 2018:

"All production code must be written in one of the approved languages: Java, Go, or TypeScript. Every change must be reviewed and approved by at least one engineer other than the change's author before it can be merged."

We just rolled out a coding assistant that writes a lot of our code now, and two teams are using it in ways that feel like they're gaming the rule.

Team A has the assistant write everything in Rust because the model is better at Rust, then auto-transpiles the Rust to Go before merge. Nobody reads the Go; the review is done on the Rust. So the code that ships is Go, but the code that was actualy written and reviewed was Rust.

Team B has the assistant write directly in Go, but the "author" on the pull request is the model (we added it as a bot acount), and the human reviewer mostly just checks that the tests pass and hits approve.

The rule was obviously written before anyone imagined a model writing code. My question: under the plain words of the rule, does either team violate it? Then walk through what the purpose of the rule would say, what the people who wrote it would probably say if you asked them now, and what a reasonable engineer reading it today would think. What is "the language" even protecting once a machine is doing the writing — is it still about the language, or about something else (reviewability, debuggability, supply-chain safety, hiring, whatever)? And if you were rewriting the rule today, what would the new version say?
