At work I got asked to generate some "random" 100-bit strings to use as seeds for a simulation, and when I sent them over, a colleague said they weren't random because I'd used a PRNG. Someone else said that's backwards: no particular string is random, only the process that produced it is. I realized I've been confidently calling individual strings random my whole life and I cant actually say what I mean by it.

So: give me a working definition of "random" as a property of a single finite string (say, 100 bits). It has to handle these cases, which I'm listing roughly from the ones I'm most sure about to the ones I'm least sure about:

(a) 100 zeros in a row. I'm sure this isn't random.
(b) 0 1 0 1 0 1... for 100 bits. I'm sure this isn't random either.
(c) a string I got by actually flipping a coin 100 times. I'm sure this is random.
(d) the exact same string as (c), but produced by a deterministic PRNG seeded with the current time. I have no idea whether this is random, and I also don't know whether "same string, different origin" should be allowed to change the answer at all.
(e) the first 100 bits of the binary expansion of π. It passes the usual statistical randomness tests, but it's also generated by a tiny program, so part of me wants to say it isn't random—but I can't say why passing the tests shouldn't settle it.
(f) the first 100 bits of the Thue–Morse sequence, built by starting with 0 and repeatedly appending the bitwise complement of what you have: 0, 01, 0110, 01101001, and so on. It has an even shorter rule than π, but at a glance it looks patternless.
(g) a 100-bit string from a hardware RNG that uses thermal noise. I'm sure this is random.
(h) a string a friend typed while trying to "make it look random." It has lots of local alternation and no long runs. I want to say it's less random than (c) or (g), because it was produced by a mind that was avoiding exactly the kind of patterns (a) and (b) have.
(i) the bits of a compressed photo of my cat. They look like noise and pass the same tests, but they encode something highly structured, so calling them random feels wrong, though I can't justify that feeling.

I know one candidate answer says a string is random iff it's shortest description is about as long as the string itself. That would call my coin-flip string random and the π string not random, which mostly matches my gut, but it also seems to make "random" depend on a choice of description language and on how clever the describer is, and it makes (d) something I could never actually check. I don't want a literature review on this—I want you to actually give me a definition, run it through (a)–(i), tell me where it gives a verdict you didn't expect or no verdict at all, and then either revise it or defend the surprises. If your definition makes (d) come out different from (c), say why the generating process gets to matter for a property of the string; if it makes them the same, say why my urge to distinguish them is misguided.
