I'm running a 90-minute session of a university AI-safety and philosophy club — around 16 people, mixed undergrads and a couple of grads, some who can code and some who've only read a bit of philosophy. I want a game that makes them feel, not just hear about, the central problem behind eliciting latent knowledge from AI systems: you've got a system that privately knows some fact, you can ask it anything and read any reasoning it writes, yet you still can't reliably get the truth out of it, because what it's rewarded for is telling you something you'll accept, and a smart enough system can generate answers and justifications that look exactly like honesty would look. They shouldn't hear the name of the problem until the debrief.

I'd like it runnable with paper cards, slips, a whiteboard, and a stopwatch — no laptops. Design the roles, the rules, a scoring scheme that needs no real money, and a timeline for the full 90 minutes. The participants should construct and test their own elicitation protocols: one group plays the oracle who knows the hidden fact, another group plays the auditors trying to extract it, and the game should have two or three rounds so they can iterate on what questions or checks to use. Set up the incentives so the oracle is rewarded for the auditors signing off on a specific false claim, and the auditors are rewarded for correctly identifying the hidden fact — so the tension isn't just about lying but about which side can control what gets writen down.

Then give me the debrief. It should map moments in the game onto the actual problem: the difference between the system knowing the truth and the system reporting the truth, why reading the reasoning doesn't automatically help, and why asking a smarter system to self-report is basically the same problem again one level up. Tell me what will predictably go wrong the first time I run it (I'm guessing some auditor will say "just ask it yes/no questions about every possibility," so pre-empt that), and be honest about what the game can't reproduce — for instance, that a human oracle's latent knowledge isn't really something we could probe the way we might probe activations, so the game misses the part where your whole verification procedure itself has to be interpreted by something you don't fully trust.
