I'm a retired physicist who's spent the last few years reading philosophy of mathematics, and I keep getting stuck on the Church-Turing thesis. What trips me up isn't the Turing machine side but the other term in the thesis: "effectively computable." Every book says its an informal notion—a function computable by a finite, mechanical, rote procedure—but then the same books say the thesis is neither a theorem nor a mere definition, precisely because that informal side is fuzzy. So I'd like you to produce a working definition of "effectively computable function," precise enough to grade the cases below rather than just giving the textbook gloss.

Cases I want counted in: Euclid's algorithm for gcd, and a Python program that lists the primes. Case I want counted out: the full halting function, the one that decides for every program/input pair whether it halts.

Now the ones I genuinely cant settle.

(a) A physical oracle: a black box, swiped from some aliens, that answers any halting question correctly, every time. No finite set of human-readable instructions describes it; its internal physics is unknown. Is the function it defines effectively computable? I lean no, but to the person using it, the box is just a faster, more opinionated pocket calculator.

(b) A trial-and-error machine that, at each time t, prints a 1 for every program that has halted by step t and a 0 for every program that hasn't, so a 0 sometimes gets changed to a 1 later. For each fixed program the printed bit eventually stabilizes to the right answer, but there is never a moment when the machine certifies that it has finished. Is the settled answer effectively computable, or is this just the halting function with extra steps?

(c) Shor's algorithm running on a quantum computer: it produces the right answer with overwhelming probability but never with certainty. Effectively computable or not?

(d) A hypothetical real-number machine whose one primitive step is exact addition or multiplication of two arbitrary reals, not digit by digit, so a single step manipulates an entire infinite expansion. Some hypercomputation people treat this kind of machine as super-Turing; others say it shouldn't count because each step already carries an infinite amount of information. Which way does your definition push?

I'm attached to keeping Euclid in and the full halting function out, and I'd like the definition to be principled rather than just "whatever a Turing machine can do," since that would make the Church-Turing thesis a tautology. So tell me, once you have the definition, whether it makes the thesis a definition, an empirical claim, or something else.
