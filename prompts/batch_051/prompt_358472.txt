I keep trying to pin down what should count as a derivative work for the GPL's copyleft reach — not the actual case law, which is a mess, but the principle you'd use to decide a new fact pattern from scratch. Give me a working definition (or a decision procedure, if a definition is hopeless) that gets these cases right and lets me sort new ones:

- a modified copy of a GPL-licensed source file, distributed as a binary;
- a proprietary program that statically links against a GPL library;
- a proprietary program that dynamically links against the same library at load time;
- a proprietary plugin that gets loaded into a GPL host's process and calls its plugin API;
- a seperate proprietary program that just invokes a GPL command-line tool and parses its output;
- a patch file distributed against the GPL original, containing only added and context lines, not a full copy of the source;
- a server that speaks a public network protocol to a GPL client (the client is GPL, the server is not).

For the record: I'm confident the first is derivative and the fifth isn't; I lean derivative on the second and fourth; the dynamic-link one I've flip-flopped on; the patch and server cases I genuinely don't know.

Run your definition through all seven, say which cases it misclassifies or just shrugs at, and either fix the definition or defend the surprising verdict. If the honest conclusion is that 'derivative work' is not doing real conceptual work here and it's all downstream of whatever policy you want, I'd rather here that than a definition that's just been optimized to fit my list.
