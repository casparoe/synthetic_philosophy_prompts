Before I read any more papers that use "tool" and "agent" as if the line were obvious, I want the full specification of what an account of that distinction has to accomplish. The purpose, for concreteness, is the one common in AI-safety discourse: the line is supposed to track which systems could pursue goals in ways that diverge from what their operators intend, not merely which systems sound autonomous.

Write the desiderata that any adequate account of the tool AI / agent AI boundary must meet, with the case or consideration behind each. The cases an account has to classify correctly should include at least: a thermostat, a chess engine that runs only when invoked, a self-driving car handling an unplanned detour, an LLM with web search and a code sandbox that can run commands, and an LLM wrapped in a scaffold that plans, executes, and keeps going until it judges the task complete. The account should respect—or consciously collapse—distinctions such as unattended operation vs. acting on one's own goals; having an objective function vs. having a terminal goal; selecting means vs. initiating ends; and narrow competence vs. low initiative. For each desideratum, say whether it is non-negotiable (the distinction collapses without it) or merely a preference of one camp, and flag any pair of desiderata you suspect cannot be jointly satisfied. Finish by stating the single requirement that does the most work in separating tool AI from agent AI. Do not survey the literature; this is a spec.

Organize the response in these sections, in order, with the lengths noted:

1. "The cases" — the concrete cases and how each constrains the line (about 40%).
2. "The distinctions" — which distinctions must be respected, collapsed, or explicitly rejected, and why (about 25%).
3. "Non-negotiable vs. camp preferences" — which requirements are load-bearing and which are optional (about 20%).
4. "The load-bearing requirement and tensions" — the single requirement that does the most work, and any jointly unsatisfiable pairs (about 15%).
