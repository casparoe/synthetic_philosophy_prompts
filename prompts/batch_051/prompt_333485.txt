I'm trying to figure out whether there's a single principle behind my sense of which uses of state and mutation make code hard to reason about, rather than just a loose family resemblance. Taking a language like Python, my gut verdicts on small cases are roughly these:

- `x = x + 1` is fine, but `x += 1` makes me slightly uneasy even though for an integer they come to the same thing.
- `lst = lst + [4]` is fine; `lst += [4]` is not, because the original list is visibly changed for any other name that referred to it.
- After `a = [1,2,3]; b = a`, the rebinding `b = [1,2,3,4]` is fine, but `b.append(4)` is not: `a` has changed too.
- `lst.sort()` bothers me because it mutates and returns nothing useful, while `sorted(lst)` is fine.
- Calling a mutating method directly on an object I'm holding in the same scope feels fine; moving the identical operation into a function that takes the object as an argument makes it not fine, even when the function's name announces what it will do.
- Replacing a whole row in a table of values is fine, but reaching through aliases to update a single cell inside a nested value is not.
- Identity-by-address (`a is b`) bothers me in a way that value equality (`a == b`) does not.

None of these verdicts is non-negotiable, but I'd be surprised if they can all be kept. My working theory is that the hard cases are exactly those where an update changes an existing value in place rather than installing a new value under a name: mutation as hidden action at a distance on whatever else shared the value. But the theory already says `x += 1` should be harmless, since integers are immutable, and it seems to say the same mutation should feel bad whether it happens via a method or a free function, which violates another verdict. So: what principle, if repaired, best captures the pattern? State it precisely, say which clause is motivated by which case, say what it rules about cases I haven't listed (copy-on-write layers, append-only logs, swapping array elements in place, two names for one object when the program is single-threaded and all aliases are visible, move semantics), and be explicit about which of my verdicts it forces me to abandon and why.
