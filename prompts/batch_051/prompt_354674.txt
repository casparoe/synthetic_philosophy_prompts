I build a desktop application that links against a copyleft-licensed library of the GPL variety, and I have spent more time than I would like trying to understand why the derivative-work boundary cuts where it cuts. What puzzles me is that the boundary does not track any technical distinction I know how to draw. If I copy a few hundred lines of a GPL program into my own source tree, rename the identifiers, and ship the result, there is broad agreement that my program is a derivative work and must itself be distributed under the GPL. If I instead write a separate program that merely invokes a GPL command-line tool and parses its output, almost everyone treats the two as independent programs. But real engineering lives between those poles: dynamic linking at load time, static linking at build time, a proprietary plugin that calls into a GPL host through a stable function interface, two processes exchanging messages over a local socket according to a schema I defined myself, a header file copied verbatim so that my compiler can resolve the signatures, or a small module that exists only to translate my application's calls into calls to a GPL service. Some of these are widely treated as making my program a derivative work, and some are widely treated as not making it one, even when the amount of expression copied, the causal dependence, the degree of functional coupling, and what a user actually sees are roughly matched.

I am not asking for legal advice, and I am not trying to settle what the license requires in any particular court. I want to understand what idea about where one program ends and another begins this whole practice presupposes. Since I have no formal training in philosophy, I would like the implicit view reconstructed in plain, concrete terms. Does the practice presuppose that a program is fundamentally an authored text, so that the decisive question is whether someone reproduced or modified that text? Does it presuppose that a program is a discrete executable process or address space, so that packaging at runtime settles it? Or does it presuppose something about the author's act of composition and intent? What rival views of the identity of a program does the practice quietly rule out? Are its parts consistent with one another—for example, is it coherent to treat two dynamically linked binaries as one work while treating two socket-connected processes as two? Please distinguish what the practice strictly presupposes from what it merely fits well with, and identify the places where it is underdetermined enough that several different views would license the same boundary.

Finally, suppose we replaced the presupposed view with a different defensible one—for example, that programs are individuated by the interfaces their authors deliberately maintain, or by the causal graph of the running system, or by what the user experiences as a single tool. What would concretely have to change in how the copyleft boundary is drawn, and which of the borderline cases—plugins, local sockets, dynamic loading, generated bindings—would flip?
