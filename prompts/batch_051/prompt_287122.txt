I'm a backend engineer (mostly SQL, some Neo4j, a little RDF at an old job) and I ended up in an argument with a philosophy friend about whether the name Sherlock Holmes refers to anything, and what it means to say something is true in the stories. The way he laid out the options: one camp says a name is just a pointer to its bearer, so a name with no bearer is a dangling pointer and sentences using it are false or maybe neither true nor false. A second camp says a name carries descriptive content along with it, so Sherlock Holmes has a kind of meaning even if nothing in the world answers to it. A third says fiction is an operator or context: Sherlock Holmes lives at 221B Baker Street is true inside the stories and false or undefined outside them. A fourth says Holmes is a nonexistent object that has properties without existing, whatever that amounts to. Then there's the truth-in-fiction side: is it true in the stories that Holmes had a gallbladder even though it's never mentioned, because he's a human and humans have gallbladders? Or do you only import background facts when the story seems to invite them?

I keep wanting to translate all of this into the vocabulary I actually trust: tables and rows, foreign keys that can be NULL or point at soft-deleted rows, referential integrity, ON DELETE SET NULL, schemas or namespaces, maybe a fiction graph where nodes don't have to dereference against the base graph. I don't want an anology, I want a real translation. For each camp, tell me which data-modeling move it corresponds to, where the mapping is exact, and where you have to fudge. Then the residue report: what in the debate has no counterpart in a database at all. I keep getting stuck on negative existentials — how do you run a query for a row that isn't there, have it come back true, and have it be about that specific missing row — and on the fact that two readers can both talk about Holmes while disagreeing about which stories are canonical. My hunch is that philosophers are just reinventing nullable foreign keys and per-schema querying, but I suspect I'm quietly deleting something. Tell me if my hunch is right and, if not, what the database model can't see. Be as precise as you can about the fudge points.
