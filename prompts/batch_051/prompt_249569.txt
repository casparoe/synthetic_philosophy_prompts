I've been thinking about the proposal to treat argumentation as a competitive sport—with scoring, rankings, and an adversarial structure—and I keep noticing a parallel with adversarial software testing, in particular fuzzing and property-based testing. In both cases you set up an opponent whose job is to break the artifact, and you treat surviving the attack as evidence of quality: a debater who handles every objection looks like a program with no known counterexample, and a scored debate looks like a test suite. But the testing side carries a well-known caveat: fuzzing can find bugs but never prove their absence, and a program that passes today can fail on a new input tomorrow. I want to know whether that caveat transfers. If it does, then even a rigorous scored debate could at most show that a position has not yet been broken by this opponent, not that it is true or likely true. Does the analogy run that deep, or does it break down because a debater can revise their position in real time while a program cannot patch itself mid-test? And if it holds, what would a coverage metric for debate look like, and could a debate sport be designed so that winning tracks truth rather than mere survival?
