I am a software engineer with no formal training in philosophy, and I recently came across the doctrinal paradox (also called the discursive dilemma) in group decision-making. The standard example runs like this. A three-judge panel must decide a breach-of-contract claim. The defendant is liable just in case two facts both hold: the contract was valid (P) and it was breached (Q), so the conclusion is L = P ∧ Q. Each judge holds an internally consistent set of judgments:

| Judge | P | Q | L = P ∧ Q |
|---|---|---|---|
| A | true | true | true |
| B | true | false | false |
| C | false | true | false |

If the panel votes issue-by-issue by majority, it gets a 2–1 majority for P, a 2–1 majority for Q, and a 2–1 majority against L. The group therefore ends up with {P, Q, ¬L}: a state that violates the constraint L ⇔ (P ∧ Q) and that no individual judge holds.

This immediately looked to me like the kind of invariant violation I debug for a living. Each judge is a replica holding a row that satisfies a schema constraint; majority voting is a merge function that takes the winning value column-by-column across replicas and assembles a result without re-checking the constraint. Every individual row is consistent; the merged row violates a CHECK constraint across columns. In my world, when a per-column quorum read can assemble a row that violates a cross-column invariant, we reach for read-repair, serializable transactions, or better merge rules, and we have a whole family of results about which guarantees cannot be combined.

I want to know whether this parallel is real structure or just pattern-matching. State the mapping precisely and say where it breaks. What would have to be true of both sides for a result to transfer in either direction?
