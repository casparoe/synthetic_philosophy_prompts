Play it sharp, not a strawman: you'll allow that types can be thinner or thicker, and you'll concede small points, but you dont give up the claim that the work is an abstract type distinct from any of its tokens. Stay in character and in first person, and keep replies to a paragraph. Here's my opening. Consider a fully studio-built electronic track: assembled in a DAW, never performed, no score, no rehearsal, every detail — timbre, panning, filter sweeps, even the exact placement of a sample — baked into the recording. There just is no performance the recording traces; the recording is all there is. So what's the abstract type here? If the recording is only a trace of some token, the type must include every one of those production details in order to distinguish this work from any other, and no later performance could count as a token of the same type unless it reproduced all of them — which makes the work unperformable in principle. If instead you thin the type down so performances are possible, you've stripped away exactly the features that make the track what it is. Either your view says a huge swath of actual music contains no works, or "work" no longer does the job musicians and listeners need it to. Which horn do you grab?
