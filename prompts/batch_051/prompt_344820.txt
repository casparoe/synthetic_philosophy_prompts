Consider a one-shot prisoner's dilemma. Two players simultaneously choose either C or D. If both choose C, each receives 3; if both choose D, each receives 1; if one chooses C and the other D, the C-player receives 0 and the D-player receives 5.

Now consider a modified version of the same underlying game. Instead of choosing an action directly, each player submits a computer program to play on their behalf. A referee gives each program the complete source code of the other program as input, runs both programs with those inputs, and pays the players according to the actions the programs output, using the matrix above. Assume that programs may refer to their own source code, that they always terminate and output exactly one of the available actions, and that they can test two strings for exact equality.

The following argument has been put to me as a way of dissolving the dilemma.

(1) Let P be the program defined as follows: if the opponent's source code is exactly the same string as P's own source code, output C; otherwise output D. The definition is well formed because P can refer to its own source.

(2) If both players submit P, then each program sees that the other's code is identical to itself, so both output C, and both players receive 3.

(3) P is a best response to P. If a player deviates to any other program Q, then P sees that Q is not identical to P and outputs D. The deviator's best possible reply to a certain D is D itself, for a payoff of 1, which is less than 3. No unilateral change of program improves the deviator's payoff, so (P, P) is a Nash equilibrium of this one-shot prisoner's dilemma.

(4) The reasoning appears not to depend on the particular payoffs 3, 5, 1, and 0. It seems to require only that both players prefer the target outcome to what the punishment action leaves them, and that the punishment action keeps any would-be deviator's payoff below the target outcome. Consider, for example, the following symmetric three-action game. The row player's payoffs are given in the matrix; the column player's payoffs are symmetric.

            X     Y     Z
      X     2     1     3
      Y     1     1     1.5
      Z     3     1.5   4

In the ordinary one-shot game, Z strictly dominates X: against each possible choice by the other player, Z gives the row player a higher payoff than X does. Nevertheless, set the target action to X and the punishment action to Y, and let R be the program that plays X if the opponent's source code is exactly R, and otherwise plays Y. If both players submit R, both output X and each receives 2. If a player deviates to any other program, R outputs Y, and the best the deviator can then obtain is 1.5, by playing Z. So the construction seems to make the outcome (X, X) an equilibrium of the program version of the game, even though each player's action in that outcome is strictly dominated in the original game.

(5) That is the conclusion I find hard to accept. If the same move that yields cooperation in the prisoner's dilemma also turns strictly dominated actions into equilibrium outcomes, then either the generalization hides a mistake, or the program version is doing something far stronger than the prisoner's dilemma story indicates.

Where, if anywhere, does the argument go wrong? Identify the step or premise you would reject, explain why it looked harmless, and say what rejecting it costs. If you think the argument is valid, state exactly what has been shown about the program version, and explain why the consequence about dominated actions should not count as a refutation of the setup.
