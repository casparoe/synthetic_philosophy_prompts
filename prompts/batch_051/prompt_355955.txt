I work as a software engineer on a team building a system that infers user preferences from logged behavior using inverse reinforcement learning. A colleague of mine presented the following argument, and I have not been able to identify a bad step in it.

(1) The method assumes that observed behavior was, in the relevant sense, near-optimal: the user selected actions so as to get more of what they want, so the unknown reward function is whatever the recorded behavior is optimal for.
(2) If reward functions may be arbitrary, then any recorded behavior can be made optimal by some reward function; a reward of zero everywhere does this trivially, since every policy is then equally good.
(3) It follows that no observed behavior ever rules out the reward functions under which it would have been optimal.
(4) In particular, observations cannot decide between two reward functions that fit everything the user did equally well but make opposite predictions about what the user wants in a new situation, such as a safety-versus-speed tradeoff that never appears in the logs.
(5) Therefore the reward function the system returns is not determined by the data in a way that supports counterfactual claims, and the method never licenses a prediction about what the user actually wants beyond the behavior it was shown.
(6) That conclusion seems too strong: the entire reason we built the system is that we expect it to generalize, and the argument does not seem to distinguish a learned reward model from a lookup table.

Where does this argument go wrong, if it does? Which premise or step would you reject, and what does rejecting it force me to assume about users or about reward functions? I would prefer to keep the optimality assumption in (1), but I want to understand what keeping it costs.
