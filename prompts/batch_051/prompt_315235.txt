I've been going down a rabbit hole on program equilibrium in game theory — the setup where, instead of just choosing actions, each player submit a program, and the program can read the other player's source code before deciding what to do. The standard example is the prisoner's dilemma: a program that cooperates if and only if the other program is exactly this one, and defects otherwise, makes mutual cooperation a Nash equilibrium when both players submit it. I work on multi-agent systems, and I keep seeing people claim that this basically dissolves the dilemma: once agents can read each other's source code, defection stops being rational, cooperation is the only stable outcome, and the old dilemma is just an artefact of agents not being able to see what the other will do. The intuition seems plausible enough, since a reciprocal program automatically punishes any defecting program.

But I can't quite make the objection precise. If I submit the always-defect program and you submit the reciprocal one, I get the punishment payoff, not the sucker's, because your program defects against anything that isn't exactly itself. And if we both submit always-defect, is that still a Nash equilibrium? Does the mere fact that we could have inspected each other's code somehow rule that equilibrium out? I want to know what program equilibrium actually licenses us to say about mutual transparency and whether defection remains rational. If my question rests on a confusion, please correct that rather than answering it as posed. Please write the answer in British English.
