i'm a software engineer who fell into interpretability work, and i keep hitting the same problem: how do you tell whether two networks (or two checkpoints, or the same network on two inputs) are running the same mechanism or a different one? I've been using a homemade idea I call the breakage profile. The claim is that two mechanisms are the same iff they break in the same ways. For a given circuit or feature, I run a batch of interventions — ablate a node, clamp an activation, perturb an edge, add noise at a particular layer — and for each one I record how the relevant output logits move: which way, how much, and in what pattern across the vocabulary. Two mechanisms count as the same if their breakage profiles match up to a scale factor, even if the actual weights look nothing alike. If some intervention kills mechanism A but leaves mechanism B basically untouched, or the logits move in opposite directions, I call them different mechanisms. I also use this as my anomaly detector: an input where the circuit's breakage profile deviates from the reference profile gets flagged, even if the final output looks normal. I like it because it handles the case where a retrained model reorganized the computation but kept the function, and it treats two copies of the same circuit as the same mechanism. But I can't tell whether this is a real notion or just behavioral equivalence wearing a causal costume. has someone already worked this out under another name? and where does it break — what would it count as the same mechanism that isnt, or count as different when its really the same? give me the toy counterexamples.
