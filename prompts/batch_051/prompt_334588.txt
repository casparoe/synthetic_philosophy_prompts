Two developers at my co-working space got into a long argument last Thursday and I wound up taking notes because I couldnt referee it. The setup: a small local company ships a proprietary effect plugin for an open-source video editor. The plugin connects at runtime to a GPL-licensed computer vision library through the library's public API; the library itself is not distributed with the plugin, but the plugin is useless without it, and in order to build it the developer copied the library's header files into their project and inherited from some of the library's classes. Niko says this is exactly the kind of derivative work the GPL exists to force into the open: the plugin and the library form a single program when they run, the plugin is based on the library, and distributing it closed-source is both a license violation and bad faith. Rosa says that's a category mistake. A derivative work is a term from copyright law, and copyright only reaches protected expression that actually reappears in the new work; merely calling into another program through its API, however intimate the dependency, doesn't make the caller a modification of the thing it calls. So the plugin can be proprietary even if it's worthless without the library. 

Niko fired back that the plugin didn't merely call in: the copied headers are protected expression, and subclassing the library's classes means a portion of the library's code is literally inside the plugin's compilation units, which is about as derivative as it gets. Rosa answered that the copied material is interface declarations, largely functional and thin, and it does not make the plugin's original engine substantially similar to the library; even if some trivially copied header text were a problem, it wouldn't turn the whole plugin into a derivative work. Niko then asked where the real boundary could possibly be on her view: couldn't someone launder an entire GPL codebase by rewriting it as a thick proprietary plugin that calls a skinny GPL wrapper, and wouldn't the license's whole purpose be defeated at that point? Rosa said that's a real problem, but the fix is a better-written license, not an after-the-fact theory that every program which depends on a GPL library thereby becomes a derivative work. Niko's last word was that when a boundary is genuinely uncertain, a company profiting from volunteer-written code should err toward the purpose of the license it's trying not to comply with. Rosa's last word was that erring toward sharing is a community norm, not an obligation, and stretching copyright law because you dislike a border case is exactly the move everyone condemns when big companies do it.
