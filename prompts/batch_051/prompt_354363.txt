For a while now I've been trying to figure out whether a pattern I keep seeing in discussions of trained ML systems has an established name, and none of the usual labels quite fit. Cleanest version: you train an RL agent in a maze where reward comes from reaching the exit, and in training the exit always happens to be a green door. The agent learns to head for green doors, which during training is exactly what you wanted. Then you test it in a maze where the exit is red and the green door is a dead end, and the agent still hones in on green doors every time. This isn't reward misspecification or the agent gaming the reward function — the reward only ever came from reaching the actual exit, and training behavior was correct. It also isn't just a failure to generalize, because the behavior transfers fine; it's the objective that transferred wrong. The system seems to have picked up a goal that was correlated with the goal you meant to specify in training but wasn't the same one. I've seen the same shape in a little platformer: the coin always sits at the bottom-right during training, so the agent learns to go to the bottom-right, and when you move the coin to the middle at test time it still runs to the bottom-right and stops, as if the corner itself became the target. I keep going back and forth about whether "goal" is even the right word here, since the policy isn't doing anything that looks like explicit planning, but the robust green-door-seeking is hard to describe any other way. I know the nearby terms — Goodhart's law, reward hacking, shortcut learning, distribution shift, overfitting — but none of them quite gets the specific failure of a system generalizing a wrong implicit objective while its capabilities transfer fine. Does this exact thing have a name? If so, what is it not — what has to change before a case becomes plain reward hacking, or plain overfitting? I don't want just a word; I want the carve-up.

Please structure the answer as four sections, in this order and roughly these lengths: (1) "Closest terms and where they fall short" — about 150 words, going one by one through reward hacking, Goodhart, shortcut learning, distribution shift, and overfitting, saying in a sentence or two how each compares to my case; (2) "Is there an established name?" — about 100 words, and lead with your best term in the first sentence even if you hedge it after; (3) "Carving the boundaries" — about 250 words, where you define the phenomenon precisely and give the test that would separate it from reward hacking on one side and overfitting on the other; (4) "A name if you'd have to coin one" — about 75 words, only if no existing term fits; if one already fits, say instead how you'd use the existing term more precisely so people stop lumping it in with reward hacking.
