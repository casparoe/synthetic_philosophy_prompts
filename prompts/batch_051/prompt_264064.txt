An old roommate of mine has an argument I can't shake, and he thinks it shows copyleft is either toothless or insane. (1) If a program links against a copyleft library, the whole linked thing is a derivative work of that library, so the program has to be distributed under the same copyleft terms. (2) But if linking through a clean interface is enough to make one work derivative of another, then by the same reasoning a text editor is a derivative of every file format it parses, an OS is derivative of every program it runs, and a browser is derivative of every page it renders. (3) That's obviously absurd, so interface use as such can't be what makes a derivative work. (4) What must matter instead is copying protected expression. (5) But in an ordinary link, the only things copied are function names and call signatures, which no one seriously treats as protected expression. (6) So either copyleft's binding power rests on something too thin to be copyrightable, or the interface test makes derivative works out of everything, and copyleft can't draw a line anywhere in between. I'd like to keep both the idea that copyleft has teeth and the idea that opening a file doesn't make your editor a derivative of it. Which step do you reject, and what does giving it up cost?
