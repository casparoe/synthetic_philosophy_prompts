I keep running into this move in arguments about teaching math, and I want someone to stress-test it. The claim is that learning math is basically building a house: you have to get the foundations right before you go higher, so if students get through calculus by hand-waving about limits, epsilons, and "it just works," everything built on top is unsound and eventually cracks. The conclusion people draw is that we should be rigor-first from day one—real definitions, real proofs, no skipping steps. I learned to code by shipping broken stuff and then refactoring once I actually understood the formal version, so I'm skeptical. Can you audit the house analogy the way you'd audit a bad API abstraction: give me the actual correspondence table (foundations, load-bearing walls, cracks, whatever), tell me where it breaks, which disanalogies actually matter for the rigor-first conclusion and which don't, whether a better analogy would change the verdict, and whether rigor-first survives once the analogy stops doing the work?
