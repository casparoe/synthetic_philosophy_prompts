Quick one for people who think about mechanistic anomaly detection. I keep landing on a view about what it means for two forward passes to count as instantiating the same mechanism, and I want to know what would actually count against it.

My position is that mechanisms should be individuated by their causal-functional role, not by which features or neurons happen to implement them. Suppose I've got a reference pass where a circuit does something like 'if the current token is a delimiter, route its position information to the next layer.' I want to say a new pass runs the same mechanism iff I can find the same causal-functional graph — nodes doing the same jobs, with the same gating conditions on downstream effects, in the same order — even if the activations sit in a completely different part of feature space and different heads are doing the work. The rival view I'm pushing against is the similarity-based one: same mechanism iff roughly the same components light up in roughly the same way, as measured by cosine distance or whatever. On my account, anomaly detection should flag runs whose role structure diverges from the reference, not runs that merely drift in activation space.

I like this because its a tidy decision procedure, it makes mechanisms portable across models and checkpoints, and it matches how circuit analysis often talks in practice: people name a mechanism by what it does ('previous token head', 'copy suppression') rather than by the coordinates of the neurons. But I can already hear the objection that 'same job' is doing all the work, and I dont want a position that's true by definition because any disagreement gets redescribed as a different role.

So here's the ask. What would count against causal-functional individuation of mechanisms, treated as the right basis for mechanistic anomaly detection? I want defeaters ranked from fatal to merely awkward. Please include at least: coarse-graining cases where two intuitively different mechanisms get the same causal description; context cases where one mechanism's role seems to change across inputs even though we'd want to call it the same mechanism; polysemantic components whose 'job' is really a disjunction; empirical evidence from circuit discovery that people individuate mechanisms by feature similarity in practice and it works better; and the general concern that 'causal-functional role' is elastic enough that the view is unfalsifiable. A committed functionalist will concede some of these and dismiss others — tell me which is which, whether the view ends up insulated into unfalsifiability, and whether that's a problem for an engineering frame like MAD. And please write the answer in British English.
