I work as a software engineer and have no formal background in philosophy, so I want to frame this question operationally. For as long as I've been coding, I have used a rough four-part definition of a programming language: it has a concrete syntax, it has a specification of semantics that fixes what a program does, it has an implementation that maps program text to machine behavior, and it is designed for humans to author as a way of bringing about computations. Here is a case I can't settle. Imagine a small company builds a tool for directing a code-generation model. Documents in this tool are JSON objects with three sections: a contract section specifying preconditions and postconditions, a policy section specifying error-handling rules, and a style section specifying constraints on allowed output. The grammar is precisely specified, and there is a checker that type-checks the documents. But the execution model is the model itself: a document is handed to the code-generation model, and the model produces a patch. The semantics of the document are not given by deterministic rewriting rules; they are whatever the model learned, so the same document can yield materially different patches across model versions, sampling temperatures, or repeated runs. The tool's authors call it a programming language because people author structured input to control a computation and because that input is mechanically checked and then executed. My colleague says it is not a programming language, because nothing in the notation itself fixes what a document means. Work through my four criteria honestly and take a position: does this qualify as a programming language, or does the case reveal that one of the criteria — especially the demand for a semantics — is doing more work than I assumed, or that the label "programming language" is not really tracking the features on my list? In particular, I would like to know whether the distinction between a program and a specification collapses once the thing consuming the specification is a learned model rather than a compiler.
