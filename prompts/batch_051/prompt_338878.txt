Consider a software organization that has adopted the following policy for LLM-generated code. Generated code may be merged only if it is written out in the same human-facing programming language as the rest of the codebase, passes the same naming, typing, and module-boundary checks, is assigned to a human engineer who must explain it in review, and remains subject to the same documentation and refactoring standards as hand-written code. No one believes the LLM needs any of this to produce working software; the same model would be equally content to emit a low-level representation no human ever reads. What does this policy presuppose about what a programming language is for? Reconstruct the implicit theory of programming languages in the policy, distinguish what the policy strictly presupposes from what it merely fits well with, say whether its review requirement and its authorship requirement presuppose the same thing, and explain what the organization would have to change if it adopted the rival view that a programming language is only a legacy interface to a compiler, dispensable once machines write the code.
