I've been going back and forth on something about iterated amplification and distillation. The setup is that a human decomposes a hard task into subtasks, supervises them (with help from the previous rounds model), and then the amplified process is distilled into a new model. The hoped-for guarantee seems to be: if the human is aligned on each subtask and the distillation doesn't mangle things, the next model stays aligned as well. That looks an awful lot like compositional verification of programs, where you prove a whole program correct by proving each procedure correct against its specification. But compositional verification only actually works when the specifications compose—you need frame conditions, invariants, rely-guarantee assumptions stating what each part is allowed to modify and what it may assume about the context. So the parallel I keep noticing is this: per-subtask approval in IDA is like verifying a procedure against its spec, and the missing bit in IDA is precisely a frame condition for alignment. If that's right, IDA's guarantee would break in the same way a proof sketch breaks when two locally verified procedures interfere with each other. But I can't tell whether this is a real point about the non-compositionality of human approval, or just a loose metaphor—after all, alignment isn't obviously a trace property the way program correctness is, and the human isn't checking a formal spec. Which is it? And if the parallel is genuine, what would a frame condition for alignment even look like?
