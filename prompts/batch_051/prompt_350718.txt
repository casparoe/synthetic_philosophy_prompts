While trying to give a precise semantics for mutation in an imperative language, I keep deriving a contradiction. Suppose an object `p` has an integer field `x`, initially `p.x == 3`, and then the single statement `p.x = 7` is executed. Consider the following argument.

(1) Indiscernibility of identicals: if an object `a` and an object `b` are the same object, then any property had by `a` is also had by `b`.
(2) The object denoted by `p` after the assignment is the same object as the object denoted by `p` before the assignment: updating a field changes the object, it does not destroy it and put a new object in its place.
(3) Before the assignment, `p` has the property of having x-coordinate 3.
(4) After the assignment, `p` lacks the property of having x-coordinate 3.
(5) From (1) and (2): every property had by the object before the assignment is also had by the object after the assignment.
(6) From (3) and (5): after the assignment, `p` has the property of having x-coordinate 3.
(7) (4) and (6) are jointly contradictory.

Since (6) is plainly false in the scenario described, at least one step must fail, or the steps must not mean what they appear to mean. Identify precisely which step or steps fail, state the reading of the relevant terms under which each failure occurs, and give the corrected formulation under which the derivation no longer goes through. Then draw the consequence for a semantics of mutable state: what must the state of an object be—a property of the object simpliciter, a relation between object and time or program point, a property of a temporal part, or something else—and does the corrected account handle repeated mutation and aliasing as cleanly as it handles this single update?
