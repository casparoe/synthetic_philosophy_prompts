I want to stress-test a rule I've carried over from my work as a software engineer into how I think about mathematics, and I'd like you to tell me where it breaks.

The rule is about telling when a statement about an object is really about the object itself, rather than about my representation of it. In type-system work, I use two tests for whether a statement P about values of a type T is a genuine property of T's specification, as opposed to an implementation detail:

1. Invariance. P must have the same truth value across every correct implementation of T, where "correct" means behaviorally equivalent with respect to T's specification.
2. Expressibility. P must be statable in the vocabulary of the specification itself, without reaching into the fields, memory layout, or other internals of any particular implementation.

I apply these tests to the natural numbers, taking the specification to be the Peano story: a first element 0; a successor operation S that maps natural numbers to natural numbers one-to-one; 0 is not the successor of anything; and induction holds. Two classic implementations are:

- The von Neumann encoding: 0 is the empty set, and S(n) = n ∪ {n}. So 0 = ∅, 1 = {∅}, 2 = {∅, {∅}}, 3 = {∅, {∅}, {∅, {∅}}}, and 4 = {0, 1, 2, 3}. In this encoding, 2 is an element of 4.
- The Zermelo encoding: 0 is the empty set, and S(n) = {n}. So 0 = ∅, 1 = {∅}, 2 = {{∅}}, 3 = {{{∅}}}, and 4 = {{{{∅}}}}. In this encoding, 2 is not an element of 4.

Both encodings satisfy the Peano axioms, so by my invariance test, 2 ∈ 4 is an implementation detail rather than a fact about the natural numbers themselves. The expressibility test gives the same verdict: membership is not part of the arithmetic interface the way zero, successor, addition, and multiplication are; writing 2 ∈ 4 commits me to one particular set-theoretic encoding.

But I am uneasy about this clean result, for two reasons. First, mathematicians do not treat the two encodings as equals: the von Neumann encoding is canonical in ordinary set theory because it extends to the transfinite ordinals, and it is the encoding standard set theory uses for the natural numbers. If the invariance test is allowed to count only canonical implementations, the verdict flips. Second, accepting my tests' verdict seems to force me to say that a perfectly precise question — is 2 an element of 4? — has no fact of the matter, while I still want to say that 2 + 2 = 4 and 2 < 4 are genuine facts. What makes those different? The expressibility test says that + and < live in the arithmetic interface and ∈ does not, but that can look like stipulating the answer rather than discovering it. Maybe set theory, not Peano arithmetic, was the real specification all along.

Work through my two tests against this case. Does the statement "2 is an element of 4" qualify as a genuine fact about the natural numbers under my criteria? Then tell me whether the criteria themselves need repair: for example, by adding a canonical-implementation exception, by weakening invariance so it ranges only over canonical or reasonable encodings, or by replacing one or both tests. Where do my software intuitions hold up, and where do they mislead?
