I teach an upper-level philosophy of language seminar — about 18 people, one 75-minute session. I want a classroom game that makes them feel why an identity like "Hesperus is Phosphorus" can be necessarily true while still being something you had to find out empirically — and I want them to run into it before I name any of the machinery.

The intuition I'm after: names are rigid (they stick to the same individual no matter which possible world we're considering), while definite descriptions pick out whatever fits the description in the world we're holding up. So two names for the same thing, once the identity actually holds, holds in every world we could coherently describe — even though the discovery that they name the same thing is empirical. Descriptions, by contrast, can slip off a name when we imagine things going differently.

Design the activity. I'd rather print and cut cards than use any software. Give me concrete materials, a scoring scheme that doesn't need real money, and a sequence that starts fully concrete and only introduces "rigid designator" and "necessary a posteriori" in the debrief. The idea should show up in what happens, not in what I say afterward.

Some concrete things I want built in:
- An actual possible-worlds mechanic: e.g., construction-paper worlds where the same underlying individual can carry different properties from world to world.
- A rule that names, once assigned, are stuck to the individual and cant be reassigned, but descriptions are evaluated fresh in each world.
- At least one world where a student who substitutes the description for the name gets a wrong result that isn't immediately obviously wrong, so the mistake is diagnosable in the debrief.
- A payoff structure that rewards tracking the name across worlds, but doesn't punish whoever first blurts out "but 'the morning star' just means the bright thing in the morning."
- A predictable moment of friction: ideally a student loses points in a way that turns visibly on the name-sticking rule, so the point lands without me having to insist on it.

Then write the debrief: map specific moments in the game (two names traveling together across worlds; a description coming apart from a name) onto the formal distinctions — rigid vs. flaccid designation, necessity vs. apriority, and how the same statement can be both necessary and a posteriori. Also tell me what will predictably go wrong the first time I run it — materials, timing, students gaming the scoring, someone confusing "necessary" with "obvious" — and how to handle each. Be frank about what the game cant reproduce. I suspect it's something like: all the counterfactuals are ones I designed, so the game makes modal verdicts look more settled than they are, and it can't show why we were entitled to make the discovery in the first place; the facilitator has to supply that part. Keep the whole thing runnable in the session, including debrief, with prep no heavier than printing and cutting.
