I'm a software engineer, not a philosopher, so appologies if I'm using these terms in a sloppy way. I work on a team that does a lot of sequence alignment and variant calling, and lately I've been going back and forth with a colleague about whether DNA is really a code or whether that's just a comfortable metaphor. I wrote down the five things I actually believe, and I want a consistency check before I bring any of them up again.

Here's what I tend to think: (1) DNA is a code in more than a metaphorical sense — a codon really does encode an amino acid, in roughly the way a byte encodes a character. (2) Information only exists relative to an interpreter or receiver; a string of bits on a dead hard drive isn't about anything, and in the cell the ribosome, tRNA, and related machinery are what make a sequence count as information. (3) You don't need an intentional designer for a code to exist; the codon-to-amino-acid mapping could be a historical accident that got locked in by selection. (4) The genetic code is arbitrary in something like the way an instruction set architecture is arbitrary: alternatives would have worked, but once one is fixed, everything built on top is constrained by it. (5) But I don't think DNA sequences have semantic content the way sentences do — a gene doesn't mean an enzyme the way the word "enzyme" means the enzyme.

So the question is whether these five all hang together. I honestly can't tell where the weak spot is, if there is one. Please go through my commitments and check them as a set: which pairs are genuinely in tension, which pairs only look like they are, and what is the cheapest thing I'd have to give up or revise first? Reply as exaclty five numbered items, each one or two sentences, no introduction or conclusion, and order them from the most serious tension to the least.
