A philosopher friend keeps telling me evidence underdetermines theory: for any finite set of observations there are indefinitely many theories that fit them, so the data never forces a single true theory. As a backend engineer I hear that and think okay, but the same is true of code: any finite test suite is passed by indefinitely many programs. You can literally write a lookup table that returns the expected value for each test case and crashes on everything else. Nobody concludes from this that testing is hopeless or that we can never say our code is right. We pick among the passing programs using simplicity, structure, code review, and cross-validation, and we mostly expect them to generalize to inputs we haven't seen. So is choosing among scientific theories just model selection with the universe as the finite, noisy test suite? I want a proper audit of this analogy. Give me the correspondence table: what maps to test cases, the hidden or generalization set, overfitting, the spec, the prior that simpler programs generalize better, and so on. Then go where it breaks. My guess is it breaks in a few ways I can't quite name: in science we can't sample new test cases on demand from a known distribution, there's no spec to check against, and the observations are historical and can't be rerun. Tell me honestly whether underdetermination is a real problem for science after the analogy is audited, or whether my friend is just describing the boring fact that many models fit the same data, same as many programs pass the same tests. Answer in British English, and dont pull punches on the parts where my analogy quietly loads in assumptions science doesn't have.
