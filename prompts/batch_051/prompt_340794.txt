I'm taking a course on free will this semester, and we've been going around in circles on the compatibilism/incompatibilism debate. I also write code part-time, nothing fancy, mostly backend stuff, and I keep feeling like the two arguments are the same argument wearing different clothes.

The compatibilist line, as I understand it, is that "could have done otherwise" should be read counterfactually: I would have done otherwise if I'd wanted otherwise, or if I'd known different things. That sounds strikingly like a deterministic function. I'd say a pure function that doubles its input "could have returned 6" without anyone thinking it secretly calls rand() inside — I just mean give it 3 and it would return 6. The incompatibilist seems to want something more: with the same inputs and the same prior state, the system could still produce different outputs. In code that's genuine nondeterminism, a race condition, a random seed, or something at the hardware level. Some incompatibilists (libertarians) then say free will must require that sort of same-input-different-output openess, even though they'd probably hate my saying it's like an RNG and prefer "agent-causation" or whatever; hard determinists instead say, fine, then free will is just impossible.

So here's what I want to know. Is this mapping deep — compatibilism is to input-sensitivity as incompatibilism is to demanding nondeterminism — or is it superficial pattern-matching based on both fields using the words "could have"? If it's deep, does anything actually transfer, like engineers asking "why did the function return X?" rather than "could it have returned Y?", or the fact that adding randomness makes a system harder to debug but doesn't obviously make it more responsible? If it breaks, tell me exactly where: maybe a function's "could have" is just a loose way of talking about a mathematical mapping, while the compatibilist's "could have" is about an agent's abilities, and those aren't the same genus.

Oh, and please answer in British English (spelling and all).
