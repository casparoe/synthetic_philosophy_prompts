I was untangling a billing service at work last week and found that someone had made the test suite green by hardcoding a lookup table for the exact inputs the tests checked — it passed everything but would fall over on any new case. For some reason that same week I'd been reading about Plimpton 322, the Babylonian clay tablet from around 1800 BC whose rows are basically Pythagorean triples, some of them huge. Nobody's sure what the tablet was actualy for, but people argue about whether it means the Babylonians "had" the Pythagorean theorem or were doing actual mathematics, as apposed to just keeping a list of numbers that happened to work out.

That's when it hit me that these might be the same question from different angles. In code, a lookup table and a function can be extensionally identical on the inputs you've seen, but nobody would say the table "implements" the algorithm; the function has a rule that compresses the table and says what to do on new inputs. So maybe Plimpton 322 is a fifteen-row cache of Pythagorean triples, and the debate about whether it's mathematics is really a debate about whether there was a generating rule behind the table, not just the table itself. But I can't decide if that parallel is doing real work or if I'm just projecting code review instincts onto a lump of clay. Is the table/function distinction actually the right way to think about when counting or bookkeeping becomes mathematics? What would the Babylonians have needed beyond the tablet for us to say they had something like a theorem, and does that same "beyond" line up with what separates an implementation from a lookup table — or does the analogy break somewhere, maybe because clay tablets don't come with specs or intentions the way a codebase does?
