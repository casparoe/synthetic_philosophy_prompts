At my last job I worked on the trading desk's back-end, and I keep going back and forth about an old rule we inherited. The compliance handbook had a rule written in the early 2000s, when humans still entered every trade, and it said exactly this: "A trader shall not execute a trade that, combined with positions the trader already holds, is guaranteed to lose money no matter how the market moves. Any order that would create such a guaranteed-loss position shall be rejected before execution."

Last year we replaced the human traders with a reinforcement-learning pricing agent, and now the thing walks around in a loop. It only ever holds one position at a time, so the rule as written basically never fires: at execution time it doesn't "already hold" the other legs. But the agent has a weird failure mode. If you offer it a choice between holding portfolio A and holding portfolio B, it picks A. Offer it B versus C, it picks B. Offer it C versus A, it picks C. Each time it swaps into the one it prefers, it pays a small fee, so it keeps cycling A -> C -> B -> A and bleeding cash. The risk system lets every leg through, because each individual trade, looked at against the current single position, is not a guaranteed loss.

So I'm trying to figure out: does the old rule, read literally, cover this? Does it cover it read as a general principle, something like "don't let anyone run a sure-loss cycle on us"? If the drafters had been asked about a stateless agent with looping preferences back then, what do you think they would have said? And what does the rule presupposes about the trader if the ban on guaranteed-loss books is going to make sense as anything more than a patch? Our head of risk says the agent is obviously irrational and we should hard-code the rule's spirit into the agent's objective, but I'm not sure the agent is irrational rather than just built for one-off trades, and I don't know what "the rule's spirit" would even be in code.
