You're an expert on program equilibrium and the theory of cooperation between computational agents. Please think carefully before answering, brainstorm a few candidates in your head first, and reject any that are just variants of the four mechanisms below. I'd rather have one good idea than a list of weak ones.

My friend and I argued for hours tonight about whether two rational software agents could ever end up cooperating in a one-shot Prisoner's Dilemma with no binding contracts, no repeat play, and no external enforcement. By 2am we'd assembled this list:

1. The classic program-equilibrium fix: each side submits its source code, and each program inspects the other's code and cooperates iff the other program would cooperate when run against it. Mutual cooperation becomes a self-consistent fixed point, not just mutual defection.

2. The FairBot move: each program cooperates with the other iff it can prove the other will cooperate with it. Two such programs cooperate; a single one defects against a program it cant prove anything cooperative about.

3. The PrudentBot patch: the same proof-based idea, but its cooperation criterion is tightened so it also defects against CooperateBot-type unconditional cooperators (it refuses to hand free cooperation to a sucker) and against outright defectors, while still cooperating with FairBot-type agents.

4. The evidential/TDT-ish move: both agents know they run correlated or near-identical algorithms, so each treats its own choice as evidence about what the other does, and they cooperate without either one reading the other's source code.

We suspect this has all the standard moves. Is there a fifth mechanism, genuinely different in structure — not a rewording, special case, or combination of the above — that gets mutual cooperation in a one-shot PD between software agents? If you offer one, say whether it survives once the agents can self-modify or face weird counter-agents. If you think the list is complete, say so and defend that.
