Here's a parallel I keep turning over and can't tell if it's deep or just a surface analogy. In programming, a recursive function with no base case — like f(n) = f(n + 1) — just spins forever without ever returning a value. That looks exactly like what philosophers call a vicious infinite regress: the classical epistemic regress, where every justified belief needs another belief to justify it and that one needs another, so justification never bottoms out. But programmers also have guarded corecursion, where an infinite process is completely fine because it's productive: you can define the stream nats = 0 : map (+1) nats, which never terminates but lets you pull off any finite prefix, so it's a perfectly legitimate object. So the distinction between an unproductive infinite loop and a productive coinductive definition sure looks like the distinction between vicious and benign philosophical regresses (the truth regress — 'p is true', 'it is true that p is true', and so on forever — is usually treated as harmless, while the epistemic regress is treated as fatal). Is this a genuine identity of structure, so that "vicious" basically means "non-productive", or does the analogy come apart somewhere important? What would have to be true on both sides for the comparison to carry over, and can you say something the parallel predicts that turns out false?
