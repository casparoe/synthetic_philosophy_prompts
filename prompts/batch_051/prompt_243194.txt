I cover science and ideas for a living, and usually I can spot a bad step, but a source walked me into this one last week and I can't find the exit. We were talking about whether a single finite string — say, 256 bits from a hardware random number generator — can be called random, and he gave me this chain.

(1) A finite string is random just in case it has no description much shorter than itself; it can't be compressed.

(2) Pick any finite string s you like. There is some programming language L_s whose print command for s is tiny, because you can build s into the language itself, so that an empty program or a one-symbol command outputs s.

(3) Relative to L_s, s has a very short description. So relative to L_s, s is highly compressible, hence not random.

(4) The construction works for every string. Whatever s is, there's a language that makes it look simple.

(5) So whether a string is random is entirely a artifact of the language you choose; no finite string is random in itself.

(6) But then calling a string random says nothing about the string, and any randomness test is just a test of which language convention you happened to adopt. That seems like too much. A string of 256 zeros and a string from a good noise source are different as strings — or at least I thought they were.

I'd like to keep (1) if I can, since compressibility is the only handle I have on randomness, but I can't tell whether I have to give up on the idea that finite strings can be random at all. Which step do I reject, and what does rejecting it cost? Hard cap: 350 words.
