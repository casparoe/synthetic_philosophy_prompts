I've been poking at desuetude — the idea that a law can lose force through prolonged non-enforcement — and it keeps lining up in my head with dead code in a program: a function that's still in the interface, still callable, but no live path actually calls it. In both cases the written artifact says "this is what the system does" while the system's actual behavior says otherwise, and the dangerous part is that someone could invoke the dormant thing tomorrow and there's no settled practice telling you what should happen.

Am I noticing a real structural analogy, or just the banal fact that institutions and codebases accumulate cruft? If it's real, spell out what would have to be true on both sides for results to transfer — for example, a desuetude-style rule that neutralizes code after N versions of sitting unused, or conversely an API-stability argument that courts should leave dormant statutes alone until the legislature formally repeals them. And I'd like you to name at least one thing the parallel predicts that comes out false. I have a hunch it would imply pruning dead law is as normatively innocent as pruning dead code, which I don't trust, so attack that if it deserves it.
