I'm a software engineer with no formal philosophy background, and I want help deciding whether a parallel I keep noticing is deep or merely pattern-matching. As I understand it, the reference class problem in probability is this: the probability assigned to a singular event is always relative to a class of similar events, and the value shifts with the class. A given patient's chance of surviving ten years depends on whether you class the patient by age, by sex, by smoking history, or by some combination, and no partition seems uniquely privileged. To me this is the same structure as choosing a cohort for a reliability metric. The probability I assign to a given deployment's failing changes depending on whether I condition on all deployments, on deployments touching the same subsystem, on Friday deployments, on deployments by the same team, or on some combination; each partition is defensible for some purpose, none for all. In both cases you start with a bare token, partition the space along many dimensions, and read off a different conditional frequency or probability; in neither case does the data itself select the partition. Is this a real identity of structure, such that results transfer between the two settings? If the analogy breaks, where exactly does it first break? Engineering has resources the philosophical case appears to lack: randomized assignment, fixing a metric's purpose before choosing the partition, reporting several metrics for several audiences. Does that mean the philosophical problem is only dissolved once a decision-theoretic target is supplied, or does the analogy instead expose an unacknowledged arbitrariness in the engineering metrics?
