I'm a software engineer with no philosophy background, so excuse me if I'm missing the standard moves. I've been using Bongard problems — the six-left-six-right grids where you have to find the rule that seperates the two sides — as a toy model for how a system can pick up a concept from a few examples. I have a variant that's been bugging me. In the usual problem, the right-hand examples are scattered all over the complement, so the intended rule looks like the only simple hypothesis. In my variant, I fix a target rule like 'large solid triangle' and generate every negative example by taking a positive and changing exactly one relevant feature: shrink it, or make it hollow, or swap the triangle for a square. If I code each box as a binary feature vector, the positives are, say, all ones, and the negatives are exactly the cells at Hamming distance 1. Now two rules fit the observed labels equally well: the intended one, 'all the features on,' and a competitor, 'it's on the right iff it's one edit away from a positive.' Once 'one edit away' is a primitive in your description language, the competitor is about as short as the intended rule, and the two make different predictions for everything at distance 2 or 3. Does the standard 'pick the simplest hypothesis' story survive my variant, or does it just need a better measure of simplicity? Would a Bayesian version fare any better, or does the problem just get moved into the prior? Or does my negative-sampling trick expose that the original setup was leaning on how the negative examples were sampled — and if so, what should a rational learner actually do when the data underdetermine the concept? I want a worked-through answer, not a survey.
