My half-formed idea is this. The argument over whether DNA is 'really' a code seems to keep talking past itself, because the word 'code' bundles together several things engineers distinguish as a matter of routine: source code written in a grammar with a defined semantics; compiled machine code executed by hardware; a protocol like TCP, which is a conventional mapping used by two parties to coordinate; and a data format or schema, which tells a consumer how to interpret a payload while leaving the consumer's behavior open. These have different properties: a protocol needs an agreed convention, source code needs an interpreter, a schema can be parsed differently depending on configuration. My hunch is that DNA resembles some of these more than others, and that a lot of familiar objections to calling DNA a code are really objections to one particular disambiguation of the term, not to the others.
