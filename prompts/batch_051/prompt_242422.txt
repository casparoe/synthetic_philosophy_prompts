I'm a software engineer with no formal philosophy background, so apologies if I mangle this. A while back I stumbled on the Kripkenstein rule-following argument and its been quietly breaking my brain ever since. The version I remember goes something like this: define a function quus(x, y) that returns x + y when both inputs are less than 57, and returns 5 otherwise. Now suppose all the addition I've ever actually done in my life involved numbers below 57. Every bit of evidence about my past usage—every sum I've computed, every test case I've written, every time I've said "plus"—is equally consistent with the hypothesis that I always meant quus, not addition. The skeptic's punchline is that there's no fact about me, my brain, my dispositions, or my history that makes it true that I meant addition rather than quus. And when I try to locate such a fact, I can't. I have a function body, a type signature, and some tests, and any finite set of tests is consistent with infinitely many functions.

But here's the part I can't let go of. Last week I wrote a tiny add(a, b) function, tested it on inputs below 57, and I know—like, know in a way I can't justify—that it means ordinary addition. If someone ran add(100, 100) and got 5, I'd call it a bug, not evidence that I'd meant quus all along. More generally, if meaning really were indeterminate the way the skeptic says, then the whole practice of writing a spec, implementing it, and reviewing it for correctness starts to look like a shared hallucination, and I don't think it is one. So the question isn't just which side wins. I want to know what it would cost to give up each side. What would it take for my intuition—that add determinately means addition—to be the thing that goes? What would it take for the skeptical argument to be the thing that goes, or to be right but a lot less important than it looks? Is there a reading where both survive, like the skeptic is making a point about justification or about what I can prove, while my intuition is about the fact that the function I wrote down pins down a meaning whether or not my mental history does? And please flag how confident you are in each move and where you're least sure. If the whole setup is confused—maybe I'm treating "meaning" like it's a variable in a program when it isn't, or the argument doesn't transfer to formal languages the way I think—just say so flat out rather than playing along.
