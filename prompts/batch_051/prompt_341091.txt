I've been arguing with a friend about the GPL, and we've ended up completely unable to agree about what actually makes one program a derivative work of another. My working tests are these: (1) B contains code copied from A; (2) B is a translation or adapted version of A's expression — same structure, new language; (3) B links against A so that A ends up inside B's running process; (4) B is basically A with patches and extra features. Now here's the case we can't settle. A company has a GPL-licensed code generator: you feed it a spec file, and it emits a large C program. The generator itself is built around a set of templates and transformation rules, and the emitted program is assembled out of those. The company writes its spec from scratch. The emitted C code contains no literal chunk of the generator — no identical identifiers, comments, or strings — but you can clearly see the shape of the generator's templates behind it. The company ships only the compiled output under a proprietry licence, and never distributes the generator itself. Walk me through my four tests one by one and say which, if any, makes this a derivative work. If none of them does, is that a genuine hole in copyleft, or does it show that inheriting the licence through the output was the wrong way to think about it all along? Where exactly do you draw the line?
