I've been reading around in literary theory—mostly the old debate about whether the author's intention fixes the meaning of a text—while also doing a lot of code review at work, and i can't decide about a parallel that keeps coming up. The analogy would be: the code is the text, the comment (or commit message) is the author's stated intention, the compiler/interpreter or test suite is the competent reader, and "what the program does when run" is the meaning. In programming, when the comments and the code disagree, the code is authoritative: nobody accepts "but I meant x = 20" as a defense when the code says x = 10, and a suite of tests is treated as a better account of what the code is supposed to do than whatever the author was thinking. That sounds a lot like anti-intentionalism about texts: the meaning is what a competent reader can recover from the public text, and the author's private intent is neither necessary nor a very reliable guide.

But when i press on the mapping it gets weird. In the Gricean sense, code seems to collapse the distinction between sentence meaning and speaker meaning into the execution result, whereas in ordinary language they come apart constantly—irony, indexicals, implicature. The sentence meaning of "great job" can be praise while the speaker means the opposite, and with a poem we rarely treat the literal sentence meaning as what the poem means. Code also has something a literary text lacks: a formal semantics and an executable test suite that checkably specifies correct behavior. A poem can't fail a test suite the way a function can.

So: is the parallel between code-comment authoritativeness and textual anti-intentionalism a deep structural point, or does it break because code has a fixed semantics plus a spec while the meaning of a text is underdetermined by the marks alone? What would have to be true on both sides for results to transfer, and can you name a prediction this analogy makes that is clearly false on one side or the other?
