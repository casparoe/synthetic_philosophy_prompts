I write a monthly science-and-ideas column, and a recurring part of the job is vetting claims of the form "evolution does X, so a machine-learning system should do X" or its reverse: "evolution is bad at Y, so gradient-based optimizers need not worry." I need a reusable decision procedure — a checklist in prose that I can run in under an hour, with magazine-level scientific literacy but no working background in evolutionary biology, on a claim's abstract, figures, methods, and surrounding argument — for deciding when the analogy between natural selection and gradient descent is doing real work and when it is merely decorative. The procedure should quietly encode, among others, these distinctions: relative fitness in a shifting population versus an absolute, fixed, externally chosen loss; an adaptive landscape the population itself remakes versus a stationary loss surface; selection among whole candidates plus recombination versus differentiable parameter updates; no foresight and no lineage-wide credit assignment versus backprop's exact credit assignment; and satisficing with path dependence versus convergence to a minimum. For each step, give the question to ask, what counts as a sufficient answer, whether the step is factual or a judgment call, and the action that follows (move on, hand off to an expert, or stop with do-not-print). Mark the steps where judgment cannot be eliminated, and build it so the verdicts would survive my editor and an angry expert source.

Then run the procedure on these three claims: (a) since natural selection produced complex adaptation without gradients, gradient-free evolutionary search is at least as principled as backprop; (b) evolution is a short-sighted hill-climber trapped by local optima while momentum-based optimizers escape them, so modern optimizers have solved the local-optimum problem evolution never could; (c) evolution keeps old adaptations while acquiring new ones, so a selection-like weight-update rule should replace backprop to end catastrophic forgetting. Ensure at least one case returns a verdict I will not like, since I have used the stupid-optimizer line in print and would rather keep it. End by stating plainly what the procedure cannot decide.

Return everything as a JSON object with exactly these keys. "procedure": an array whose entries each have "step" (integer), "question" (string), "sufficient_answer" (string), "kind" (one of "factual", "judgment", "expert_handoff"), and "action_on_fail" (one of "move_on", "hand_off", "do_not_print"). "worked_cases": an array whose entries each have "case" (one of "a", "b", "c"), "claim_restated" (string), "decisive_step" (integer), "verdict" (one of "print", "qualify", "kill", "refer"), and "one_sentence_justification" (string). "limitations": a string. Do not include anything outside this JSON object.
