I keep running into the same obstacle and I'm wondering whether it has a name. Say you want a machine to do exactly the task you give it and otherwise not disturb the world — to avoid side effects in the everyday sense. To tell whether something is a side effect, you need a baseline: the world as it would have gone if the machine hadn't acted. But that baseline needs a pretty complete model of the environment, and any real action diverges from it in indefinitely many ways. A robot that picks up a cup also moved some air, warmed the room a tiny bit, redirected the light, and so on. So you have to decide which differences count, and once you start deciding which changes matter and which don't, your right back to supplying values — which was exactly what the "nothing else" requirement was supposed to let you postpone. The no-action baseline isn't neutral either: if the machine doesn't deliver the package, someone waiting on the medicine gets worse, so sitting there has its own value-laden consequences. Each fix I try seems to either smuggle in values or collapse into triviality: define side effects as any deviation from no-action and the best policy is to never act; try to count only "unrelated" deviations and you've already specified what the task was supposed to accomplish. I've heard the frame problem mentioned nearby, but this seems different. Does this thing have a name of its own? I don't just want a label — I want the carve: what exactly is the core issue, how does it relate to the frame problem and to ordinary talk of unintended consequences, which attempted definitions get around it rather than just renaming it, and if there's no settled term, what should it be called?
