Okay I've been turning over a parallel and I can't tell whether it's deep or just the sort of thing that sounds deep after midnight. In Kripke's picture, a proper name is a rigid designator: it picks out the same individual in every possible world where that individual exists, even if the individual has quite different properties in different worlds. A definite description isn't rigid — the tallest person in the room picks out different people in different worlds. So far so good.

Now take a modern object-oriented language with reference semantics. Object identity is separate from equality: two objects can be equal (same fields) but not identical (different references), and a reference keeps pointing at the same object as that object mutates. So names map to object references or IDs, and descriptions map to queries or property lookups — the object with field x = 5 non-rigidly tracks whatever satisfies the lookup in the current state. This struck me as more than a loose analogy, because sorting out identity from equality is exactly what you have to do to make refernece semantics work, and Kripke's whole move is to insist that names track identity, not descriptions.

Then the part where I got excited: the necessary a posteriori. Hesperus = Phosphorus is, on this view, necessarily true if true at all, since both names rigidly designate Venus, but you can only come to know it by looking at the world. The programming analogue would be that whether two references are identical is something you only discover at runtime by inspecting the actual state, yet within a fixed run, once they are identical, that identity isn't a contingent feature of the state you happened to look at — or is it? This is where it starts to wobble for me, because variables get reassigned and different runs can produce different aliasing, so maybe the fix is to restrict the analogy to immutable bindings, or to map possible worlds to states of a single execution rather than to different executions. I'm not sure that saves it.

So the question: is this a genuine identity of structure, or am I pattern-matching on the word identity? Where exactly does it break? If anything survives, does anything from programming — the distinction between value semantics and reference semantics, or the need for identity criteria when objects persist across state changes — transfer back and teach us anything about Kripkean names? And if it only survives artificially, say what the analogy would have to predict that turns out false.
