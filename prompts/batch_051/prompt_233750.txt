I recently started working through Structure and Interpretation of Computer Programs by Harold Abelson and Gerald Jay Sussman with a reading group, and we have been stuck on section 3.1, “Assignment and Local State.” The authors describe a strategy for organizing programs around computational objects:

> “This view of a system can be a powerful framework for organizing computational models of the system. For such a model to be modular, it should be decomposed into computational objects that model the actual objects in the system. Each computational object must have its own local state variables describing the actual object’s state. Since the states of objects in the system being modeled change over time, the state variables of the corresponding computational objects must also change.”

Our group has been arguing over a chain of reasoning that seems to show this strategy cannot deliver the modularity it promises. (1) If a program is decomposed into computational objects in the way this passage describes, then each object needs mutable local state. (2) But objects in any nontrivial system interact, and when they interact, one object’s operations can read or mutate another object’s state or shared variables. (3) Once that happens, the state of one object is no longer local to it: its behavior depends on the history of the whole interacting system, not just on its own state history. (4) So to reason correctly about what any one object does, you have to reconstruct relevant parts of the histories of the other objects it has touched or been touched by. (5) But the entire point of modularity is to allow localized reasoning about one component without tracing the whole system. (6) Therefore the object-based strategy with assignment and local state undermines the modularity it claims to provide, at least for interacting systems. The conclusion seems too strong — it would push us away from stateful objects toward pure, stream-like models by default — but each step looked plausible to me. Which step should be rejected, and what would rejecting it cost for a language or design method that tries to manage mutation? Please answer in American English.
