I've been going around in circles on this argument that no finite string of bits can be random, and I want a committed verdict, not a survey of options.

(1) A finite string of bits is random only if it is incompressible: no program much shorter than the string outputs exactly that string when run.
(2) Take any string of length n whose shortest outputting program is longer than n/2.
(3) Now consider the description: "the lexicographically first string of length n whose shortest outputting program is longer than n/2." This description needs only n and a simple recipe, so for large n it is far shorter than n/2. If it counts as a program, then it outputs the string, so the string has a program shorter than n/2 after all. Contradiction.
(4) Therefore, for large n, no string of length n can have a shortest program longer than n/2; otherwise step 3 would give it a shorter one.
(5) But a string is random only if its shortest program is at least roughly n bits long. So no sufficiently long string is random, and the short ones are too short to be random in any serious sense anyways. Hence no finite string is random.

I can tell something is off in step 3—"if it counts as a program" is doing a lot of work—but I can't decide whether tightening that up saves the conclusion or kills it. Is the argument valid as stated? If not, which step fails first, and under exactly what reading of "program"? Could the argument be repaired by being stricter about what counts as a program, and what does that do to the conclusion? Take a definite side.
