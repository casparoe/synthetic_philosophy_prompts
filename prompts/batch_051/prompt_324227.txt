I'm giving the opening remarks at a two-day workshop I co-organized, twenty minutes, before the first panel. The workshop is called "Intent Alignment Without Value Alignment?" and the real fight in the room is this: half the audience are ML people from safety-adjacent labs who use "aligned" to mean the system does what the operator actually intended or specified, in the cases we can test or specify, and they want to bracket questions about which values are the right ones for the moment. The other half are philosophers (plus a couple political theorists) who hear that and think it's either naive or a dodge, because "what the operator intended" is itself shot through with value assumptions and operators can intend awful things. I'm a philosopher by training but I've spent enough time around the engineers to think the narrow definition is a real object of study, just not a neutral one. The speech has to do three things: show each camp a sharper, more charitable version of the other camp's position; explain why the narrow definition is worth keeping even if it is not value-neutral; and close by setting up the question the workshop is meant to chew on rather than announcing my own verdict. Use one concrete running example if you can — maybe a fine-tuned assistant that is helpful in exactly the way the reward model specified but in practice defers to whoever is asking, which the engineers count as aligned and the philosophers count as misaligned — and make the example do some work rather than just decorate. Try not to let technical terms from either side sit around unexplained for the side that doesn't use them — "normative" and "axiology" for the engineers, "specification" and "reward model" for the philosophers — but also dont re-explain things the people who use those terms already know. Write the actual speech, not a plan for it.
