I've been reporting on how AI coding tools are changing what actually gets written down in software companies, and a comment from a developer has been nagging at me. She said her team barely writes code anymore: they maintain what they call "the spec," a forty-page natural-language document written in a flat, legalese-ish English, full of numbered clauses like "when an account is three days past renewal, suspend read access but not write access." An LLM turns the spec into Python, and the humans mostly review the generated diff and then edit the spec instead of the code. When the same paragraph produces different code across runs, their fix is to tighten the English, not to patch the Python. I honestly can't decide whether they're programming or just writing unusually fussy documentation.

So here's my working definition of a programming language, four criteria. One: a notation with rules for combining meaningful parts, so that a text has structure that doesn't depend on the author simply insisting on it. Two: it's executable automatically, meaning a machine can carry out the instructions without a human using judgment at each step. Three: it's precise enough that what's expressed doesn't drift between runs or between different implementations of the translator. Four: it can express genuinely algorithmic things — conditionals, repetition, calls to reusable modules. Under that definition, is "the spec" a programming language, and is the team programming when they draft and revise it? Go through the criteria honestly. Where the answer is no or murky, say whether the problem is with the criteria themselves rather than with the spec. And I have my suspicious it's really criterion three doing all the work: maybe determinism was never what made something a program, or maybe it's exactly what did.
