Here's an argument I keep going back and forth on, about GPL copyleft and where one program ends and another begins. I think the conclusion is right but I can't tell if the reasoning is to slick.

(1) At one extreme, a program that statically links a GPL library into its own binary, calls its functions, and shares its in-memory structures is pretty uncontroversially a derivative work of that library — it's got adapted library code baked into the binary.
(2) At the other extreme, a separate program that just sends HTTP requests to a GPL-licensed server across the internet is pretty uncontroversially not a derivative work of the server program — its just another program talking to it.
(3) Between those two poles there's a smooth continuum of coupling: static linking, dynamic linking, dlopen-style loading, same-machine IPC, remote procedure calls, REST APIs over a network.
(4) Each step along this continuum changes the relationship only by degree — a bit more or less shared address space, a bit more or less distance — never by kind.
(5) If each step changes things only by degree, then no step can mark a sharp boundary between "these are one derivative program" and "these are two programs merely interoperating."
(6) So where one program ends and another begins isn't a discovered fact about the code; it's a line we draw for policy reasons. Which means the GPL's "derivative work" boundary is a policy choice, not something the code itself determines.

I suspect (4) or (5) is doing something sneaky — it smells like a sorites argument — but I can't pinpoint exactly how the conclusion could fail when every step looks so plausible. Is the argument valid? If not, which step fails, and on the strongest reading of the premises does the conclusion still go through?
