In a discussion at my school’s computing-and-philosophy club, a member defended this claim: when two programs play a one-shot prisoner’s dilemma and each program is given the other program’s source code as input, their both cooperating shows that they have reached something called program equilibrium. By that, they meant the programs are not merely emitting cooperative outputs that happen to align, but are each conditioning on what the other program actually is—its code—rather than on some incidental feature of the situation. I doubt that one observed run of the game licenses that conclusion, because the programs could both cooperate for uninteresting reasons: one or both might cooperate against every possible input, or might be matching a superficial string in the other’s source code. How could one test the claim that a given pair of programs has genuinely achieved program equilibrium, rather than merely produced outputs that look like it? I would like a concrete experimental design: which variants of the programs or their source code would you run, what pattern of results would support the interpretation that they genuinely condition on each other’s source code, what pattern would support the interpretation that they are only shallowly matching outputs or features, and—after the best such test—what would still be left open about saying that the programs really condition on each other’s source code?
