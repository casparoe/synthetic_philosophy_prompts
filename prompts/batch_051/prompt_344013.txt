I build ML systems, and I've noticed that when people say a model should be legible rather than merely accurate, they seem to mean different things by 'legible' depending on the case. I'd like a working definition of a legible model output (or, if you think legibility attaches to the model rather than the output, a definition of a legible model) that gets these cases right:

- A logistic regression credit-scoring model that prints the coefficient on each input feature.
- A 400-node decision tree that a human can in principle trace from root to leaf for any single prediction.
- A saliency heatmap showing which pixels a vision classifier responded to.
- An LLM that returns a yes/no decision together with a fluent paragraph of reasons generated after the decision.
- A model that accompanies each prediction with the nearest input that would have flipped it and a note on which features differ there.
- A machine-checked certificate from a proof assistant that a consensus protocol satisfies a safety property.
- A large transformer whose forward pass has been partially decomposed into circuits that a specialist team can describe, but which a working engineer cannot retrace end to end.

I suspect 'legible' is doing two jobs: one about whether a human can follow the computation, and another about whether the reasons offered would survive deliberate changes to the inputs they cite. If you agree, give me two definitions and say which cases move between them. If you disagree, defend a single definition and run it through all seven. Either way, tell me which verdict you are least sure about and why.
