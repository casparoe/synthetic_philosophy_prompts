I have been trying to articulate what makes reasoning about mutable state harder than reasoning about pure functions, and I want an assessment of the distinction I have ended up with.

I call it the sameness split. In a purely functional setting there is, for most reasoning purposes, one notion of sameness: two expressions with the same value are interchangeable, and equational reasoning works by substituting equals for equals. Mutation splits this into two notions that can come apart. Token-sameness holds between two names when they designate the same object, so that an update through one name is visible through the other. Content-sameness holds between two objects when they currently have the same value. Mutation is the operation that characteristically preserves token-sameness while breaking content-sameness: if `x` and `y` name the same list, and one mutates the list by appending an element through `x`, then `x` and `y` still name the very same object, but the content now differs from the content that `y` had a moment ago. The classic difficulty of mutable state, I claim, is not fundamentally about time or concurrency or even aliasing as such; it is about this split. Our default style of reasoning presumes the two notions of sameness coincide, and mutation is the first circumstance that forces them apart.

I also want to defend a corollary: the standard remedies can be classified by which sameness they try to restore. Value semantics and persistent data structures make token-sameness track content-sameness, so that equal values are interchangeable and the split collapses. Linear and uniqueness type systems do the opposite: they keep the split but restrict each object to at most one live name at a time, so that token-sameness can safely be treated as if it were content-sameness within a scope, because no other name can observe the divergence.

I would like an honest assessment: is this a genuine distinction or only a redescription of the standard value/reference distinction? Does the account get the order of explanation wrong — does the split already presuppose time, rather than explaining why time enters reasoning? And where does it fail? For instance, does it say anything about local in-place mutation with no aliases, where the split is present but unproblematic; about equality that is too expensive or undecidable, which makes even pure code reason about identity; or about concurrency, where a third notion of sameness — sameness across moments of observation — seems to be doing work the split cannot capture? I am not attached to the label; I want to know whether the theory locates the real difficulty or merely relocates it.
