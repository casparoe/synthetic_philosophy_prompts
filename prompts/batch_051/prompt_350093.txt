Here's an argument a statistician colleague gave me over coffee, and it's left me unsure whether I'm entitled to say anything at all about the randomness of a finite string.

(1) If a finite string is random, it's random in it's own right, not because of the process that emitted it; a fair coin can land HHHHH, and someone can deliberately type out 0110100111.

(2) The only intrinsic feature that could make a string random is incompressibility: the string is random just when the shortest program that outputs it is roughly as long as the string itself.

(3) But for any particular string, there's some programming language in which that string gets a very short description—say, a language whose single instruction '1' outputs exactly that string.

(4) So incompressibility is language-relative, and by choosing the language after seeing the string you can make any string come out trivially compressible.

(5) Therefore no finite string is intrinsically random, and 'is this finite sequence random?' has no well-defined answer.

I want to say that 0101010101 is less random than 1001110110, and I can't shake that, but I also can't find the step where the argument cheats. Which premise do I reject, and what does rejecting it cost?
