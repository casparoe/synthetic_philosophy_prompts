I built the following argument for a reading group and now distrust it, because its conclusion seems to rule out aliasing — and with it, a great deal of ordinary imperative programming. But I cannot locate the faulty step.

Let `x` and `y` be two variables whose value is one and the same mutable list `L`, and suppose that initially `L[0] == 0`.

(1) If a variable is not the target of an assignment during a computation, then its value is unchanged by that computation. (The frame assumption.)

(2) We perform exactly one assignment: `x[0] = 1`. The variable `y` is never the target of an assignment.

(3) By (1), the value of `y` is unchanged after the assignment. Since before the assignment the value of `y` was a list whose first element is 0, we may infer that `y[0] == 0` still holds afterwards.

(4) But the value of `y` is `L`, and the value of `x` is `L`; they are one and the same list. After the assignment, `x[0] == 1`. Since identicals are substitutable, whatever holds of the list denoted by `x` also holds of the list denoted by `y`; so `y[0] == 1` afterwards.

(5) Contradiction: `y[0] == 0` and `y[0] == 1` in the same final state.

(6) Therefore at least one of the following must be abandoned: the frame assumption, the substitutivity of identicals, or the claim that two variables can share one mutable object. Yet all three appear indispensable to reasoning about state.

Where does the argument go wrong? If a premise must be rejected, which one is it, and what does rejecting it cost — both for formal semantics and for how a programmer is allowed to reason locally about assignment and functions?
