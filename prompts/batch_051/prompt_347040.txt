I'm on the license-compliance committee for a midsize software company, and we've built up a little pile of our own precedents about when our code counts as a derivative work of GPL-licensed code (and so has to be GPL'd). These cases always come down to the same fuzzy question: where does one program end and another begin? We have a new proposal to rule on, and I'd like you to act as a lawyer who specializes in open-source licensing and help us stay consistent with ourselves.

Our past calls, in the order we made them:

1. Our proprietary photo editor shells out to a GPL command-line encoder as a separate process, writing an intermediate file to /tmp and reading back the result. We ruled: not a derivative work; no GPL obligation.
2. We statically linked a GPL physics library into our game and called its internal, undocumented functions; we shipped it all as one binary. We ruled: derivative work; GPL applies.
3. We took a GPL utility, modified its source, added proprietary code, and shipped the result. We ruled: derivative work; GPL applies.
4. Our phone app talks to a GPL-licensed server over HTTPS using a public REST API; users install the two pieces seperately. We ruled: not derivative.
5. We dynamically linked a GPL library into a desktop app, called only its documented public functions, and shipped the library and the app together in one installer. We ruled: derivative work; GPL applies.

The new proposal: a proprietary plugin for a popular GPL-licensed host application. The plugin is a .so/.dll that the host loads into its own process, but the plugin talks to the host only through the host's stable, documented plugin API. It never touches host source or internals, and a clean-room clone of the host could load the same plugin unchanged. We would distribute only the plugin from our website; the user would download the GPL host separately.

I want a committed answer, not a menu of options. Think it through carefully: first brainstorm the candidate rules that fit all five past decisions, and write them down before you pick. Then tell me what each live rule predicts for the plugin case, which past decision is the closest analog, and then commit: what should we decide if we want to be consistent with our own precedents? If our precedents genuinely underdetermine it, say what principle we'd be adopting with each choice and which choice you'd recommend. End by naming the single further hypothetical case that would best tell apart whatever rules are still live.
