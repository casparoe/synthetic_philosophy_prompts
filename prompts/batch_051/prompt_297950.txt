I lost an afternoon this week to a bug where I did `b = a`, then appended to `b`, and was genuinely suprised that `a` changed too. I know the jargon — references, values, mutability — but I've never actually settled on what I mean when I say two things in a program are "the same thing." I want a working definition of sameness/identity for variables and state that handles these:

- `a = [1,2]`, `b = a`, then `b.append(3)`. Same thing?
- `x = 10`, `y = x`, then `y = 20`. Same thing, or just equal?
- Two list literals `[1,2]` and `[1,2]` bound to different names. Same thing?
- A function that mutates an element of a list argument, so the caller sees the change, vs. one that rebinds the parameter to a new list, so the caller doesn't.
- A tuple that holds a list, where I mutate the list. Did the tuple change?
- A database row that gets changed with an UPDATE vs. a row I delete and replace with a new row that has the same primary key. Same row?
- A file on disk that I open, edit, and save. Same file, or a new version of it?

The list aliasing case feels like the clearest possible yes and the int rebinding feels like the clearest possible no; the function, DB, and file cases are where my gut keeps flipping. Give me the rule, run every case through it, and tell me which case most makes you want to bend or abandon the rule. If you think "same thing" is doing two jobs here, you can split the term instead of forcing one definition.
