I keep hitting the same wall in an argument with a friend about what the GPL actually requires. The whole thing turns on what counts as a "derivative work," but none of us can give a defintion; we just point at cases and gesture. So give me a working definition of derivative work — for software, under a strong copyleft license like the GPL — that gets these cases right:

- You copy about 50 lines of GPL'd code into your own program and distribute the result.
- You fork a GPL project, modify it heavily, and distribute the modified version.
- You merely run a GPL program on your own laptop and never distribute anything.
- You write your own program, link it dynamically against a GPL library, and ship only your program.
- You write a plugin for a GPL application using its plugin API, and distribute only the plugin.
- You write a seperate command-line tool that calls a GPL utility via fork/exec, and ship only your tool.
- You reimplement what a GPL program does from scratch, never looking at the source, working from a spec you wrote yourself.
- You distribute only a config file and a shell script that invokes a GPL program; the user has to get the GPL program themselves.

I'm confident the first two are derivative works and merely running it on my laptop is not. After that I'm genuinely confused, and so is everyone I ask. Propose the definition, run it through all eight, and tell me where your definition gives a verdict you think is wrong or no answer at all. Also flag which of your verdicts you'd least want to defend.
