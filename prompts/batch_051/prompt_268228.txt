I'm putting together a one-page proposal for a small grant in formal epistemology, and I want the project to grow out of a puzzle I've had since I first read about Kolmogorov complexity and Solomonoff induction. For infinite binary sequences, algorithmic randomness gives us a sharp, widely accepted criterion, and for generating processes we don't hesitate to call a source random. But when someone asks whether a particular finite string, say 200 bits, is random, every serious answer seems to change the subject: we are told the string is incompressible relative to some reference machine, or that it passes a specified battery of statistical tests, or that it is typical of an ensemble. We are never told that the string itself simply is random. I suspect the original question is badly posed and that randomness for finite objects is better treated as a relation to a machine, a test family, a prior, or an inferential purpose. But I also feel the pull of the opposite view: there is something right about calling a finite string random when it would have been unreasonable to expect any deterministic rule we could have specified in advance to produce it.

I'd like the proposal to make a version of this relational picture precise without collapsing into the triviality that every string is random with respect to some description and non-random with respect to another. The central question would be roughly: can we give a principled account of when a choice of reference class or test family is the appropriate one for a given inferential task, so that calling a string random or non-random becomes a verdict about how the string bears on that task rather than a disguised report of someone's prior? The proposal should state the question precisely, explain why the existing treatments leave it open (references to positions and named views are fine, but no literature review or citations; I'll supply those myself), and explain why the obvious alternatives are inadequate: a purely process-based account says nothing about a string whose provenance is unknown, and the standard formal notions for infinite sequences leave finite strings with a graded deficiency rather than a verdict. It should also lay out a realistic six-month plan, say what a useful deliverable would look like (a formal criterion, or a negative result showing no criterion can meet a short list of desiderata), and distinguish a failed project from a boring answer.

Please write the proposal in continuous prose only, with no headings, bullet points, bold text, or tables, the way one would write an email or a letter. And wherever it is most honest, say which consideration would most likely break the project's framing and what would change your mind about the relational claim itself; I'd rather see the failure mode stated explicitly than have the proposal oversell the approach.
