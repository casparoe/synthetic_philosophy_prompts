I'm a software engineer who got roped into TAing a "Philosophy and AI" elective this semester — my only qualification is that I've read some planning code and sat through the first few lectures, so I'm comfortable with STRIPS and BFS but shaky on the actual philosophy. The midterm had a short-answer question, and I have to grade a student's answer to it. The question was:

"Explain the frame problem as it was originally formulated in AI, and then assess whether modern automated planning techniques have solved it."

Here is the student's answer, word for word:

"The frame problem was introduced by McCarthy and Hayes in their 1969 paper. The basic issue is that if an agent knows a bunch of facts about a situation and then performs an action, a logical system has to be told both what changes and what stays the same. If you only write down the effects — e.g. painting the table red — the system can't infer that the wall is still white, that the table's position is unchanged, and so on. The naive fix is to write 'frame axioms' for every action and every fact that isn't changed, but that grows like actions × facts and is totally impractical. So the problem is really about how a finite cognitive system, under time pressure, figures out which of the many things it knows are relevant to update and which it can safely ignore. That's why Dennett saw it as a deep problem about the mind, not just an implementation detail for AI. Later planning systems like STRIPS and the successor-state axioms used in situation calculus solved it in practice, by making the closed-world assumption that anything not explicitly changed by an action stays the same, so you only have to list effects."
