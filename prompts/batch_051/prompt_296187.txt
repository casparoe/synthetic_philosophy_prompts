I am a student taking a course in the philosophy of computing, and I keep noticing an asymmetry in how engineering organizations treat programming languages. When a human writes code, the choice of language is treated as a consequential decision: a Python script submitted to a Rust shop will be questioned on grounds of type safety, performance, maintainability, and team expertise, even if it passes the tests. When a language model writes code, that same organization often treats the language of the generated code as an implementation detail and reviews the result only by whether it behaves correctly. The same program, in the same language, is held to two different standards depending on its author. Is there a principle that justifies this asymmetry, or does it reveal that part of the earlier concern with language choice was never about the code but about the coder? I want the strongest justification you can find, tested against nearby cases: a model-generated C program with a latent memory-safety bug that passes the test suite; a human-authored Python script introduced into a Rust codebase for a one-off task; and a repository where humans and models take turns authoring the same files. Then say whether the asymmetry should be kept, extended, or abandoned.
