I've been trying to get my head around the Kripke stuff about rigid designators, and I keep feeling like it maps onto something we already have in programming, but I can't tell if it's a real structural parallel or just a vocabularly accident. As I understand it: a proper name is supposed to pick out the same individual in every possible world, while a description like 'the teacher of Alexander' picks out whoever happens to satisfy it in each world. That sounds almost exactly like the difference between a const reference and a state-dependent expression: a const reference still points to the same object no matter what happens to the rest of the program state, while something like 'the oldest active user in the DB' evaluates to different people in different states. If that mapping is right, does the necessary a posteriori distinction show up too? Say two const references compare equal — I only find that out by running the program, but once they're bound to the same object, isn't the identity fixed across all the states the program can reach, the way 'Hesperus is Phosphorus' is supposed to be necessarily true but only knowable empirically? Or am I smuggling in a bad analogy by treating possible worlds like program states — maybe worlds are total ways things could be while program states are just partial snapshots? I'd like to know exactly where this parallel earns its keep and where it actually breaks.
