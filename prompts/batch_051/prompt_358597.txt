So I teach an undergrad seminar on intellectual property and free software — about 16 students, one 90-minute session. I want a classroom game or structured simulation that makes them feel the problem behind copyleft rather than just hear about it: where does one program end and another begin? I want them to run into the fact that all the clean-sounding tests people invoke (static versus dynamic linking, plugin versus separate program, modification versus mere aggregation, distributing versus running over a network) get treated as if they settle whether something is a derivative work, but real combinations of code keep falling in the gaps, and someone still has to draw the line anyway. The activity should force them to draw it themselves, repeatedly, under time pressure, and then watch their own rulings start to wobble. Ideally they run smack into the problem before it's named, so I'd want no lecture up front.

I'm imagining something like teams assembling a product from code cards — modules, libraries, patches, wrappers, network services — under simplified GPL-style rules, with a rotating license board that has to rule on each combination: derivative work or not, and what obligations follow, with small point stakes for shipping features versus staying compliant. The debrief should map the moments where they were argueing to the real pressure points in copyleft: aggregation clauses, the license's language about what counts as a work based on the licensed code, the old linking disputes, and the gap between copyright's derivative work doctrine and whatever extra reach the license gets by contract. Also tell me what will predictably go wrong the first time I run it, and be honest about what the game cannot reproduce — I suspect it's something like real outcomes being settled by courts, jurisdictions, and market power, not just by getting the rules right.
