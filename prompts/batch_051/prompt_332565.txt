I've been trying to settle what I actually think about a boundary question in free software, and I'd like you to help me extract the principle behind my reactions. Suppose a program is distributed under a copyleft license of the familiar kind (the GPL is the usual example, but I don't want to rest anything on its exact wording): you may use, modify, and redistribute it, but any work that counts as a derivative work of it must be distributed under the same terms. The practical question is always where one program ends and another begins. Here are my verdicts on particular cases. Copying the whole source and renaming every variable is plainly derivative. Porting the program by translating its source line by line into another language is derivative, but reimplementing the same command-line interface from the published documentation, without reading the source, is not—even though the two reimplementations may behave identically. A plugin that is loaded into the program's process and calls its internal API feels derivative to me, as if it is part of a larger program; a separate utility that merely invokes the program's command-line tool and pipes data in and out does not, even though it is equally useless without the program. A five-hundred-line macro written in the program's own extension language that adds a new feature feels derivative, while a twenty-line preferences file for the same program does not, and I cannot say what changes between the two. A game level or a grammar file consumed as data does not feel derivative even when the program is nearly useless without it. A code generator that emits modified copies of the program's source is itself not derivative, but the copies it emits are. And when a small copyleft library is statically linked into a large proprietary application, I find myself saying the whole application is derivative—but only because I don't see a principled place to draw the line, and that verdict makes me uneasy.

Is there one coherent account of what makes something a derivative work that captures all of these, or nearly all? Please state the candidate principle, or a small set of candidates, as precisely as you can, showing which clause handles which of my verdicts, and tell me honestly which of my verdicts it cannot accommodate and whether you would overturn that verdict rather than complicate the principle. Then apply the account to the cases I keep going back and forth on: a shim that intercepts the program's function calls at load time without any linking at build time; a generic script interpreter that can run scripts written in the copyleft program's extension language; and a trained model file that the copyleft program loads at runtime.
