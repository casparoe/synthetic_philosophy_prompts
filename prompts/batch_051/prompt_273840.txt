Okay so in my decision theory seminar we've been doing acausal trade—the idea that two agents who can't communicate, can't enforce a contract, and maybe don't even share a causal past can still "trade" because each side's decision algorithm treats the other's likely decision as evidence about what it will itself decide to do. The toy case: two agents in disconnected branches, one cares about apples and one about oranges; each can spend 1 util to deliver 100 utiles to the other; there's no punishment for defection, but if each algorithm can predict the other from source code, mutual cooperation can be a fixed point.

A guy in class proposed a mechanism he called the Acausal Trade Registry. Any agent can register a public commitment: published source code that says "I will perform action A (a precise, costly-to-me, beneficial-to-a-named-other action) iff the Registry's verifier certifies that the named other has registered a symmetric commitment of comparable value." The verifier can check wether the commitments are symmetric, compute some kind of symmetry score for the payoffs, and publish everything, but it cannot observe whether the acts are ever performed—they happen in different causal branches, so execution is essentially unverifable by design. Registration is open, and the verifier is just a deterministic algorithm that everyone can inspect.

The proposer claims this fixes the "who goes first" problem and gives cooperators a public focal point instead of pairwise guesswork about who else is the acausal-cooperative type.

I'm not asking whether acausal trade is rational or whether this registry is a good idea in the abstract. I want to know how it would actually behave if a bunch of agents took it seriously. Who registers first, with what sorts of commitments, and why would anyone register given the total lack of enforcement? How would it get gamed—registering lots of commitments and selectively defaulting, writing vague commitments that game the symmetry metric, bluffing with forged certifications, or committing to code that crashes before the action executes? Does the registry make genuine cooperators easier to find or easier to imitate? Does it just move the trust problem to the verifier, and can that be fixed without reintroducing causal enforcement? And does the stable version end up looking more like pairwise mirror-commitments between agents who can read each other's source code, in which case what is the registry actually adding?
