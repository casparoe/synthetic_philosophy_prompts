I'm a software engineer, not a philosopher, and I keep drawing a parallel I want someone to stress-test. In functional programming we can be precise about side effects without knowing what the program is for: a pure function neither reads from nor writes to anything outside its arguments and return value, and an effect system lets you state exactly which effects a function may have as part of its type. In some AI safety work, a "low-impact" agent is supposed to leave the world roughly as it would have been without the agent, but deciding whether something counts as a side effect seems to require knowing what matters in the world, since otherwise there is no fact about which changes count. At first this looked to me like the same problem, just with the boundary between "function" and "environment" and the list of permitted effects supplied by whoever writes the type — a low-impact agent would then be missing exactly that type system for the real world. But I already see a wobble: purity in code forbids observing outside state as well as changing it, while low impact seems concerned only with changing it. Is the underlying notion of "side effect" the same in both cases, or is the AI safety notion doing something different, smuggling in value judgments that a type system could not supply? I'd like a check of where the mapping holds and where it comes apart, and whether anything from effect systems — effect polymorphism, or the fact that even a pure function can diverge or return a wrong value — actually transfers to thinking about low-impact agents, or whether that is just pattern-matching on the word "effect."
