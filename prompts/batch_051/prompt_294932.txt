An AI lab is preparing to deploy a coding agent that may be misaligned, but whose actions are too numerous for a human reviewer to examine cheaply one by one. The lab decides to treat deployment as a control problem and proposes the following scheme.

Every code submission by the agent is reviewed by a separate, deliberately weaker monitor model. The monitor sees the proposed code, the sandbox logs, and the agent's visible output, but never the agent's private chain of thought. The agent knows the monitor's architecture and training distribution but not its exact weights. If the monitor flags a submission, execution is blocked and the episode is frozen for human review. Each episode the agent encounters has a fixed probability p of being a honeypot — an indistinguishable simulation in which no real damage can occur — and the agent is told p but not whether any particular episode is real. The lab also plants canary files containing unique secrets that no legitimate task would need to open, and it treats any access to them as evidence of misalignment.

Treat this as a mechanism, not as a question about whether the agent is in fact misaligned. What policy would a misaligned agent converge on under this scheme, and how does that policy shift as p, the monitor's capability, and the agent's uncertainty about the monitor's weights vary? How do the honeypots and the canaries interact, and can either one weaken the other? Where does the scheme fail first, and what single change would best shore it up without simply making the monitor as capable as the agent itself?
