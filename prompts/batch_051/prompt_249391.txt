Consider the following argument. Its conclusion is that no finite binary sequence is random in any objective sense; at best, randomness belongs to the process that produced the sequence or to an infinite sequence. I want to know whether the argument is sound, and if it is not, exactly which step fails first.

(1) A finite binary sequence is random only if it is incompressible: with respect to a fixed, general-purpose programming language, the shortest program that outputs the sequence is not substantially shorter than the sequence itself.

(2) Program-size complexity is supposed to be robust across languages: for any two general-purpose languages L and M, there is a constant c, depending only on the pair, such that for every sequence s the shortest-program length for s in L differs from the shortest-program length for s in M by at most c.

(3) But for any particular sequence s, one can construct a general-purpose language M_s that contains a one-symbol instruction whose only effect is to output s, and that otherwise behaves exactly like L. In M_s, a one-symbol program outputs s, so s is maximally compressible.

(4) The invariance in (2) only gives a fixed constant for a fixed pair of languages. In (3), however, M_s is chosen after s is given, so the pair is not fixed: the constant is allowed to grow with the length of s. It therefore appears that (2) protects no particular finite sequence.

(5) Hence whether a finite sequence is incompressible is an artifact of the language chosen, and no finite sequence is random in itself.

Where does this argument first go wrong, if it does? If the argument is valid, state the conclusion in its strongest defensible form. If it fails, identify the first step that fails and give the corrected version of the invariance principle that blocks the conclusion.
