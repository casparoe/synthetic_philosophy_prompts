I've been going around in circles on wether it makes any sense to call a finite string of bits random, and I'd like you to find the principle behind my gut reactions — or tell me which ones have to go. Here are my verdicts.

(a) I type the string 01010101010101010101010101010101 on purpose. Obviously not random.
(b) The exact same string comes out of a fair coin I just flipped. I still want to say the string isn't random; only the process was. But that bugs me. If the process was random, how can its outcome not be random?
(c) The string 31415926535897932384626433832795, which is just the first 32 digits of pi. I don't want to call it random, because there's a short recipe for it. But if someone handed me that string without telling me where it came from, I'd probably call it random-looking, or even just random. That also bugs me, because the string itself didnt change.
(d) A different string from a fair coin that happens to look unpatterned, say 01001101011010010110111000011011. I call it random.
(e) A string produced by a standard pseudorandom number generator with a fixed seed — I won't write out the bits. I call it not random, even if it passes every statistical test I know, because the whole thing is regenerable from a small seed.
(f) The string 101. I have no idea what to say; maybe randomness just doesn't apply to strings that short.

Is there one principle that delivers all or most of these? If not, which verdicts do I have to overturn, and what's the cleanest view of finite-string randomness that survives? Also: what does your principle say about a long string deliberately constructed to pass all the standard randomness tests but that actually has a short hidden description — and about that same string if it arose by chance?
