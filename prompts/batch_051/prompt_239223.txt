Lately I've been going in circles about whether a finite sequence can be random at all in the algorithmic sense. On one hand, any finite string is the output of some program, so if you allow yourself to pick the programming language after seeing the string, you can make its Kolmogorov complexity tiny; that makes it look like randomness can't be a property of the string itself. On the other hand, people do run finite strings through things like the NIST test suite or Maurer's universal test and say a particular string "passed" or "failed", as if the string were the object being tested. And there's also the notion of randomness deficiency relative to a fixed universal prefix machine, which seems meant to assign a number to a finite string rather than a yes/no.

I'd like to understand what, exactly, someone could coherently mean by calling a specific finite string random. Is it really a property of the string, or is it only a property of the string together with a choice of reference machine, or perhaps of the process that produced it? If a skeptic said "for any finite string, I can always pick a universal machine that makes it look non-random," what's the best response that rescues a usable notion of finite-string randomness without hand-waving? I'm not asking for the details of particular statistical tests; I want the conceptual picture of where the arbitrariness enters and how much of it can be neutralized.
