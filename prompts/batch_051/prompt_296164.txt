Two people in my department's foundations-of-probability reading group got into it last week over whether you can ever say of a particular finite string that it is random, and it got suprisingly heated. I'm a philosophy-of-science PhD student in the group and they asked me afterwards to adjudicate; I honestly couldnt, so I'm outsourcing. The exchange went roughly like this:

(1) Sonia opened with: a finite string is just an outcome. Randomness is a property of the generating process, not the product. A fair coin has exactly the same probability of producing 00000000000000000000 as 10011010111001011010, so there is no sense in which one string is "more random" than the other. If the process was random, the output is random, full stop.

(2) Marcus said that can't be the whole story, because we constantly reason about random-looking versus structured-looking data — audits, lottery drawings, failed QRNGs. Kolmogorov complexity gives a string-level notion: a finite sequence is random to the degree that it is incompressible, i.e., the shortest program that prints it is about as long as the string itself. That is a fact about the string, not about how it was made.

(3) Sonia came back that incompressibility is not absolute. It is defined relative to a chosen reference machine, and for any particular finite string there is a legitimate universal machine with a short built-in code for exactly that string; the invariance theorem only stabilizes things up to an additive constant, and for a twenty-bit string that constant is the whole game. Besides, "incompressible enough" is a graded matter — you have to pick a cutoff for what counts as random, and that cutoff is arbitrary. So the string-level notion does not deliver a yes/no answer either.

(4) Marcus replied that once you fix a universal reference machine, the constant is fixed, so for long strings the ranking is robust, and picking a cutoff is just like picking a significance level in a statistical test — conventional, but not arbitrary, and it does not show there is no fact about the data. He added that Sonia's view has the opposite problem: if only the process matters, then looking at the output can never tell you anything, and you would have to treat 0000...0 as exactly as suspicious-or-not as a high-complexity string, which makes randomness testing pointless.
