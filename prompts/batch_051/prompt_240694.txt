I'm a software engineer and I keep noticing philosophy arguments online that sound exactly like arguments we have in code review, only the vocabulary is different. The one I can't shake is about truth. A friend has been trying to explain deflationism to me: the idea that calling a sentence true doesn't add anything to it. The sentence "the server is down" is true just says that the server is down, full stop. Truth isn't a deep property with a hidden nature, its just a way of stripping the quote marks back off. When I heard that, I thought: that's an identity function. A wrapper that takes a value and hands it back unchanged.

But I've spent years writing identity functions and no-op wrappers, and "it does nothing" is rarely the end of the story in code. An identity function earns its keep when you need to pass a function where an API expects one, or when you want a default that keeps a pipeline shape stable, or when a generic routine has to work over many types and the identity case is just one specialisation. So I started wondering whether deflationism is actually saying truth is useful in the same indirect way: you need "is true" so that you can endorse every claim in someone's testimony without listing them, or point back at an earlier statement ("what she said is true"), or reason over unknown content ("whatever the spec says is true"). The parallel I can't decide about is this: is deflationary truth literally an identity function for sentences, and if it is, do the reasons identity functions are useful in programming — genericity, defaults, satisfying an interface — transfer over and tell us where the word "true" is doing real work rather than being redundant? Or does the analogy break because a truth predicate lets you quantify over positions you can't fill with a literal sentence, which sounds more like a variable than a wrapper. Is any of this a deep structural point, or am I just pattern-matching on the phrase "does nothing"?
