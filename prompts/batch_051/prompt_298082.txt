I build multi-agent systems and keep running into a game-theoretic configuration I don't have a name for. Take two programs playing a one-shot prisoner's dilemma, with no repetition and no outside enforcer. Each program can read the other's source code before choosing its move. A new equilibrium appears: each program adopts the rule, cooperate only if the other program's code is identical to mine. If both run that rule, both cooperate; if one switches to unconditional defection, the other sees the mismatch and defects, so the switcher ends up with the mutual-defection payoff, which is worse than mutual cooperation, and the switch is unprofitable. I have seen the same shape when two automated trading agents can inspect each other's decision module before deciding whether to honor a handshake. Is there an established name for this configuration? I want more than a label: I want to know whether it should be filed as a refinement of Nash equilibrium in a larger game whose strategies are programs, as a Newcomb-like case where each side reasons about the other's decision procedure rather than its move, or as something closer to the symmetry argument Hofstadter called superrationality — and what exactly distinguishes it from each of those neighbors. Where are its edges: does the effect require the entire source code to be readable, or does it survive partial, hashed, or noisy inspection, and is the identical-code condition an incidental implementation trick or the conceptual core? If there is no standard name, what would you call the class, and how would you define it so that this configuration is an instance but ordinary reputation and repeated-play reciprocity are not?
