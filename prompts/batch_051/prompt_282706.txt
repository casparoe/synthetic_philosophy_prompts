I am a software engineer at a company that ships an on-premises application, and I have been going back and forth with a colleague about our use of a copyleft-licensed library. The library is dynamically linked into a core service of ours: our code and the library run in the same process, and the container image we distribute to customers contains both. My colleague claims this forces us to release the source code of the entire service under the copyleft license. I have no formal background in law or philosophy, and I am finding it hard to say exactly where his reasoning goes wrong or whether it goes wrong at all.

His argument, as I understand it, runs as follows. (1) A derivative work is, roughly, a work that recasts, transforms, or adapts a preexisting work. (2) The container image we distribute is a computer program that contains the library's code, combines that code with ours, and adapts the library to our purposes. (3) A computer program can be a work for copyright purposes. (4) Therefore, the container image is a derivative work of the library. (5) We distribute that derivative work. (6) A copyleft license requires that derivative works be licensed as a whole under the same terms as the original. (7) Therefore, we are required to license the source code of our entire service under that copyleft license.

I have two intuitions: the argument seems to leap from the combined image to our separately authored source code, and step (6) seems to assume that the license reaches our preexisting code rather than just the library's code as used in the combined work. But I cannot make either distinction precise. Is the argument valid? If not, which step fails, and under what reading? If it is valid, why doesn't it make all separately authored programs that sit alongside copyleft code impossible to distribute without open-sourcing everything?
