I have a distinction I keep using and want checked. I split "revision" from "mutation" proper. Revision is when a name is rebound to a wholly new value; nothing about the old value carries forward except through explicit data flow. Mutation proper is when a cell is written through while the cell persists, so the name denotes the same cell with changing contents over time. My hypothesis is that the famous difficulty of state isn't really about values changing; it's about identity plus shared observation. A mutated cell is the same individual across time even though none of its current properties need persist, and—more importantly—two lexically distant regions that never mention each other can share the cell and thereby change each other's results without either region's text changing. I've been calling that last relation "silent agreement." The strong claim: silent agreement is necessary and sufficient for mutation to be hard. If a language prevented it—say, by guaranteeing that every cell has a single owning lexical region at any given time—the remaining mutation would be no harder to reason about than assignment in a functional language. Is the revision/mutation distinction sharp, or does it blur in edge cases? Is the necessary-and-sufficient claim true, or does it fall apart once you look at loops, concurrency, or object identity? And what existing idea have I reinvented?
