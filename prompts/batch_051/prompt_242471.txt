ok so for a philosophy club thing I'm collecting objections to the idea that our internal language of thought is basically a programing language (like Lisp or Python) and not natural language. So far I've got five and I keep getting told there aren't really any others, but I don't buy it. The five: (1) symbol grounding — the symbols in a program only mean anything because a programmer or some outside interpreter gives them a meaning, so code on its own isn't about anything; (2) code is discrete and serial, so it has trouble with analog or imagistic thought, like mentally rotating a map; (3) indexical thoughts (I, here, now) are hard to code because their content depends on the context of use, not on anything stored in the representation; (4) thought can be vague and still be thought, but a vague instruction in a program just crashes it or makes it do something you didn't want; (5) phenomenology — a calculator running an algorithm isn't literally thinking about numbers, and nothing about executing code explains what it feels like to think. Can you give me one more objection that is genuinely different in structure from all five — not a rewording, not a special case, not a combination of them? Then tell me what it adds that the five don't, and be honest about whether it's actually a good objection or just sounds clever.
