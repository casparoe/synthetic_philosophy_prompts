Assume we are working with a copyleft license under which an unmodified program A can be used freely, but any derivative work of A must be published under the same license. The only question that matters here is whether a second program B is a derivative work of A in the following stipulated sense: B is derivative when A and B are, in substance, one program rather than two programs that happen to interoperate. To determine that, weigh four considerations.

1. Code. Does B incorporate or adapt A's expression — for example, by containing part of A's source or a line-by-line translation of it into another language?
2. Execution. Do A and B execute as one combined program, as when they are linked into a single executable, share an address space, or run in one process?
3. Interface. Is the boundary between them bespoke to A — modeled on A's operation names, data structures, or control flow — or is it a stable, independently specified protocol that any conforming implementation could satisfy?
4. Function. Does B depend on A the way an application depends on a generic platform, or the stronger way a component depends on the program it extends, by having no point except as a front end for A?

No single consideration is decisive; they are weights and may point in different directions.

Now consider this case. A company sells a proprietary program called Console separately from an unmodified GPL-licensed simulation engine. Console contains none of the engine's code and does not link to it: it launches the engine as a child process and exchanges JSON over a local socket. The protocol is stable, documented, and uses general verbs like start, pause, step, and sample; the company can point to an interface specification written independently of the engine's internals, and it insists that any engine implementing that specification could be substituted. Yet every Console feature is a control surface for running and inspecting this engine, Console's configuration files mirror the engine's settings one-for-one, and Console has no known use except with this engine. The two arrive in a single installer, are marketed as one simulation product, and are always run together, but they remain two executable files under two licenses.

Is Console a derivative work of the engine under the stipulated test? Take the four considerations in order and say how strongly each points, and where the test underdetermines the verdict. Then say whether the case reveals a flaw in the test: are the Interface and Function considerations really the same criterion double-counted, or are they genuinely distinct? Finally, state how you would revise the test so that the marketing decisions — bundling, installer, labels — cannot smuggle in a verdict that the four considerations have not earned.
