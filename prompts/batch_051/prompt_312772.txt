I'm in a cryptography course and the professor keeps saying 'random' as though it's a property a finite string can have, while a friend who does statistics insists the word only applies to a process, never to a sequence. We blew up a dinner over some cases: a run of 20 heads in a row (exactly as likely as any other run of 20 flips, but everyone would call it non-random); the first million digits of pi (they passed every test we threw at them, but they come from a boring deterministic formula); a 100-bit string fresh from a fair coin that has no obvious patterns; a 1-megabyte file from a hardware random number generator that happens to contain a long run of repeated bytes and compresses a little; the string 010101... repeated a thousand times; and a sequence drawn from a genuinely random source that, by pure chance, spells out a recognizable sentence in ASCII. My friend says all that matters is how the string was produced. I keep wanting to say that if I had to bet on the next bit, the pi digits are effectively random and the alternating string isnt, whatever their histories are.

Can you give me a working definition of 'random' for a finite sequence — or argue properly that the word doesn't apply to sequences at all and only to sources? Run your definition (or your argument) through all six cases and tell me where it gives the wrong answer, no answer, or an answer you'd have to strain to defend. Bonus if it explains why we keep sliding between the process-sense and the string-sense of the word.
