(1) The standard line in CS is that "efficiently computable" = polynomial time, and anything superpolynomial is infeasible in practice except on toy-sized inputs.

(2) SAT is NP-complete, so unless P = NP there is no polynomial-time algorithm that solves all SAT instances.

(3) P != NP is the only sane bet at this point (if P = NP, integer factorization is polynomial and essentially all of crypto as we run it breaks, so I'm not going to treat P = NP as live).

(4) So SAT is infeasible in general, and since my scheduling problem is NP-hard (I did the reduction myself) it's infeasible in general too.

(5) But my solver handles industrial instances with millions of variables and is running in production for actual users. That is not "toy-sized."

(6) So either "efficient = polynomial time" is just wrong, or complexity theory has nothing useful to say about the computations I actually care about.

I cant accept (6), it throws out all of algorithms class, but I dont see which earlier step broke. Where does this argument go wrong, if it does?
