I teach an upper-level undergraduate course on programming languages, and we have been covering state, evaluation order, and the ways different languages handle object identity. For the midterm, I set the following question, worth 10 marks:

"Define aliasing and referential transparency. Explain how the presence of mutable state makes program reasoning harder than in a purely functional setting, making specific reference to these two notions. Then assess the extent to which the difficulty is removed by (a) adopting value semantics and (b) restricting oneself to immutable data."

One student wrote the following answer:

"In a language with reference semantics a variable is a reference to an object rather than the object itself, and assignment copies the reference rather than the object. Aliasing occurs when two variables hold references to the very same object. This only causes trouble when the object is mutable: if it is changed through one name, the change is visible through the other name, so the behavior of a piece of code can be affected by updates made elsewhere that are not apparent from the code itself.

Referential transparency is fundamentally a species of determinism: an expression is referentially transparent exactly when it yields the same value every time it is evaluated, and a function is referentially transparent exactly when it returns the same output for the same inputs. Mutable state threatens this because the same expression may produce different values at different moments, and because reordering or duplicating an expression can change what is observed, so equals can no longer be freely substituted for equals.

Value semantics repairs much of this. Under value semantics, assignment copies the entire object, so no two variables ever denote the same object, and aliasing cannot arise at all. This restores a good deal of equational reasoning. Immutability goes further still: an immutable object can be shared without risk because no one can change it, and for purposes of ordinary value reasoning its identity need not be tracked. Immutable, value-semantics code therefore removes the hard part of reasoning about shared state; what remains is only the ordinary difficulty of getting the intended algorithm right."

Please tie the comments to specific sentences of the answer rather than giving a general impression.
