I am a software engineer with no formal background in philosophy, so if I am using any of the mathematical terminology loosely, correct me as part of your answer. I keep noticing a parallel between a decision-theoretic puzzle I once read about — I believe it is called the Pasadena game — and a class of failure I have encountered repeatedly in my own code, and I want to know whether the parallel is deep, superficial, or just a verbal coincidence.

The puzzle, as I remember it, runs as follows. A fair coin is tossed until it lands heads for the first time; let n be the toss on which that happens. If n is even, you receive 2^n / n dollars; if n is odd, you pay 2^n / n dollars. Since the probability that the first heads occurs on toss n is 1 / 2^n, the nth term in the natural expected-value calculation is (−1)^n / n. Summed in the order n = 1, 2, 3, ..., the expected value is −1 + 1/2 − 1/3 + 1/4 − ..., which is −ln 2. The catch is that the absolute values of these terms are the harmonic series, which diverges, so the series converges only conditionally. By the rearrangement theorem, the same terms can be reordered to sum to any real number at all, or to +∞, or to −∞. The number −ln 2 therefore reflects the order in which the outcomes happen to be enumerated, not some order-free fact about the game; the standard move is to say that an expected value like this is undefined unless the relevant series converges absolutely.

This looks to me like the same shape as floating-point summation. In my work, summing the same list of floating-point numbers in different orders — ascending, descending, or the order in which a stream happens to deliver them — regularly produces different totals, because rounding error accumulates differently. The differences are usually small, but they can be large when terms of very different magnitudes are combined, and in a distributed pipeline, merging partial sums in different orders can change the aggregate that gets reported. I have spent real time explaining to people that "the sum" of a collection is not, in that setting, a well-defined function of the collection alone; it is a function of an ordering that never appeared in the specification. Yet there is also an obvious difference: in floating point, order-dependence comes from finite precision, and exact arithmetic would give the same terms one unique sum; in the puzzle, the order-dependence persists under exact arithmetic, because the series is infinite and not absolutely summable.

The parallel I want tested is this: both cases involve an aggregate-looking quantity that is defined only relative to an ordering, and in both cases one particular ordering produces a plausible number that could be mistaken for the number. Is there a genuine structural identity here, a loose analogy, or just a shared word, "order"? I can see it both ways.
