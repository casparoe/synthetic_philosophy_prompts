I teach an undergraduate seminar on concepts and categories with about eighteen students, mostly philosophy and cognitive science majors with a few design students, and we have a ninety-minute block. I want a hands-on activity built around the "letter spirit" problem: what makes every lowercase 'a' an 'a' despite enormous variation across typefaces, hands, and contexts. The activity should get students to discover, by producing and sorting forms themselves, three claims I will refer to throughout the schema by these codes: "no_local_feature_list" — no fixed list of local features (closed bowl, vertical stem, diagonal stroke, two-story shape, and so on) settles whether a mark is an 'a'; "style_as_holistic_constraint" — category membership is entangled with style, so the very same mark can be an 'a' in one surrounding style and a different letter in another, and style operates as a global constraint on a whole set of forms rather than as a property of any single form; and "top_down_context" — in ordinary reading, recognition is partly supplied from above by neighboring letters, words, and expectations. The terms should not be introduced until the debrief, and the activity should contain no up-front lecture.

Design the complete runnable activity, with at least these three components (you specify their details):

1. A production task in which students draw variants of 'a' under constraints that force them to choose among conflicting local features, so that different students produce different but defensible 'a's.
2. A boundary-drawing task on a small artificially generated family of glyphs — for example, a grid built by varying two continuous parameters such as bowl openness and terminal treatment — on which any line between 'a' and not-'a' is arbitrary, and on which the best boundary appears to shift when the same forms are re-embedded in a different surrounding style.
3. A context or repair task in which marks students reject or misclassify in isolation are read correctly once embedded in a word or sentence, making the top-down contribution tangible.

For each phase, give facilitator setup, instructions for participants written to be read aloud, time allocation, a note on what should happen and why it matters, and the likely failure modes with concrete handling that does not give away the insight. Any handout should be described precisely enough that I can make it from the description. Then supply a debrief that points back to specific moments in the activity and ties each to one of the three coded ideas, and state plainly what the activity cannot reproduce about real reading or letter perception and what the facilitator must supply or concede.

Format the entire deliverable as one JSON object with this schema:

- "title": string, a short name for the activity
- "learning_goal": string, one sentence on what students should come away seeing
- "logistics": object with "group_size" (string), "time_budget" (string), and "materials" (array of strings)
- "phases": array of objects, each with:
  - "phase": string
  - "duration_min": number
  - "setup": string, what the facilitator prepares or displays before the phase
  - "participant_instructions": string, to be read aloud
  - "facilitator_notes": string, covering what should happen, the design rationale, and what to watch for
  - "failure_modes": array of objects with "symptom" (string), "cause" (string), and "handling" (string)
- "debrief": array of objects, each with:
  - "activity_moment": string, the concrete moment to point back to
  - "idea": one of "no_local_feature_list", "style_as_holistic_constraint", or "top_down_context"
  - "guiding_question": string
- "cannot_reproduce": array of objects, each with "feature" (string) and "what_to_say" (string)
- "closing": string, a short paragraph for the facilitator to read that names the problem only at the end
