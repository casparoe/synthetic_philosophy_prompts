Two coworkers of mine got into it at lunch today over one of those urn games, and I can't figure out who's right. They were talking about two bags. Bag A has exactly 50 red and 50 black jellybeans. Bag B has 100 jellybeans, each either red or black, but nobody knows the mix. A bet pays $20 if you draw red.

(1) Tim said preferring to draw from A for red and also preferring A for black is irrational. If you prefer A for red, you're assigning less than 50% to red in B; if you prefer A for black, you're assigning less than 50% to black in B. A single probability distribution can't do both, so your choices can't be represented by any consistent set of beliefs — it's a classic violation of the sure-thing principle. Incoherent, full stop.

(2) Maya said that gets it exactly backwards. The whole point is that the evidence doesn't force a single probability on you. Bag B is compatible with a whole set of priors, anything from zero to a hundred reds — that's imprecise probabilities in a nutshell. Preferring A both ways is just refusing a bet whose worst case is worse when a safe alternative is sitting there. You can model that with maxmin expected utility: maximize the worst-case expected value over your set of priors.

(3) Tim came back: fine, but if you let maxmin run, you end up treating every unfamiliar situation as if the worst case will happen. Order a fish you've never had, and a maxmin agent has to assume it's spoiled. Worse, with a set of priors, evidence can dilate the set — different priors learn different things, so you can end up more indecisive after seeing more data than you were before. That isn't rationality, it's paranoia plus a license to never update cleanly.

(4) Maya shrugged: all that attacks one decision rule, not imprecise probabilities. The framework doesn't force maxmin. You can use interval dominance — only pick an option that beats the alternative on every prior in the set — or an optimism-weighted rule between worst and best case, or just report the interval and let context decide. Anyway, the Ellsberg pattern shows up reliably even with small stakes and clear instructions, so a good decision theory should accommodate it rather than call it a bug. If it doesn't fit the single-prior formalism, that's a problem for the formalism.
