Systems programmer here. The vocabulary I actually think in is scope, allocation, references, reachable states — and I've been trying to understand the quantified modal logic fight over the Barcan formulas without leaving that vocabulary, because every time I read the real thing I can't tell wether the two sides are disagreeing about logic or about model setup.

Take the two inferential moves people argue about. One says: if it's possible that there is something that is F, then there is something that is possibly F. The other says: if there is something that is possibly F, then it's possible that there is something that is F. (I'm deliberately avoiding the symbols and the standard names because I want the translation to do the work.) In my head the first one compiles to something like: if some reachable state allocates an object that passes the F-check, then an object that could pass the F-check must already be allocated in the current state. The second compiles to: if the current state has an allocated object that, in some reachable state, would pass the F-check, then there's a reachable state where an allocated object passes the F-check. Is that compilation right? Where does it fudge? And what settings of the underlying machinery — fixed pool of objects vs per-state allocation, reachability being one-way vs an equivalence — make each direction valid or invalid?

I don't want an analogy, I want a systematic translation. And afterwards I want the leftover report: which parts of the philosophers' quarrel survive the translation, which parts turn out to be choices of representation convention, and which parts have no counterpart at all in my state-and-allocation picture. In particular, is the claim that everything that exists exists necessarily a substantive consequence that falls out of one of these formulas, or is it just what you get when you assume one fixed object pool, translate 'exists' as 'is in the pool', and then act surprised that the pool never grows?
