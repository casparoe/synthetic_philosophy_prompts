I cover science and ideas for a general-interest magazine, and I keep turning over a parallel between philosophy of language and software engineering that I cannot tell is a real structural identity or just an attractive metaphor.

Classically, philosophers distinguished analytic sentences, whose truth or falsity is supposed to be fixed by meaning alone, from synthetic sentences, whose truth or falsity depends on how the world is. Quine's well-known critique was that no principled boundary of this kind can be drawn: where we place the line is, he argued, a matter of convenience, because our beliefs answer to experience as a whole rather than one sentence at a time.

Software has a distinction that feels similar. Some errors are compile-time errors: undeclared variables, type mismatches, calling a function with the wrong number of arguments. These are caught before the program runs, by checking the code against the language's static rules, without any particular input. Others are run-time errors: a division by zero on a particular input, or an out-of-bounds array access, which appear only when the program meets the world, so to speak. What interests me is that the compile-time/run-time boundary is not a fixed fact about programming. A richer type system can move familiar run-time failures into compile-time by encoding more of the intended behavior in the types themselves; for example, if the type tracks the length of an array, an out-of-bounds access can be ruled out before execution. So what counts as checkable without running the program is, in large part, a design decision about the language.

The parallel I see is this: analyticity is to natural language what static checking is to a programming language. On this reading, Quine's claim that the analytic/synthetic boundary is movable becomes the claim that natural languages have no privileged type system: which judgments we treat as rule-governed and immune to empirical revision is a choice we make, not a joint we discover. That seems to sharpen Quine's point in a satisfying way.

But I can also feel the analogy stretching. A programming language is an artifact with an explicit syntax and a more or less formal semantics, and a compiler can be assessed for soundness against a specification. Natural language is evolved, shifting, and only partially formalized, and it is unclear what would play the role of the specification against which "meaning alone" checks a sentence. Worse, moving an error from run-time to compile-time does not change what the program computes; it changes what we catch early. If the analogy were exact, Quine's revisability point would have to be read as a thesis about what we can catch early in enquiry rather than about what the world makes true, and I cannot tell whether that is a sharpening or a distortion.

Is this a genuine identity of structure, a loose analogy, or a confusion? If it is genuine, state the mapping precisely: which notion of analyticity corresponds to which notion of static checking, and what is the analogue of the type system on the natural-language side? What would have to be true of both sides for results to transfer? And what is something the parallel predicts about language, programming, or enquiry that turns out false?
