I am a high school student taking an introductory programming course at the same time as a philosophy elective on change and identity, and I have been unable to shake the feeling that a technical distinction from one course is the same problem as a metaphysical puzzle in the other. In the programming course we saw that in a pure, mutation-free setting an expression always evaluates to the same value, so a thing's identity and its current contents can safely be blurred together. As soon as we introduced assignment and in-place mutation, the two came apart: a variable became a persisting location that can take on different values at different times, two or more names can refer to the very same mutable object (so updating it through one name is visible through the others), and in order to know what an expression denotes you have to know which state the program is in at that point, which in turn depends on the path that led there. The statement 'x = x + 1' looks like a contradiction until we read the equals sign as a command to update a location over time rather than as a claim of numerical identity.

This immediately reminded me of the problem of change from the philosophy side: a single leaf is green in summer and red in autumn, and the difficulty is to say how one and the same thing can have incompatible properties. The standard philosophical moves—distinguishing the persisting object from the properties it has, or indexing properties to times, or treating the object as a sequence of stages—sound almost identical to the moves we make when we distinguish a variable from its present value, time-index the values of a location, or rewrite a mutable program in an immutable style by keeping a sequence of versions.
