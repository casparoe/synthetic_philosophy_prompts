The student wrote: "P is the class of problems solvable in polynomial time, which means they can be solved fast enough in practice, and NP is the class of problems where a candidate solution can be checked in polynomial time. NP-complete problems are the hardest in NP: every problem in NP polynomial-time reduces to them, and Cook and Levin showed SAT is one of them. So if P ≠ NP, which nearly everyone expects, no NP-complete problem can be solved in polynomial time, and therefore any algorithm for one must take exponential time in the worst case. That gives a real epistemic gap: for these problems a witness can be checked quickly once you have it, but finding it is infeasible, which is just the distinction between knowable in principle and feasibly knowable. The main wrinkle is the worst-case/average-case distinction. NP-completeness is a worst-case claim: it says there is some instance that trips up the algorithm, not that most instances are hard. Modern SAT solvers handle industrial instances with millions of variables, so in practice the hard instances seem rare. But that only limits how pessimistic we should be about particular cases; it doesn't undermine the point that such knowable-but-unfindable truths exist, since the worst case is enough to show the gap is there. And if P = NP turned out true, all of NP would be polynomial-time solvable and the checking/finding gap would close; since P ≠ NP is the reasonable working assumption, the gap stands."
