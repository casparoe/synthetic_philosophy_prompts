I've been writing a little proof-assistant library in my spare time and got into a dumb argument with a coworker about the natural numbers. You can encode naturals as pure sets the standard way: 0 = ∅, 1 = {∅}, 2 = {∅, {∅}}, and so on, with each number being the set of all smaller numbers. In that encoding, 4 = {0,1,2,3}, so 2 is literally an element of 4. But you can also encode them so each number is just the singleton of the previous one, and then 2 is not an element of 4. My coworker says the first encoding is the real one, so it's just a fact that 2 ∈ 4, full stop. I said we're just choosing a data structure and the membership question is relative to the encoding. But I'm not entirely comfortable with my own answer: is there a fact of the matter about wether 2 is an element of 4, independent of how you encode numbers as sets? And if there isn't, what should that change about how I write the library — for example, should I avoid exposing things like 2 ∈ 4 as theorems about the naturals, or is it fine once the encoding is fixed? Or are we just bikeshedding?
