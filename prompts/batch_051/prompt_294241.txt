so i'm in this class on software and intellectual property and we keep coming back to the gpl and the idea of a derivative work, and honestly the more i look at it the more it feels like a whole metaphysics of "what a program is" is being assumed without anybody saying so. The practice as I understand it: if I write a proprietary program and link it against a gpl'd library, then distribute the result, the whole thing has to be gpl'd—and this seems to hold whether the linking is static or dynamic, even though in the dynamic case my code and the library stay seperate files at runtime and the user could swap the library out. But if my proprietary program instead launches a gpl'd program as a separate process and talks to it over a pipe, a socket, or command-line arguments, the usual understanding is that they're two distinct works and my code can stay proprietary. That's supposed to hold even when my program is mostly a front end and the two exchange a lot of data, so long as the communication stays at "arm's length"—but people also say how intimate the communication is matters, which sounds to me like the same mystery just moved down a layer. So the same functional relationship—my code can't do its job without gpl'd code, and they pass data back and forth—gets classified differently depending on whether the boundary looks like a function call or a process boundary. Companies actually rely on this: they'll avoid dynamic linking but will happily shell out to gpl'd command-line tools. Some open-source lawyers also think the dynamic-linking-makes-a-derivative view is wrong, so the line is contested even among people who enforce it. What theory of where one program ends and another begins does this practice presuppose? Is it about copying text, about shared execution, about control, about how intimate the communication is, or something else? And is the practice coherent—does it strictly presuppose one theory, or is it compatible with several rival theories that give different answers in the edge cases? I'd also like to know what would have to change if you replaced the presupposed theory with a purely functional-dependence view (anything useless without gpl'd code counts as a derivative) or with a purely textual view (only literal code copying counts). I keep wanting to say it's just practical line-drawing, but then I can't say what the line is drawing between.
