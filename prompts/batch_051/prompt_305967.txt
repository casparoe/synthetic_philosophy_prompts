I'm taking a philosophy-of-computing class and got into an argument with a friend who does programming-language theory, and I want to figure out who's actually right. His line is the classic one: since basically every language anyone seriously uses is Turing-complete, the choice of language can't matter to what gets computed — languages are just notation, different syntaxes are interchangeable in principle, and so caring about the language itself (as opposed to libraries, tooling, community) is a category mistake. That has always felt a little off to me, but now that a huge amount of code is being written by LLMs I'm finding it even harder to hold. Models are dramatically better at Python than at some equally Turing-complete but obscure language, not because of anything about expressiveness but becuase of how much training data exists, how the tokenizer happens to cut the language up, and how much code in that language is available to imitate. The failure modes look different too: a model doesn't respect the idea that notation is irrelevant — it just reproduces patterns it has seen, so a language with weird syntax or a tiny corpus becomes a real source of errors in a way the Turing-equivalence argument has no vocabulary for. So here's what I'm asking about. Does the old argument that Turing-completeness makes language choice inessential survive the shift to machine-written code? Does the development just add practical considerations that leave the argument itself untouched, does it break one of the argument's premises, or does it actually invert the conclusion (language choice now matters even more, but for reasons the argument was built to rule out)? And if a premise breaks, is there a repaired, weaker version of the argument that still says something worth keeping? I'm less interested in which language is actually better and more in what happens to the argument itself.
