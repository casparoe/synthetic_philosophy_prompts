You are a professional philosopher working in aesthetics and the ontology of art, comfortable with arguments about abstract objects and comfortable talking to someone who thinks in terms of code. Think carefully; I want a negotiated verdict, not a victory for one side.

I am a software engineer with no formal philosophy background, and I have been trying to apply one of my default mental tools to music. The tool is the type/token distinction in its programming form: one definition, many instantiations. A type keeps reappearing nondestructively; each time it runs or is instantiated, a new token is created. Applied to music, the view that attracts me is roughly this: a musical work is an abstract, repeatable structure, and each performance and recording is a token of it. That is elegant and unifying. It explains why thousands of performances can all be the same song, why a cover that changes key or instrumentation is still a performance of the same work rather than a new one, and why two people on different continents can play "the same piece" while sharing no physical thing. It also gives a clean criterion: two performances are of the same work when they instantiate the same specification, just as two objects are instances of the same class when they satisfy the same definition.

But I have a firm intuition that pulls hard against this, and I cannot shake it. Consider a track built entirely inside a DAW: layered samples, automation, precise timing, a finished rendered file. There is no score sitting above the audio, no set of instructions that exists independently of the produced object and waits to be instantiated. It feels wrong to say this recording is merely a token of an abstract type, the way a running process is an instance of a class that already exists in source. If a different producer plays the same notes on different instruments, the result does not feel like a new token of the same work in any full sense; it feels like a different item that resembles the first. Now consider a freely improvised performance. Saying the performance executes a pre-existing abstract work seems perverse: whatever work there is seems to be created by, and perhaps vanish after, that very performance. The intuition is that for at least some music, the performance or recording is ontologically primary, not an instance of an independently existing type.

I have also run into a neighboring idea that works differ in how much they specify: a leadsheet fixes melody and harmony but leaves almost everything else open, a full symphonic score fixes much more, and a finished master fixes every audible detail. It feels as though the type/token picture should bend, not break, as the amount of specification rises — but I cannot tell whether that is a real observation or a way of avoiding the conflict.

I want to keep the unification that drew me to the type theory in the first place, but I do not want to flatten studio-constructed and improvised music into a framework that seems to get their ontology backwards. I can see several possible resolutions: debunk my intuition as a confusion between a work and its tokens, or between a work and how I experience it; amend the theory so that some types are fixed retroactively by their first or only token, while others remain repeatable in the usual way; abandon the type view for at least some music and treat certain works as particulars; or split the term, so that the kind of thing picked out by "work" differs across musical practices. I need to know what would justify each of these moves, not merely which one you prefer. Give me the strongest version of the type theory and the strongest version of the intuition. Then tell me which should yield, which should be revised, and whether there is a reading on which both survive without collapsing into equivocation. I do not need a literature review; I need the structure of the argument.
