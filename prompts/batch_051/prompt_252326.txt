I'm a software engineer who builds products on top of large language models, and I have no formal background in philosophy, so I'll state the argument the way I understand it. The stochastic-parrots argument runs roughly as follows: a model trained only on the surface form of text, by next-token prediction, with no access to anything its tokens refer to and no communicative intent, cannot acquire meaning or understand language; it only reproduces distributional patterns from its training data. The systems that argument targeted were static, text-only models that did nothing but emit text.

Now change one thing. After its initial text training, with no further weight updates, the model is given a Python interpreter: it can pause, run code, read the interpreter's output, and continue its response. The output it reads is not prose selected to predictably follow the prompt; it is causally determined by the semantics of the programming language and by the behavior of the code the model itself wrote. The model thereby gets a feedback loop with a non-linguistic process, even though all the feedback arrives as text.

Does the stochastic-parrots argument survive this development, or does one of its premises give way? I want to know precisely which premise is under pressure: the premise that the system has access to nothing but linguistic form; the premise that a causal feedback channel to a deterministic interpreter does not count as access to reference or meaning; the premise that meaning requires something like perception or communicative intent rather than any coupling to an external system; or some premise I have not isolated. If the argument needs repair, state the repaired version exactly and say whether it still cuts against tool-using models of this kind, or whether it now establishes only something weaker—for instance, that they understand code but not language, or have a sliver of grounding that falls short of understanding. Please argue for a definite position rather than surveying both sides.
