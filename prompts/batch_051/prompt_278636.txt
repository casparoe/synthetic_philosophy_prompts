I'm a software engineer, so my default theory of identity is basically content addressing. If two files hash to the same SHA-256 I treat them as the same thing, and if someone told me to care about which of two byte-identical copies was "the original" I'd say they were confused about how files work. But I got pulled into a conversation about art forgery and now I'm not so sure. The thought experiment that bothers me is a painting and a perfect physical duplicate—same pigments, same canvas, same brushwork down to the cracks and the dust, I'm stipulating a molecule-for-molecule copy. The art-world intuition seems to be that these are two different objects: one is the original and the other is a fake, and they can have wildly different value and different names, even though no physical test can tell them apart. At first I wanted to file that under "people are irrational about originals." But then I noticed I already accept something similar at work. Two git commits can point to the exact same tree and still be different commits because they have different parents, authors, timestamps, and signatures; the diff might be byte-identical but I treat the one signed by the maintainer as the release and the other as some random person's copy. Build tools and trust decisions run on the provenance, not just the content hash. So the parallel is: in both cases, when the current physical or bitwise state is identical, we reach for causal history to decide whether something is "the thing" or "a copy of the thing," and value and trust track that history. Is this the same distinction showing up twice—is art provenance doing roughly what signed commits are doing—or are these two different moves that just look alike because both use the word "authentic"? If they're the same, does anything transfer, like the idea that a chain of custody is only as strong as the earliest trusted signature, or that provenance can be cleanly separated from content in a way that doesn't really hold for paintings? Or does the art case have an extra ingredient, like actual historical contact with the artist's hands, that software simply has no analogue for? I've been going back and forth on weather this is deep or just me pattern-matching, and I'd like someone to check where the analogy holds and where it breaks.
