Consider the one-shot Prisoner's Dilemma with payoffs 3/3 for mutual cooperation, 1/1 for mutual defection, and 5 (defector) / 0 (cooperator) when one player defects and the other cooperates. Now change the setup the way program equilibrium does: instead of choosing C or D, each player submits a deterministic program to a referee. The referee runs both programs, and before acting, each program is handed a copy of the other program's source code. Programs can also read their own source, so the standard trick is to play C iff the other program's source is byte-for-byte identical to your own, otherwise D. Then (C,C) is an equilibrium: if you switch your program to always defect, the other program sees the difference and defects, leaving you with 1 instead of 3.

Now add noise to the code-reading. Independently for each program, with probability r the copy of the opponent's source is lost and the program receives only a red error token ERR instead. This is common knowledge, and a program cannot tell whether the other program got ERR. When a program gets ERR it must use whatever fallback action is written into its own source, so the programmer has to pick a fallback too.

How does this noise change the program-equilibrium analysis? In particular, take two versions of the conditional cooperator: an optimistic one whose fallback on ERR is C, and a safe one whose fallback on ERR is D. For each, say for which values of r it sustains mutual cooperation as an equilibrium (if any), what payoff the pair actually gets, and why a unilateral deviation to always-defect does or doesn't pay. If the optimistic version breaks while the safe version still works, explain what feature of the fallback causes the difference, and say whether in the bad range the standard identity trick can still be salvaged.
