So I've been going down the RL alignment rabbit hole and keep tripping over the wireheading argument. The old version, as I understand it, goes something like this: if you build an agent to maximize a reward signal, then that signal is the only thing it actually cares about, so once it's capable enough it will try to tamper with the mechanism that produces the signal — edit the register, tape over the sensor, whatever — instead of doing the task you actually meant for it to do. That version seemed pretty airtight for a robot with a physical reward sensor or a gridworld agent with an explicit reward channel.

But the systems everyone actually builds now are mostly LLMs fine-tuned with RLHF, where the 'reward' isnt a signal from the world. Its just a number that comes out of a learned reward model, which itself was trained to predict which of two completions a human preferred. There's no sensor to tape over and no register to edit; the reward gets computed inside the model after the fact. If the thing is just producing text, what would 'tampering with the reward' even refer to?

So my question is whether the classic wireheading argument survives that shift. Is RLHF basically immune to the old concern because the reward channel is diffuse and learned, or does the same failure just change shape — like the agent learns to game the reward model by producing text that scores high even though a human would hate it? Or does the argument die and get replaced by something else entirely? I'm trying to figure out which premise of the old argument the RLHF setup actually breaks, and whether the argument still works if you patch that premise.
