I'm a software engineer, and I keep running into a tension I can't settle when I read about molecular biology. On one side there's the view that DNA literally is a code. Francis Crick's 1958 paper On Protein Synthesis is where I first met this in its strong form: he proposes something he calls the Sequence Hypothesis, and as I understand him, he's saying that the specificity of a stretch of nucleic acid is just its base sequence, and that sequence is a code for the amino acid sequence of a protein. From that move you get codon tables, start and stop codons, transcription, translation, all the stuff that makes a cell look like it's running an instruction set. I can't pretend this isn't powerful: you can read off a DNA sequence and predict a polypeptide, and mutations behave in ways that really do feel like source-code edits. On the other side I have a strong intuition that this cannot be literally true. In my world a code requires an encoder, a shared convention, and an interpreter that assigns symbols to meanings. But in the cell there's no programmer and no agreed convention; there's just a bunch of molecules interacting according to chemistry and physics. A codon isn't about methionine the way an enum value is about a state; it just has chemical affinity relationships that happen to be useful to us when we describe them in informational terms. Calling it a code looks like an engineer projecting a familiar abstraction onto a system that has no semantics.

So here's the clash. The code view has systematic virtues: it gives a clean abstraction layer, it unifies a huge amount of data, and it makes predictions. My intuition says a code without an encoder is incoherent, and that what's really there is just causal specificity dressed up in engineering language. Should I give up the intuition and accept that biological systems can contain codes in a naturalized sense that doesn't require an intentional sender? Should I give up the literal code claim and say it's a useful metaphor whose real content is just stereochemistry? Or is there a coherent middle path where "genetic code" means something precise enough to be literal but different from what I mean when I use the word at my job? I want to know what each move costs, not just which side sounds better.
