A friend who works in AI safety keeps insisting there's a clean, observable difference between a control measure and an alignment technique, and that you can spot it by asking whether the measure still makes sense under the assumption that the model is genuinely trying to help. His go-to example: monitoring every output before it executes is a control, because a well-intentioned model wouldn't need guarding the same way; training the model to critique its own plans is not a control, because it only helps if the model is already pulling in your direction. I dont buy that the difference is observable. A misaligned model can present as clumsy or confused while it probes, and a helpful model can still write the dangerous script if it lacks some fact about the environment, so the two cases generate the same failure surface.

So here's what I want. Take a concrete safety measure—say an overseer that reviews code before it can run in a sandbox and blocks anything that looks like exfiltration or sandbox logging tampering. How would one test the claim that this measure presupposes the underlying model may be misaligned, rather than merely guarding against the errors of an otherwise well-intentioned model? Give me the best operationalization you can: the manipulation or comparison or ablation you'd run, the results that would push each way, and an honest statement of what the test still couldn't settle (in particular, whether the model actually is misaligned, as opposed to whether the measure treats that as a live possibility).
