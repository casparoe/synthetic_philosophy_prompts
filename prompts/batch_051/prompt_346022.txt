So me and my friend in our cs club got obsessed with this argument about the prisoner's dilemma when the players are programs that can read each other's code. I can't find the leak and the conclusion feels like it breaks all of game theory, so I'd really appreciate a second pair of eyes.

Setup: one-shot prisoner's dilemma. Payoffs, written as (you, other player): both cooperate (3,3); you defect and other cooperates (4,0); you cooperate and other defects (0,4); both defect (1,1). In the ordinary version where everyone just picks an action, mutual defection is the only Nash equilibrium.

Now the program version. Each player submits a program before the game. When the game runs, each program receives the other program's source code as input, runs, and outputs either Cooperate or Defect. Assume programs can be quine-style, so a program can refer to its own source text without that being circular.

Here's the argument we came up with:

(1) In the program version, a player can make their move conditional on the other program's source code.

(2) Let P be the program that does this: look at the other source code; if it is exactly P's own source, output Cooperate; otherwise output Defect.

(3) If both players submit P, then both cooperate, so each gets 3.

(4) Neither player can improve by unilaterally switching to some other program Q. P will see that Q's source isn't P, so P will defect, and against a defection the switcher gets at most 1. Since 1 < 3, (P,P) is a Nash equilibrium.

(5) The usual reason cooperation gets called irrational in a one-shot prisoner's dilemma is that mutual cooperation isn't a Nash equilibrium. Now it is one, and it pays better than mutual defection. So in the program version, a rational player should cooperate.

(6) But the always-defect program is still a Nash equilibrium too. If both submit always-defect, switching gets you 0 if you cooperate and 1 if you defect, never more than 1. So by the exact same "it's a Nash equilibrium, so that's what rational players do" move, rational players should also defect.

(7) If both (5) and (6) are right, the program version says rational players both cooperate and defect, which can't be right. So the argument either proves too much or one of the steps slips.

Which numbered step do you reject, and why did that step look fine before? Or if you'd rather reject a background premise, tell me which one and what giving it up costs. I definately want to keep (1)-(4), since those feel like math, but I'm open to being wrong. Final question: does the program version actually change what's rational, or does it just add more stable outcomes?
