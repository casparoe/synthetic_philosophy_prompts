I'm a backend engineer and the vocabulary I actually trust is databases: tables, rows, primary keys and foreign keys, nullable columns, constraints, views, materialized views, query isolation, all that. I've been reading around the Sherlock Holmes stuff and I want a translation job.

The claims I keep tripping over are these. (1) "Sherlock Holmes" is an empty name — it doesn't refer to any real person — but "Sherlock Holmes lives on Baker Street" is still true in some sense: true in the fiction, not true outright. (2) Some things are true in the stories only implicitly: the text never says Holmes has a liver or that he never visited the moon, but we usually count them as true in the fiction anyway, while other things (what color socks he wore on a given Tuesday) are just indeterminate. (3) Some philosophers want to say Holmes actually exists as an abstract object created by the stories, and others say that's just refusing to take "empty" seriously.

Restate each of these in database vocabulary as faithfully as you can — e.g., is an empty name a nullable foreign key, or is it more like the referenced row just not existing (which in SQL land are different things), and is truth in fiction a query over a view with extra constraints imposed? — and then give me a residue report. Which parts map cleanly, which had to be fudged, and which have no counterpart in database talk at all? In particular I want to know whether my instinct is right: Holmes is a row in a story table whose foreign key into a real-entities table never resolves, and truth in the fiction is whatever you can derive from the story row(s) plus the defaults and constraints you're willing to impose. Or does that quietly drop something the philosophers are actually arguing about?
