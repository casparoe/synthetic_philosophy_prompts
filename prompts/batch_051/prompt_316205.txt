I am a high school student, and I keep noticing a pattern in how groups make decisions, but I do not have a name for it and I do not know whether it has been studied. I would like to know whether it has an established name, and, more importantly, how to carve it off from nearby things it might be confused with.

The clearest example came up in our school's honor board. Three students sit on the board. They must decide two questions separately: whether the accused student did the act, and whether the act broke the rule. A student is punished only if both answers are yes. Suppose the three members vote like this:

- Member A: did the act, yes; broke the rule, no. So A votes against punishment.
- Member B: did the act, yes; broke the rule, yes. So B votes for punishment.
- Member C: did the act, no; broke the rule, yes. So C votes against punishment.

If the board tallies each question separately, it finds that the first question passed 2 to 1 and the second question passed 2 to 1, so it concludes that the student should be punished. But two of the three members individually concluded against punishment. The group's final position does not match any member's actual individual position.

I have seen the same shape elsewhere. A three-person committee decides whether to adopt a textbook. It votes separately on whether the book is affordable and whether it is rigorous enough; a book is adopted only if both are yes. One member votes yes and no, another votes no and yes, and the third votes yes and yes. The committee's question-by-question tally says yes to both questions, so it adopts the book, even though a majority of the members individually voted against adoption.

My questions are these. Does this pattern have an established name? If it does, what exactly is its definition, and how is it different from ordinary majority rule, from the error of assuming that what is true of the parts must be true of the whole, and from other well-known voting paradoxes? If there is no established name, I would be glad to hear a proposal. A bare name would not satisfy me; I want the conceptual boundaries, the edges, and the cases that look similar but are not the same.

Please first give a careful prose explanation. Then, after the prose, include a brief structured summary in JSON with exactly these top-level fields:

- "nearest_terms": an array of strings, each an established term or concept that might name the pattern; set to [] if none.
- "best_fit": a string naming the candidate that fits best, or "none".
- "definition": a string defining the pattern precisely.
- "distinctions": an array of objects, each with fields "concept" and "how_it_differs", explaining a nearby concept that should not be confused with this pattern.
- "boundary_cases": an array of strings describing conditions under which the pattern disappears or stops being troubling.
- "proposed_name": a string giving a name you would coin if no established term fits, or "not needed".
