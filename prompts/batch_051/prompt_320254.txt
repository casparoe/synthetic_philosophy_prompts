Here is a working definition, used in policy discussions, of what makes an AI system open source. A system counts as open source only if: the trained weights are publicly downloadable without case-by-case approval; the license permits modification and redistribution, including commercial use and the release of derivative models; the complete training and inference code is available; the training data are either publicly available or documented in enough detail that an independent team could reproduce a comparable model; and the original developer retains no mechanism for altering or disabling the model after release. Now consider a release by a frontier lab, which I will call Meridian. Its weights and inference code are downloadable by anyone under a license that permits fine-tuning and redistribution, including commercial use, but only for models run at or below a stated compute threshold; creating or deploying a derivative above that threshold requires a separate license from the lab. The training code is released, but the training data are only described in a very detailed data sheet that specifies sources, filtering, and data-mixture proportions; the underlying corpora are withheld, so the training run could be approximated but not reconstructed. Finally, Meridian can be run locally with no contact with the lab, but the lab also operates a hosted inference service, and for models served through that endpoint it retains a remote kill switch. Is Meridian open source? Work through each criterion, marking where the case is determinative and where the wording leaves the matter underdetermined. Then turn to the underlying debate about whether frontier AI should be open-sourced: say which of these criteria are actually carrying the safety and governance weight rather than merely tracking the label, and whether treating the open-source label as the central question clarifies or distorts that debate.
