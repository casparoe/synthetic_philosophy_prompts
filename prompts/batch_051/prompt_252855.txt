Consider the one-shot Prisoner's Dilemma with temptation T=5, reward for mutual cooperation R=3, punishment P=1, and sucker payoff S=0. In the program-equilibrium construction, each player submits the source code of a computer program rather than choosing an action directly; each program receives the opponent's source code as input and must output cooperate or defect. The canonical cooperative device is a program that outputs cooperate exactly when the opponent's source code is identical to its own, and defects otherwise. Two copies of this program cooperate, while a unilateral switch to an always-defect program is detected and punished with defection, so mutual cooperation is a Nash equilibrium.

Now alter one feature of the setup. The channel through which a program inspects its opponent's code is imperfect: with probability ε, independently for each player, the program receives not the opponent's source but a special error token ⊥, which is guaranteed never to be the source code of any legal program; with probability 1−ε it receives the true source. The value of ε is common knowledge, and every program must still return cooperate or defect on every possible input, including ⊥. The canonical program's identity test fails on ⊥, so it defects there; call this the strict program. Contrast it with a lenient program, which cooperates if the input is either its own source or the error token, and defects otherwise.

Work through the equilibrium analysis of this noisy construction. Compute the expected payoffs when the strict program plays itself, when the lenient program plays itself, and when a player unilaterally deviates to always-defect or to the alternative program. Using the payoffs stated above, determine the range of ε for which two copies of the lenient program form a Nash equilibrium and say which deviation becomes profitable outside that range; also state whether two copies of the strict program remain an equilibrium for all values of ε, and explain the intuition behind any asymmetry between the two programs. Then consider whether the lenient idea survives in a weakened form: if a program cooperates on the error token only with some probability p, can it sustain mutual cooperation while deterring always-defect even at error rates where full lenience fails? Finally, say briefly whether this version shows that program-equilibrium cooperation is fragile, or only that the canonical program is not the best device once inspection is imperfect.
