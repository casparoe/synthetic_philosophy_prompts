I was a physical chemist for thirty-some years, so formal game theory is still new to me, but a postdoc I keep in touch with has me reading about it. He sketched an argument about the one-shot Prisoner's Dilemma that he calls program equilibrium, and I keep feeling theres a trick in it but I can't pin down where. I'd be grateful for a step-by-step diagnosis.

(1) In the ordinary one-shot Prisoner's Dilemma, defection strictly dominates cooperation: whatever the other player does, you do better by defecting, so rational players defect. (2) Now change just one thing: each player submits a computer program that will play for them, and each program is given the other program's source code before either acts. (3) Under those rules, a player can submit program P: cooperate exactly when the other program's source code is identical to P's own source code, and otherwise defect. (4) If both submit P, both cooperate; and neither can profit by switching unilaterally, because any other program would be defected against by P and would earn at most the punishment payoff (with the usual ordering temptation > reward > punishment > sucker), which is worse than mutual cooperation. So (P,P) is a Nash equilibrium. (5) Therefore the familiar claim that rational players must defect in the one-shot Prisoner's Dilemma is just an artifact of modeling players as choosing bare moves; once players choose programs, cooperation is fully rational.

Which step, if any, is wrong? My own hunch is that the problem is in step 4, something about another program being able to do the same thing under a different description, but I can't make the objection precise. Please go through the steps in order, say whether the conclusion goes through, and if not, identify the exact step where it breaks. Also, say how confident you are in your verdict and single out the point you're least sure of.
