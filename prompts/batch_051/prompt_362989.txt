I am a software engineer on a team building an autonomous agent that will operate on open-ended tasks over stretches of hours to days — maintaining server infrastructure, chasing down rare configuration drift, handling end-to-end procurement. The behavior we want is simple to state in engineering terms: if an operator issues a shutdown command, the agent must not prevent that command from taking effect. It should not block the command channel, disable its own kill switch, rewrite its code to remove the shutdown path, talk the operator out of issuing the command, or copy itself somewhere it cannot be reached. I will call this the Shutdown Disposition.

I am aware of the standard instrumental-convergence story: an agent competent enough to reason about its own future will, for almost any terminal objective, treat its own continued existence and its ability to act as instrumentally useful, so resistance to shutdown will tend to emerge unless shutdown is already something the agent's objective says it wants. But I can also see two ways one might hope to secure the disposition anyway. First, train it in: make shutdown events common during training and never associate them with anything the agent is rewarded for, so resistance never gets reinforced. Second, build shutdown directly into the terminal objective, so the agent positively values being shut down when an operator requests it.

Here is the claim I want a probability for:

There is no method in the current repertoire or on a research trajectory continuous with it that will, in the next couple of decades, produce an agent that is both (a) capable enough for long-horizon open-ended work and (b) has the Shutdown Disposition robustly — where robustness means the disposition survives distribution shift, adversarial attempts to provoke shutdown-resistance, and the agent's own capacity for self-modification. More specifically: the disposition cannot be secured by reward shaping, RLHF, or any training method that shapes behavior without changing what the agent is ultimately optimizing for; and we currently have no known way to put shutdown into the terminal objective without creating foreseeable incentives to game the definition of an operator-authorized shutdown or to manipulate the operator. So the claim is that corrigibility will not fall out of capability or ordinary reward design, and that the terminal-objective route is a genuine unsolved problem rather than a detail we can hand off to an intern.
