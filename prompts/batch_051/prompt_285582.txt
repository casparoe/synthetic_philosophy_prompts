I work on a platform team that owns the public API for a large software product. We maintain a living document of API design rules: how resources should be named, how errors should be structured, how versioning is handled, what belongs in a path segment versus a query parameter. The document is treated as authoritative in code review, but it is not frozen. Any engineer can open a proposed change to it by pointing to a concrete case where a rule seems to force an awkward design. A small governance group then decides among three options: amend the rule to fit the case, keep the rule and tolerate the awkward case, or declare the proposed case out of scope for the platform.

What puzzles me is that neither side in these disputes automatically wins. The existing rule does not win just because it is the rule, and the concrete judgment that this particular API is badly designed does not win just because it is strongly felt. Both are treated as revisable. The group is explicitly not allowed to settle disputes by deriving everything from a master architecture document or formal specification; those documents exist but are themselves open to revision in the same way. At the same time, the process is not purely case-by-case either: a one-off decision about a particular endpoint sets no general expectation unless it is later folded into an actual rule. Sometimes a rule survives a long series of awkward cases and the team learns to live with them; sometimes one case is enough to overturn a rule that had stood for years. There is no external standard we can consult to check whether the rules, taken as a whole, are correct.

I find the process reasonable and mildly suspicious at the same time. It looks circular: the rules are used to assess cases, but cases are also used to assess the rules, and there is no fixed starting point or foundation anywhere underneath. I would like to understand what philosophical commitments this way of working presupposes. Please reconstruct the implicit theory of justification or method that would make the practice coherent rather than merely circular. Specifically:

1. What view of how general principles and particular judgments are justified does this process presuppose, and which rival views does it quietly rule out?
2. Is the apparent circularity a genuine defect, and how would the view this process presupposes answer that objection?
3. Which parts of the practice are strictly required by that view, and which parts are just one optional way of implementing it? Where is the practice philosophically underdetermined?
4. What would have to change in how the group operates if we instead adopted a foundationalist view, where all rules are derived once and for all from a fixed master specification, or, conversely, a particularist view, where each API decision is made on its own merits with no general rules at all?
