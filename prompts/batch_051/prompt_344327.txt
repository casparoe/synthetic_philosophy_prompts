Two people in my building got into it last night about whether a finite string of bits can be random, and I honestly couldn't tell who had the better of it. Sam's in stats and Priya's in CS. I'll do my best to reproduce the argument.

Sam: "Randomness is a property of the generating process, not the string. Flip a fair coin ten times and the result is random because the process is random. The string 0110100110 isn't random or non-random in itself; it's just the record of a random event. Asking whether a string is random is like asking whether a number is lucky."

Priya: "But if I show you 1111111111 and 0110100110 and ask which one came from the fair coin, you'd pick the second every time. Your intuition has to be tracking something in the strings. So 'random-looking' at least is a property of strings."

Sam: "All ten-bit strings are exactly as likely under a fair coin — 1111111111 has probability 1/1024, same as 0110100110. The preference is just pattern-matching. And any string can be made to look special after you've seen it: 0110100110 is somebody's birthday in binary, or it spells something in ASCII, whatever. Stories are cheap, so they can't underwrite randomness."

Priya: "Right, stories are cheap. That's why you don't use stories, you use compression. A string is random if its shortest description is about as long as the string itself. 1111111111 compresses to 'ten ones,' but a typical ten-bit string can't be compressed. That's a fact about the string alone, no process involved."

Sam: "Shortest description in what language? I can rig a language where the one-symbol expression 'x' denotes 1111111111, and then it's one character long. Compressibility is relative to the language, so its not a fact about the string."

Priya: "You fix a universal language — a general-purpose programming language, say — and take the shortest program that prints the string. Different universal languages only change the length by an additive constant. That's the Kolmogorov complexity idea."

Sam: "But for a finite string the constant can be bigger than the whole string. For ten bits the constant difference between two languages can be hundreds of bits. So the theory only gets a grip in the limit of long strings; a particular short string never counts as random. Randomness ends up a property of infinite sequences, and we never see those."

Priya: "There's a graded notion that works for finite strings, though. Think of the tests you'd run before believing a string came from a fair coin: frequency of ones, longest run, alternations. 1111111111 fails the frequency test badly; typical strings pass everything simple you throw at them. Some finite strings are more typical of a fair coin than others, and you can measure by how much."

Sam: "A test is just a rule someone chose. For any specific string I can define a test it fails: reject if the string is exactly this one. So every finite string fails some test. If you restrict to simple tests, we're back to compressibility and the language-relative problem. And 'typical of a fair coin' is a claim about a process, which is my whole point."

Priya: "The point is to restrict to effective tests — ones you can actually compute — and then there's a universal test that catches whatever any computable test catches. That gives a real number for each string, a deficiency score, not a crude yes/no."

Sam: "But what does the score mean if there's no process in view? It's literally how hard a Bayesian with a uniform prior would be surprised. If you're not trying to infer the source or predict future bits, why care about typicality? A string like 1111111111 is only 'non-random' because it fits the hypothesis 'not a fair coin,' and that's a process claim."

Priya: "I'm not claiming anything about what caused the string. I'm claiming the pattern in the string itself grounds the distinction. Complexity relative to a fixed universal machine is well-defined even for short strings — noisy, but defined."

Sam: "Noisy, machine-relative, and finite. That can't do the work of making the string random, full stop."
