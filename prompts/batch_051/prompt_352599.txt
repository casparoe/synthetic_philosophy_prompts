The standard case for pausing or sharply throttling frontier AI through compute thresholds goes roughly as follows. Dangerous capabilities are, to a first approximation, set by training compute; very large training runs are few, physically centralized, and detectable through chip purchases, electricity use, and known datacenter footprints; therefore a regulator that cannot yet define dangerous capabilities can still get leverage by imposing a ceiling on training compute, above which any run triggers scrutiny, licensing, or a halt, all of which can happen before deployment. Now suppose the field changes in the following way. The next large jump in capabilities comes not from larger pretraining runs but from inference-time compute: a moderately sized base model is run at deployment for extended search, self-correction, or tool use, and the behavior of a long, expensive inference run is distilled back into a small, fast model whose measured training compute is unremarkable. In that world, does the compute-threshold case for a pause still go through, does it need repair, or is it dead? Please identify which premise the changed world actually attacks, state what the original argument needed to be true in order to generate a pause before dangerous deployment, and consider whether a repaired version aimed at inference compute, total deployed chips, or some measure of effective compute inherits the original chokepoint advantages or quietly becomes a different and weaker argument. I am asking about the anatomy of the argument, not for a policy recommendation.
