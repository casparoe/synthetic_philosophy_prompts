Here's a parallel I keep going back and forth on, and I want a blunt verdict on whether it's deep or just superficial. The math side is the old identity problem for numbers. You can build the natural numbers out of sets in different ways. In the von Neumann way, 0 = ∅ and each number after that is the set of all the earlier ones, so 4 = {0,1,2,3}, which makes 2 ∈ 4 literally true. In the Zermelo way, each number is the singleton of the previous one, so 4 = {3}, and then 2 isn't an element of 4. Structuralists take this to show there's no fact of the matter about whether 2 is an element of 4: membership facts are just artifacts of your chosen encoding, and what's real is the structure, the pattern all the encodings share.

The programming side of the parallel: this looks exactly like the differece between an abstract data type and its implementation. A stack is defined by its operations, push and pop and so on, and it's a category mistake to ask where in the underlying array the third element sits, because that's representation-specific and two implementations of the same stack will answer differently. Same way, asking whether 2 ∈ 4 is like asking a question about bit patterns or cons cells behind an abstract value. So maybe the identification problem is just the observation that set theory is an implementation language for arithmetic, and "is 2 ∈ 4?" is as confused as "is the second element stored before the third in the stack's array?"

But here's where I hesitate. In programming, the whole point of an ADT is that the representation is sealed; you have an abstraction boundary and then you never speak in terms of the internals again. Set theory doesn't seem to have an outside like that. ∈ is the one primitive relation the language gives you. There is no level at which the natural numbers exist apart from some representation or another. So maybe the structuralist is doing something subtly different from drawing an abstraction boundary, and the analogy is doing more work than it earns. Which is it? Is there a way to make the parallel precise, and if I try, what's the first place it breaks? And can you tell me something the parallel would predict that turns out false?
