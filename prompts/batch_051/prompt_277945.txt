My friends Priya and Tom run a small nomic club—the whole game is that the members pass rule changes by following the rules currently in force—and last week they got stuck on a single proposal. The rulebook contains Rule C: "Any rule in this book, including this rule, may be amended by a two-thirds vote of the members." Priya proposed changing "two-thirds" in Rule C to "seven-eighths," so that Rule C itself would need a seven-eighths vote for future amendments, while every other rule would still need two-thirds. The vote was 70% in favor.

Priya says it passes: old Rule C set the procedure for the vote she held, and 70% clears two-thirds. The new rule only governs future amendments of Rule C, so applying it to the vote that enacted it is retroactive and misses the point. Tom says that is exactly the self-ratifying move he objects to: she is using the old threshold to install a higher threshold, and if the new seven-eighths threshold governed this very change it would fail. A rule that can bootstrap itself into a stronger version of itself becomes whatever the current two-thirds block wants it to be; a 70% coalition can ratchet the requirement up to 95% and lock itself in, and the original two-thirds rule can't sensibly authorize that, because it would let two-thirds do what the amended rule says should take seven-eighths.

Priya answers that every amendment changes what future actors may do; if a two-thirds body may lower another rule's threshold, it may lower its own too, so the "ratchet" runs both directions, and the written rule says "including this rule." Tom replies that this just shows self-application makes Rule C sovereign over its own scope. A procedural rule cannot be the judge of whether it applies to itself; if we decide *that* by reference to Rule C, we have assumed Priya's conclusion. There has to be some unwritten meta-rule, and the natural one is that the original unanimous adoption of the rulebook, not a later 70%, is what authorizes a change to the book's amendment clause.
