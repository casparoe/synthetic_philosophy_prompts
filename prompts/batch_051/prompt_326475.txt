I keep going back and forth on whether it even makes sense to call one particular finite string random, so I want your take on how to cash that out. Say I'm looking at one specific 200-bit string, the actual output of 200 coin flips I did. Please rank the five views below from best to worst as accounts of what "this particular finite string is random" should mean. Also give each one a score out of 10, where 10 means you'd be happy making it your main criterion, and give a sentence or two of reasoning for each. Oh, and please write your answer in American English.

1. Statistical view: the string is random iff it passes the usual statistical tests — balanced frequencies, runs, no glaring autocorrelation.
2. Incompressibility view: the string is random iff its Kolmogorov complexity is close to its length; that is, no program much shorter than the string can print it.
3. Unpredictability view: the string is random iff no computable betting strategy, seeing only the earlier bits, can make unbounded profit by betting on the next bit as the string is revealed.
4. Typicality view: the string is random iff it isn't special under a simple prior — for example, no short program's output distribution assigns it much higher probability than it assigns to most other strings of the same length.
5. Causal view: the string is random iff it was produced by a genuinely chancy process, like a fair coin or radioactive decay, no matter what pattern it happens to display.

Then, separately: if you had to introduce this topic to someone who thinks a finite string can never be random because any particular string could have been produced by some deterministic process, which one of these would you teach first, and why?
