Right, here's one I've been chewing on. In Lewis Carroll's "What the Tortoise Said to Achilles", the Tortoise accepts the premises and even accepts that Z follows, but keeps turning each new conditional into yet another premise to be granted before he'll budge. The bit that made it click for me is this:

> "If A and B and C are true, Z must be true," the Tortoise thoughtfully repeated. "That's another Hypothetical, isn't it? And, if I failed to see its truth, I might accept A and B and C, and still not accept Z, mightn't I?"
> "You might," the candid hero admitted; "though such obtuseness would certainly be phenomenal. Still, the event is possible. So I must ask you to grant one more Hypothetical."
> "Very good.  I'm quite willing to grant it, as soon as you've written it down.  We will call it
>      (D)  If A and B and C are true, then Z must be true.
> Have you entered that in your note-book?"
> "I have!" Achilles joyfully exclaimed, as he ran the pencil into its sheath. "And at last we've got to the end of this ideal race-course! Now that you accept A and B and C and D, of course you accept Z."
> "Do I?" said the Tortoise innocently. "Let's make that quite clear. I accept A and B and C and D. Suppose I still refused to accept Z?"

The standard read is that this regress is vicious: Achilles never gets to force Z, because the rule that would let him draw the conclusion keeps getting absorbed into the premise set as a further premise. But philosophers don't treat every infinite chain as fatal — some are dismissed as harmless, or as merely potential, or as not doing any real explanatory work. So a decent chunk of the regress debate is about what makes one infinite chain vicious and another benign.

Here's the parallel I keep seeing, and I can't tell if it's deep or if I'm just pattern-matching on the word "infinite". In programming there's a distinction between an infinite loop that never produces anything — it just spins, and the rest of the program never gets a result — and a productive infinite process like a lazy stream that keeps emitting values forever (an infinite list of primes, say, or a server's main loop). The first is a bug; the second is an intended design. Programming-language theory formalises this as the difference between inductive definitions, where every value has to be built up in finitely many steps and a recursion with no base case fails to terminate, and coinductive definitions, where a process can run forever so long as every finite observation of the output is well defined. Loose translation: one thing must finish, the other must keep going.

So my proposed mapping would be: vicious regress = nonproductive loop, and benign regress = productive/coinductive process. The Tortoise's regress comes out vicious because no step is ever discharged — the premise set grows, but Z is never emited, so to speak.
