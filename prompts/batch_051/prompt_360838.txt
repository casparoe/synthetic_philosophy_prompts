After last week's seminar on algorithmic randomness, two people in my reading group ended up arguing at the bar about whether a finite sequence can be random, and I mostly just sat there trying to keep track. Maya said we had it backwards from the start: you can't look at a finite string and call it random. If she writes 011001010 on a napkin, the string itself is just a string; it's random only if a genuinely chancy process produced it, and any finite sequence whatsoever could of been produced by some deterministic process, so no finite sequence is random "in itself." Randomness, she said, is a property of the generating process, not of the output. Sam pushed back: if he shows her 1111111111111111 and 0010110100111010, she'd call one random-looking and the other not before knowing how either was made. What she's responding to, he said, is that the first has a very short description and the second basically has to be listed bit by bit, so incompressibility gives a string-intrinsic sense in which one sequence is more random than another. Maya answered that incompressibility is relative to a description language: for any finite string you like, she can rig up a machine that prints exactly that string on a very short program, so the string isn't incompressible as such; it's only incompressible relative to a machine, which makes it a fact about the pair, not the string. Sam said that only goes so far, because once you fix a universal machine, switching to any other universal machine changes the shortest description by at most a constant, and for long strings that constant doesn't matter; whether a 10,000-bit string has a 200-bit description or needs all 10,000 bits is a fairly objective fact about the string, and that's exactly how a finite sequence can be random. Maya came back: even an incompressible 10,000-bit string can be printed by a dumb deterministic program that just writes each bit down, so every finite string is the output of some trivial deterministic process; incompressibility is just a fact about how many bits we need to pin a string down, i.e. about us and our notation, not about the world being chancy. Sam's last move was that the process view can't handle pseudorandomness: a deterministic generator can pass every feasible statistical test, and we're perfectly happy to call its output random for cryptography; if only the generating process mattered, no deterministic algorithm could ever produce randomness in any sense, which can't be right. And anyway, he said, finite strings are all we ever actually observe, so a theory that makes all finite strings non-random would make randomness unobservable.

I honestly couldn't call it. Can you adjudicate the exchange move by move—say who is right about which specific point, where each one overreaches, and what they're both missing about the finite versus infinite case?
