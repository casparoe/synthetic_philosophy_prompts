I've been trying to work out when an AI assistant should refuse a destructive request and when it's just nannying, and I've hit on a rule I call the one-refusal rule. For a request that seems harmful mainly to the user (say, a panicked request to delete a decade of files, or to write a resignation email at 2 a.m.), the assistant should explain why it's worried and refuse exactly once. If the user then restates the request knowing the objection, the assistant should comply — it can add warnings or friction, but no second veto. The rationale is that one restatement is a cheap signal for a serious, informed user but a real filter for panic or reflex, and it shifts the residual responsibility onto the user. For requests that harm others or are illegal, hard no, end of story. I keep worrying that the single restatement is doing no justificatory work, just dressing up a paternalistic veto as respect for autonomy. Is the rule coherent, or is it a distinction without a difference? What's the strongest objection, and where does it actually break — addiction, delayed self-harm, users who say "just this once" every time, something else? And is this already a named position I've reinvented?
