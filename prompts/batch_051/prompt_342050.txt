In my philosophy of language course we have been working through Kripke's distinction between rigid and non-rigid designators, and I think I have found a parallel that might be either illuminating or misleading. A rigid designator picks out the same object in every possible world (or at least in every world in which that object exists), whereas a definite description picks out whatever happens to satisfy it in a given world; this is why Hesperus = Phosphorus, if true, is necessary even though it was discovered empirically, while a purely descriptive identity such as the morning star's being the evening star is true but not necessary. In the relational databases I work with, a stable primary key or object identifier seems to play the role of a rigid designator: it keeps referring to the same record while the record's other attributes are updated, while a descriptive query such as 'the customer in apartment 4B' behaves like a definite description, resolving to different records as the data change. Discovering that two identifiers generated by separate systems refer to the same customer is likewise an empirical, administrative discovery, but once the identity holds it appears to hold across all subsequent database states, rather than being a contingent coincidence of the current attributes.

I would like to know whether this parallel is deep or only superficial. Please make the mapping precise, and test where it holds and where it comes apart. In particular, what would have to be true of possible worlds for them to behave like database states? Possible worlds are usually taken to be complete, while database states are partial and mutable, and natural-language descriptions may fix their reference differently from SQL predicates. If enough of the structure is shared for results to transfer, does anything from Kripke's critique of descriptivism carry over to the claim that a database record is nothing over and above the current values of its attributes? If the analogy breaks, name something specific it would predict that is actually false, and say what is missing on one side.
