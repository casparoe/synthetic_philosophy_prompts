I'm a PhD student in philosophy of technology, and this came up while I was prepping a seminar on existentialism and computing, so I'd love someone to stress-test an analogy I keep going back and forth on. I've been rereading Sartre, specifically the slogan that existence precedes essence: there is no fixed human nature laid down before you choose; you show up first, and what you are is just the sedimentation of what you do. That structure looks to me almost exactly like the difference between class-based and duck-typed programming. In a class-based language, the class exists before any object and fixes in advance what an instance can be and do; essence precedes existence. In a duck-typed language there is no such prior essence, and an object's type is whatever its current collection of methods and attributes does at runtime — you read the type off the object's behavior, not the other way around.

Even the standard charge of incoherence against Sartre seems to have a programming echo: the objection is that saying human beings have no fixed nature is itself a claim about human nature, a nature whose content is to lack one; and, in a similar way, a dynamically typed language doesn't literally escape types, because dynamically typed works as a type category and the interpreter still enforces a semantics underneath. So the question isn't just wether the analogy is cute, but whether it is deep or superficial. Does the fact that duck typing still depends on a hidden runtime do any philosophical work — for instance, does it help state why Sartrean facticity and radical freedom are compatible, or does the analogy break exactly there, since a runtime has no projects, bad faith, or responsibility? Please state the mapping precisely, say what would have to be true of both sides for any result to transfer, and name at least one thing the parallel would predict that turns out false.
