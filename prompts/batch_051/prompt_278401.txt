I have been struck by a structural resemblance between a working rule in software maintenance and a strand of thinking about the meaning of texts. In the first, when code and comments conflict, the code is authoritative: comments can misdescribe the system, but the running system does only what the code says. In the second, an anti-intentionalist view holds that when a work's language and its author's later account of its meaning diverge, the work itself is authoritative, and the author's statements are at best evidence. Is this a genuine identity of structure, or only a loose analogy? If it is genuine, what would have to be true of both software and literary works for results to transfer in either direction? And what is one prediction the parallel would license that turns out false on one side but not the other?
