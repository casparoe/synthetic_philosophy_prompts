Imagine an anonymous one-shot freelance marketplace for small coding tasks that replaces reputation with the following scheme. Each side uploads a short program to an escrow server. When a client and a freelancer are matched, each program gets to read the other program's source before it acts; the server then runs both programs together, each under a hard cap of, say, ten million operations. Each program must halt and output exactly one of two moves: 'commit' or 'back out.' If both commit, the work and payment go through; if either backs out, the match dissolves and no money, work, or reputation changes hands. Two complications: a program that exceeds the step cap is treated as if it output 'back out' (but only after the other program's move is already locked), and both programs are posted publicly after the match. Walk through this as a mechanism rather than a business proposal: what do users actually submit, which kinds of programs come to dominate over repeated rounds, how do the step cap and the publication rule get gamed (think self-referential code that tries to simulate or spoof it's opponent, code that behaves differently while being read than while being executed, and timeout exploits), and does this eliminate the need for reputation or just rebuild it in a less legible form? Where does the first exploit appear, and could the failure modes be patched by tweaking the publication rule or the step cap without reintroducing a central authority?
