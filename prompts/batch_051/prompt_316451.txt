Here is a parallel I keep turning over, and I cannot decide whether it is structural or merely verbal.

In philosophy of biology, the word "function" splits into two rival readings. On the etiological, selected-effects reading, a trait's function is the effect for which the trait was selected: the heart's function is to pump blood because ancestral hearts persisted and spread precisely insofar as they pumped blood; the function is fixed by history. On the causal-role reading, a trait's function is what it does now that contributes to some capacity of the containing system we have chosen to explain: the heart's function is to pump blood because, in the present organism, pumping contributes to circulation, and circulation contributes to survival; the function is fixed by the current arrangement of parts. The familiar trade-off is that the etiological reading supports normativity (a heart that cannot pump is malfunctioning, not functionless) but struggles with novelties and co-opted traits not yet selected for their new role, while the causal-role reading handles novelties but over-generates: relative to an ill-chosen background capacity, a tumor's growth counts as its "function," and nothing can ever be said to be broken.

Now take a legacy software system. Good engineers separate two questions about a module: what was this code originally for, and what does it actually contribute to the running system today? The first answer lives in stale comments, commit messages, and old design documents; it is the effect that explains why the code survived in the first place. The second answer lives in current data flow and behavior: how the module figures in what the system does now, regardless of what it was written to do. The same module can answer the two questions differently. A component written to generate end-of-quarter reports may now serve only as the de facto input sanitizer for a newer service; maintainers rely on that behavior even though nobody set out to build it.

The mapping seems clean: original rationale is to etiological function as current contribution is to causal-role function. But the mapping also seems suspicious, because in software the historical side involves actual designers with intentions, whereas in biology the selective history involves no intentions at all. On the other hand, the persistence of code across refactors, outages, and copying may supply a selection-like history without any single designer intending it, which pulls the two sides back together.

Tell me whether this is a deep isomorphism, a loose analogy, or a confusion. State the exact mapping. Say what would have to be true on each side for the results of the biological debate — about normativity, over-generation, exaptation, and novel functions — to transfer to software design and maintenance. And name at least one thing the parallel predicts that comes out false, the place where the analogy should have worked but does not.
