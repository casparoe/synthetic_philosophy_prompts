I've ended up defending a position at work that I'm not sure I can be budged from, which is exactly why I need to know what would budge me. I work on AI evaluation, and I've come to think that calling a model "dishonest" or "deceptive" should not be a claim about whether its output is false. It should be a claim about the relation between what the model's own evidence supports and what the output conveys. On this view, a model that states a true claim as certain, when its training or context gives it no real warrant for that claim, is being dishonest even though the sentence is true; and a model that outputs something false while flagging it as a low-confidence guess made from limited evidence is not being dishonest, just wrong. What makes deception deceptive, I keep saying, is the gap between the representaton the model has and the confidence it performs, not the gap between the sentence and the world.

My colleagues hate this. They say it lets models off the hook for saying false things that happen to be useful, and that it smuggles in a demand for something like introspective warrant that current systems don't have. I still think I'm right, but I don't want to be one of those people whose view is unfalsifiable. So I'd like to know: what would count against this position? I want the cases and arguments that should actually move me, ranked from fatal to merely awkward. Are there cases where a model has every right to be confident but we still want to call it deceptive because of what it does with a truthful sentence—say, exploiting a user's known background beliefs to mislead by true assertion? Or cases where the model's evidence genuinely warrants a claim but the claim is harmful in a way that should count as dishonest anyway? And I want to know which of these a defender of my view should concede as counting against it, rather than dismiss as a different problem. The single thing I'd personally find most persuasive would be a case where a system asserts a true proposition with genuinely warranted high confidence and yet we'd all still call it deceptive—if such a case exists, tell me. And if the view can be adjusted to handle each counterexample, at what point does that become a bug rather than a feature?
