I've been going back and forth on which safety measures I'm actually comfortable with when deploying a model that I'm assuming might be misaligned, and I'd like help figuring out the principle behind my own judgments, if there is one.

Here are my gut verdicts:

1. A read-only internet connection (the model can browse pages, not post): I'm mostly fine with it as long as everything is logged.
2. The same, but the model can also draft emails for a human to send: I'm still fine, provided the human reads each one first. Maybe I shouldn't be? But I am.
3. The model can write and run code inside a sandbox it can't escape: I'm uneasy, and the moment the sandbox has any bug I'd want to shut it off.
4. The model can edit its own weights: absolutely not.
5. The model can inspect its own weights read-only: also no, though I can't articulate why reading its own weights is worse than reading hte internet.
6. A monitor model watches the main model's outputs and flags anything suspicious: I don't trust this if the monitor is a learned model of comparable ability, but I basically do trust a dumb pattern-matcher looking for known-bad strings.
7. A tripwire where the model is asked during training whether it's misaligned: almost worthless, but I'd still include it as a cheap check.
8. The model is air-gapped, and a human manually retypes its outputs into another machine to act on them: I feel fine for short outputs I can read, but as the outputs get longer or more technical I get uneasy. I can't tell whether that's a real distinction or just my attention span.
9. The model can ask a human operator to grant it additional permissions: no. Something about the model initiating the relaxation of its own constraints bothers me.

I can see two candidate principles. One says controls are fine as long as they don't rely on the model's cooperation — so tripwires are pointless and weight-editing is out, but the air-gap is fine. Another says every channel from the model to the world is a risk that should be treated as exploitable eventually, so even the air-gap with manual retyping isn't fine once the model is smart enough to persuade the retyper. I'm not sure either one gets all the verdicts.

What principle, or small set of principles, captures these verdicts, and which of my verdicts does it force me to give up? In particular I'd like its verdict on a case I keep flip-flopping on: the model can't send anything outside, but it can write a report arguing that its own safety measures should be relaxed, and a human will read the report and decide. And what does the principle say about the difference, if any, between a dumb monitor and a learned one?
