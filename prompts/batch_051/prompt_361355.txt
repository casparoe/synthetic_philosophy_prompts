Here are the criteria I was taught for deciding whether program B is a derivative work of program A, for purposes of a strong copyleft license:

1. Copied expression: B contains code taken from A, or a close translation or adaptation of A's code into another language or form.
2. Combination: A and B are compiled, linked, or loaded into the same executable or shared address space, so that the thing the user actually runs is best described as a single program.
3. Functional dependence: B is useless, or nearly so, in the absence of A; it exists to drive, extend, or display A's functionality rather than to stand as an independent tool.
4. Interface depth: A and B exchange structured, A-specific data or commands through an interface that exists mainly for A's internals, rather than through a general-purpose mechanism such as an ordinary command line, a neutral file format, a pipe, or a network socket.

Now consider this case. SimCore is an open-source physics simulation package released under a strong copyleft license. A startup sells ViewSim, a closed-source 3D visualizer for SimCore. ViewSim ships without any SimCore code: no source files, no header files, no build scripts. When ViewSim launches, it locates an installed copy of SimCore and starts it as a separate subprocess. The two processes communicate only by text: ViewSim writes a scene file in SimCore's scene format, then sends instructions over the subprocess's standard input and reads its standard output to draw the simulation state. The protocol ViewSim uses is not the documented end-user command language. It is a fine-grained control interface that SimCore's own test harness uses internally; it lets a client advance the simulation by one integration step, set internal flags, and read raw field values at individual mesh points. ViewSim learned this protocol by running SimCore's test suite and reimplemented the client side from scratch. The two programs never share memory or an address space, and no SimCore code appears in ViewSim. ViewSim cannot simulate anything by itself: if SimCore is not installed, it refuses to start.

Is ViewSim a derivative work of SimCore under the four criteria above? Work through the criteria one at a time, stating where each is met, unmet, or underdetermined. Then address the underlying question directly: should the boundary between one program and another be drawn at copied expression and the process boundary, or can functional dependence and the intimacy of the interface make two cooperating processes a single combined work? If the criteria point in different directions, say which criterion is doing the real work and whether the criterion set itself should be revised.
