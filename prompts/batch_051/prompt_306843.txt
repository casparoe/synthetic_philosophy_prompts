I'm a self-taught software developer. I never studied physics beyond school, but over the past year I have been trying to teach myself special relativity, and I keep coming back to the Rietdijk–Putnam argument. As I understand it, the argument runs like this: because simultaneity is relative, two observers in relative motion can disagree about which spatially separated events happen at the same time. One observer's 'now' can therefore include an event that lies in the other observer's future. If being real just means being present for some observer, then future events must already be real; so the universe is a block in which past, present and future all exist together, and the moving 'now' is only a perspective rather than a fact about the world.

The thing is, this immediately reminded me of how a git repository behaves. The repository's object database stores every commit, including commits on branches I am not currently on and commits that are descendants of my current branch from the point of view of another ref. The working tree has something like a present — the state at HEAD — but the repository itself does not privilege HEAD; every commit is equally real, and checking out an old commit does not make the later ones disappear. Two refs, or two clones, can also disagree about which commit counts as the latest state, somewhat as two observers can disagree about which events count as happening 'now'.

Is this a genuine structural parallel, or only a loose metaphor? I suspect the obvious break is that in git the commits 'ahead' of my current branch have already been made, whereas the whole point of the Rietdijk–Putnam argument is to show that the as-yet-unobserved future is somehow already there. I would like you to lay out where the mapping holds and where it comes apart, say what would have to be true on both sides for the analogy to be exact rather than suggestive, and identify something the parallel seems to predict that is clearly false. Please write your answer in British English.
