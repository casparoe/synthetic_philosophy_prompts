I teach a graduate seminar in the philosophy of intellectual property, and I am assembling an exam exercise on the ontology of software. Set aside case law and citations for this exercise; I want conceptual analysis, not legal history.

Consider a strong copyleft licence. Its obligations travel with the covered program and with derivative works based on that program, but not with an independent program that merely interoperates with it. The hard conceptual problem is deciding where one program ends and another begins. Below are five candidate principles for drawing that boundary. Score each principle from 0 (completely fails) to 10 (fully succeeds) according to how well it tracks the most defensible underlying rationale for copyleft. Then give exactly one sentence justifying each score.

Before you score anything, state in one sentence the underlying rationale you are using as your standard. Think carefully about that rationale before you begin, and make the scores consistent with it. Keep the entire response under 300 words.

1. Textual derivation: two programs are one work only if one program's source code was produced by copying or modifying the other program's source code.
2. Runtime integration: two programs are one work when they execute in the same address space and exchange data through shared structures rather than through a defined module interface.
3. Semantic dependence: two programs are one work when the second would be unable to perform any non-trivial function, or would lose its point, without the first program's specific behavior.
4. Extension intent: two programs are one work when the later program was written to alter, augment, or replace part of the earlier program's functioning rather than to treat it as a general-purpose platform.
5. User-facing unity: two programs are one work when a competent ordinary user experiences them as a single integrated tool rather than as a bundle of cooperating tools.
