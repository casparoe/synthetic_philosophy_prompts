PROBLEM (20 points)

In the one-shot Prisoner's Dilemma, write C for cooperate and D for defect, with the following payoffs:

- (C,C) = (3,3)
- (C,D) = (0,5)
- (D,C) = (5,0)
- (D,D) = (1,1)

In a program equilibrium, each player submits a computer program; both programs receive the other's source code as input and output C or D. Assume a sound proof system strong enough to prove elementary facts about these programs, and assume each program's proof search is cut off after some fixed but unspecified number of steps.

Define:

- DefectBot(X): outputs D for every input X.
- CooperateBot(X): outputs C for every input X.
- IdentityBot(X): outputs C iff X is byte-for-byte identical to IdentityBot's own source code; otherwise outputs D.
- FairBot(X): searches for a proof that X(FairBot) = C. Outputs C iff it finds one before its cutoff; otherwise outputs D.
- PrudentBot(X): searches for proofs that X(PrudentBot) = C and X(DefectBot) = D. Outputs C iff it finds both before its cutoff; otherwise outputs D.

(a) [5 points] Explain why (IdentityBot, IdentityBot) is a program equilibrium, and why (DefectBot, DefectBot) remains one.

(b) [7 points] Give the action profile FairBot produces against DefectBot, against CooperateBot, and against itself. Explain how Löb's theorem resolves the apparent circularity in FairBot's self-inspection. Then state in one sentence the defect of FairBot that PrudentBot is designed to repair.

(c) [8 points] A student objects: "The program-equilibrium idea is an artifact. Since programs can read each other's code, I can just submit SimulatorBot, which runs the opponent's program, computes what the opponent will do against SimulatorBot, and then returns D whenever the opponent would return C against SimulatorBot, and returns C whenever the opponent would return D. Against FairBot this returns D while FairBot returns C, so SimulatorBot gets 5 and FairBot gets 0. Cooperative equilibria are therefore an unreal artifact." Assess this objection. In particular, explain what, if anything, is wrong with the phrase "computes what the opponent will do against SimulatorBot" in a setting where SimulatorBot's own action is part of what determines the opponent's action.

STUDENT'S ANSWER

(a) Two IdentityBots see the same code, so each sees a byte-for-byte match and outputs C; both get 3. If one player switched to any other program Q, the remaining IdentityBot would see that Q's code differs from its own and output D, so Q's payoff is at most 1, which is worse than 3. Hence (IdentityBot, IdentityBot) is a program equilibrium. (DefectBot, DefectBot) is also an equilibrium: DefectBot outputs D no matter what, so the best any alternative program can do is output D and get 1, rather than output C and get 0.

(b) Against DefectBot, FairBot cannot prove DefectBot(FairBot) = C because that statement is false, so FairBot outputs D; the profile is (D,D). Against CooperateBot, FairBot can prove CooperateBot(FairBot) = C directly from CooperateBot's definition, so FairBot outputs C; the profile is (C,C). Against another FairBot, each side's action seems to depend on the other's proof search, but Löb's theorem lets each FairBot prove the other's cooperation without first simulating the other, so FairBot plays C against itself. FairBot's defect is that it cooperates with CooperateBot, which cooperates even with defectors; PrudentBot's added requirement that the opponent also defect against DefectBot lets PrudentBot output D against CooperateBot while still cooperating with FairBot and with itself.

(c) The objection is correct, and it shows why program equilibrium is unrealistic. SimulatorBot reads FairBot's source code and runs FairBot with SimulatorBot's own code as input. Because FairBot will find the proof that SimulatorBot outputs C, FairBot outputs C. SimulatorBot then outputs D, exactly as specified, and collects 5 while FairBot gets 0. This works for the same reason the earlier cooperative equilibria work: both programs can condition on the other's code. Program equilibrium can therefore deliver cooperation only if we artificially forbid programs from simulating one another. Once simulation is allowed, defection regains its advantage, and the cooperative equilibria are artifacts of that restriction.
