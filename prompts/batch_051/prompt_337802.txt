I'm a software engineer, not a lawyer or a philosopher, and I've spent more time than I care to admit trying to extract a usable test from the GPL's language about derivative works. I'd like to report my gut verdicts on a set of concrete cases and ask what principle, if any, captures them.

The text I keep returning to is Section 2 of the GNU General Public License, version 2, published by the Free Software Foundation in June 1991. The passage that gives me trouble is this:

"These requirements apply to the modified work as a whole. If identifiable sections of that work are not derived from the Program, and can be reasonably considered independent and separate works in themselves, then this License, and its terms, do not apply to those sections when you distribute them as separate works."

The next sentence says, in substance, that when those same sections are distributed as part of a larger whole that contains the Program, the license's terms extend to the whole and to every part of it, regardless of who wrote each part.

Here are my cases and my honest, un-theorized verdicts.

1. I fork a GPL-covered program, edit hundreds of files, and distribute the result. Verdict: the whole distributed program must be GPL. This is the easy baseline; I'd need an argument to overturn it.

2. I copy a single 20-line function from a GPL-covered library into my otherwise original codebase, which I distribute under a permissive license. Verdict: not fine. The whole codebase must be GPL, because it now contains part of the Program.

3. My proprietary program, at runtime, starts a GPL-covered command-line program as a subprocess, sends it input, and parses its output. The two are installed separately and communicate only through text streams. Verdict: fine. My program is not a derivative work; I'd be stunned if this were a violation.

4. My proprietary plugin loads into a GPL-covered application's process through the application's documented plugin API, calls the application's functions, and shares no source code with it. The plugin is distributed separately. Verdict: not fine. I'd treat the plugin as needing to be GPL when distributed for that application, though I can't fully justify that from the text.

5. My proprietary program dynamically links to a GPL-covered shared library at load time. The library is distributed separately as a .so file, and my binary contains no part of the library's code. Verdict: not fine. The combination is a derivative work. But this feels very close to case 3, and I cannot articulate why one is fine and the other isn't.

6. I implement a library with the same API and the same algorithm as a GPL-covered library, but I never read its source; I worked only from a written description of the algorithm. Verdict: fine. This is a clean-room reimplementation and is original expression.

7. I distribute a Docker image that bundles my proprietary binary together with a GPL-covered binary and a startup script that runs the GPL binary as a subprocess. Verdict: I'm uneasy in a way that the separate-install subprocess case doesn't make me uneasy, but I can't say whether that unease is legal or just a feeling that I've put two programs inside one artifact.

The pair I keep going back and forth on is case 3 and case 5. From the machine's point of view, both are just one program handing control to another at runtime. But my gut says one is clearly fine and the other clearly isn't. The GPL's own definition of "work based on the Program" says it includes "a work containing the Program or a portion of it," yet neither my dynamically linked binary nor my subprocess-spawning program literally contains the other's code. So what does "containing" do the work here?

Is there one principle—or a small set of candidate principles—that captures all seven verdicts and the GPL's own language about wholes and parts? If not, which of my verdicts should I overturn, and why? What does the resulting principle say about a case I haven't listed, such as a program that links against a GPL library but where the end user, not me, performs the actual linking step? Please state the principle precisely, tie each clause to the case that motivated it, and be candid about which of my verdicts it cannot accommodate.
