I teach a small epistemology seminar — about 16 undergrads, one 75-minute session — and next week we're doing the anti-luminosity argument and the KK principle. I want to run a game that makes them feel the force of anti-luminosity before we name it: the thought that there's no sharp boundary in how things seem to you, and that the idea that knowing means knowing that you know gets wobbly when the thing known is something like *that still looks blue to me*. By the end of the debrief I want them to see that any condition you're always in a position to know when you're in it demands a sharpness our own discriminations don't have.

Design an in-class activity built around a projected color gradient — say 25 patches running from obviously blue to obviously green, with each adjacent pair almost impossible to tell apart. The core mechanic I have in mind: everyone commits to a private first-order cutoff (the last patch that still looks blue) and then a challenger picks the two patches straddling your cutoff, shuffles them, and you have to sort them above chance for points. Set the wagers small, use points not money, and rig the incentives so people learn quickly that any sharp cutoff is a loosing bet.

After that first pass, add a second-order round: everyone places another cutoff, this time for the last patch where they *know* it's blue (or would say they know that they know it's blue), and run the same challenges. The payoff scheme should make the tension between the first-order and second-order cutoffs visible — for instance, give points for consistency, but let consistency plus the challenge phase push people into something like the anti-luminosity induction, where their cutoff gets dragged patch by patch to the end of the series.

Give me: full rules and a materials list a tired grad student can set up in ten minutes, a point scheme that needs no real money, a debrief script that maps exactly what happened in the game onto (i) luminosity, (ii) the reliability premise in the anti-luminosity argument, and (iii) the KK principle, plus a list of what will predictably go wrong the first time I run it and how to handle each. And be frank about which part of the formal anti-luminosity argument the color-patch game can't reproduce and what I'll have to supply myself in the last five minutes — I want the game doing as much of the teaching as possible.
