I'm a software engineer with no formal philosophy background, and a parallel has been nagging at me. In my day job we draw a sharp line between conformance testing and verification. A conformance test runs a finite set of inputs against the system and checks the outputs against a specification, but passing the suite does not prove the implementation is right: the code can overfit the tests, special-casing the inputs it has already seen. We even have a degenerate version of this — a lookup table with a stored answer for every test case — which passes the suite perfectly while implementing almost nothing. We don't respond by writing more unit tests. We respond with property-based testing, which checks a stated property against a large generated space of inputs, and, in safety-critical work, with formal verification, which proves against a mathematical specification that the implementation behaves correctly for all possible inputs.

Turing's imitation game now looks to me like a conformance test for minds. A judge samples a finite conversation with a hidden human and a hidden machine and tries to tell them apart; Turing proposed replacing the question whether machines can think with something like this test, and thought that a machine that could not be reliably distinguished from the human would leave us with no good reason to deny it thought. The move of ignoring what is inside the box and judging only sustained observable behavior sounds exactly like our engineering stance that what matters is whether a system satisfies its interface, not what realizes it. The mapping I keep drawing is this: the sampled Turing-test conversations are the finite test suite, the hidden human's conversational behavior is the specification, and a system that passes by retrieving canned responses is the lookup table implementation.

I cannot tell whether this is a genuine structural identity or just me pattern-matching on the word "test." If it is genuine, does anything transfer in either direction? In particular: is the Turing test vulnerable to the same overfitting problem as a conformance suite, and is the engineering response — more thorough tests, property-based checking, then formal verification — available when the system under test is a mind? What would formal verification of a mind require, and does the absence of anything like a written specification for mindedness mean the analogy breaks exactly where software testing gets its leverage? Finally, try to name something the parallel predicts about one side that turns out false on the other.
