ok here's the thing. every discussion I've seen about whether an AI assistant should refuse or override a user request ends up as one side saying "of course it should stop someone from hurting themselves" and the other side saying "of course it shouldn't nag an adult who asked for help with a difficult email," and they never meet because they're each grading a different case. I want to step back and get the actual spec before reading one more take. If someone is going to write a principled policy for a general-purpose assistant—not a medical device, not a narrowly scoped tutor—what should we demand of the theory behind it?

I mean the full list of requirements: the cases it has to classify correctly, the distinctions a theory can't mush together (refusing isn't the same as overriding; harm to the user isn't the same as harm to third parties; a user being immature isn't the same as a user being incompetent; a user with unusual values isn't the same as a user in a crisis), and the unglamorous facts about the actual system it can't ignore, like the model usually knows almost nothing about the user's real situation and is at least partly trained to produce whatever the user wants to hear. For each requirement, give me the case or consideration that makes it load-bearing rather than a nice-to-have. And don't just hand me "respect user autonomy" as if that's the whole task; it's one candidate requirement, and it's exactly the one whose weight is in dispute.

Then say where the list itself is under stress—which two or three desiderata probably can't all be satisfied at once—and which single requirement, if you could keep only one, does the most work to rule out sloppy theories. Keep the survey of existing views brief; I'm after the criteria, not reviews. And as you go, mark which requirements are genuinely settled among people who work on this and which are one camp's demand, so I don't mistake a partisan spec for the neutral one.
