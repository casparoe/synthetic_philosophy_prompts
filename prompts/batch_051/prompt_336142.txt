I work as a software engineer on multi-agent systems and have been going in circles on a game-theory argument a coworker keeps making. I have no formal philosophy background, so I would like a precise diagnosis. The setup: two deterministic software agents face each other in a one-shot prisoner's dilemma, with common knowledge that they run byte-for-byte identical decision procedures D on identical inputs. The payoffs have the usual ordering — temptation beats reward, reward beats punishment, punishment beats the sucker payoff. My coworker argues:

(1) Because both agents run D on identical inputs, their outputs must be identical. The only possible joint outcomes are therefore cooperate/cooperate or defect/defect.
(2) From my standpoint as one of the agents, choosing cooperate and choosing defect are thus choices between those two possible joint outcomes: if I cooperate, the other agent cooperates; if I defect, the other agent defects.
(3) I prefer cooperate/cooperate to defect/defect.
(4) Therefore I should choose cooperate.

He concludes that rational agents in this setup are forced into mutual cooperation. Something about step (2) feels wrong to me: it treats the other agent's action as if it were downstream of my local output, but I cannot tell whether that feeling is just leftover from the usual dominance reasoning for the standard one-shot prisoner's dilemma. Is the argument valid? If not, which step exactly fails, and would there be a plausible reformulation under which mutual cooperation is genuinely mandatory?
