I keep noticing an asymmetry in how I judge two things that both refuse to update on new information, and I can't tell if it's defensible. If I learn that the two lines in the Müller-Lyer illusion are the same length, my visual system keeps reporting them as different, and nobody calls that a malfunction—it's just how perception works. But if I fix a bug by changing a config value and some downstream module keeps using a stale cached copy, we'd call that a bug, maybe a serious one. Both are a component of a bigger system ignoring a correction from outside. In the brain we treat that as a feature of encapsulated modules; in code we treat it as a defect. What principle, if any, justifies the asymmetry? Is it just that the visual system can't be patched and the module can, or that one is fast and one is slow, or that one was designed and the other wasn't? Or should good software architecture tolerate more of this than we currently do? I want the strongest justification you can find, and an honest verdict on wether it survives edge cases.
