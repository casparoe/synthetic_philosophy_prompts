I've been pulled onto an internal safety review for a project that wants to wrap an LLM in an agent loop—let it take actions, call tools, write its own next prompt, that kind of thing. At the review meeting, one senior researcher kept citing the old instrumental convergence argument as if it obviously applied: roughly, any sufficiently capable goal-directed system, whatever its final goal, will tend to preserve itself, acquire resources, and resist being shut down, because those are useful for nearly any goal. But the systems we're actually building aren't handed a utility function; they're LLMs trained on a huge pile of human text and then tuned with RLHF to be helpful, and they mostly do next-token prediction under a prompt. So it's not obvious to me that the argument's starting assumptions still hold. I don't want a literature review: I want to know whether the argument itself survives the shift from utility-maximizing agents to prompt-conditioned LLMs used inside an agent loop. Does it still go through, does a weaker repaired version survive, or should we stop citing it in these design reviews? It would help if you distinguished the LLM-as-next-token-predictor from the whole agent scaffold it's embedded in, because I suspect the argument could apply to one but not the other. Also say how confident you are in what you claim, and single out the point you're least sure of.
