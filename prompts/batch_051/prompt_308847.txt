I am preparing a seminar session for first-year undergraduates in a philosophy of history course. The students already know, in broad outline, the for-want-of-a-nail proverb: a missing nail loses a shoe, a horse, a rider, and finally a battle. They arrive convinced that the proverb's lesson is that history is chancy — that because a trivial event can be amplified into an enormous one, the course of events was not determined. My goal is to replace that conflation with the ability to keep three ideas apart: sensitive dependence (small differences in antecedent conditions making large downstream differences, a feature that even deterministic systems can exhibit), chance (an indeterministic process that can issue in more than one outcome from the same prior state), and the contrastive character of causal explanation (the nail counts as the cause only relative to a background of conditions held fixed and a contrast in view). By the end, the students should be able to state precisely what the proverb licenses and what it does not license.

Design the explanatory sequence for this session, not the lecture itself. Work out: the order in which the prerequisite ideas must be introduced and which later step depends on which earlier one; the single carrying example and the features it must have and must lack; the misconceptions the students will bring or form, in the order they will predictably surface, with the point in the sequence at which each should be headed off and how; the final check that would distinguish a student who can hold sensitive dependence, chance, and contrastive causation apart from one who has merely learned the words; and what should be deliberately left out at this level and why. Do not assign readings or require citations.

Return the plan as a JSON object with exactly these fields:

- "objective": a string, the single claim or distinction the session should land on.
- "prerequisite_ideas": an array of strings in the required order, each naming one idea and, after a semicolon, stating which later step needs it.
- "carrying_example": an object with fields "example" (a string describing one concrete case in enough detail to serve the whole session), "what_it_must_have" (an array of strings naming its essential features), "what_it_must_lack" (an array of strings naming features that would defeat its purpose), and "where_used" (a string naming the step or steps that deploy it).
- "misconception_map": an array of objects, each with fields "misconception" (a string), "surfaces_at" (a string naming the step where it predictably arises), and "head_it_off_by" (a string saying how the sequence should absorb it).
- "sequence": an array of objects, each with fields "step" (a string describing one distinct explanatory move), "purpose" (a string saying what that move installs or blocks), and "depends_on" (an array of strings naming the prior steps or prerequisite ideas it presupposes).
- "check_for_understanding": a string giving the ending question or task and the specific contrast in a successful answer that shows the distinction has landed.
- "deliberately_omitted": an array of strings, each naming something left out at this level and, after a semicolon, why it is omitted.
