I've been reading Carroll's dialogue with Achilles and the tortoise for a logic course, and at the same time messing around with compilers, and I can't shake a parrallel. In the dialogue the tortoise accepts p and accepts p→q, but won't accept q. Achilles adds the principle that if p and p→q are true then q must be true, as an extra premise; the tortoise now wants a further premise saying that this new premise plus the first two force q, and so on forever. Now the computation side: take a program written in language L where the only thing that can run L-programs is an interpreter written in L itself. You seem to get the same regress — to run the interpreter you need something that runs the interpreter, forever. It bottoms out in practice because the CPU just executes instructions without needing another instruction telling it to execute instructions (or a compiler gets bootstrapped from a hand-written version and then compiles itself). So the tortoise looks like someone insisting that a CPU must be handed an instruction saying "follow instructions" before it will follow any instruction, then another instruction saying to follow that one, and so on.

I'm trying to explain Carroll to CS friends and want to know whether this is a real structural analogy or just pattern-matching. State the mapping as precisely as you can. Is the logic-side analog of the hardware level the fact that we simply infer in accordance with modus ponens instead of consulting it as a premise? And here's the thing that bugs me: computers can have an interpreter for L written in L (a metacircular evaluator), and it works fine because something outside it eventually executes it. Should there be a "metacircular rule" on the logic side, a rule that licenses its own application? If not, what exactly is broken in the transfer? Also tell me at least one thing the analogy seems to predict about deduction that is actually false, if you can think of one.
