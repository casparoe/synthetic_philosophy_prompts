I've been chewing on AI safety a lot lately and I want someone to poke at my position before I write it up for a team doc. I'm a software engineer with no philosophy background, so I keep reaching for the only tools I trust — guarantees and worst-case analysis — and I think I've tangled a few of them up. Here's the set, roughly:

(1) I think the right formal target for alignment is a no-regret guarantee. Like in online learning: we want an algorithm whose regret against the the best fixed safe policy in hindsight is sublinear in the number of decisions, so the average regret goes to zero. That's the guarantee we can actually prove, so I think it's the right thing to aim for.

(2) I think that's enough to call the system safe. If regret is sublinear then the system is, on average, nearly as good as the best safe policy, so it can't be doing much harm over time. Thats basically my whole safety argument.

(3) I think the real threat model is adversarial. An adversary (or just bad luck / distribution shift) gets to pick the worst possible state or input for the system to face, so I should be reasoning in minimax / worst-case terms, not average-case.

(4) I think the system should be a straight expected-utility maximizer. Rejecting EUT is incoherent because you can Dutch-book anyone who doesn't, so I don't see how you get around it.

(5) And I'm treating a hard off-switch / corrigibility as the ultimate backstop. Even if everything else goes wrong, a human can just pull the plug, so the system has to be correctable by a human.

Run me through it like a code review: which of these pull against each other for real, which are fine once you look closer, and where the cracks are, what specifically has to give to close them? I want them ordered by how bad the crack is, not a flat list, and for each one I want the minimal change that fixes it. And if one of these is the load-bearing piece the rest is quietly resting on, point that out. Skip the general AI-safety lecture, I just want the internal audit of this set.
