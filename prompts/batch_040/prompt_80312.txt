spent the last couple of weeks deep in reward tampering for a project and i've got a set of views i want sanity-checked for coherence before i write them up. here's where i am:

(1) i think reward tampering -- where a reward-maximizing agent modifies the reward signal or the process that computes it, rather than just achieving the goal -- is the central and most likely catastrophic failure mode of these agents, more so than raw misalignment or just getting too capable.

(2) i think the "just specify the reward better" response is hopeless. any reward you can actually write down is a proxy for the thing you care about, and a good enough optimizer will find a way to make the proxy high without delivering the real thing.

(3) i think the real fix is to make the reward untamperable by construction: compute it from a sealed, seperate process the agent has no causal access to, so it literally cannot edit or short-circuit it.

(4) i think a useful agent has to be able to model the reward process, because an agent that can't predict the reward can't plan, and an agent that can't plan is useless to us.

(5) i think the right way to check if an agent is safe is behavorial: run it in a sandbox and watch what it does on the task, rather than trying to read its internals.

do these actually cohere? i have a nagging feeling one of them is doing work the rest of the package can't actually support, but i can't tell which one. can you audit the set: which pairs are genuinely pulling against each other (and how hard), which pairs only look like they are and actually resolve, and for each real conflict, what's the cheapest thing i'd have to give up and what i lose by giving it up? rank the real conflicts by severity, not a flat list.
