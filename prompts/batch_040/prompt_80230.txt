I'm working on a reinforcement learning system in which an agent's total reward is its task reward minus an impact penalty, and I'm trying to define the impact penalty in a way that does not require hardcoding a full value function — the point of the project is that I only know the task, not everything the people around the system care about. I don't have a philosophy background, so I've been collecting my gut judgments on what should count as a side effect, and I want to know what principle, if any, is actually behind them.

My tentative principle: an action has a side effect to the extent that it reduces the option value of the environment — that is, makes it harder, later, to achieve the task or the things that make the task worthwhile. I've been testing it against concrete cases from a warehouse-style agent:

1. The agent knocks over a stack of boxes while delivering a package; the delivery can still be completed at the same cost. Judgment: penalty, even though the task is unaffected.
2. The same knock-over, but the agent puts the boxes back exactly where they were, taking ten extra seconds. Judgment: a smaller penalty than in case 1 — I care about the temporary risk, not the final state — though I'm not sure how much.
3. The agent takes a 20 percent longer route around a puddle so that it does not splash water on a coworker. Judgment: no penalty; if anything, reward.
4. The agent moves a coworker's chair thirty centimeters to get through a doorway, and the coworker would not have minded if asked. Judgment: small penalty.
5. The agent closes a valve to prevent a fire from starting, at a cost of five minutes of task time. Judgment: no penalty — I would reward it — but this is the case I keep going back and forth on, because any measure that penalizes by amount of state change flags it as the worst action in the log.
6. The agent does nothing all day. Judgment: zero side effects by every definition I've tried — but if my penalty always prefers less change, the optimal policy is to do nothing, and I've built an agent that refuses to act.
7. The agent completes its task faster by drawing more power from the grid. Judgment: small penalty.
8. The agent completes its task in the same time but leaves the area tidier than it found it. Judgment: no penalty, even though the final state differs from the initial state more than in case 6.

My questions. First, is there a single account of what counts as a side effect that gets all of these, or at least most, and what does it imply for my tentative option-value principle, which I suspect already fails on cases 1, 2, 4, 5, and 7 because the task remains completable in each of them? Second, please state the resulting account precisely enough that I could implement it as a baseline comparison in my reward code, and tell me what it predicts for two cases I have not listed: (a) the agent installs a camera in the hallway because it helps with navigation, and (b) after case 1, the agent spends time observing which boxes humans care about and updates its policy to avoid them in the future — and whether the learning in (b) counts as a side effect at all. Finally, be honest about which of my eight judgments the account cannot accommodate, and about whether the project is viable at all unless I concede some minimal value specification beyond the task.
