I'm a software engineer — backend, mostly data pipelines and A/B testing infrastructure — with no formal philosophy training, and the reference class problem has been nagging me because it keeps showing up in my work under different names: which base rate should I use, which cohort is the right one to compare against, is this user an atypical member of the group I'm drawing the rate from. I've been trying to sort it out by writing a short essay to send to a friend who is a philosopher, and I'd like your comments before I send it, especially on whether the central argument is sound and on whether I'm missing a standard objection. Here is the draft.

The reference class problem, as I understand it, is this: when I want to attach a probability to a single case — will this flight be delayed, will this patient respond to the treatment — I reach for a frequency in some class (flights, patients with this condition), but any individual belongs to many classes at once, each with its own frequency, and there seems to be no fact of the matter about which class the individual really belongs to for purposes of probability. My claim is that this is not a problem about probability at all but a problem about granularity of description, and that it dissolves once you notice the reference class is not discovered but chosen, and that the choice is constrained by the decision you are about to make: the right class is the one whose frequencies bear on the consequences of the action you are considering. In my A/B testing work we never actually ask what the true conversion rate of this user is; we ask, given that we are about to show this user variant B, what should we expect and what should we do — and the question picks the class. So the reference class problem looks to me like the same kind of pseudo-problem as asking what the true average of a dataset is before saying what you will do with the average. The part I am least sure about is whether this dissolves the problem or merely moves it: a critic can say the decision picks the class only when there is a decision, but sometimes the task is precisely to estimate the probability (a statistician's job) or the action is insensitive to which class you pick, and then the criterion gives no answer; and a deeper critic can say that even when the decision picks a class, it often picks one in which I am an atypical member, so the class frequency is a poor guide to my case — which I think is the real engine behind the Doomsday argument, and which I have not addressed.

So concretely: (1) Is the dissolution argument — the decision context picks the reference class, so the problem is a pseudo-problem — defensible, or does it just relocate the problem, and is there a standard name for the objection I have half-described? (2) On the A/B testing analogy specifically: is it illuminating, or does it smuggle in the assumption that there is always a decision in view, which is exactly what is in dispute? (3) Is the atypicality point in the last sentence the right thing to worry about, and can you state it more cleanly than I have? (4) More generally, does the "granularity, not probability" framing read as a rehash of something standard, or is there a genuinely new angle in it?
