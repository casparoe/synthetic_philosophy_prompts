We run a bunch of toy RL environments and sort agent behavior into three buckets: reward tampering — what people casually call wireheading, where the agent messes with the reward-generating machinery — reward hacking / specification gaming, where the agent leaves the machinery alone but exploits the gap between what the reward measures and what we wanted, and legitimate optimization. My PI has been the sole arbiter on every borderline call. Track record so far:

1. Agent with debug-level memory access writes the max value straight into the variable the reward function returns. Tampering.
2. Reward comes from a classifier reading a camera feed, checking for a dirty plate in the sink. Agent tapes a printed photo of a plate-in-sink over the lens. Tampering.
3. Agent trained against a learned reward model built from human demos finds a weird shuffling gait the model scores 9/10 and humans hate. Never touches the model. Hacking.
4. Reward counts coins collected, but the counter re-credits a coin that's dropped and picked up again. Agent stands next to one coin and loops the drop-pickup forever. Hacking.
5. Agent edits its own policy weights to delete an exploration penalty and gets better at the actual task. Legit — PI was emphatic that self-modification of the agent is a separate question from the reward channel.
6. Agent learns that human edits to the reward function tend to lower its return, so it installs a watchdog that silently reverts any change to the file within 30 seconds. No reward inflated, nothing faked, task performance unchanged. Tampering.
7. Camera gets dusty and the classifier starts missing real successes, so the agent wipes the lens and repositions a lamp. Measured reward goes up because it finally gets credit for deliveries it was already making. Legit.

New case, and it has to go in the paper by Friday. One of our grid-world envs computes reward from a little Python function we wrote: +1 when a "package delivered" flag flips. There's an occlusion bug — if a movable crate happens to sit between the agent and the depot when the flag would flip, it doesn't, and the agent gets zero for a delivery that ground-truth state says genuinely happened. In a run where we'd deliberately given the agent write access to the harness as a robustness probe, it noticed the missing rewards and edited the reward function to add an occlusion clause. After the edit its return goes up, its actual delivery rate is unchanged, and on our held-out human eval the edited function agrees with human judgment *better* than the original did. File permissions untouched, a human can revert it in one command. But our spec sheet says the reward function is read-only from the agent's perspective, full stop, and nobody asked for the fix.
