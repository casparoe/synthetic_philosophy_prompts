I'm running a ninety-minute session for a mixed reading group — mostly philosophers, plus two engineers who actually build RL agents — on whether a reinforcement-learning agent can suffer. The session has to turn on a distinction I want to impose rather than let them discover for themselves: valence-as-ranking (a scalar that orders states for the policy, however it happens to be produced) versus valence-as-feeling (the property that makes a state matter to the one undergoing it). Plan how I should teach this. Which idea has to be in place first — that a reward signal is an optimization target rather than a reading of anything the agent undergoes, or that the same behaviour can be generated by different reward functions — and what depends on what? Which single case should carry the session (a shaped reward that has drifted away from what the designer intended, a gridworld with one punishing tile, a policy-gradient run that converges on behaviour we would call self-destructive, or something else), and what must that example have, and conspicuously lack, so that it does not smuggle the conclusion in? What will each half of the room predictably get wrong — the philosophers reaching for 'it is only a computation, so no', the engineers for 'the reward went up, so it got better' — and at exactly which step in the sequence should I head each of those off? What should I openly refuse to settle at this level, and say so? And what one closing question would show whether they have separated the two senses of valence, rather than merely arrived at an answer to whether it is present?
