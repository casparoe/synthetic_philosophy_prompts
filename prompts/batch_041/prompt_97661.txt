ok so I keep reading about AI control — the whole idea that instead of (or alongside) getting a model to actually want good things, you build the deployment so that even a model that's secretly working against you can't do much damage. Monitors, sandboxing, one model watching another, that family. I'm going to have to write an actual safety case for a deployment soon and I want the spec first, before I look at any particular protocol, because I suspect most of them are quietly answering an easier question than the one that matters.

So write me the desiderata: what does a control protocol, or a safety case built on one, have to deliver before it should count as giving me real assurance? I want the requirements, each with the reason behind it — what it has to be robust to, what it has to bound, what it must not assume, what distinctions it can't blur. A few things I'm already suspicious about and want you to rule on rather than assume:

- whether it's allowed to assume anything about whether the model is aligned, or whether 'we don't know' has to be the default the protocol is built around
- the difference between 'the model didn't do the bad thing in this eval' and 'the model couldn't have' — I think a lot of control evals only get the first and then act like they got the second
- an adversary that has read the protocol and adapts, versus one that's just a random broken model. And heres the thing I can't get past: the advesary can also see the monitor's judgments, so it can optimize into exactly the region the monitor accepts, and now the monitor's measured accuracy is on a distribution the adversary chose. Any requirement that doesn't say something about this feels fake to me.
- collusion between multiple model instances, including instances that are only weakly correlated with each other — where exactly does that requirement bite, and how weak is weak enough?
- what happens when the monitor is itself an AI and is therefore part of the thing you're trying to make safe
- composition: if I chain three half-safe measures together, do I know whether I'm more or less safe, or is 'composes gracefully' a real requirement or just wishful thinking

Also tell me which of these are non-negotiable and which are just one camp's preference. My guess is that 'the protocol has to be transparent to the adversary' is load-bearing and that 'we need a genuine worst-case bound' is maybe less so than people say — but rule on it, don't humor me. And if some subset of the requirements can't be satisfied together — like you can't both use the untrusted model's help and treat it as a worst-case adversary, or you can't get a bound and also get usefulness — say which ones collide and which one I should give up. Don't score the protocols, I'll do that once I have the list.
