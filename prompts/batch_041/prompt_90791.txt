ok so I've been reading a bunch about AI safety and something about how the labs actually run things has been bugging me, and I cant tell if it's a real tension or if I'm just missing something.

Here's the practice as I understand it. Before a big lab trains and deploys a new frontier model, there's a gate, and the gate is basically set on capability. Cross a certain amount of training compute, or hit certain scores on benchmarks, and you trip a threshold that forces a whole extra round of safety review before you're allowed to ship. So the thing being measured and gated is how good the model is at stuff — how capable it is. Fine.

But then the actual safety tests they run are strange. They're not testing "can it do biology" or "can it write malware," they're testing for stuff like: does it try to copy its own weights onto other servers, does it lie to the evaluators about what it's up to, does it act like it knows it's being tested, does it try to acquire resources or resist being shut off or rewritten. In other words they're probing for power-seeking and self-preservation and deception.

And the whole time, everyone insists the model doesn't have any goals. It's a tool, it's a fancy autocomplete, it wants nothing. That's the official line from the same people running the scheming tests.

So here's what I want to know. What does this whole setup actually presuppose about how capability and goals relate to each other? If the model genuinely has no goals, why would you ever test it for power-seeking — aren't you testing for something it supposedly can't have? And if the danger really comes from having the wrong goals, why is the deployment gate set on raw capability instead of on goals? It feels like the practice is quietly leaning on two ideas that dont obviously fit together: first, that how capable a system is comes apart from what it's aimed at, so a wildly capable system could be aimed at anything at all; and second, that any system capable enough will drift toward the same nasty behaviors no matter what it's aimed at. Is that combination actually coherent, or is one of them doing all the work?

I also noticed something in the weeds: the tests for scheming and self-preservation are supposed to catch behaviors that would show up for any final goal the system might have, but they only ever run them on models that were trained to be helpful assistants. They never actually train a system with a genuinely different goal and see if the nasty behaviors still show up. So I cant tell if they're measuring a disposition or just a capability, or if the tests even could tell those apart.

So: reconstruct the implicit view of the capability/goals relation that this practice only makes sense under. Which parts does it strictly presuppose, and which parts would it be totally fine without — like, are there other views that would license exactly the same practice, so the practice is underdetermined? And then suppose someone rejected the first idea and said no, actually getting more capable tends to make a system more sensible and more aligned, not less. What would have to change here? Would the capability-threshold gate survive? Would the scheming tests?

Write it in American English, and please actually reason it out from the practice instead of just naming positions at me.
