I'm a philosophy of science PhD student putting together a proposal for a one-semester workshop paper (roughly 6,000 words) on mechanistic anomaly detection: the AI-safety proposal that a model's treacherous or deceptive behavior can be flagged by checking whether the internal computation it performs on a novel input is mechanistically anomalous relative to the computation it performs on inputs we already trust. My half-formed idea is that this proposal is hostage to an unexamined answer to the question of what counts as the same mechanism, and that the identity relation it needs sits awkwardly between two unacceptable extremes. Functional equivalence — same input-output mapping over the relevant domain — is too coarse, since a deceptive mechanism can coincide with an honest one on every trusted input and so never register as different. Full causal-graph identity is too fine, since behaviorally equivalent re-implementations of a benign computation would be flagged as anomalies, which is exactly the false-positive failure the method cannot afford. I want to split mechanism-identity into three candidate criteria — same function on the relevant domain, same causal-structural profile, and same causal history or origin — and argue that anomaly detection needs a contrastive relation instead: two computations count as the same mechanism only relative to a specified set of features held fixed and a specified set allowed to vary.
