Trying to write up my actual view on AI alignment for a reading group and I want to stress test it before I present. Roughly where I've landed: (1) the alignment problem should be stated narrowly -- it's about getting a system to be trying to do what we intend, full stop; whether it then does the right thing is downstream and maybe not part of the same problem at all. (2) The reason to go narrow is that "load in the true human values" is a non-starter: we can't specify our values, argueably there's no determinate thing there to specify, so a research program built on it is chasing a ghost. (3) But the thing I actually care about morally is outcomes -- if we hand a system a decent proxy and it flattens the world optimizing it, the wrong is in the outcome, and it's on us because we chose the proxy. Which makes it sound like the wide version is the one that really matters and the narrow one is a dodge. (4) Corrigibility -- the system letting us interrupt or correct it -- I file under the narrow one, not as a separate value to be loaded in. (5) And honestly I'm not sure "alignment" even names a real problem distinct from ordinary safety engineering; it might just be "build the thing so it doesn't hurt people," which we already know how to think about.

Which of these actually pull against each other, and how hard? Which only look like they conflict? Rank the real tensions by severity, give me the cheapest fix for each, then tell me the single revision that cleans up the most and what I lose by making it.
