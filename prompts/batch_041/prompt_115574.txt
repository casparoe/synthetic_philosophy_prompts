Background so we're not talking past each other: when we assign a probability to a one-off event -- this surgery, this coin, rain tomorrow -- we seem to have to drop the event into a class of similar events and use the frequency (or the stats) in that class to get the number. That class is the reference class. That's the picture I'm working with.

Here's the argument:

(1) Any probability claim about a single event has to be grounded in a reference class: a set of relevantly similar events whose frequencies fix the number.
(2) Any single event belongs to indefinitely many reference classes, and they can disagree, even flatly. My patient is in "people who had this operation" and also in "people who had this operation, with this comorbidity, this marker, this surgeon, on this weekday." One class says 90% survival, a much finer one says 40%. Both are literally true of her.
(3) Nothing in the event itself, and nothing in logic, singles out one of those classes as THE correct one. Which one you use depends on your interests, your data, how much detail you bothered to record.
(4) So the number you attach to a single-case probability is arbitrary.
(5) So there's no fact of the matter about the probability of any single event.
(6) So single-case probabilities don't exist at all -- "there's a 70% chance of rain tomorrow" isn't true or false, it's not even the kind of thing that can be true or false.
(7) But that's clearly wrong. Insurers price policies on single cases, doctors consent patients on single cases, you and I decide whether to grab an umbrella on single cases, and these judgments beat chance and are often right. A view that says all of that is meaningless has gone wrong somewhere.
And notice it's worse than single cases: if any class can always be refined, then even "this die is fair" is arbitrary, so the thing seems to kill statistics too, which is another reason to think I messed up.
