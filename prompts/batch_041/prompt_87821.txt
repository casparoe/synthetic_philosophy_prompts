I work on a small team building a robot that plans with a symbolic layer sitting on top of a learned controller, and we keep having the same fight. When a behaviour changes after we tweak the planner, half of us say the symbol caused it and half say no, the symbol is just a name we stuck on a pattern in the controller's activations — the little balls did all the shoving and we drew a circle round some of them. (You know the picture: a table of dumb magnetic balls careening around and clumping into higher-level blobs we're tempted to call concepts.) I want a procedure we can actually run before we write "the agent chose X because it represented Y" in a paper or ship it to a customer, because if we're wrong we've shipped a robot whose reasoning is decorative: the questions in order, what counts as a pass on each, where it bottoms out in "can't tell from here," and which steps are really values calls about which level we've decided to explain at. We've got an afternoon per claim, not a PhD, and I dont want a treatise. Run it on three: a planner token whose removal reliably kills a behaviour; a token that predicts the behaviour perfectly but whose removal changes nothing; and the one I expect to hate, where no single token matters, the behaviour is stable, and only the whole pattern predicts it. Tell me straight where the procedure is just hand-waving in a lab coat. And say what would change your mind about your own verdict.
