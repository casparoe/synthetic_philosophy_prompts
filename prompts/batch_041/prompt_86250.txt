I work on the pricing and reserving side of a mid-sized property-and-casualty insurer, and the step I keep getting wrong is the very first one: deciding what set of past cases a new risk belongs to. Actuaries call this picking the class; philosophers, I am told, call it the reference class problem, and the version that bites us is that every policyholder is unique, so the set of past cases exactly like them is empty or has one member, while the set of past cases loosely like them is large but arguably irrelevant to the risk in front of us. Our current practice is folklore — an underwriter's instinct about which variables matter, occasionally a modeler's segmentation — and it produces the usual embarrassments: we underprice a new category because we fold it into an older one, or we decline to write a line because the only genuinely comparable cases number in the single digits. I have a master's degree in statistics but no formal exposure to the philosophical literature on this, and I suspect that literature has already mapped the traps we keep falling into.

Please write a decision procedure my team could actually run when we have to assign a new risk to a reference class and turn it into a frequency or a severity estimate. I want the questions asked in order, what counts as a sufficient answer to each, the point at which the procedure stops and says the data will not support a price, and the points where it has to hand the decision to a human because the choice turns on which error we would rather make rather than on any fact. The procedure should be candid about the moves that look like statistics but are judgment calls — for instance, the pressure to keep narrowing the class until the estimate becomes whatever we wanted, and the way two defensible ways of splitting the same data can point in opposite directions (I believe this is Simpson's paradox, and I would like to know when it is and when it merely looks like it). It should be usable by an analyst who knows regression and basic probability but has never read Carnap or Reichenbach, and it should say what to do when the class we would most like to use is too small to support any estimate, and when the class we can support is too broad to be credible.

Then run it on three cases: a routine commercial auto renewal for which we have years of comparable data; a cyber-liability policy for a firm in a sector we have barely written before; and a life insurance applicant with a rare medical marker whose only closely matched historical cases number a handful. Include at least one case in which the procedure tells us something we will not want to hear — that we should decline to price, or price off a class we consider unfair, or concede that the disagreement cannot be settled by collecting more data. Close by saying plainly what the procedure cannot do. Keep the whole response under 1,000 words.
