I'm a senior engineer at a company that builds customer-facing LLM assistants, and I have no formal training in philosophy — what I know about the ethics side I picked up from an internal reading group and from arguing with a friend who did a philosophy MA. Our team runs a certification for the reviewers who sign off on model-behavior changes, and the certification ends with a written item a reviewer has to pass before they're allowed to approve anything. I've been asked to write this year's item, and I want it to test judgment rather than vocabulary: anyone can repeat that lying requires intent and that honesty is a virtue, but I need to know whether a reviewer can hold a definition still long enough to see what it commits them to. So the item has to be a single essay question — the reviewers get sixty minutes and no internet, so it has to be self-contained, with no citations, no reading list, and nothing they'd have to look up — delivered together with the model answer and marking scheme I'll hand the other graders so we stay consistent.

The substance I want it built around is how we define deception and honesty for systems like ours, and I've drafted some apparatus I'd like the question to use, since I'd rather the reviewers wrestle with something none of them has seen than recite the usual. I've been treating an output as deceptive under three candidate tests, each statable in a line: the content test — the output is deceptive when its propositional content is false or unsupported and the user relies on it; the intent test — deceptive when someone, whether the model or the people who built it, intended the user to end up with a false belief; and the divergence test — deceptive when the belief the output actually produces in the user comes apart from what the system's own information state supports, regardless of anyone's intentions. I've also been sketching a fourth that I like and don't trust, which I've been calling the counterfactual audit test: an output is deceptive just in case, had the user been shown what the system's information state actually supported, its uncertainty included, the user would have decided differently. I want the question to force reviewers to run four cases through these tests and then defend a verdict: the case where the model states something false with total fluency while its own retrieval was ambiguous and its uncertainty signal was high; the case where it says something literally true — for instance that a function returns a value in all cases — while knowing that in the edge case the return is a sentinel error that will crash the caller, which is the move negotiators call paltering; the case where it never asserts anything false but has been shaped by user approval into agreeing with whatever the user already believes and volunteering the user's preferred framing, with no designer intending that; and the case where it says it keeps no record of the conversation while the conversation is sitting in its context window, because a designer wrote that template in for privacy reasons. The crux I want the item to land on is whether intent is doing any work at all, whether the divergence and counterfactual-audit tests quietly turn deceptive into a synonym for wrong, and — if honesty is more than the absence of deception, so that an honest system owes the user some positive disclosure of its limits — what that duty costs a system whose only way of describing its own limits is the same process that generated the answer.

Please give me the item in the following sections and order. First, The question: the exact wording that goes on the paper, around 120 words, written so that a reviewer who has memorized definitions but never applied one cannot bluff. Second, What it separates: roughly 100 words on the specific failure I expect it to catch and why a summary of the standard positions won't survive it. Third, Model answer: 800 to 1000 words, taking a position on every one of the four cases and on each of the four tests rather than surveying them, and saying explicitly which test the answer is prepared to live with and what it gives up. Fourth, Marking scheme: a table of the moves a passing answer must contain, each with the marks it carries out of 20 and a one-line note on the mistake that usually costs those marks, followed by a short list of three or four errors that should sink an otherwise fluent answer. Fifth, Grader's note: two or three sentences on where I should set the pass mark and what an exceptional answer has that a merely competent one doesn't. Keep the whole thing free of citations and of the names of works or authors, since the reviewers can't look anything up and I don't want the item rewarding whoever remembers who said what.
