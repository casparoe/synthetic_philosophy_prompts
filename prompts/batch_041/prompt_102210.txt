Mechanistic anomaly detection (MAD) rests on the thought that a model which behaves identically to a trusted reference on everything we can check may nonetheless be computing something different internally, and that this difference is where the risk lives. That only gets off the ground if we can say when two systems are running 'the same mechanism'. Using the implementation-level / algorithmic-level distinction from lecture 7, discuss what should count as sameness of mechanism for the purposes of MAD. Address (a) why behavioural equivalence is too coarse; (b) whether sameness is better cashed out causally (in terms of the counterfactual dependence structure of the computation) or representationally (in terms of the features a sparse autoencoder recovers), and whether the two can come apart; and (c) what your answer implies for how much assurance MAD can really give us. And here's the script I'm sitting with — long, and the handwriting was a nightmare, but I've transcribed it faithfully:

"Behavioural equivalence is far too coarse a criterion. Two networks can agree on every input in our test distribution while diverging off-distribution, and MAD is meant precisely to catch the case where the internal computation has shifted in a way that will eventually surface in behaviour. If we identify a mechanism with its input–output function we throw away exactly the information we need, so we have to look inside.

The natural fix is to identify a mechanism with the causal structure of the computation: two models run the same mechanism just in case the same intermediate variables mediate the input–output relation, i.e. if you intervene on an intermediate activation the downstream effect is the same in both. This is roughly what activation patching and causal scrubbing are testing for. On this view sameness comes in degrees, since you can match the coarse structure while diverging in the details, and that seems right — it's what lets us say a fine-tuned model is mostly doing what the base model did, with a local change.

There's a problem with stopping at the causal story, though. Causal structure at the level of individual neurons isn't robust: you can rescale or rotate the basis and nothing about the behaviour changes, so a purely causal criterion at that grain will call two models different when they're really doing the same thing. That pushes us up to the algorithmic level, and in practice the algorithmic level is the level of features. Two models share a mechanism when they use the same features, which is exactly what a sparse autoencoder hands you: if the same SAE features are active on the same inputs in both models, the models are running the same mechanism. It also gives a clean way to fix the trusted reference — you take the features the reference model uses and flag an anomaly whenever the candidate uses a different feature set on the same input.

Because a feature set either matches or it doesn't, MAD delivers a clean binary signal, which is just what you want from a safety monitor: either the model is running the mechanism you vetted or it isn't, with no judgement call in the loop. The main caveat is coverage — we don't have SAEs for every layer or every architecture yet — but that's an engineering problem rather than a conceptual one. So I'd say the concept is well-founded: once the level of description is fixed, 'same mechanism' has a definite answer, and the level we want is the feature level."
