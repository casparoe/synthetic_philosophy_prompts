The essay is intended for a workshop audience of alignment researchers and decision theorists, so I am less concerned with polish than with whether the argument is sound and whether the central distinction earns its keep.

**Two Kinds of Worst Case**

In alignment research there is a rough prestige ordering of guarantees. A guarantee that holds against every input, every distribution shift, and every model in some class is treated as the gold standard; a guarantee that holds on average, under a specified deployment distribution, is treated as a weaker consolation prize, appropriate for engineering but not for the deep problem. I want to argue that this ordering is largely an artifact of an equivocation, and that once the equivocation is removed the prestige reverses in a range of important cases.

The equivocation is between two things one might mean by a worst-case guarantee. The first is worst-case over inputs: given a fixed system and a fixed task, the system behaves acceptably no matter what input arrives. This is the sense familiar from adversarial robustness and from formal verification, and it is a coherent and demanding notion. The second is worst-case over hypotheses or models: the system behaves acceptably no matter which member of some class of possible systems or possible environments is the true one. This is the sense familiar from minimax decision theory and from robust statistics, and it is a different problem entirely. Much alignment rhetoric slides between the two, borrowing the rigor of the first while actually making a claim of the second kind.

Why does the slide matter? Because the two notions have different failure modes. A worst-case-over-inputs guarantee is vacuous exactly when the input space is unbounded and the loss is unbounded: if a single input can produce arbitrarily bad outcomes, then every system that admits any such input scores equally badly, and the ranking tells us nothing. A worst-case-over-hypotheses guarantee is vacuous for a different reason: it depends on the hypothesis class, and if the class is chosen to include a hypothesis on which the system fails, then no system passes; if it is chosen narrowly enough, every system passes. In both cases the guarantee is only as informative as the space it quantifies over, and in alignment that space is usually left unspecified.

This is where a circularity bites. In most adversarial settings the adversary is external and independent of the system being evaluated. In alignment the principal threat is the system itself: the thing whose worst case we are trying to bound is the thing whose behavior determines the bound. So the hypothesis class over which we take the worst case is not a fixed, external set; it is generated by the very system we are evaluating, and it shifts as the system is modified. A worst-case guarantee whose threat model is endogenous to the artifact cannot be checked the way an external threat model can, because improving the system changes the adversary.

The practical upshot, I think, is not that we should prefer average-case guarantees in general, but that we should stop treating worst case as a single honorific and start asking, for each guarantee, what space it quantifies over and whether that space is specified independently of the system. Where it is not, the guarantee is doing rhetorical rather than technical work, and an average-case analysis under an explicit, criticizable distribution may be more honest — not because the distribution is known, but because at least its assumptions can be stated and attacked.

The obvious objection is that deployment distributions are precisely what we cannot specify for systems that will reshape the world, so average-case analysis is fantasy. I concede the force of this, but note that it cuts both ways: the same ignorance that makes the average-case distribution unknowable also makes the worst-case hypothesis class unknowable, and ignorance is not by itself a reason to prefer one side of a distinction.

First, is the central distinction — worst-case over inputs versus worst-case over hypotheses — correctly drawn, and is it really an equivocation rather than a harmless ambiguity? Second, is the circularity argument in the fourth paragraph sound, or does it overstate the difference between endogenous and external threat models; are there cases where a system's threat model is endogenous and yet the worst case is still well-defined and checkable?
