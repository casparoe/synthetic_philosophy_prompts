I build sandboxed runtimes for a living — the capability-based kind, where a process can only do what it holds an explicit capability for, no ambient authority, and confinement is basically just "there's no handle in the table". So my default picture of any world is: whatever is reachable from the handles you were given, and "X isn't available to this process" just means "no capability to X is in its table".

I've been trying to get my head round Skolem's paradox for a month now (I still can't say it propperly) and I want it restated in that vocabulary — properly, not as a loose analogy. My understanding: if first-order set theory (ZF, or ZFC) has any model at all, it has a countable one, a whole universe of sets that something outside it can enumerate one by one, and yet inside that universe the theory proves there are uncountable sets, including one it calls the set of all subsets of its natural numbers. The line I keep seeing is that the bijection between the naturals and that set exists outside the model but not inside it, so "uncountable" only means "no bijection in the model".

So translate it. Models as sandboxes, the model's elements as the objects in the sandbox, the sets and functions the theory can actually define as the capabilities the sandbox can name and invoke, "uncountable in M" as "no capability in the table enumerates it", the observer outside as the host, definability as whatever the sandbox's own table can express. Be as faithful as you can, and don't smuggle in my framework's assumptions and call it translation.
