I'm the token philosopher on the model deployment review commitee at a mid-sized AI company. Next Thursday we have to vote on whether to let the safety team ship a monitor that reads a direction in a model's activation space and flags when the model is representing the user as emotionally vulnerable or easily manipulable. If it fires, the model gets extra guardrails. The legal team says calling that a representation is making a mental-state attribution we can't defend; the interpretability team says it's just a useful correlation and the name doesn't matter. I think the name matters because the whole justification for the guardrail is that the model is tracking something real about the user, not just that the direction correlates with the label in our eval set.

Draft the memo I'll circulate before the vote. Lead with the bottom line in the first sentence, then the reasoning, no preamble and no restating of the question. I want a concrete recommendation -- approve, reject, or approve with conditions -- with a time frame for whatever you recommend. My own inclination is to adopt a three-test rule for any representation-based monitor before deployment. First, the direction has to come from an unsupervised method that just looks at activations (variance, clustering, whatever), not from a probe trained on labels, because a supervised probe can find a direction that predicts the label without the model actually using it. Second, there has to be a causal intervention: patching or ablating the direction should change the model's behavior in the predicted way, and a random direction matched for size should not. Third, the direction has to generalize: it should show up in held-out contexts and predict behavior on tasks that weren't used to find it. If it passes all three, treat it as a representation for deployment purposes; if it passes only the first two, call it a useful correlate and don't let it trigger guardrails; if only the first, don't ship it.

The main objection I keep hearing is that this is operationalism: the tests just define representation into existence, and the real question is whether the model has intentional states at all. Another is that the tests are too strict, because some real representations might be causally inert or only show up in the model's own reports. Take those seriously -- I'd rather the memo say what we're giving up than pretend the standard settles the metaphysics. Also make clear what happens to the existing monitor if we adopt the rule, and who has to run the tests before Thursday.
