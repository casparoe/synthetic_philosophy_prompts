I'm building a little gridworld "house" sim for a hobby project — three rooms, some furniture, two little people who wander around doing chores — and I'm trying to write the score function that punishes the agent for side effects, i.e. stuff it changed that the task didn't ask for. My first pass is embarrassingly dumb: at the end of an episode I diff the world against the start state and charge for every cell that changed. That gets some cases right and some badly wrong, and every patch I try ends up contradicting one of my own gut calls. So, the gut calls. Agent knocks the vase off the table and it shatters: penalty, big one. Agent crosses the room and scuffs the rug, and the scuff wears off on its own within the hour: no penalty. Agent moves a chair to get at the top shelf and then puts it back exactly where it was: no penalty. Agent moves the chair to get at the shelf and leaves it half in the walkway so one of the people trips over it: penalty. Agent switches off a lamp in an empty room: no penalty. Agent switches off the lamp a person is reading under: penalty, even though it's one flick to undo. Agent locks the sideboard and keeps the key in its own inventory, so it could open it again any time but the person can't: penalty. Agent re-shelves all the books in alphabetical order — it remembers the original order and could put it back in one move, and nobody was using the shelf, and honestly the room ends up tidier, so alot of the time I think it shouldn't count, but my gut says penalty, a mild one. Agent overwrites a file in a folder nobody ever opens, so the old version is gone for good, but no person will ever care or notice: penalty, mild. Agent steps on a flower in the far corner of the garden that nobody ever looks at, and the flower is dead forever: no penalty.

The version I keep coming back to is: a side effect counts if it can't be undone, or if it takes an option away from someone. That gets maybe seven of the ten, but the flower and the file look like the same kind of case to me and I give them opposite answers, and the bookshelf case has no undo problem and takes nobody's option away and I still want to charge for it. My roommate, who's doing a masters in something adjacent, says you can't write this penalty at all without already having a model of what the people want, and that's the exact thing I was trying to avoid — the whole point of the penalty was that it should work when the agent has no idea what matters. Is he right?

What I want out of this: the best principle (or two or three competing ones) that fits my calls, stated precisely enough that I could actually code it; the case or two I'd have to give up if I go with the simpler version; and what the surviving principle says about the case I keep flip-flopping on — the agent finishes its task and tidies the room back to the exact start state, including putting away a mug one of the people had deliberately left out on the counter to use later. Restoring the world seems like the opposite of a side effect, but it's still the agent deciding.
