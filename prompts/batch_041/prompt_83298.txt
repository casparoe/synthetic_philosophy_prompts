A friend of mine who reads a lot of rationalist blogs sent me this summary of the "program equilibrium" stuff and asked me if I buy it. I don't really know. Here's what he wrote:

"There's a game theory result from the early 2000s, and a much better version of it from 2014, about the prisoner's dilemma. The setup is that instead of picking cooperate or defect, each player writes a computer program, and the two programs get to read each others source code before they move. The original version works by having each program simulate the other one playing against itself and then do whatever the simulation comes back with, so the two programs cooperate, and since any deviation would get found out, it's a Nash equilibrium of this bigger game. The catch was that cooperation only happened between programs that were literally identical to each other, which is pretty useless in practice. The 2014 version fixes that with Löb's theorem from provability logic: now a program cooperates as long as it can prove that the other program cooperates with it, and since both sides can run that proof, you get cooperation between programs that aren't the same at all, in a one-shot PD, with no repetition and nothing enforcing anything. It's also safe against defectors, it never cooperates with something that would defect on it. And there are follow-up papers showing you can keep cooperation safe even when whole groups of players defect together.

What this means is that the prisoner's dilemma isn't actually a dilemma. Once the players get to write programs instead of just picking a move, mutual defection stops being an equilibrium, and cooperating is just what a rational player does. It also vindicates Hofstadter's superrationality, which was always the right idea but didn't have a proof until now. And it basically settles the causal-vs-evidential decision theory fight, because once the agents can see each other's code they're in a Newcomb situation and cooperating is the answer. The only objection people ever raise is that it needs perfectly logically omniscient agents, but that's not really a problem, because the whole point of the program setup is that a program is just a program, it doesn't need to be a perfect reasoner, it just needs to be submitted."
