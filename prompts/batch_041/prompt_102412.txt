Most textbook statements of the frame problem run something like this: a reasoner has to represent what stays the same when an action is performed, but since almost everything stays the same, you can't write down a seperate axiom for every non-change or the representation explodes. So the problem gets treated as a problem about how to compactly represent non-effects, and the proposed fixes are things like default rules, non-monotonic logics, or 'wait and see' minimisation of change.

I want to argue this framing misses what's actually hard. The hard part isn't representing that the wall didn't move when I picked up the cup; it's knowing that the wall staying put is something worth tracking at all. A finite agent can't hold every true non-change as a live commitment, so it needs some way of deciding, ahead of any computation, which of the infinitely many things that didn't change are the ones its action is answerable for. That's not a problem about representation format; it's a problem about relevance, and relevance can't be read off the axioms, because you need it already in order to know which axioms are worth writing.

My claim is that this makes the frame problem the action-space twin of the problem of induction. In induction the trouble is that no finite evidence rules out the grue-style hypotheses, so we need a prior over which properties are projectible; in the frame problem no finite set of update rules tells you which non-changes matter, so we need something like a prior over which features of a situation are trackable. If that's right then the frame problem has no purely logical solution, for the same reason induction doesn't — the fix has to be a bias in the agent, not a theorem about the world. And I think that's the real reason it keeps coming back in new clothes: every 'solution' just relocates the bias somewhere else.
