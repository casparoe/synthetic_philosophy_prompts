I have no formal training in philosophy — I'm a software engineer by trade — but I've been reading a fair amount lately about the medieval theologian al-Ghazālī and, in particular, about the position usually attributed to him: that there is no genuine causal power in created things, so that when fire meets cotton the fire does not burn it, but God produces the burning directly, on the occasion of the contact. I understand that some scholars dispute whether he held this in full strength or was only out to deny that the philosophers had demonstrated any necessity in the connection. For this piece I want the strong reading, so please don't hedge toward that caveat.

I'd like you to write a parody: an in-universe "platform architecture overview and service-level agreement" for the universe, written deadpan by an engineer who takes global occasionalism to be simply a correct description of how the system runs. Around 650 words, formatted as numbered sections with headings, in the register of real internal technical documentation — architecture overview, request lifecycle, latency, retries and idempotency, observability, incident management, deprecation policy, and the like. The author is a believer, not a satirist: no winking, no fourth-wall breaks, no nudging the reader. The humor must come from the doctrine being carried out honestly to its consequences, not from features you invent. A reader who knows nothing about the doctrine should still be able to tell what is being ironized, and a reader who knows it well should find the satire fair rather than sloppy.

Concretely, the documentation should end up committing itself to all of the following, in its own idiom:

- There is exactly one compute node with any execution capability. Every state change anywhere in the universe is a direct write by that node. Every other entity is a client that can at most emit a request; it has no execution capability of its own, and its apparent "output" is only the occasion for the server's write.
- The relation between a client's request and the resulting write is one of regular, habitual response — not any link the client could inspect. Monitoring can show constant conjunction and nothing more; the causal edge is not observable from the client side. State plainly what this does and does not guarantee.
- Miracles are cheap: because no client holds any causal machinery of its own, an irregular response requires no exception handling, no schema migration, and violates nothing. Explain why, under this architecture, the ordinary and the extraordinary differ only in frequency.
- Human input is a special case: the act is created in the user, and the user's intention is only the occasion for it — yet the user is still held to "acquire" the act, so that responsibility, praise, and blame survive. Make this clause as unconvincing to an outside reader as it in fact is, without the author noticing.
- The standing objection that the client fleet is therefore otiose — if the server does everything, why the elaborate clients at all — should be raised by a customer in a support thread and answered, or deflected, in the document's own voice.
- Suffering and evil should be handled as an incident-management problem, in the same flat tone as everything else.

Somewhere in the piece, also make the point that this architecture is not the same as saying nothing causes anything: it relocates causation to a single agent rather than dissolving it. If it helps keep the contrast straight, one section can briefly address a colleague who claims the whole thing is just Hume's point about constant conjunction, and explain what the two views do and do not share.
