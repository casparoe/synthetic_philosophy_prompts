Two friends of mine in a game theory reading group got in an arguement last week that I couldn't referee, and I'm genuinely curious who's right about what.

Background, since it's a bit niche: we were looking at "program equilibrium." It's a one-shot prisoner's dilemma, except instead of just picking cooperate or defect, each player writes a small computer program, and each program gets to read the other player's program before anything is actually played out. The classic move is a program that says: cooperate if the other program is identical to me, otherwise defect. If both players submit that program, each reads the other, sees a match, and both cooperate — and (the claim goes) neither can do better by submitting something else. So mutual cooperation is supposed to be an equilibrium even in a one-shot game, with no future and no enforcer.

Ravi: this basically makes the prisoner's dilemma evaporate. The dilemma only bites if you assume my choice is independent of yours. Let players condition on each other's decision procedure and mutual defection stops being forced — cooperating becomes a perfectly stable, rational thing to do. So the "dilemma" was an artifact of a bad assumption about independence.

Sam: no, it's a change of subject, not a solution. The original game is *defined* by there being no channel between the players; you've quietly swapped in a different game where the channel exists. And it's brittle in a way that gives the trick away — the cooperating program only works because it checks whether the other program is *literally the same program*. So if I write a behaviorally identical program but add a pointless extra line, then your program reads mine, sees it isn't identical to itself, and defects, and mine reads yours and defects too. Cooperation here requires the two programs to be textually identical, which isn't a theory of rational cooperation, it's a theory of cloning. On top of that, "defect forever" is *also* an equilibrium, so nothing in the setup actually picks out the cooperative one.

Ravi: that's unfair. Every solution concept needs some idealization — Nash equilibrium needs common knowledge of rationality, and nobody calls that cheating. And the version you're mocking is the crudest one; you can write robust programs that read the other code and handle non-readers sensibly instead of just comparing strings.

Sam: that's my worry in a different outfit. The robust program still keys off reading your *program*, not your *behavior*. Take someone who would genuinely cooperate every single time but whose code is a black box you can't read. The "cooperating" program reads that black box, sees it isn't a copy of itself, and defects — and since the black box cooperates anyway, the cooperating program walks off with the best payoff in the game. So it doesn't reward cooperating, it rewards being a legible copy of the right program. A setup that punishes the actual cooperator and hands the jackpot to its own syntactic twin isn't about cooperation at all, it's about mutual transparency.

Ravi: the same is true of contracts. Contracts reward verifiable commitments, and we don't say contract law is a change of subject. Sam: contracts work because there's an enforcer and a future. Here there's no future, no enforcer, one shot — so the only thing doing any work is the assumption that the other player's code is readable and means what it says. That assumption *is* the entire theory.
