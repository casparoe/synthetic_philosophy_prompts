I work as a software engineer, and I repeatedly find myself in the same argument about machine ethics. One camp wants an explicit moral theory encoded in the machine — rules, constraints, a hierarchy of duties — which the machine then applies. The other camp says morality cannot be fully written down in advance, so the machine should learn from human judgements and generalise. What puzzles me is that both sides seem to accept that no finite rule-set will cover every case, and that a learned system offers no guarantees either; so the factual ground is largely shared, yet the argument has not moved in years. My suspicion is that the real disagreement is not about which method works but about what an ethical machine is: the first camp treats a system that merely conforms to a rule as a lookup table rather than a moral agent, and insists that it be able to give reasons for what it does — when it causes harm, it should be able to say which principle it followed; the second camp thinks that demand is anthropocentric and that being reliably disposed to act well is enough. Is that the right diagnosis, or is the impasse really a hidden factual disagreement, a verbal dispute about the word 'ethics', or two groups answering different questions — one about engineering feasibility, the other about moral status? Please diagnose the disagreement, using what each side actually claims, and say what, if anything, would count as progress. Answer in British English.
