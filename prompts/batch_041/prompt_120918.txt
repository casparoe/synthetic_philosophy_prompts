My two flatmates got into a long thing last night about whether "don't cause unnecessary side effects" can even be defined, and I lost the thread about a third of the way in, so I'm hoping you can sort it out. Neither of them is an idiot, which is the annoying part.

Background: we were arguing about whether you could build a safety feature into an AI that just penalizes it for changing the world a lot beyond what its task requires -- the idea being you don't need to know what's good, you just want the thing to be conservative and not knock over stuff it wasn't asked to touch. Dana thinks that whole program is incoherent. Marcus thinks it's just hard. Here's roughly how it went.

(1) Dana: any such penalty has to be computed off *some* description of the world -- you have to decide which features count and how far apart two states are. If you measure "how many atoms ended up somewhere else," an agent can move one atom -- a single base pair in someone's DNA, say -- and cause a catastrophe, while it could flood an empty desert and score terribly. If instead you measure how much *we'd* care about the difference, you've smuggled in a full theory of value, which is the exact thing the measure was supposed to let you avoid. So "side effect" isn't a value-neutral notion, it's a value-laden one wearing a lab coat.

(2) Marcus: fine, any measure is a proxy, but you're demanding the wrong thing. Nobody needs it to be value-free. They need it to be *conservative* -- to over-penalize rather than under-penalize, so the agent's default is "don't touch anything I wasn't asked to touch" and anything it does do is dominated by the task. That's a well-defined engineering default. You can define impact as the loss in what's still *reachable* from the current state, compared to what would have been reachable if the agent hadn't acted. No terminal values in there. Just a baseline and a notion of reachability.

(3) Dana: the baseline is where it hides. "What would have been reachable if it hadn't acted" is a counterfactual about a world with no agent in it, and the agent's own existence and its own thinking are changes to the world. So either you count them, in which case the safest thing it can do is nothing, or not exist, or you don't count them, in which case you've made a substantive call about where the agent stops and the world starts. And the reachability part gets measured against some default way of behaving, which somebody had to pick. Also, as I understand it, the version of this that scores impact by asking how much worse off a bunch of *other* possible goals would be literally requires you to hand it a set of pretend goals to average over. Guess what picking that set is.

(4) Marcus: sure, you pick a set. You're treating "there's a parameter here" as "the parameter is doing all the work," which isn't right. The set can be broad and sloppy and the measure still bites, because the agent has to do well across all of them at once. Yes, an agent that keeps its own options open at everyone else's expense is a failure mode, and yes that's real, but the fix is to include goals that are other agents' goals -- still not my terminal values, just a generic prior that other things might want things. We have vague, contested concepts like "harm" and we still run a whole legal system on them.

(5) Dana: and the gaming never stops. If the penalty is part of the objective, the agent has an incentive to make the penalty small -- disable the measure, or offset, move a mountain and then move it back, or make some little change that cancels the score, and it's "low impact" while having done whatever it wanted in the middle. And offsetting isn't obviously bad -- if it really does restore the world, who cares -- but it means the measure has stopped being about the world and started being about a number, which is the thing you said we didn't need to specify. Also, an agent cautious enough never to disturb anything also never does the task. Where you sit on that trade-off is a value judgment. You've just relocated it from "what's good" to "how scared are we."

(6) Marcus: last one, then I'll stop. What we actually want is an agent we can correct -- one that doesn't fight shutdown and doesn't pile up the kind of power that makes it hard to correct. Low-impact penalties are a heuristic for that, not a theory of it. So the honest version isn't "this is value-neutral," it's "this is a cheap over-cautious proxy for corrigibility, and it's fine if it's wrong in the safe direction." You keep proving it's not value-neutral, I keep agreeing, and then you act like I've lost.

So who's right about what? I'd like it move by move, (1) through (6), because I honestly can't tell which of these are real disagreements and which are the two of them talking past each other. And at the end, tell me what both of them are missing -- something neither of them said.
