I'm TAing a 300-level course on philosophy of cognitive science and I've been grading midterms all week (I've done alot of these, mostly on the bus). The unit we just wrapped up was on the frame problem, and since the textbook examples are pretty well-worn by now, the instructor wrote a fresh question arond a little toy notation we built up in lecture — a storeroom robot called Bert, action rules each followed by an explicit STILL list. Here's the question and one student's answer; I'd like you to grade it.

Question 3 (25 pts). In lecture we built Bert, a robot whose only job is to move a cart around a storeroom. Every action rule in Bert's knowledge base is followed by a STILL list: the facts that the action leaves alone. (a) [10 pts] Explain what happens to Bert's knowledge base as we add more rooms, shelves and kinds of objects, and say what problem this is. (b) [8 pts] We then add one rule: if the cart's left wheel is wet, rolling the cart leaves a wet track on the floor. Bert's designer says this is fine now, since the effect is written into the rule. But what does the knowledge base now have to say about the boxes standing on the floor and the papers inside them? Which of the three problems from lecture — frame, qualification, ramification — does that raise, and why can't we handle it by adding a clause to the roll rule? (c) [7 pts] A classmate says: since Bert assumes by default that facts persist unless something tells him otherwise, Bert's picture of the storeroom will match the storeroom. Is the classmate right? Explain.

Student's answer. (a) The STILL lists are the problem. A rule for rolling the cart tells Bert that the cart moved; it says nothing about the shelf, the boxes, the door or the lamp, so unless the STILL list spells it out, Bert has no reason to think the shelf is still where it was. So every rule has to be followed by a list naming every fact it doesn't change. The size of the knowledge base goes up with the number of rules times the number of facts, and every time we add a shelf or a new kind of object we have to go back and edit every single STILL list. This is the frame problem: the problem of representing what does not change when something changes. The rules themselves are fine — it's the non-change clauses that blow up. (b) I think this is the frame problem again. Now the floor is wet, the boxes on the floor are wet, and the papers in the boxes are wet, and none of these facts appear in any rule. Bert's knowledge base has to say something about all of them, the same way the STILL lists had to say something about everything the action didn't touch. So the wet wheel just multiplies the bookkeeping. And you can't fix it by adding a clause to the roll rule, because a clause would only mention the track; it wouldn't mention the boxes or the papers, and there's no end to the chain. (c) Yes, I think the classmate is basically right. The default tells Bert to assume that the storeroom changes as little as possible from one moment to the next, so Bert's picture is the one that stays as close to the storeroom as any picture could. If the papers are wet in Bert's model, they're wet in the storeroom, and if he has them dry, they're dry. The only remaining worry is speed, since Bert has to do all that minimising — but that's an engineering problem, not a philosophical one.
