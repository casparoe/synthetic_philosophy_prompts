Explain the conceptual core of program equilibrium. In the standard setup, two players face a one-shot Prisoner's Dilemma and each submits a program; the two programs are then run against each other, and each is permitted to read the other's source code before deciding whether to cooperate or defect. Mutual cooperation is supposed to be an equilibrium of this arrangement even though it is not a Nash equilibrium of the underlying one-shot game. I want the explanation to move past the observation that the players are now playing a different game and to do the actual work: what precisely makes defecting against a cooperator unprofitable once the opponent's source code is observable, what role the programs' ability to condition their choice on each other's code plays, and why the result does not secretly rely on repetition or on a shadow of the future.

Then consider a variant that I believe puts pressure on the idea. Each program can read only a noisy copy of the opponent's source: with small probability, a single bit of that code is flipped before it is read. In addition, there is a small chance that the opponent is a fixed defector whose code responds to nothing. Explain what becomes of the cooperative equilibrium under these conditions: whether cooperation survives, in what sense it survives, and what the answer reveals about whether the original result is a robust fact about rational agents or a knife-edge artifact of perfect mutual readability. Along the way, be precise about the difference between an equilibrium of the program game and a merely self-enforcing outcome, and about what a program must be able to do for its cooperation to be credible.
