Question (three parts, 20 points total):

(i) In lecture I gave you three gaps that get run together alot. The meaning gap: running a program with the right input/output profile isn't by itself understanding, because syntax isn't enough for semantics. The simulation gap: a computational model of a process isn't an instance of that process. The implementation gap: a physical system only counts as implementing a program relative to a description we impose on it, so "this machine is running that program" isn't a fact about the physics. Which of the three is doing the actual work in the Chinese room argument, and which aren't? (8 pts)

(ii) State the systems reply, and say whether the Chinese room argument survives it. (7 pts)

(iii) What does the argument establish about whether machines can think, and what does it not establish? (5 pts)

Student's answer:

The Chinese room is aimed at strong AI, the claim that running the right program is sufficient for understanding. In the setup, a man who knows no Chinese sits in a room with a rulebook and slips fluent Chinese answers back out under the door. He doesn't understand a word of Chinese, and neither does the room. The gap doing the work here is the meaning gap: the man is manipulating symbols purely syntactically, and syntax doesn't add up to semantics no matter how good the input/output profile gets.

But the argument also leans on the simulation gap, and I think this is really the same point. A computer simulating a hurricane doesn't get wet; a computer simulating understanding doesn't understand. The room simulates a Chinese speaker, it isn't one. Anyone who says the machine understands is making the same mistake as someone who says the weather model is raining.

The implementation gap is the premise underneath all of this. Since a physical system only implements a program relative to a description we bring to it, the room doesn't intrinsically contain the program, which is why the man can't get understanding out of it — if the program were really there in the physics, he would be understanding Chinese, which he obviously isn't.

The systems reply says the man doesn't understand, but the system does: understanding is a property of the whole room — man, rulebook, cards, door — not of the man inside. Searle's answer is that the man could memorize the rulebook and the whole database, do all the work in his head, and he still wouldn't understand Chinese; he'd just have memorized a lot. That seems to handle it, since after internalizing the system the man is the system and he still doesn't understand.

What the argument establishes is that a program isn't sufficient for understanding, so no purely software solution gets us thought. What it doesn't establish is that machines can't think; a machine with the right causal powers would think, and whether silicon could have those powers is an empirical question. So the target is the sufficiency claim, not machine thought in general.
