I am a third-year student in a course on algorithmic game theory and multi-agent systems, and I am trying to understand why program equilibrium is treated as a genuine solution to cooperation rather than a computational artifact. As I understand it, a program equilibrium is a Nash equilibrium of a game in which each player submits a program and each program can read the other player's source code. The standard example is the one-shot Prisoner's Dilemma, where two programs that each cooperate if and only if the other program's source code is identical to their own form an equilibrium. But this seems to me to be either uncomputable or vacuous. If a program is to implement any conditional strategy richer than syntactic identity—for example, cooperate if and only if the other program would cooperate against it—then it must decide a semantic property of the other program, which by Rice's theorem no general algorithm can do. So the interesting version of program equilibrium requires hypercomputation. If, instead, we restrict programs to inspecting only syntax, then the equilibrium is a trivial artifact of that restriction and should disappear as soon as players can write more expressive programs. And even in the standard example, the equilibrium seems to depend on the two players being identical; if they have different payoff functions or write in different programming languages, the identical-code program defects and cooperation collapses. So my question is: why is program equilibrium considered a general solution to cooperation rather than a knife-edge result for symmetric, identical agents?
