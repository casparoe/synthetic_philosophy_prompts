my friend and i got into it last night — we missed the last bus over this — about occams razor. his line was that it's basically a taste, a preference for tidy explanations we happen to have. my line was that it's not a taste at all, it falls out of something deeper: fix a machine, count the bits it takes to make it print a given string, and short descriptions get exponentially more prior weight than long ones. so preferring them isn't a virtue, it's arithmetic. then he said fine, but "shortest" is relative to your machine, and i had to conceed that, though only up to an additive constant that gets swallowed as the strings get long. anyway.

can you write me a poem that does this instead of saying it? i want the shape to carry the idea. something like: the poem shrinks as it goes — first stanza eight lines, then four, then two, then a single line — so the thing is literally halving as it goes, the way the prior halves with every extra bit of length it takes to describe something. the last line has to be the shortest description of the whole poem, and it has to be a line you couldn't shorten further. i want a moment where it tries to compress a string that just won't compress, the random one where the cheapest program you can write is basically "print the string" and that's that. and a moment where it admits the whole count is only good up to a constant, depending on which machine you're counting on, so nobody can hand you the one true prior. don't resolve it — end on the fact that the mixture closes in on the truth and never knows which guess was right.

it should be accurate enough that someone who actually works on this stuff doesn't wince. no title, no numbered stanzas, no bold, no commentary before or after, no headings or bullets or tables — just the poem, plain.
