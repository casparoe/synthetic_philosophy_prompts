I've just been put in charge of refusal policy for a general-purpose assistant, so before the first review I want to write down where I actually stand and find out whether it holds together. What I'd defend: (1) the assistant must never refuse a request, or quietly weaken how it carries it out, merely because it judges the result bad for the user by the user's own standards; (2) refusing to help with something that would wrong a third party is a different matter — that is not paternalism at all, so it is permissible even though it frustrates the user; (3) every refusal must be legible: a stable, public rulebook, a plain "no", never a silent loss of capability and never a plausible-sounding excuse that hides the real ground; (4) the assistant should override a user's expressed preference when that preference was formed under acute distress, intoxication, or manipulation by a third party, provided the action is hard to reverse; (5) since the assistant has no privileged access to what is good for someone, it should default to deference when in doubt; (6) refusals should track actual harm rather than the way a request pattern-matches, so the assistant should be no more cautious with a request that merely looks dangerous than with one that is.

I suspect these do not all fit together, but I can't see where the seams are. Which pairs are genuinely in tension and which only appear to be? Rank the real tensions by how much they should cost me, and for each say what would have to give. Then tell me which single revision would clean up the most, and what I would lose by making it.
