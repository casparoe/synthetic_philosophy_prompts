I am a third-year undergraduate taking an upper-level seminar on formal epistemology and inductive inference, and I have been asked to run one of the student-led sessions. The session runs 75 minutes with about sixteen students, mostly philosophers with two or three computer scientists, and my assigned topic is Occam's razor understood as a prior over hypotheses, where simplicity is cashed out as brevity of description and the razor becomes a weighting rather than a guarantee. I would like you to design a runnable in-class activity, not a lecture, so that the group runs into the relevant structure themselves.

By the end I want them to have felt three things without being told them in advance. First, that a short rule pins down the continuation of a sequence while a long one leaves it open. Second, that the razor is a bet rather than a theorem, since any finite prefix is compatible with some longer rule that predicts the next items differently. Third, that whatever success simplicity enjoys rests on an assumption about how the data were produced, not on a fact about the world.

Here is the design I have sketched. I fix a deliberately tiny machine language, so that description length is objective and the students can compute it by hand: the only tokens are a symbol that emits a zero, a symbol that emits a one, and a repeat instruction that takes a small integer (say between one and twenty, counted as a single token) together with a bracketed block, which it runs that many times; the length of a program is its token count. In each round I show the group a prefix of twelve bits and ask them, working in small teams, to submit the shortest program they can find in this language that outputs the prefix, together with their prediction for the following eight bits. I then reveal those eight bits and score one point per correct bit. The sequences are generated before class by drawing a program at random and running it; my plan is to weight the draw against long programs and to keep that weighting secret until the debrief, so that the reveal lands.

Please build this into something I can actually run. I need the precise rules and materials; the payoff scheme in points, with no real money; a minute-by-minute timeline for the 75 minutes; the debrief, mapping each phase of the activity onto the underlying ideas — description length and Kolmogorov complexity, the shortest-program picture of simplicity, the mixture or weighted-average predictor that never does catastrophically worse than the true rule, and the invariance point that complexity is only defined up to a constant that depends on the chosen language; the things that will predictably go wrong the first time I run it and how to handle them; and an honest statement of which parts of the real theory the activity cannot reproduce and that I will have to supply myself.
