I run a small reading group at work for engineers who want to get sharper on decision and game theory, and I'm the one writing the take-home for the last session. The topic is program equilibrium — the thing where two bots play a one-shot prisoner's dilemma, but each bot gets to read the other one's source code before it moves, and somehow they both cooperate and neither wants to bail. I get the vibe of it and I definately don't get the mechanism, so I want to write a question that forces students to actually explain it rather than recite the vibe back.

Here's the setup I'm going to hand them, so you can build the question around it: two players. Each writes a program and submits it to a referee before either one sees the other's. Each program is given, as its input, the full source text of the *other* program. Each program prints C or D. Payoffs: both C, 3 each; both D, 0 each; one defects while the other cooperates, 5 to the defector and -1 to the cooperator. Nobody can edit their program after seeing the other one's.

The thing I want them to grapple with is this. The obvious program — read the other program's source, figure out what it's going to print, print C if it's going to print C — obviously doesn't work, because the other program is doing the same thing to you and you've got a loop with no bottom. But the version that supposedly does work doesn't simulate anything, it *proves* things, and I've been told its Löb's theorem doing the heavy lifting, which means nothing to me. So part of the question has to force them to say what the fix actually is and why the loop stops being a problem once you do it that way.

I also want them to get the equilibrium bookkeeping right, because this is where everyone hand-waves, me included: is 'both cooperate' a Nash equilibrium of the game they're actually playing? Equilibrium over what — the programs, or the moves? And what has to be true of the two programs for any of this to work (access to each other's code, access to their own, same proof system, enough time to actually find the proof), and what happens if one of the players is a black box I can only query and can't read?

One more thing to work in: a colleague insists the whole trick secretly requires a program to be able to quote its own source code, and that in a normal programming language you can't do that without a quine hack. I have no idea if he's right. Build the question so that a good answer has to take a position on it.

Level: smart engineers, no formal logic background past 'I've heard of Gödel', so the model answer has to be followable by them. But I don't want it softened into 'cooperation is possible when there's commitment' — the mechanism is the whole point.

Format, in this order:

- 'The question' — the version I can hand out as-is, around 250 words, with a short restatement of the setup so it stands on its own.
- 'Model answer' — around 700 words, what a strong student should say, written at that level.
- 'Marking scheme' — five must-hit points, marks adding to 20, and under each point one line on the mistake that usually costs students that mark.
- 'A vs B' — three or four sentences naming the move or two that separate an A answer from a B answer.
- 'Corrections' — if I've got any of the mechanism wrong up above, tell me in two or three sentences at the end. I'd rather hear it from you than from the group.
