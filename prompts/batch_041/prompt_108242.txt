I am a software engineer with no formal training in mathematics, game theory, or philosophy, and I design abstract two-player strategy games as a serious hobby. I publish rule sets, and in my design notes I have now twice asserted that a given game is a first-player win on the strength of a strategy-stealing argument that I had not actually checked. I would like a written procedure I can execute before I make any such assertion again, and I would like it to be honest about the cases in which the argument simply does not apply.

The principle I want operationalised, as I understand it, is this. In a two-player game with perfect information, no chance, and symmetric positions, if the game cannot end in a draw and if possessing an additional stone or move is never a disadvantage, then the first player cannot lose: were the second player to have a winning strategy, the first player could play an arbitrary opening move, then adopt the second player's strategy, treating the surplus stone as a harmless extra. The argument establishes only that a win exists; it does not exhibit it, and it says nothing about the length of the game or the difficulty of finding the strategy.

Please produce the procedure, in the following shape.

1. An ordered list of checks to run, each phrased as a question with a pass/fail test I can actually carry out, and for each check a statement of what would count as a sufficient answer and what the check does not establish.
2. Explicit stopping points: the checks after which the procedure returns NO, meaning the strategy-stealing claim is not available to me, and the checks after which it returns YES, meaning the first player cannot lose but nothing more.
3. A list of the steps that are irreducibly judgment calls rather than tests, marked as such, with a note on what each depends on.
4. Where the argument yields more than mere existence — a constructive strategy, a parity result, a bound — say so; where it cannot, say so plainly.

Then run the procedure end to end on three games, showing the outcome of each check:

(a) Hex. The board is a rhombus of hexagonal cells; each player owns two opposite edges of the rhombus; players alternate placing one stone on any empty cell; the first player to form a connected chain of their own stones joining their two edges wins; the game cannot end in a draw.

(b) Cornerstone. On an empty six-by-six grid, players alternate placing one stone of their own colour on any empty cell; the first player to occupy all four cells of some two-by-two block wins; if the grid fills with neither player having done so, the game is a draw.

(c) Passing Stones. A pile of seven stones; players alternate removing one or two stones; whoever removes the last stone loses.

Finally, a short section on limitations: the classes of game on which this procedure will silently misfire, the mistakes I am most likely to make while running it, and the questions it cannot decide that I will have to decide for myself.

Constraints: I have no formal background, so keep every test executable by someone who does not know the standard vocabulary; the whole procedure has to be runnable in about twenty minutes; it should be written so that I can paste it into my design notes; and if the honest answer for one of my three games is that the argument does not apply, I want that said plainly rather than softened.
