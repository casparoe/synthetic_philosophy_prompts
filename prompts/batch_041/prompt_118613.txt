Two guys in my decision-theory reading group got into an arguement last week and I keep getting asked to referee it, but I honestly can't. Here's the setup they both agreed on first. Two players each write a computer program. Both programs get handed to a referee, who runs them at the same time, and — this is the key bit — each program is allowed to look at the other program's source code before it prints cooperate or defect. Payoffs are the usual prisoner's dilemma: both cooperate, 3 each; both defect, 1 each; you defect while the other cooperates, you get 5 and they get 0.

Sam says this solves the prisoner's dilemma. Write the program "cooperate if and only if the other program would cooperate with me, otherwise defect," and neither side can gain by switching: if I defect, the other program sees it and defects too, so I walk away with 1 instead of 3. So mutual cooperation is an equilibrium — being transparent about your code does the job a contract or a repeated game would do. Rational agents who can read each other's source should cooperate.

Ravi says that's not solving the prisoner's dilemma, it's changing it. The original game gave each player two moves and no window into the other's head. The moment you let them condition on each other's source code, you've built a different game that just happens to have a cooperative equilibrium. You might as well say you solved the PD by letting them sign a contract.

Sam shoots back: real agents aren't black boxes. I can predict what you'll do by modeling you, and you know I'm doing that, and so on. The sealed-box version of the PD is the artificial one. If transparency is realistic, program equilibrium is the right model of the situation, and it says cooperate.

Ravi: two problems. One, "cooperate iff the other cooperates" is only one equilibrium — "always defect" is also an equilibrium, because if the other always defects I can't do better than defect. So the theory doesn't single out cooperation; it just adds a cooperative equilibrium next to the defecting one and says nothing about which to pick. Two, the program's reasoning is self-referential: to decide, it has to figure out what the other program does, and that program is figuring out what it does... The usual fix is to let a program prove facts about the other's behavior, and that runs straight into a Gödel/Löb-style wall — a program can't reliably prove what a program that's reasoning about it will do without proving so much that it proves anything at all. So the "solution" is either just another equilibrium, or it doesn't work for the sophisticated agents who'd actually need it.

Please adjudicate this move by move — rate each of the four moves from clearly mistaken to clearly right and justify each rating, then say who's more right overall and what both of them are missing. Give it to me as exactly five numbered points, one or two sentences each, with no intro and no wrap-up: points 1 through 4 for the four moves, point 5 for the overall call.
