Ive been going on about this to anyone who'll listen, so here goes. Look at how we actually build "LLM agents": you write a system prompt telling the model who it is and what it cares about, hand it tools, let it loop -- thought, action, observation, thought again -- and you log the thought field and later read it back as the model's reasons for doing what it did. Then it does something dumb and everyone switches registers instantly: it's not an agent, it's a simulator, nobody's home, it's just running a character. Same person, sometimes the same afternoon. Meanwhile the same pipeline trains the thing out of sycophancy, which only makes sense if it's the kind of thing that can be flattered, and the same system prompt instructs it to say it has no feelings if asked.

So what does the practice actually presuppose? Does handing something persistent goals, a memory and a scratchpad commit you to an agent in there whose goals those are, or can the whole thing be described from the simulator side without loss -- the persona doing all the work and the thought field just being more text? Which parts of what we do strictly require the agency reading, which merely fit it, and where is the practice underdetermined, so that both stories license the exact same engineering? Steelman both, then tell me what would have to change if we took the simulator line seriously and let it drive -- no goals, no memory of having been an agent, no intent in the thought field.
