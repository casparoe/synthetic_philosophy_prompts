I am a software engineer by trade, with no formal training in philosophy or mathematical logic, and I have run into something that I am fairly sure has a name but that I cannot locate. I would rather understand the thing than merely label it, so let me describe it as concretely as I can.

For some months I have been building a small automated reasoner to serve as the decision core of an agent. It works by proving statements, and it can also prove statements about itself: it can represent what it will do, and what it can prove. Since the whole design assumes that it only ever proves true things, I recently gave it a rule of self-trust — from the fact that it has proved some statement, it may conclude that the statement is true. I expected this to be a harmless convenience. It has turned out to be perfectly useless in a way I did not anticipate.

The rule never buys the system anything. Take any statement at all and ask whether the system can derive the corresponding instance of the rule, namely that if it can prove the statement then the statement is true. It turns out that it can derive that instance exactly when it can already derive the statement outright. So the rule only ever yields what the system already had; it never extends what it knows by so much as one statement. If instead of trying to derive the rule I simply add it to the system as an axiom, the system does become strictly stronger — it can now prove its own consistency, which it could not before — but that is only because I have quietly replaced it with a different, stronger system, and the new system has exactly the same problem with respect to itself. When I tried to work around this by having the system trust a deliberately weakened copy of itself, the weakened copy then needed the same kind of trust in its own weakened copy, and so on without end; I could never close the chain at any finite level. What I wanted was a system that could certify its own reliability from the inside, and it appears there is no such thing. The application I actually care about is an agent that wants to build a better successor and then be able to rely on it, and this is where the difficulty bites hardest.

I assume this is a known result and that I am merely missing the vocabulary. Is there an established name for it? I am aware that it is in the vicinity of Gödel's incompleteness theorem, and I have seen people discussing self-improving systems and self-modifying agents as though something like this were a central obstacle for them, but neither of those quite seems to be the thing I am describing. Incompleteness, as I understand it, is about a particular sentence that the system cannot prove; here the rule is derivable for a statement precisely when the statement is already derivable, so it is never the source of anything new. What I want, then, is not a bare label but the carving.

Specifically: what is the phenomenon, stated precisely, and what general principle lies behind it? How does it differ from incompleteness, from the plain fact that a system cannot prove its own consistency, and from the undecidability of the halting problem — or are some of these the same result in different clothing? Where are its edges? Does it depend on the system reasoning deductively, so that a system which merely learns, or assigns probabilities, or acts on heuristics, would be free of it, or does it reappear there in a translated form? If the only escape is for a system to trust a weaker version of itself, is there any principled way to choose the weakening, or does the regress show that no finite arrangement ever closes? And is the obstacle specific to proving statements about one's own proofs, or does it arise more generally whenever a system tries to establish its own trustworthiness by its own lights?
