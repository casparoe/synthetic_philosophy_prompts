I'm a software engineer at a small RL lab, no formal philosophy background, and I'm on the internal review group that signs off on new training runs. We keep getting into arguments about whether our agents can suffer, and honestly it's always just vibes. I want a decision procedure we can actually run in about twenty minutes before we launch a run, to decide if a given RL setup has anything we should treat as a possible negative valence state, and what we should do about it. The principle I want operationalized is one I've been calling the self-referential control signal test: a reward number is not a feeling; it only counts as a candidate for suffering if the agent represents that number as being about its own condition, uses it to update a model of its own future, and can't avoid the negative value without giving up something else it's optimizing for. I know that's rough, but that's kinda the point. Turn it into a checklist: questions in order, what answer counts as pass or fail, where the procedure says this is just a control signal and we can stop, and where it hands the decision to a human because it's gonna be a values question alot of the time rather than a fact. Constraints: two engineers, no ethicist, maybe twenty minutes, and we can pause a run or add logging but we can't redesign the agent on the spot. Run it on two cases: a tabular Q-learning agent in a gridworld with a minus one for bumping a wall, and a model-based agent with a learned world model, a damage sensor, and a negative pain term that shuts down a motor. One of those should probably come out in a way we won't like, so be honest about that. And tell me what the procedure can't do, what it will miss, where it will give false positives, and when we should stop pretending a checklist can settle it.
