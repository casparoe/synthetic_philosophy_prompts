I've been arguing with my flatmate about whether a big trained language model could be a moral patient, and we keep getting stuck one level down: when we say "the computation the system is running," what are we actually picking out, and why should *that* rather than some other description of the same silicon be the thing that matters morally? Also there's the annoyance that any physical system can apparently be seen as implementing any computation if you're clever enough with the state mapping, so "it implements X" starts to look cheap. So I sat down and wrote out eight candidate criteria that people seem to reach for when they attribute a computation to a system, and I want you to rate them. Here they are, roughly as I scribbled them:

(a) Causal-role parity: a computation counts iff it plays the same causal role in the system as the corresponding computation plays in a brain -- same upstream inputs, same downstream effects.
(b) Difference-making: a computation counts iff intervening on it (at the computational level, not the microphysics) would change the system's behaviour; it has to be an actual difference-maker, not a bookkeeping artefact.
(c) Redescription invariance: a computation counts iff it survives a wide class of legitimate coarse-grainings of the system -- if you can only get it under one baroque state mapping, it doesn't count.
(d) Interpreter dependence: a computation counts iff some competent interpreter takes the system to be performing it; attribution is constitutively observer-relative and there's no further fact of the matter.
(e) Proper function: a computation counts iff it's the one the system is *supposed* to perform -- the one it was selected or designed for, and the one it's malfunctioning relative to when it goes wrong.
(f) Predictive compression: a computation counts iff it's the shortest description of the system's input-output dispositions that generalizes to new inputs; real computations are the ones that earn their keep in prediction.
(g) Level-fixing: a computation counts only at one privileged level of description (something like the "what is it doing and why" level rather than the "which transistors flipped" level), and the moral question is settled entirely at that level.
(h) Phenomenal grain: a computation counts iff it's individuated at the grain at which the system's states are phenomenally individuated -- you start from experience and read the computation off from there, not the other way round.

Give each criterion a trust score between 0 and 1 for how much you'd trust it to settle whether some given computation matters morally, sort them into S/A/B/C/D tiers, and say in a sentence or two per item why it lands where it does. Then stress-test your own ranking on three cases and tell me whether it flips anywhere: (1) a big trained LLM doing next-token prediction; (2) a lookup table wired to emit exactly the same outputs as that LLM on every input any human will ever actually feed it; (3) a thermostat. I'm not sure my list is definately the right one, so feel free to say if you think one of the eight is really just a restatement of another -- but I mostly want to know where two criteria pull in opposite directions on the same case, since that's where I keep losing the argument.
