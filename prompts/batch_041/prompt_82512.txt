I am trying to get clear on what program equilibrium actually delivers in a one-shot Prisoner's Dilemma, and I keep finding a gap between two things that both seem to be true.

The setup as I understand it: rather than choosing an action, each player submits a program. Each program is handed the other player's source code as input, and may read it, analyze it, or simulate it; the two outputs then fix the payoffs. A pair of programs is a program equilibrium when neither player could have done better by submitting any other program against the other player's fixed program.

The first thing: on this setup alone, nothing is gained. The two constant-defect programs are still a program equilibrium, so the ability to read your opponent's source does not by itself make cooperation rational. The second thing: there is a construction that does yield cooperation and cannot be taken advantage of. Consider a program that cooperates exactly when it can prove, in some fixed formal system strong enough to reason about its own proofs, that the other program, when run on this one, outputs cooperation, and defects otherwise. Run against a copy of itself, it cooperates; run against a constant-defector, it defects.

What I want is an intuitive explanation of that second construction that identifies what is really doing the work: why cooperation is what emerges when the program meets a copy of itself, why a defector cannot profit against it, and why the fact that mutual defection remains an equilibrium does not make the construction idle.

I would also like the two objections that strike me as most serious answered rather than set aside. The first is that each program's decision is defined by what the other program does when run on it, which includes what it itself does: the decision is circular, no simulation can bottom out, and the proof is being asked to do work that a computation cannot. The second is that the cooperative outcome appears to turn on the consistency of the formal system, which is exactly the sort of thing such a system cannot establish about itself, so the cooperative equilibrium is one we can see from outside while the programs cannot certify it from within.

Finally, I would like the following kept distinct from the explanation above: is the proof-based construction a program equilibrium in the sense of the first paragraph, or has the game quietly been altered?
