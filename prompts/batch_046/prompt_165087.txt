Two engineers, Mara and Leo, are calibrating an anomaly-detection system for an industrial heat-exchange loop. The loop’s behavior is monitored against a baseline recorded when the system included an on-prem PID controller, a fixed sensor array, and a physical cooling valve. Recently the controller was migrated—identical code, same vendor—to a remote cloud instance. The network path now introduces slightly variable latency. The loop begins to oscillate, and the detector flags an anomaly.

Leo argues that the mechanism itself has changed. The mechanism, he says, is constituted by the actual entities and their spatiotemporal relations: the server box, the local network links, the packet-transmission activities with specific delays. Replacing the on-prem server with a remote instance replaces entities and alters relational properties (location, routing, latency profile). By the standard view that a mechanism is an organized set of entities and activities that produce the phenomenon, this is not parameter drift within one mechanism but a different mechanism altogether. Comparing the new oscillating behavior to the old baseline is therefore comparing apples to oranges; the flag is misleading because it treats a new mechanism as if it were the old one malfunctioning.

Mara replies that mechanism identity should be fixed by functional-causal organization, not by token substrate or geography. The controller’s causal role—receiving temperature signals, computing error, emitting valve commands—is preserved exactly. The latency shift is a parameter change within the same causal graph, analogous to a valve wearing down and altering flow dynamics. Anomaly detection tracks mechanism types, not token identities; otherwise every identical sensor swap would require retraining. The baseline describes the expected dynamics of this functional mechanism, so altered dynamics caused by substrate migration are correctly flagged as anomalies within it.

Leo counters that if substrate independence is granted, then replacing the valve with a different brand having the same flow curve, or running the algorithm on quantum hardware, also leaves the mechanism unchanged. That makes mechanism identity too cheap: it collapses into bare functional equivalence, stripping anomaly detection of its anchor. Any substitution that preserves input-output behavior becomes “the same mechanism” even when the physical system is entirely different.

Mara responds that Leo is conflating mechanism-type identity with token-system identity. Detectors do not track every bolt; they track the organized causal structure responsible for the phenomenon. A worn valve and a migrated controller both preserve the mechanism type while altering parameters or peripheral conditions. The flag is meaningful precisely because it detects that this mechanism type is now operating outside its baseline dynamics.

Leo presses further: latency is not an internal parameter of the controller alone but a relational property involving the communication pathway. The entities and activities that actually produce temperature regulation now include remote packet transmission with different temporal properties. By the “entities and activities” criterion Leo invoked, replacing those entities and activities is replacing parts of the mechanism, not tweaking a parameter.

Mara answers that this makes mechanism identity intolerably fragile. If every wire heating slightly and changing resistance, or every router updating its firmware, counts as replacing an entity, then there is no stable mechanism over time—only a sequence of micro-mechanisms. Anomaly detection becomes impossible because there is nothing stable to be anomalous with respect to.

Leo offers a principled distinction: property variation within the same token (a wire heating, a chip aging) is parameter drift; replacement by a token-distinct component performing the same activity in the same organizational relation (a different server in a different location) is mechanism change. He concedes ambiguity at the margins—upgrading a CPU in the same chassis—but insists that remote virtualization clearly crosses the line into replacement.

Mara rejects the line as metaphysically arbitrary. Whether the controller runs on-prem or in the cloud, the causal graph linking temperature, computation, and valve actuation is structurally identical. For the purposes of detection and explanation, that structural identity is what should matter; Leo’s token-identity criterion imports distinctions that do not map onto the causal dependencies the system actually monitors.
