I am a software engineer without formal training in philosophy, but I have been trying to formalize my intuitions about ownership in code and data. I want a consistency check on whether the following commitments actually hang together.

(a) I reject Lockean labor-desert justifications for owning abstract ideas, because ideas are non-rivalrous and using them does not diminish the originator.

(b) I accept the idea-expression distinction: copyright should protect specific expressive implementations (source code as authored text), but not functional algorithms or system architectures.

(c) I think open-source licenses generate a conditional moral obligation: if you build upon shared code, you should return your improvements to the commons, at least for the parts that genuinely extend the shared base.

(d) I believe that a proprietary module which merely imports an open-source library through a stable API is not a derivative work, because dependency is not authorship.

(e) However, I think that training a machine-learning model on open-source repositories and then using it to generate proprietary code violates the reciprocity principle in (c), since the model internalizes collective labor without returning its outputs.

Please audit these for internal tension. Specifically: does (a) undermine the moral basis for both (c) and (e)? Does the distinction I draw in (d) between API dependency and derivation survive whatever principle makes (e) true? Is the conflict between (b) and (e) only apparent, dissolving once we separate expression from statistical pattern extraction? Rank the tensions by severity, identify the single revision that would restore the most consistency, and distinguish genuine contradictions from ones that resolve once the commitments are parsed precisely.
