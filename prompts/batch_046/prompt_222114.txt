I want to argue that the usual “always switch” reasoning collapses not because people mess up the expected-value arithmetic, but because the argument hides a weird assumption about the prior distribution over envelope pairs. In the classic version people act like there’s a uniform distribution over all (x, 2x) pairs, which is already improper and gives you infinite expectation if you’re not careful. I think the real issue is that in any actual decision context—like that auction, or like an algorithm offering you two opaque recommendations—there has to be some bounded support or decay in the prior (maybe exponential), otherwise the decision problem isn’t well-formed to begin with. So the paradox isn’t telling us to switch; it’s telling us that an unbounded uniform prior is incompatible with making a real choice.

I also want to compare this to recommendation systems that present two “mystery” options where one is supposed to be twice as good on some hidden metric. If the system’s generation process has a budget constraint, the switching argument should break down in the same way.
