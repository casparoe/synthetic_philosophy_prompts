I've been trying to wrap my head around Quine's take on moral values for a side project comparing ethical framworks to system architectre, and I think I stumbled into a reductio but I can't see the exit. Here's the argument I sketched in my notes (there's probably a typo in step 3, I wrote "contract" twice).

(1) Quine treats moral judgments as part of our conceptual scheme — not anchored in direct sensory input like "the server is down," but more like the API contract we agreed the service must honor.

(2) In the web-of-belief picture, beliefs near the center — logic, math, and presumably the social norms that keep the system running — are protected: if the periphery conflicts, we revise the periphery.

(3) So if a fairness metric (say, demographic parity) conflicts with raw predictive accuracy, Quine's method says we should reinterpret the accuracy data or tweak the model, not tear up the fairness contract, because the contract is central.

(4) But Quine also insists that no belief is unrevisable, not even logic. So fairness contracts are revisable in principle.

(5) That means they're simultaneously central/protected and fully revisable/unprotected, which looks like a straight contradiction.

(6) The only way out is to deny that moral values belong to the conceptual scheme at all, which forces them into the observational periphery — but then "this model is unfair" becomes just an empirical report like "this server is hot," which feels wrong.

(7) So Quine's view seems to prove that moral values are contradictory, or that they don't exist. I don't buy that, but I also don't want to give up the idea that fairness norms are more like architecture rules than temperature readings.

Tell me which step to reject, then explain why that step looked okay and what the standard positions have to pay to drop it. I want to keep (1) and (3) if I can, since they match how my team actually treats ethics in code reviews, but I'm open to losing either.
