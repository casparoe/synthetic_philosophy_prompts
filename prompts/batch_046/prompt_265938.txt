I'm a software engineer working on alignment infrastructure, with no formal background in philosophy, and I've been trying to formalize my intuitions about whose values an AI system should serve before presenting them to my team. Here is my current position: (1) I hold a version of liberal neutrality—the system should not embed a comprehensive conception of the good life, but should operate like a well-designed API that does not enforce a particular data schema on its clients. (2) When users hold conflicting values, I think we should aggregate preferences through an explicit social-choice mechanism rather than defaulting to the developer's moral intuitions; specifically, I favor a weighted Borda count over pure utility maximization because it respects pluralism and avoids collapsing all goods into a single metric. (3) I believe there should be hard refusal boundaries for requests that cause direct, severe, and irreversible harm to non-consenting parties, and I want to justify these on procedural grounds—analogous to a network protocol dropping malicious packets—rather than as endorsements of any particular moral theory. (4) I think both the aggregation weights and the refusal rules should be fixed at deployment time and not dynamically adapted based on real-time user feedback or shifting market share, because allowing runtime adjustment would let transient majorities colonize the design architecture. (5) I also think the system should actively promote epistemic virtues—calibrated confidence, transparency about uncertainty, and resistance to manipulation—on the grounds that these are instrumental preconditions for any user's own reasoning, not parts of a comprehensive doctrine about how to live.

These commitments feel coherent to me, but I worry I'm helping myself to hidden assumptions. Choosing Borda aggregation seems like it already smuggles in normative commitments about fairness and pluralism, which may conflict with my neutrality claim. Locking weights and refusal rules at deployment also looks like it undermines the idea that the system genuinely serves aggregated user values, since the aggregation is frozen at the moment of release rather than responsive. Meanwhile, the refusal boundaries feel as though they might be value-laden despite my procedural framing, though perhaps that tension dissolves on inspection if minimal harm-prevention rules function more like security protocols than like moral endorsements. I need an audit, not a lecture: rank the tensions between these commitments by severity, identify which pairs are genuinely incompatible versus only apparently so, specify for each real conflict which commitment must give and what the least costly revision would be, and then tell me which single revision would clean up the most conflicts without destroying the overall architecture.
