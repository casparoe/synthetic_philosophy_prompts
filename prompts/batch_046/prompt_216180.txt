Right, I'm a software engineer with no formal philosophy background, but I've been thinking about the logical omniscience problem — the thing where standard epistemic logic says if you know A and A implies B, you automatically know B, which is obviously wrong for real agents or AI.

My position: treat an agent's belief state like a git repo with lazy evaluation. The agent technically 'has' every logical consequence, just like a repo has every branch, but nothing is loaded into working memory until an action actually needs it. So omniscience isn't a modelling error; it's describing the repository, not the running process. The limitation is compute, not logical closure.

What would count against this? I don't want the standard 'people aren't perfect reasoners' reply — I want the actual defeaters ranked from fatal to merely awkward. Does this collapse knowledge into mere potential knowledge? What about moral or practical cases where someone should immediately know a consequence — does lazy evaluation unfairly excuse them? And if belief is version-controlled data, what happens with conflicting beliefs that need merging — do I end up with inconsistencies the git analogy can't resolve?
