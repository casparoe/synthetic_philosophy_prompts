Lewis defines a convention as a regularity in behavior that solves a coordination problem, where everyone conforms because they prefer to do so and they have common knowledge of this. In the open-source case, the error-handling format is a convention because developers all use it and know they all use it. The coordination problem is solved because everyone wants compatibility.

Lewis requires that for something to be a convention, every participant must actually prefer that specific format over every other possible format in absolute terms, not just prefer matching whatever others do. So if a developer secretly likes a different format but uses this one to fit in, that breaks Lewis's conditions — he wouldnt count it as a true convention because the preference isnt absolute.

Also, Lewis's account needs explicit reasoning about mutual expectations: each developer must consciously think I expect that you expect that I will use this format. Without that explicit second-order reasoning, its just habit or imitation, not a Lewisian convention. Thats why conventions in distributed systems are actually weaker than Lewis thought — they run on implicit copy-paste behavior rather than genuine common knowledge of preferences.

Finally, Lewis can accommodate incremental evolution without requiring a discrete agreement event, since a regularity can stabilize gradually as common knowledge builds up over time. The open-source case fits this well: theres no single moment of collective choice, just slowly hardening expectations that everyone relies on.
