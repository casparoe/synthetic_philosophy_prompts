Question: In the context of strategic interaction among computational agents, define program equilibrium and distinguish it from a standard Nash equilibrium in behavioral strategies. Then discuss the effect of symmetric source-code transparency on cooperative outcomes in iterated dilemmas, particularly regarding commitment devices. Finally, consider a scenario in which two autonomous maritime systems must coordinate collision-avoidance maneuvers without real-time communication: does the logic of program equilibrium favor publishing one's navigation algorithm in full?

Student answer: Program equilibrium is essentially a Nash equilibrium where the strategies are computer programs rather than probability distributions over actions. Because programs can be copied and executed, the equilibrium requires that no agent can replace its own program with another that yields a strictly higher payoff given the opponent's code. This is different from behavioral strategies, where agents only randomize over actions.

When source-code transparency is symmetric, cooperation becomes unstable. Each agent can verify that the opponent's program contains a defection trigger, but since inspection is mutual, both can also rewrite their own code to defect first while maintaining a cooperative facade. Therefore, symmetric transparency collapses cooperative outcomes into mutual defection, similar to the one-shot prisoner's dilemma.

Applying this to autonomous vessels, the logic suggests they should not publish their navigation algorithms. Keeping the code private prevents the opponent from exploiting predictable avoidance patterns, which aligns with the program-equilibrium result that opacity protects against first-strike rewrites. Thus, program equilibrium favors secrecy over open-source coordination in high-stakes navigation.
