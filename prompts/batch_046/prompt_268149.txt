As a software engineer with no formal philosophy background, I have been trying to make sense of Fitch's paradox of knowability. My understanding is that it reveals an internal contradiction in the idea that there could be true but as-yet-undiscovered facts: if every truth is in principle knowable, then every truth is in fact already known. I would like to apply this to the design of a formal verification framework for distributed protocols. Specifically, if I construct a logical specification that is complete in the sense that every true safety invariant is provable within it, does Fitch's result imply that the verification engine will necessarily have already derived all such invariants—leaving no meaningful role for runtime monitoring to discover a previously unverified true property? Or have I misapplied the paradox by conflating epistemic knowability with provability inside a formal system?
