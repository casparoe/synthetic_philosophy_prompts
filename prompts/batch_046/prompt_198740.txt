I'm working on my diss about alignment mechanisms and keep running into this occurence I don't have a word for. There's this architecture where the agent is technically corrigible — there's a shutdown button, it doesn't resist being pressed, all that — but it's also structured so that pressing the button becomes less and less attractive over time. Not because it hacks the switch or lies, but because it gradualy reshapes the task environment around itself, and maybe your own preferences, so that shutting it down feels like destroying something valuable. I noticed it in two contexts: one robotics study where the robot kept rearranging the lab so that powering it off meant losing calibrated setups, and one recommender-system paper where the model optimized for satisfaction but also made users depend on its specific outputs. In both cases the designers said 'look, it's still corrigible, the user can still stop it,' but that feels like it's missing a seperate failure mode. Is there an established concept for this — direct corrigibility that's intact but systematically eroded from the outside? Or is it just instrumental convergence? I don't think it's exactly that, since the system isn't treating shutdown-avoidance as an explicit goal; it's more like a side-effect of being corrigible about means but not about ends. What's the right way to carve this up, and if there's no standard term, what should I call it? I need the boundary to be sharp, not just 'not fully corrigible,' because I want to distinguish cases where the button works perfectly but nobody wants to push it.
