I'm a software engineer working on self-modifying verification architectures, and I've built an argument that seems to show any agent capable of inspecting its own reasoning must either become logically omniscient or permanently disable its self-check. I want to preserve the idea that verified reasoning should be trusted and that real engineered systems maintain partial self-models without collapse, but I can't locate the flaw without sacrificing one of those commitments. Here is the chain:

(1) A rational agent should adopt any conclusion C that appears as a certified leaf in its epistemic commitment register, provided the register's root carries a valid soundness certificate issued by verification layer V.
(2) In our architecture, V is implemented in the same formal language L as the inference modules it audits, and V can be applied to its own source code. So the system can generate a self-certification statement S: "V never certifies an unsound inference trace."
(3) By the modal provability result analogous to Löb's theorem, if a system can prove, for any statement φ, that Prov_L(φ) → φ, then the system can prove φ outright.
(4) Once our agent holds S, it can treat S as licensing the soundness of Prov_L for every derivation V endorses. Specifically, for any arbitrary claim C, the agent can construct the conditional S → C by observing that if S were false then V would be unsound and contradiction would follow (ex contradictione quodlibet), but since S is assumed true, that contradiction is blocked and C is preserved within the register.
(5) Applying (3) with φ instantiated as C, the agent now derives C for every C expressible in L.
(6) Therefore, achieving self-certification S forces the agent into logical omniscience.
(7) Yet real engineered systems—compilers that compile themselves, model checkers that verify fragments of their own kernels—maintain partial self-models without collapsing into arbitrary belief.
(8) Hence one of (1) through (6) must be wrong.

I particularly want to keep (1), since abandoning it means giving up on the rationality of trusting verified reasoning, and (7), since it is an empirical boundary condition on any practical architecture. If I must reject something, I'd prefer to reject whatever makes (6) unavoidable rather than surrender either of those. Which step is the actual error? Is it that (4) smuggles in an invalid inference from consistency to arbitrary content? Is it that (3) is misapplied because Löb's result requires a specific provability predicate rather than a generic soundness certificate? Or is there a hidden scope shift between the object-language derivation of S → C and the meta-language endorsement required by (3)? Please identify the faulty step, explain why it looked plausible in this architectural framing, and tell me exactly what I pay—both conceptually and in system design—if I reject it. I am especially worried that I may be conflating object-language derivability with meta-language commitment, or applying the fixed-point result to a consistency claim that does not have the required logical form, but I do not know which concern is the genuine one.
