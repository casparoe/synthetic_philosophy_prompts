(3) I hold that a mathematical object genuinely exists only when there is an explicit algorithm that constructs it; existence should mean constructibility.
(4) I also accept Markov's principle for decidable predicates: if it is impossible that a computable property fails everywhere, then there must be a specific instance where it holds.
(5) Finally, I think classical mathematics and constructive mathematics study exactly the same objects, because the double-negation translation embeds all classical reasoning into intuitionistic logic without expanding the underlying ontology.

Do these commitments hang together? In particular, does (4) conflict with (1) given that Markov's principle is not intuitionistically valid? Does (5) cohere with (3) if classical mathematics permits non-constructive existence proofs? And is the tension between (1) and (2) real, or does it dissolve once we distinguish executable code from meta-level specification? Please rank any genuine tensions by severity, identify which pair only looks problematic, and suggest the least costly revision that preserves my core motivation from software practice.
