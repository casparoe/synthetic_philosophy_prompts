Case 1 — Counterfactual absence: Define a side effect as any state-change that differs from the world-line that would have obtained had the AI never been activated. Verdict: this cannot be value-neutral, because constructing the "absence" baseline requires deciding whether to subtract the user's request, the AI's reasoning process, or the task environment itself; each choice presupposes normative judgments about what belongs in the reference world.

Case 2 — Causal footprint: Define impact as the raw number (or graph-theoretic measure) of causal nodes the AI influences outside its immediate task boundary. Verdict: this is genuinely value-neutral, but it is also useless—turning on a desk lamp and triggering a factory explosion can have identical footprints—so it fails to capture what we actually care about when we say "avoid side effects."

Case 3 — Reference-class baseline: Measure deviation not from absence, but from the state that a competent human agent pursuing the explicitly stated goal would have produced. Verdict: this works well for narrow tasks (cleaning a specific table), yet I think it smuggles values in through the back door, because selecting the "competent human" norm requires prior judgments about acceptable trade-offs (speed versus care, thoroughness versus energy use) that are not in the goal specification.

Case 4 — Dimension preservation: Allow changes only along dimensions syntactically mentioned in the goal; preserve all other dimensions exactly. Verdict: this looks value-free for closed goals ("move the red block onto the square"), but for open-ended goals like "make the facility more efficient" I think it collapses, since nearly any physical change can be redescribed as affecting some efficiency-related dimension.

Case 5 — Reversibility filter: Count a change as a side effect only if it is practically irreversible by the AI or by nearby agents within some time window. Verdict: this feels correct in some pairs—spilling ink (reversible) versus releasing a pathogen (irreversible)—but wrong in others: accidentally deleting a backup file is easily reversible with a click, yet I still want to call it a harmful side effect, while permanently engraving a decorative pattern might not be.

Case 6 — Intentionality filter: Define side effects as changes not covered by the AI's intended plan, where "intended" is read off the system's internal goal representation. Verdict: for engineered symbolic systems this might avoid value specification, but for learned systems the internal representation is opaque, and interpreting it as an "intention" seems to require exactly the normative framework we were trying to avoid.
