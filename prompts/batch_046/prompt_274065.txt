I've been noticing a recurring structural pattern in discussions about how a rational system should relate to its own future conclusions. The setup is usually this: someone proposes a meta-rule—call it the Trust Rule—stating that if the system's core reasoning module produces a result under conditions of adequate information, consistency, and time, then the system ought to adopt that result. At first this sounds like a sensible safeguard against stubbornness. But then a specific difficulty appears. To apply the Trust Rule to itself, the system needs to determine whether the Trust Rule was itself produced by the core module under adequate conditions. That determination, however, is itself an output of the core module (or of a meta-module that inherits the same architecture). So the system is attempting to use the very mechanism whose reliability is in question in order to certify that mechanism.

I've seen this arise in different practical guises. One involves predictive calibration: a system maintains a confidence score for its own forecasts and updates that score based on observed outcomes. But interpreting those outcomes requires applying the very forecasting framework being calibrated; if the framework is systematically biased, the interpretation of outcomes is distorted, which distorts the update to the confidence score, which then feeds back into future forecasts. The loop is not broken by external feedback because the feedback is processed through the system being evaluated. Another case involves consistency verification: a system tries to check that its belief set contains no contradictions, yet the verification algorithm is implemented by the same reasoning apparatus that generated the beliefs, so trusting the check requires already trusting the apparatus.

The pattern feels distinct from ordinary circular reasoning. In a typical circular argument, premise A assumes conclusion B and B assumes A, and one can often break the circle by finding an independent entry point. Here the circularity is vertical: every attempt to step outside and evaluate the system from above lands back inside, because the evaluation tool is part of the system. It also differs from the liar paradox, since there is no direct contradiction—only a failure to bootstrap self-certification without an arbitrary exemption or an ungrounded axiom.

Is there an established concept or precise literature for this specific vertical circularity in self-evaluation? I am not asking about general skepticism, the problem of the criterion, or standard bootstrapping failures; I mean the structural feature where a system's meta-evaluative procedure is necessarily implemented by the system being evaluated, particularly in formal discussions of reflection principles and self-trusting agents. If there is a named obstacle—especially one that arises when an agent tries to adopt a principle linking provability to truth—what is it, and how exactly does it map onto the calibration-loop and consistency-check cases I described? If there is no single established term, can you name and define the phenomenon precisely, including what distinguishes it from induction-related circularities and from cases where evaluation succeeds because it is carried out by a physically or architecturally separate subsystem? I want the conceptual carving, not a bare label: what the phenomenon is, what it is not, and where its boundaries lie—for instance, whether it vanishes when the meta-evaluator shares no reasoning architecture with the object-level system, or whether some shared dependency is enough to regenerate it. I am not asking for citations, bibliographies, or reading lists—just the identification and the boundary conditions.
