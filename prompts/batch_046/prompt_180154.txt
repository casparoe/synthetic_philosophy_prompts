I've been working through Skolem's paradox on my own and tried to push it into a concrete case, but now I have an argument that seems to destroy the coherence of "uncountable" altogether. Here are the steps:

(1) If a first-order theory describing infinite sets is consistent, then the Löwenheim-Skolem result guarantees it has a model containing only countably many objects.

(2) Inside such a model there is an object that the model treats as the power set of the natural numbers, and the model includes a relation it interprets as "no bijection exists between this object and the natural numbers."

(3) Because the whole model is countable, an observer outside can list every member of that power-set object with a natural number.

(4) Now suppose I actually build a computer program that constructs and runs this exact model. The machine assigns each member of the power-set object to a distinct memory address, so within the running program there is a literal, inspectable pairing of each member with a number.

(5) Therefore, inside the running program itself, there is a concrete bijection between the natural numbers and the object the model calls uncountable.

(6) But that directly contradicts the model's own internal claim that no such pairing exists.

(7) So either the program fails to represent the model (which seems false, since every specified relation is implemented), or the model asserts something that is false inside the very system meant to realize it.

(8) If that holds, then set theory describes objects that cannot be consistently realized, and the notion of an uncountable set is incoherent.

This proves far more than I intended, since mathematicians evidently use these structures without contradiction. I especially want to keep (2) — that the model genuinely asserts the absence of a bijection — and (4) — that a concrete implementation produces an internal listing. Which step should I reject, and what does rejecting it cost? Is the error that the computer's memory-address pairing is not a relation available inside the model, or is there a deeper mistake in treating the running program as identical to the model it represents?
