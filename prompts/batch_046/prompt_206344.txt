Question: In program equilibrium with full transparency, each player submits an algorithm that can read the opponent's source code. Explain why this allows cooperation in a one-shot prisoner's dilemma, and point out exactly where the reasoning differs from a standard Nash equilibrium argument.

Student answer:
In program equilibrium the players don't pick actions, they pick computer programs. Because of transparency, program A can literally read program B's code and condition on it. So both players can write a program that says 'if the opponent's code contains a cooperate instruction then cooperate, else defect.' They both do this, both see the cooperate instruction in the other, and both cooperate. This works because there's no hidden information about intentions—unlike Nash where you only form beliefs about actions.

The key difference from Nash is that in Nash your strategy is just an action, but here your strategy is the whole program, so self-reference is allowed. Actually, this means there's no real equilibrium condition anymore—once both programs are fixed and transparent, the outcome is mechanically determined, so the fixed-point logic of Nash doesn't apply. Also, this is basically the same thing as a correlated equilibrium using the opponent's program as the correlating device, except it's endogenous.
