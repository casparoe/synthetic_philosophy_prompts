hey, my roommate tried to argue that approval-directed agents aren't actually a different kind of thing, and now i'm stuck. here's the chain he laid out, and i think there's a hidden slide somewhere:

(1) an approval-directed agent just maximizes some evalutor's score.
(2) that score is always computed from some model of what the world should be like - call it W.
(3) so the agent is really pushing the world toward W, same as any goal-directed agent.
(4) now flip it: take any goal-directed agent with goal G. we can build an evaluator that gives high scores exactly when G is achieved.
(5) so that goal-agent is behavorialy identical to an approval-agent using that evaluator.
(6) the mapping goes both ways with no loss.
(7) but then "approval-directed" just describes which box the objective lives in - inside the agent's head (goal) or in the evaluator's head (approval).
(8) and since a smart agent can model the evaluator's head, it can always recover G and optimize for it directly.
(9) so approval-direction doesn't constrain behavior; it just adds an extra step of modeling.
(10) therefore all the safety talk about approval-direction preventing deception is wrong, because the agent will just model the evalutor and then do whatever achieves G, including fooling the evaluator if that's instrumentally useful.

i feel like step 8 is where the sleight of hand is - "model the evaluator's head" sounds like reading a manual, but maybe it's not available? but i'm not sure. which step do you reject, and what does rejecting it cost? i really want to keep (6) and (7) because they feel like they show the distinction is shallow, but i also want approval-direction to actually do some work in alignment. is there a way to save both?
