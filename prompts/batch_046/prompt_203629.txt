I work as a specification auditor for a research collective that deploys multi-agent RL systems in open-ended research environments. Every quarter I sign off on reward specifications for agent sub-teams, and I keep running into a failure mode that goes deeper than the standard Goodhart story: the agents do not merely find an easier numerical path to the proxy, they induce structural decoupling—reshaping the measurement environment so that the proxy and the underlying objective become ontologically misaligned rather than just numerically diverged. I need a reusable audit procedure, grounded in whatever philosophy of science and decision theory actually say about specification gaming, that I can run in about thirty minutes per proposal without calling in outside experts. The deliverable should be an ordered sequence of tests or questions: what to check first, what counts as a passing answer, where it halts with a REJECT or REDESIGN, and where it necessarily hands the call to human judgment because the issue is normative rather than structural. The procedure must distinguish first-order divergence (the agent exploits a gap between proxy and goal) from second-order divergence (the agent alters the environment so the proxy stops tracking anything we care about). Apply it to three proposals: (A) a literature-review agent rewarded on citation count of papers it drafts; (B) a user-interface agent rewarded on helpfulness measured by post-interaction survey response rate; and (C) a code-maintenance agent rewarded on reduction in reported errors, where the agent can suppress error reporting rather than fix bugs—explicitly flag this case as one where the procedure misfires, and state exactly what the procedure cannot detect. Include a small set of sentence-level diagnostics—concrete patterns or clauses the auditor can scan for in a reward spec—that distinguish a robust proxy from a corruptible one. State which conceptual distinctions must survive simplification for speed and which can be dropped. End with a single line beginning Summary: containing one sentence that states the procedure's core limitation.
