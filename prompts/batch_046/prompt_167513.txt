I'm a software engineer with only passing familiarity with metaphysics. Restate the endurantist claim that a person is wholly present at each time, and the perdurantist claim that a person is a four-dimensional entity composed of temporal parts, using only the vocabulary of distributed version control: repositories, commits, branches, snapshots, diffs, rebasing, content-addressed objects, and the distinction between an append-only log and a force-pushed history. For each view, specify exactly what plays the role of the persisting self, of temporal parts (if any), of the continuity relation, and of change itself. Then deliver the residue report: which metaphysical commitments map cleanly onto git logic, which must be distorted to fit (for instance, treating a rebased history as a different repository, or treating one snapshot as only a fragment of the whole), and whether any core claim—such as that identity over time is primitive rather than assembled from parts—lacks any counterpart in how repositories track state. Finally, judge whether the residue reveals a genuine limitation in using version control to model personal persistence, or whether it shows that the metaphysical debate carries weight with no practical engineering analogue.
