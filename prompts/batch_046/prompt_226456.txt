I'm a software engineer with no background in formal philosophy. My conceptual toolkit is built around statically-typed languages, compilation and linking, runtime dispatch, interface contracts, concrete implementations, dependency graphs, and distributed service architectures.

Please restate the problem of universals — specifically the three positions usually called realism, nominalism, and conceptualism — using only the vocabulary and conceptual machinery of software engineering and programming-language semantics. Do not treat programming as a loose metaphor; articulate each philosophical position as if it were genuinely a claim about what types, classes, interfaces, build artifacts, instances, and linked binaries are, and about how they exist or fail to exist independently of particular running processes.

Then deliver the residue report. For each of the three positions, specify:
- which parts translate cleanly into software concepts,
- which parts can only be preserved by distorting either the philosophical claim or the engineering concept,
- and which parts have no counterpart whatsoever in how software is built, deployed, and executed.

Finally, address this architectural fact: in a distributed system, a single interface can be satisfied by implementations residing in unrelated repositories, compiled separately, and connected only at runtime through service discovery, with no shared source code or build-time dependency. Ask whether this fact maps cleanly onto any of the three philosophical positions, whether it forces a distortion of all three, or whether it reveals a dimension that none of them can express.

Conclude by assessing whether the residue — the parts that do not survive translation — points to a real limitation in the engineering vocabulary, or whether it suggests that some portion of the original philosophical debate is less substantive than its traditional formulation implies.
