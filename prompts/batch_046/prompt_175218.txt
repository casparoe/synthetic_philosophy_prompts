ok so i was arguing with my roommate about revealed preference and whether utility is just bookkeeping. he laid out this chain and i can't find the hole:

(1) Revealed preference says that if you choose A over B, that's all there is to "preferring A" — no hidden mental state.
(2) So we can define U(A) > U(B) purely from observed choice behavior, even if the agent denies it.
(3) Now apply this not just to goods but to choice-architechtures: sometimes people pick the menu that lists A first, sometimes the menu that lists B first. By (1), picking menu-M reveals a preference for M.
(4) But picking menu-M is just another choice, so it needs its own revealed-preference analysis. That means there's a meta-utility U'(M) > U'(N).
(5) And the choice of menu-M was made inside some framing context C, so C itself is an object of revealed preference, giving U''(C).
(6) This repeats: every choice happens in a context, and every context can be chosen, so we get an infinate stack U, U', U'', ...
(7) But real agents have finte brains, so they can't instantiate an infinate hierarchy of revealed preferences.
(8) Therefore revealed preference can't apply to real people unless we arbitrarily stop the regress at some level.
(9) If we do stop it arbitrarily, then "utility is just bookkeeping" only works for that level and fails for the others — which means there's a real, non-bookkeeping difference between object-level and meta-level preferences.

i think the slip is somewhere between (3) and (5) — maybe treating the framing context as a choice object when it's actually just a parameter? — but i'm not sure what giving that up costs. does it save revealed preference, or does it just push the problem up one level? and if utility is only bookkeeping at the base level, is that enough to defend the anti-mental-state view?
