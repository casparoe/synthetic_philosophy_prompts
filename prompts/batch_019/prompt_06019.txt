I've been teaching a graduate seminar this term on formal theories of cooperation -- Newcomb's problem, folk theorems, that whole cluster -- and the last couple sessions were on program equilibrium: Tennenholtz's old idea that if two agents can commit to programs that read each others source code before acting, cooperation in a one-shot Prisoner's Dilemma can be an honest-to-god Nash equilibrium, no repeated play or reputation needed. What really got the class going was the later refinement where, instead of a program just checking "is your code identical to mine," it searches for a formal proof of the other program's behavior -- the FairBot-style agents that cooperate iff they can prove the other program cooperates with them, and that manage to actually pull off mutual cooperation via a clever use of Löb's theorem (there's a fancier cousin called PrudentBot that also won't get taken advantage of by unconditional cooperators, but that's not really the crux). About half the room thought this was a genuinely deep result about rational cooperation; the other half thought it was an elaborate diagonalization trick that just relocates the equilibrium-selection problem one level up, since mutual unconditional defection is every bit as much a program equilibrium as mutual "fair" cooperation is, and nothing in the math tells you why a real agent should run the fancy proof-searching program instead of the dumb defecting one.

I'd like to see the strongest version of that disagreement actually played out, partly because I want to steal it for a class handout. Could you write a dialogue between two people co-writing a paper -- something about whether AI systems that can inspect each other's source code should be designed with these dispositions -- who get stuck arguing about this the night before the deadline and can't move forward on the draft until they sort it out? One of them thinks the Löbian construction is a real, rigorous vindication of something like Hofstadter's superrationality: an actual dissolution of the one-shot trust problem, not a rebranding of it. The other thinks "cooperation" is doing a lot of unearned work here, that the whole result only goes through given a shared proof system, a specific bound on proof length, and common knowledge of source code, and that once you're honest about everything being assumed there's nothing left that should surprise a hardened game theorist. I don't want either of them scoring easy points -- I want real responses to each other's specific objections, some circling back, maybe a small concession or two -- and by the end I'd like it to be obvious exactly where their disagreement actually bites, rather than just that it exists. Doesn't have to be long, but give me a genuine back-and-forth rather than two speeches stapled together.
