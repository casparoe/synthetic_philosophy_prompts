I have been reading about the frame problem in classical AI, and I am struggling to see why philosophers still treat it as a deep, unresolved puzzle rather than a solved engineering problem. As I understand it, the difficulty is how a reasoning system is supposed to know which facts remain unchanged after it performs an action, without explicitly checking every single one. But this is exactly what ordinary software architecture handles as a matter of course: a database transaction touches only the rows an action actually modifies and leaves everything else untouched by default, an ECS game engine only touches the specific components a given system is designed to operate on, and a React re-render diffs the virtual DOM so that only the nodes that actually changed get updated. In every case, "no change" is simply the default state, so there is nothing left to check. Given how routine this pattern is in production systems, what exactly do AI researchers and philosophers think is still missing?
