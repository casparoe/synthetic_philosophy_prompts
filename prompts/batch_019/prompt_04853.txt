QUESTION: The St. Petersburg game pays you $2^n if a fair coin lands heads for the first time on toss n. Its expected value is well-defined, it's just infinite. The "Pasadena game" is a variant where the payout if the coin first lands heads on toss n is (-1)^(n+1) · 2^n/n instead — so as n grows the payoffs alternate between big windfalls and big debts.
(a) Explain why decision theorists say the Pasadena game's expected value is "undefined," rather than just adding up 1 - 1/2 + 1/3 - 1/4 + ... = ln(2) ≈ 0.69 and calling that the answer.
(b) The usual fix for the St. Petersburg paradox is to point out that nobody's utility for money is actually unbounded/linear — once you use a bounded utility function the paradox disappears. Does switching to a bounded utility function also rescue the Pasadena game the same way? Explain.

HER ANSWER:

(a) The reason is that 1 - 1/2 + 1/3 - 1/4 + ... only converges conditionally, not absolutely — if you replace every term with its absolute value you get the harmonic series 1 + 1/2 + 1/3 + ..., which diverges. Whenever a series is conditionally convergent like that, there's a theorem (Riemann's) saying you can rearrange the terms to make it add up to literally any number you want, or diverge to +infinity or -infinity, or never settle down at all. Since nothing about the game itself tells you to sum the payoffs in the order n=1, then n=2, then n=3, etc rather than in some other order, there's no fact of the matter about what "the" sum is. Compare this to St. Petersburg, where every payoff is positive, so no matter what order you add in you either get the same finite number or +infinity — order never matters there. So Pasadena isn't just a bigger St. Petersburg, it's a genuinely different, worse kind of problem. That said, I don't think it's crazy to treat ln(2) as at least a reasonable ballpark for what the game is "worth," since that's the number you get without doing anything cherry-picked to the order — you're just adding the terms in the order the tosses would naturally occur.

(b) Sort of, but not really. The St. Petersburg fix works because switching from money to log(money) turns 2^n into n·log(2), which grows slowly enough for the sum to converge. But that exact trick can't work for Pasadena, becuase half the payoffs are negative, and log of a negative number isn't defined. So the standard move doesn't even apply here. That means bounded utility functions don't rescue Pasadena the way they rescue St. Petersburg — you'd have to fix the game some other way, like putting an explicit cap on the payoffs themselves, rather than just reinterpreting money in terms of utility.
