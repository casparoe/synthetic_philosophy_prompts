Over the last few months I've gotten interested in the game theory surrounding autonomous agents that negotiate with one another, and that's how I came across the idea of "program equilibrium," which I believe traces back to a paper by Moshe Tennenholtz. The setup replaces the usual move in something like a one-shot Prisoner's Dilemma with a submitted program: each player hands in a piece of code that receives the other player's code as input and outputs a move, so a strategy can condition on what the opponent actually is rather than on some fixed guess about opponents in general. What really hooked me was a follow-up result I found through some AI-safety-adjacent reading, where a bot (I want to say it's literally called "FairBot") cooperates with another program only if it can produce a formal proof that the other program cooperates with it, and thanks to a clever bit of self-reference via Löb's theorem, two copies of this bot each end up proving that the other cooperates and thereby actually cooperate, without either one ever having to simulate or run the other as a subroutine.

I brought this up over drinks with two friends from an informal reading group a few of us run at work, and it split them into two camps that still haven't reconciled. One friend, who spends a lot of her free time on decision theory, thinks the Löbian result is a genuinely new way of grounding cooperation — resting not on repetition, reputation, or an external enforcer, but on mutual transparency and formal reasoning about each other's source code — and thinks this will matter enormously once AI systems are routinely inspecting one another's code before interacting. The other, whose background is more classical game theory from economics, thinks the whole construction is a kind of sleight of hand: it only works because it quietly restricts attention to a narrow menu of provability-based bots built to recognize each other, sidestepping rather than solving the halting-problem-shaped obstacle to simulating an arbitrary opponent, and that it just relocates the original coordination problem to a prior question of which bot everyone happens to be running. He's unconvinced any of it survives contact with genuine uncertainty about who, or what, you're actually facing.

I'd like it to go deep enough into the mechanics to actually earn its conclusions — touching on the infinite-regress problem that naive mutual simulation runs into, how routing everything through a proof system is supposed to escape that regress, and the objection that these bots reliably cooperate only with close relatives of themselves rather than with arbitrary rational agents.
