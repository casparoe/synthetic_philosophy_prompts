Here's the draft:

The classic objection to computationalism (the idea that having a mind just is a matter of implementing the right computation) is that "implementation" is too cheap a relation to carry that kind of weight. Putnam and Searle both pointed out that if all it takes for a physical system to implement a computation is that there exists some mapping from the system's physical states onto the computation's formal states, then you can gerrymander such a mapping onto almost any sufficiently complicated system after the fact — a wall, a rock, the swirling of water in a stream. Pick weird enough states of the rock and you can supposedly line them up with the state-transition table of any finite automaton you like, including, in principle, one that's "running" a mind. If that's right, computationalism trivializes: everything is implementing every mind all the time, which is absurd, so implementing-the-right-computation can't be what makes something a mind.

Aaronson's move (at least as I understood it) is that the trivialization only works if you don't charge for the mapping itself. If you require the decoding function from physical microstates to computational states to (a) be efficiently computable, and (b) stay correct under counterfactual perturbation — i.e. if you'd nudged the rock a bit, the decoded computational state has to change the way the target computation says it should — then finding such a mapping for a rock, with respect to a nontrivial target computation, costs about as much computation as just running the target computation directly. There's no shortcut. Real computers aren't special because of some magic ingredient, they're special because engineers already paid that cost upfront, wiring things up so the encode/decode step is cheap (voltage above 3V = 1, full stop). So the "everything implements everything" argument is quietly assuming a free mapping, and once you price the mapping in complexity terms, rocks and waterfalls stop qualifying while your laptop still does. (Honestly at this point I'd read like three overlapping things back to back and I'm not 100% sure which part is Aaronson's own contribution versus stuff he's building on from Putnam's critics, so feel free to correct the attribution too.)

Here's where I want to take this: a lot of the "it's just a stochastic parrot, fancy autocomplete" dismissals of LLMs are, structurally, Ned Block's old Blockhead argument — a big enough lookup table could ace the Turing test with zero real cognition going on, so passing language tests proves nothing. But the actual weight file of, say, a 70B model is laughably small next to the lookup table you'd need to store canned replies to every plausible conversation prefix — we're talking many, many orders of magnitude off. So whatever's happening in there, it can't be brute-force table lookup. By the same complexity-accounting move Aaronson uses against the rock, the model has to be doing something efficient and non-trivial with those parameters — some real compression of regularities in language and the world. Which means the "it's just interpolating, don't take it seriously" crowd are making the same mistake as the rock people: treating a cheap dismissal as free when it actually costs something.

I'm definately not trying to sneak in a claim that this proves the model understands anything or is conscious. I just want to know whether the narrower claim — that "it's just a lookup table in disguise" fails as an objection to LLMs for basically the same reason it fails as an objection to computationalism in general — actually holds up, or whether I've mangled the argument somewhere along the way. Anyway, tear it apart wherever it needs tearing.
