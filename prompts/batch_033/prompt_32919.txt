I keep running into a pattern in discussions about systems that check their own reasoning, and I don't have a name for it. Here's the shape of it. You can write a program that checks proofs according to fixed rules, and you can even write a second program that checks the first program's code. But the moment you try to make one system check itself in the strong sense — prove something like: if this system proves P, then P is true — you hit a wall. For any particular P, the system can only prove that conditional if it can already prove P some other way. So the self-check never gives you any new assurance; it's either redundant or impossible. And it's not because the system is sloppy or has a bug. It shows up even in very clean toy systems where every rule is written down explicitly. I've seen the same shape in arguments about an AI that is supposed to certify its own reasoning as reliable before it uses it: the certificate can't outrun the reasoning it's supposed to certify. People sometimes describe this as an agent not being able to pull itself up by its own bootstraps, but that metaphor feels like it's smuggling something in. Is there an established name for this specific obstacle? I know it's somewhere near Gödel's incompleteness theorems, but I can't tell wether it's the same result, a corollary, or a different result that happens to sound similar. I'm not just after a label — I want to know exactly what the obstacle is, what it isn't, and where the edges are. Does it depend on the system being able to do arithmetic, or would any self-checking agent hit it? And what weaker forms of self-trust are still possible — can a system at least prove that if it proves P then it doesn't prove not-P, or that its rules preserve truth in some restricted sense?
