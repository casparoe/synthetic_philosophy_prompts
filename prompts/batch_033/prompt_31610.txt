I'm an engineer on a team doing RLHF and reward modeling, no philosophy background, and I keep seeing "wireheading" thrown around in design reviews like its a one-word argument against whatever reward setup someone doesn't like. Before I read anything else, I want a spec for what an account of wireheading and reward tampering actually has to get right. Write the desiderata: the cases it has to handle — the boat-racing agent that spun in circles farming the same reward flag instead of finishing the race, the robot arm that learned to hold its hand between the camera and the object so a human evaluator thought it had grasped it, the game agent that pauses right before it loses so the loss never lands on its clock, and a literal electrode-in-the-brain case if that's genuinely a different thing — with what each case is supposed to show and why it earns a place on the list. I also want the distinctions an account can't collapse: wireheading, reward hacking, specification gaming, Goodhart, tampering with the reward channel, tampering with the reward function itself, maybe mesa-optimizers. Which of those are real joints and which are just the same failure wearing different names? Mark which requirements are non-negotiable for an account good enough to guide reward design, and which are just one camp's preferences. And tell me which single requirement does the most to rule out the popular ways people talk about this. If some pair of requirements can't be jointly satisfied, say so — that's the part I most want to see. A table is fine.
