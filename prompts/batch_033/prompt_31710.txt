I am a software engineer with no formal training in philosophy, and I would like you to act as an expert in the philosophy of law and formal systems. Please think carefully about the problem below, beginning by brainstorming its underlying conceptual structure before giving your recommendations.

I am building the governance layer for a professional association's online platform. The association's bylaws are represented in a rules engine as structured rules, and members can propose and vote on amendments to the rule set. The amendment procedure is itself one of the rules in the set, so members can propose changes to any rule, including the rule that specifies how rules are changed. There is no separate constitutional document outside the system; the platform's stored rule set is meant to be authoritative.

I have hit a set of edge cases that feel like more than ordinary engineering edge cases:

1. If a proposal changes the amendment threshold from two-thirds to three-fifths, which threshold governs the vote on that very proposal?
2. If a proposal marks itself, or another rule, as unamendable, should the engine enforce that? What should happen if a later proposal first amends the amendment rule to remove that protection?
3. How should the engine handle two amendments passed in the same voting cycle that conflict with each other, or an amendment that repeals the very rule under which it was just passed?
4. Is there a principled reason to keep one meta-rule outside the mutable rule set, or can a fully self-contained system handle these cases coherently?

I keep having the feeling that no matter how I resolve one case, the same difficulty reappears one level up.

Please give me a principled analysis. Are these edge cases symptoms of a design flaw, or do they reflect something inherent to any rule system that can modify its own rules? What should I actually implement, and what should I tell the association's leadership about the limits of any such system?

Use American English throughout.
