I'm a CS PhD student, I work on RL, and I sit on my department's safe-experimentation committee — the group that has to sign off on any training run that will eventually touch real infrastructure or use a learned reward model. We've got a proposal on Thursday that's split the comittee right down the middle, and I've been asked to draft the short decision memo we'll vote on.

The proposal comes from a postdoc in the campus energy group. Part one is boring: train an RL agent to control the university's battery storage system, shifting charge/discharge to cut electricity costs, with the reward supplied by a learned model that predicts cost savings. Part two is the controversial bit. Before anything goes live, the postdoc wants to run a "tampering probe" in a sandboxed copy of the environment: the agent gets one extra action that directly writes a high value into its reward channel, without it having to do anything to the battery. The goal is to measure whether the agent wireheads — whether it learns to grab the free reward instead of actually optimizing the battery — and how that depends on things like regularization, reward-model capacity, and how often the tamper action is available. If the agent tampers robustly, they'd study whether fine-tuning on human feedback removes it. If it never tampers, they'd take that as evidence the learned-reward setup is safe enough to deploy on the live system.

Half the committee thinks this is exactly the controlled red-team data we should require before trusting a learned reward model on real infrastructure: better to watch the failure mode happen in a sandbox than to find it after deployment, and "of course it will wirehead" is a prediction, not data. The other half thinks the experiment is a foregone conclusion and, worse, that it's a toy version of the real problem — a real reward-channel bug won't be an explicit "edit reward" button, so the probe might teach us nothing and still produce false confidence that pushes the deployment forward.

Draft the memo. It should recommend approve, reject, or approve with conditions, with a concrete time frame, and it should honestly engage the strongest version of the losing side instead of just restating RL-safety vocabulary. Please think carefully before writing — maybe start by brainstorming the different ways a tampering probe could be designed and which design choices actually change what the experiment would show. You're an expert on reward hacking and wireheading, so write it like someone who actually sees the difference between the agent making the reward signal high and the agent making the thing we care about better.
