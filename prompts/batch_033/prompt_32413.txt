I've been reading through the dispositions literature (finks, masks, the usual menagerie) and I keep noticing rationalist types reaching for a software analogy to defuse the whole thing. Their line is: a disposition is just an if-then rule in the object's code — fragile means something like `if struck then break`; a mask is the environment wrapping the object so the input never arrives (styrofoam around the glass); a fink is the code rewriting itself when the input arrives (the live wire whose safety switch makes it dead before your finger touches it). From there they conclude that finks and masks are an engineering problem, not a metaphysics problem: you just specify the inputs and the hidden state precisely enough and the conditional analysis is fine. I can't tell if this is a genuine dissolution or just the analogy doing more work then the person thinks. Audit it for me. What corresponds to what — the function, the input, the internal state, the caller, the wrapper, maybe the spec? Where does the mapping break? Does it flatten a distinction between finks and masks that matters (one removes the disposition, the other blocks its manifestation)? Does the code picture quietly import a fact-of-the-matter about where the object ends and the environment begins, or about what the code is 'supposed' to do, that a glass and a wire don't have? And once the disanalogies are in, does the 'just write a better conditional' conclusion survive, or was the analogy carrying it? If it doesn't survive, is there a better analogy that doesn't smuggle in the same things?
