I work as a software engineer on an infrastructure team, and I keep running into the same puzzle whenever I have to estimate the probability that a particular event will happen: a deploy will cause an outage, a database migration will corrupt data, a service will fail overnight. The standard approach I was taught is to find a population of similar cases and use its base rate. But for any individual case there are always several populations I could choose, and they point in very different directions. A colleague with some philosophy background told me this has a name, the reference class problem, but I haven't read any of that literature.

Instead, I started writing down my own verdicts about which population feels like the right one. (1) For a trivial, well-tested change to CSS going out on a Tuesday morning, I use the class of similar cosmetic changes and call the risk negligible; I would not use the base rate for all deploys, which is much higher because it includes large backend migrations. (2) For a large, untested change to our payments code submitted by a new contractor late on a Friday, I use the class of large untested Friday changes to payments by newcomers and call the risk high; using the overall deploy base rate would feel irresponsible. (3) If a specific engineer has shipped over a hundred similar changes without incident, I prefer their individual track record, even though it is a very small class and even when a broader class suggests something different. (4) For a genuinely novel change, such as our first-ever migration between two storage engines, I don't trust any single closest class; I average several rough analogies, but I can't say why those analogies and not others. (5) In a risk review with nontechnical leadership, I will sometimes report the overall base rate for a change that I would personally estimate much higher using a narrower class, and both numbers feel appropriate to their contexts, yet that seems to assign two different probabilities to the same event.

My working rule has been something like: use the narrowest reference class with enough data, and when no such class exists, average the most causally relevant analogies. But I can't make causal relevance precise, and the rule doesn't explain verdict (5). Is there a single principle that captures which reference class, or which way of combining them, is correct for a given case? Which of my verdicts does it force me to give up, if any? And what would it say about a case I keep going back and forth on: a change that falls into two equally specific reference classes pointing in opposite directions, where neither class is obviously more causally relevant than the other?
