In a recent discussion, a colleague pressed the following argument on me, and I find myself unable to locate the flaw with precision.

(1) In the standard one-shot Prisoner's Dilemma, mutual defection is the unique Nash equilibrium, so rational players defect.

(2) But consider a "program game" variant: each player submits a computer program to play on their behalf, and each program receives the other's source code as input before selecting Cooperate or Defect.

(3) Define the program FairBot as follows: given the other program P as input, output Cooperate if and only if P(FairBot) = Cooperate. (Assume the programs have access to a provability predicate and can reason about each other's outputs using Löbian logic, so the apparent circularity is resolvable.)

(4) If both players submit FairBot, then each FairBot verifies that FairBot(FairBot) = Cooperate, and both cooperate. Moreover, this is a Nash equilibrium of the program game: if one player deviates to a program that defects against FairBot, FairBot detects this and defects in response, yielding a worse outcome for the deviator.

(5) So program equilibrium shows that cooperation in the one-shot PD is rationally achievable—the standard result that defection is mandatory was an artifact of restricting to strategies that cannot condition on one another's decision procedures.

(6) But the same reasoning appears to generalize. For any strategic interaction with a cooperative outcome that Pareto-dominates the equilibrium, we can design a program that cooperates conditional on the other program's cooperation and submit it. The cooperative outcome becomes an equilibrium of the program game.

(7) This seems to dissolve all social dilemmas—tragedies of the commons, free-rider problems, arms races—once we move to the program level. But real-world cooperation problems plainly do not dissolve just because we can imagine writing computer programs that read each other's source code.

(8) Therefore, something must be wrong with the program equilibrium argument. Either the cooperative equilibrium is not genuinely accessible to rational agents, or the move from the program game back to real-world strategic reasoning is illegitimate, or the argument rests on a technical assumption that fails in practice.

I am inclined to think the problem lies somewhere in step (6)—that the generalization is too quick—but I cannot articulate exactly why FairBot-style reasoning does not carry over to arbitrary games, nor what principled restriction would block the generalization without also undermining the original PD result. Where does the argument go wrong, and what does saying so commit one to?
