I've been reading on my own about the idea that the best theory is the simplest one, and that this can be made precise by measuring a theory's simplicity as the length of the shortest computer program that reproduces it. But I put together an argument that seems to show the whole project collapses, and I can't find the weak point. (1) A hypothesis is simpler than another just in case its shortest description, in bits, is shorter. (2) Description length is always measured relative to some programming language. (3) For any hypothesis at all, I can invent a language in which that hypothesis has an extremely short description: if my hypothesis is that the planets move in ellipses, I simply build a language whose one-character command means "output that the planets move in ellipses." (4) So any hypothesis can be made as simple as I like by a suitable choice of language. (5) If simplicity depends on which language I happen to pick, then preferring the simpler hypothesis is just preferring my notation, not discovering anything about the world. (6) The more sophisticated version of this idea, which assigns each hypothesis a prior probability based on the length of programs that generate it, inherits the same problem, since those lengths are equally language-relative. (7) So the formal version of "prefer the simplest theory" fails: simplicity is a feature of how we write things down, not a guide to truth. The conclusion feels wrong to me — I'd like to keep (1), and I suspect something is off about (3), but I can't say exactly what goes wrong there or why it doesn't equally threaten (6). Which step should I reject, and what does rejecting it cost?
