Here is my situation. I understand the basic incompressibility idea: a string is Kolmogorov-random, roughly, if no program substantially shorter than the string itself outputs it. What I cannot sort out is whether this, or anything else, makes it coherent to say of a *specific* finite sequence -- say, the 10,000 bits I just recorded from a hardware random number generator -- that it is random. My confusions are these:

First, probability seems not to help. Under a fair-coin model, every length-n sequence has exactly the same probability, so the all-zeros string and a jumbled-looking string are equiprobable. Yet the theory wants to call one random and the other not. So randomness appears to be a property of the sequence itself rather than of any process that generated it -- but is that a defensible position, and what exactly is the property?

Second, machine-dependence. Incompressibility is defined relative to a universal machine, and I gather that for any fixed finite string one can cook up a universal machine relative to which that string is maximally compressible, so the invariance theorem only buys asymptotic robustness, up to an additive constant that swamps anything one could say about my particular 10,000 bits. Does this mean the notion is simply undefined for individual finite strings, or is there a standard repair (fixing a reference machine, working with randomness deficiency relative to a distribution, or something else), and how principled is it?

Are these three claims actually consistent, and if the tension between (b) and (c) is real, what exactly are the practitioners doing -- testing against a bounded class of alternatives, and if so, does that collapse "randomness" into "passes the tests we happened to run"?

Was the move to infinity a solution or a retreat?
