so I've been reading the old LW/Overcoming Bias stuff on the planning fallacy and outside view again, and it keeps bugging me that everyone says "just take the outside view, use the base rate" as if that were one move. it isn't, because of the reference class problem: my side project is simultaneously "a software project by a solo dev" (mostly abandoned), "a project by someone with my track record" (i finish maybe 40%), "a hobby project in my specific niche" (no data at all), and "a project I'm unusually excited about this time" (base rate undefined). each class gives a different forecast and there's no obvious fact of the matter about which is *the* class.

please describe the most important implications of the reference class problem for how someone like me should actually do personal forecasting and planning. concretely: is there a principled way to choose or weight reference classes, or is it curve-fitting all the way down? when (if ever) does the inside view legitimately beat the base rate, given that the whole selling point of reference class forecasting was that our inside-view judgments are biased? and does the problem infect the big formal versions too (i.e. is Flyvbjerg-style optimism-bias uplift itself hostage to class choice)?
