So I'm a gameplay programmer, zero philosophy training, and I need help from someone who's actually read this stuff.

For our NPC system we modeled what characters know using basic modal logic, and it immediatly blew up on us. The standard setup says that if a character knows something, they know every logical consequence of it. So a guard who knows the passcode "knows" that its SHA-256 hash is some specific 64-character hex string, and a shopkeeper who knows basic arithmetic apparently already "knows" whether the Collatz conjecture is true. Obviously useless for building believable characters. I googled around and apparently philosophers call this "logical omniscience" and have been arguing about fixes for decades.

Write me a decision tree that takes someone from "ok, the standard possible-worlds account of knowledge/belief is too strong" to a named fix. Requirements:

- 8-12 branch nodes. Every node has to be phrased as a question someone could answer without already knowing the literature -- no "do you accept Hintikka-style semantics?" type nodes.
- At least half the nodes should be built around concrete little cases, not abstract principles. E.g.: can a person believe P, and also believe "if P then Q", while genuinely not believing Q? Is there a real difference between "knowing" that 2+2=4 and "knowing" some theorem that takes 300 pages to prove? Can someone believe of each drawer in a desk that it might contain the keys, while being certain the keys are in exactly one drawer?
- One node can be engineering-flavored: does the account need to be mechanically checkable / implementable for bounded agents, or is it fine if it just describes ideal reasoners? (I suspect this one does a lot of work but I want to see it on the tree.)
- Leaves must include at least: filtering knowledge by what the agent is "aware of" or attending to; allowing impossible worlds where logic itself breaks; treating knowledge as what the agent can derive within some limited number of steps/resources; just denying that belief is closed under consequence; splitting the notion in two (implicit vs. explicit belief) and saying the problem conflates them; and the "it's an idealization, deal with it" option of not fixing anything.
- Flag any pair of leaves the tree can't actually separate -- my guess is some of these collapse into each other in practice and I'd rather have that said out loud than papered over.
- If some combination of answers is logically possible but nobody seems to hold it, put it on the tree anyway as an unoccupied leaf with one sentence on whether it's incoherent, just unattractive, or genuinely unexplored.

End each leaf with the fix's name and a 1-2 sentence sketch of what my NPC system would look like if I implemented it that way, so the tree is actually useful to me and not just a philosophy taxonomy.
