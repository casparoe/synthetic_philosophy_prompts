So I'm a backend engineer, no philosophy background, and last week a coworker and I got into an argument over lunch about the Axelrod prisoner's dilemma tournaments from the early 80s — the ones where Anatol Rapoport's Tit for Tat cleaned up against a bunch of much fancier strategies. We both know the standard lessons (be nice, be forgiving, be clear, etc.). But then I went down a rabbit hole and found this 2004 paper by Moshe Tennenholtz called "Program equilibrium" (published in Games and Economic Behavior, I think), where instead of just picking a strategy, each player submits a computer program that gets to READ the other player's source code before deciding what to do. Wikipedia renders the flagship program from that literature roughly like this:

algorithm CliqueBot(opponent_program):
    if opponent_program == this_program then
        return Cooperate
    else
        return Defect

And apparently if both players submit this thing, mutual cooperation is an equilibrium, because anyone who swaps in a different program gets defected on. Which, as a programmer, kinda broke my brain a little — the cooperation doesn't come from repetition or forgiveness at all, it comes from the code inspecting itself in the other guy. There's even a criticism listed that it's fragile, like if one player adds an extra space character the whole thing collapses into mutual defection, which is hilarious and also feels really deep?

Here's what I actually want: run the Axelrod tournament back through this lens. If the entries in that tournament had been allowed to read each other's source code, what changes? Would Tit for Tat still do well, or would it get eaten alive by programs that exploit it, or would everyone just converge on something like CliqueBot? Be careful about the mapping for me — Axelrod's entries were basically black boxes, the game was iterated rather than one-shot, and nobody's "payoffs" were really source code — so tell me honestly where the program equilibrium model fits the historical episode and where it just doesn't apply, rather than forcing it. And then go the other direction: what does the tournament, as it actually happened, show about the theory? Is it evidence that cooperation needs repetition and reciprocity and the whole source-code-reading trick is a curio, or does it show that Axelrod's setup was the artificial one? One more thing, since it's my day job: on public blockchains, smart contracts literally do publish their code for anyone (including other contracts) to inspect, so is something like DeFi actually closer to Tennenholtz's program game than to Axelrod's tournament? I don't want citations or a reading list, just the analysis, and don't just regurgitate the standard Axelrod conclusions at me — I've already heard those alot.
