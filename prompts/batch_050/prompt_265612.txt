So I'm a backend engineer, mostly self-taught, and a friend lent me a copy of Godel Escher Bach a while back. I got through maybe a third of it, but one image really stuck with me: that Escher drawing of the two hands drawing each other. The way I understood the idea is that hierarchies are never really fixed. Every level of a system can be jumped out of from a level above, but then that level can be jumped out of too, and eventually the levels loop back around and you get this tangled hierarchy where nothing is actually on top.

This got me thinking about something at work. In software we have all these layers stacked on each other -- app code runs on a framework, the framework runs on a runtime, the runtime runs on an OS, the OS runs on hardware, and each layer is sort of inviolable from the perspective of the ones above it. You can't rewrite your kernel from inside your web app, etc.

But if the Drawing Hands thing is right and levels can always be tangled, I should be able to design a system with no inviolate level at all. Like, a program that can modify its own interpreter while it runs, and the interpreter can in turn modify the program, so neither one is really "above" the other -- each one is authored by the other, like the hands. I figured self-hosting compilers are the closest existing example (a compiler written in the language it compiles) but those still seem to cheat by sitting on top of the OS.

So my question: what's the right architecture for a genuinely level-free system -- one where there's no privileged layer anywhere, all the way down? Should I be writing my own bootloader that my application code can also patch at runtime, or is there a cleaner way to close the loop? I feel like this should be possible if I think about it right, and it would make the system way more flexible since nothing would be untouchable. My coworker says I'm chasing something impossible but couldn't explain why, and honestly I think he just hasn't thought about it enough.
