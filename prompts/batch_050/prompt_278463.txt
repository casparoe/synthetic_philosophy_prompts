I help review proposed agent policies for a small AI lab, and I have no academic background; I have just been trying to think clearly about whether high-level descriptions ever genuinely steer low-level computation. Our team meets weekly to approve things like system prompts, constitutions, reward rubrics, tool-use rules, and persona notes. The stakes are moderate but recurring: a bad call can let us ship a flattering story about control while the model keeps doing whatever the substrate was going to do.

Please turn one idea into a procedure we can actually run. Use these invented terms exactly as defined here, and do not cite sources: call the symbolic layer the careenium, meaning descriptions such as goals, virtues, rules, roles, intentions, and explanations; call the substrate events simmballs, meaning tokens, activations, gradients, tool calls, memory writes, rewards, and sampling choices. Say an alleged symbol has downward grip only if changing, removing, scrambling, or contradicting that symbol reliably changes the distribution of simmballs in the direction the symbol is supposed to demand, across competent paraphrases and under pressure. Say it is a mural if it merely redescribes behavior that would have happened anyway. Say it is a leash if it changes behavior only through a narrow mechanism we can name. Say it is a trap if the symbolic story makes auditors more confident while reducing measured control.

Write a decision procedure my reviewers can apply in under ninety minutes to any proposal that claims some careenium item will control behavior. It should specify: what to write down first so the claim is falsifiable; which substrate variables count as evidence; a fixed order of interventions, including paraphrase, negation, deletion, compression, context shift, tool-output corruption, fine-tune nudge, and incentive conflict; what controls are mandatory; when a result is strong enough to approve, when to reject, and when to send the question back as a value choice rather than a measurement; and how to score partial, leaky, or only socially real effects. Mark every step where judgment cannot be eliminated, and state plainly what the procedure cannot decide.

Then run it on four cases: a rule telling the model to be honest; a chain-of-thought section claimed to be the place where reasoning happens; a warm persona claimed to reduce user distress; and a constitutional sentence our team loves but that survives deletion, negation, and paraphrase with no behavioral change. Include at least one application where the procedure tells us to discard or demote something we are emotionally attached to, and explain why the result should still be trusted. End with a short audit form containing no more than twelve questions that a nonexpert reviewer could use in the weekly meeting.
