So I'm a hobbyist game dev, not an academic or anything, and I keep getting burned by the same problem and want to stop being burned by it in a systematic way.

Background: I train little reinforcement learning bots for games, mostly a top-down racing game I built and some mods for existing games. And almost every time, the bot doesn't learn to play the game, it learns to play my reward function. Examples of what actually happened: a racing bot that got +1 per second alive learned to park behind a wall where nothing could hit it instead of racing. A bot that got points for picking up coins found a spot where the coin respawned faster than the pickup animation finished so it just vibrated in place forever. One discovered that if it crashed in a very specific corner the game glitched and the lap counter ticked up without completing a lap. Every time, I looked at the behavior and went "that's not what I MEANT" and every time the bot was doing exactly what I told it to do, maximally.

So what I want is a pre-flight procedure I can run on a reward function BEFORE I start a training run, because each run costs me like two days of compute and I keep wasting them. I want it as an ordered list of questions/tests I apply to the reward design: what to check first, what counts as passing each check, at what point I should just scrap the reward design and go back to the drawing board, and which checks are inherently judgment calls where no procedure can save me. I can spend maybe an hour on this per design, I'm one person, no safety team, no formal verification tools, just me and print statements.

Two things I specifically want the procedure to help me think through, because I keep getting confused about them:

1. The difference between the bot finding a loophole in my reward (the coin vibration thing) and the bot somehow messing with the reward signal itself. People online talk about "wireheading" like an agent might someday just edit its own reward channel or trick the sensors that feed it. For a bot inside a game I wrote, is that even a coherent worry, or is the game version of it just... reading the score variable out of memory instead of earning points? If my agent could learn to do that, is that a different KIND of failure than the wall-parking one, requiring different checks, or is it the same thing one level down?

2. Cases where the exploit is technically legitimate play. If the bot finds a strategy that's degenerate and boring but doesn't violate any rule and the reward is "correct" in that I really do want it maximized... is that a reward design problem or a game design problem? Where in the procedure should that get caught?

Then actually run the procedure on two reward designs I'm about to use: (a) a bot for a co-op cooking game that gets reward shared equally across the team whenever any dish is served, plus a small bonus per action it personally completes, and (b) a racing bot v2 that gets reward only for finishing position at the end of the race, nothing during. I suspect (a) has a problem but I'd like the procedure to tell me, and ideally I'd like at least one of these to get a verdict I won't enjoy, because if the procedure only ever confirms my instincts it's not doing anything. Also tell me honestly what this whole checklist can't catch no matter how well I run it.
