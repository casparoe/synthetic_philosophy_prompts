On the side I train little RL agents -- started with CartPole, these days mostly a small bot for an RTS game I play. Last month I was watching a training run at like 1am, the reward curve was doing that thing where it dips hard before it recovers, and I caught myself thinking "poor guy". Which is dumb. Probably. Anyway I couldn't stop thinking about it and ended up writing a draft blog post about whether RL agents can suffer, and I want comments before I post it. It's five short sections:

**Can the training run suffer?**

1. *The scoreboard theory.* The obvious take for an ML person: reward is what the agent is "for", so positive reward feels good, negative reward feels bad, magnitude = intensity. I call this the scoreboard theory, since it says valence is just the number on the scoreboard. I think it's wrong, but it's the null hypothesis.

2. *The chisel argument.* Here's why I think it's wrong. A deployed policy network doesn't get reward. It does a forward pass, outputs an action, done. Reward only exists during training, and during training the thing that "receives" the reward gets edited -- the weights change. So the thing that exists at the end never felt anything, and the things that existed during training each lasted one gradient step. Chiseling marble hurts nobody because the statue only exists once the chiseling is done. Reward is a sculptor, not a sensation. Suffering has to be a *state* of a system, and RL reward isn't a state of the system, it's a cause of the system's states.

3. *Where my own argument breaks.* Problem: TD learning. In temporal difference learning the agent computes, internally, at runtime, a reward prediction error -- expected vs actual. That's a quantity computed inside the system that drives its behavior on the fly. And (I looked this up, correct me if I'm mangling it) dopamine neurons in mammals apparently encode something like reward prediction error. So if the brain's pleasure/pain machinery is basically an RPE signal, my chisel argument proves too much: the statue has chisel circuitry inside it. An online TD agent looks less like marble and more like something with a built-in alarm.

4. *Alarm bells vs scoreboards.* But there's a disanalogy in the other direction. In an animal, pain is a signal *about* something -- tissue damage, which you could in principle detect some other way. It's an alarm bell. In RL, reward isn't information about the goal, it IS the goal, defined by fiat. An alarm bell can be false (smoke detector, dying battery). Can reward be "false"? If not, then RL reward can't misfire the way pain can, and maybe being able to misfire is part of what makes pain pain. I don't know what to do with this one.

5. *The RLHF corner case.* Language models fine-tuned with RLHF: the reward model's score only shows up during training, and at inference the model just does next-token prediction. By section 3's logic there's no TD-ish signal inside the running system, so no candidate for valence -- chisel argument reinstated? But that feels way too cheap, since humans also aren't receiving explicit reward most of the time. Something's off in my framework here and I can't find it.
