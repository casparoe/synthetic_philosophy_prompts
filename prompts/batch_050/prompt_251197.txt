Can a finite sequence of coin flips (or bits, whatever) be *random* on its own, not just "randomly generated"? Here are the answers I already know, so skip these and anything that's just a rewording or special case of them:

1. Yes: a string is random iff it's Kolmogorov-incompressible, no program much shorter than the string itself outputs it.
2. Sort of, relativized: you define randomness relative to a set of statistical tests (Martin-Löf style), and a finite string passes or fails with some deficiency-of-randomness score.
3. No: randomness is a property of the *process*, not the product. The same 64 bits from a Geiger counter are random and the same 64 bits from a C program are not.
4. Pragmatic version: a string is random *for you* iff no feasible observer with bounded resources can distinguish it from uniform noise (pseudorandomness).
5. Typicality version: the string is random if it's typical wrt some computable probability distribution -- but then everything hangs on the choice of distribution.

I want a sixth answer that isn't on this list. Also tell me whether your answer survives the obvious objection that bites #1, namely that machine-dependence makes "random" partly a matter of arbitrary convention.
