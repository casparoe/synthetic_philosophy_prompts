Ok so I'm a software engineer (distributed systems, mostly backend) with zero philosophy training, and I got into a dumb argument at work that apparently philosophers have been fighting about for decades. The argument: my team does on-call rotations, code review, incident response etc, and a coworker said "we as a team decided X" and I said no, a bunch of individuals each decided X, there's no extra "team decision" anywhere in the system. He sent me some stuff about "collective intentionality" and now I'm three Wikipedia pages deep.

I want to write a blog post for other engineers about this debate, and the centerpiece should be a decision tree that takes a reader from "two people can do something together" (I'll grant that much) to a named position. So: pretend you're a philosophy professor who specializes in action theory, but one who's had to explain this stuff to impatient engineers before. Think carefully and brainstorm the logical space first before writing the tree itself.

Requirements:

- Each branch node has to be phrased as a question about a concrete case, not about the theory. Use cases an engineer would actually have intuitions about: two people carrying a couch, an open source project with 3000 drive-by contributors, a flash mob, a riot that "escalates," a deployed microservice mesh that no single person fully understands, a code review where the reviewer approves something bad. No node like "do you believe intentions can be irreducibly plural?" because that presupposes you already know the jargon.
- The questions should separate on things like: does doing something together create actual obligations between the participants, is there some extra mental state beyond the individuals' intentions plus everyone knowing the situation, can you be part of the group project without ever having decided to join it, that kind of thing.
- Leaves I want to end up at: Bratman's shared intention view, Searle's we-intention view, Gilbert's joint commitment view, Tuomela's we-mode thing, the team reasoning crowd (Bacharach/Sugden, if I'm even getting the names right), and a hardcore deflationary leaf where it's just convergent individual intentions all the way down (that's my prior, so make sure I can actually reach it and it isn't set up as the loser leaf).
- If there are combinations of answers in the space that nobody defends, include them as empty leaves and say briefly whether the spot is empty because the view is incoherent, just unappealing, or genuinely unexplored. I find that part weirdly interesting.
- Flag any pair of leaves the tree can't cleanly separate — I have a feeling Searle and Tuomela might be hard to tell apart with only case-based questions, but don't take my word for it.

Also, a few ground rules for how you answer: be opinionated, don't just do the neutral survey thing where every position is "an important perspective." If a position has an awkward commitment, say what it is at the leaf. And if my whole setup is confused somewhere — like if I've garbled one of these views, or a decision tree is actually a bad instrument for this debate because the positions don't line up on a shared set of questions — tell me that plainly instead of politely building me a broken tree. I'd rather get pushback than a nice-looking diagram that's philosophically wrong.

Keep it under, I dunno, 900 words if you can, tree plus short notes.
