For the philosophy of probability course I'm taking, our next unit is on algorithmic randomness, and I want a decision tree my seminar group can use to locate themselves on one question: can a finite sequence be random? Write the tree starting from this shared commitment: "I have been handed a binary string of fixed, known length, and I am asked whether it is random." Each branch node must be a question -- ideally a forced choice between two verdicts on a concrete case -- that someone can answer without knowing which position it sorts them into. Each leaf should be a named position, followed by two or three sentences giving that position's verdicts on the test cases below.

The leaves must include at least: Kolmogorov-style incompressibility (a string is random when no program much shorter than it outputs it); a model-relative view on which randomness is deficiency relative to a chosen statistical model or class of tests; a von Mises-style view on which randomness is stability of frequencies under subsequence selection; the process-only view that randomness attaches to generators, not outputs; a resource-bounded or epistemic view that a string is random relative to an observer's computational powers; and a deflationary leaf holding that the question is ill-posed for finite strings. If your tree wants additional leaves, add them.

Use these five strings as the diagnostic material for your nodes:
(A) 1000 zeros, produced by a fair coin whose tosses all happened to land heads;
(B) 1000 zeros, produced by a broken machine that only ever outputs zero;
(C) the first 1000 bits of pi's binary expansion;
(D) a patternless-looking 1000-bit string produced by a pseudorandom generator with a 32-bit seed;
(E) an 8-bit string.

These cases are chosen to force the real separations: A and B are the same string, so any view on which randomness is intrinsic to strings must deliver the same verdict on both, while process views must diverge -- make the relevant node that forced choice, not a summary of the debate. C passes standard statistical tests but has a very short description; D is in principle compressible (the seed) but unpredictable to any feasible observer; E is short enough that the additive-constant problem for Kolmogorov complexity bites -- build one node around that fork: accept verdicts only relative to a fixed machine and threshold, restrict the question to long strings, or abandon absoluteness.

Two further requirements. First, flag any pair of leaves your tree cannot separate with these cases, and either supply a case that separates them or state briefly why you suspect none exists (I suspect incompressibility and model-relative deficiency coincide everywhere here -- confirm or correct me). Second, mark any region of the answer-space your questions allow but no named position occupies, and diagnose it: incoherent, merely unattractive, or unexplored. Six to ten branch nodes; present the result as an indented outline I can print as a flowchart.
