I am a software engineer deciding whether a particular deployment is likely to cause an incident. A colleague argues that the reference-class problem makes this kind of prediction fundamentally arbitrary:

1. Any frequency-based estimate for a particular event requires selecting some of its features to define a reference class.
2. Every event has indefinitely many true descriptions, so it belongs to many possible classes whose observed frequencies conflict.
3. A selection rule is justified only if it retains the features that are causally or predictively relevant.
4. We cannot establish which features are predictively relevant without first dividing past cases into classes and comparing their outcomes.
5. Therefore, justifying any selection rule presupposes an earlier selection rule, producing either a regress or a circle.
6. The regress could be stopped only by a unique narrowest class containing no further causally relevant distinctions; but any actual class can be subdivided by some feature whose relevance remains open.
7. Hence all frequency estimates for the individual event are equally unsupported.
8. Bayesian methods cannot help, because weighting or averaging different classes merely pushes the arbitrary choice into the prior.
9. Therefore, absent a deterministic model, no prediction about an individual case is rationally better than any other.

This seems to prove too much, since some deployment models plainly have better out-of-sample records than others. Which premise or inference should I reject, and what does rejecting it cost? If several exits are defensible, please compare them rather than simply appealing to the practical success of machine learning.
