So I've been reading about program equilibrium — the idea that in a one-shot prisoner's dilemma, if each player submits a computer program and the programs can read each other's source code before moving, then "cooperate if and only if the other program's code is identical to mine" is an equilibrium, so rational agents can cooperate after all. Neat. But a few things bug me.

First, the identical-code trick feels like a cheat, since it only works on exact clones. So I tried inventing my own version: a program that doesn't demand identical code, but instead tries to prove "if I cooperate, the other program cooperates too, and if I defect, it defects" — cooperates only if it finds such a proof, otherwise defects. My hope was this lets different-looking programs cooperate with each other, not just clones.

My questions: (1) In the original setup, is the cooperative equilibrium actually special, or can basically any conditional behavior be an equilibrium — i.e., is there a huge multiplicity problem and the theorem doesn't really tell you what will happen? (2) Does my proof-based idea escape that multiplicity or just move it somewhere else — e.g., could there be lots of different stable "cliques" of programs that cooperate within the group but not across? (3) What breaks if the programs only get a noisy or partial look at each other's code rather than the full source — does everything collapse back to defection, or can something survive? Please explain the conceptual issues, I don't need formal proofs. Lead with your bottom line in the first sentence, then the reasoning, no preamble and no restating my question.
