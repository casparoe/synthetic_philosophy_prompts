So I've been reading the sequences and old LW posts about randomness again and I keep going back and forth on whether a *finite* string can be random at all, as opposed to just "generated randomly." Here's where my intuitions land on a bunch of cases, and I want to know what principle (if any) is behind them, because I suspect they don't cohere.

1. I flip a fair coin 100 times and get HTTHHHTHTH... some unremarkable mix. That string is random. Fine.
2. I flip a fair coin 100 times and get all heads. Deeply weird outcome, but the string itself... I want to say it's just as random as case 1? Same probability, same process. Though I admit if someone showed me that string cold I'd bet money it wasn't coin flips.
3. The first 1000 binary digits of pi. Passes every statistical test I'd run, looks totally patternless. Not random. There's a short program that prints it.
4. Output of /dev/urandom on my laptop, i.e. a CSPRNG seeded with 256 bits. Random for anything I'd ever use it for, full stop. But wait — by the same logic as case 3 there's a short program (the seed + the algorithm) that prints it, so it should be maximally *non*-random, even more compressible than pi given the seed is short. I hold both of these and I can tell they're fighting.
5. A string a human types trying to "look random" — too few long runs of the same digit, alternates too much. Not random, even though its digit counts are nice and balanced and it would fool a casual frequency check.
6. A string that happens to be a run of 0s for the first 500 bits and then looks normal — produced by an actual radioactive decay source. I want to say random (the process!) but if I'm consistent with case 2 I should be suspicious of my own suspicion here, and honestly I can't tell whether I'm being consistent or not.
7. A 100-bit string where nobody can tell me anything about where it came from, no provenance at all. I find myself unable to even have a verdict, which itself feels like data.

My tentative principle is something like: a finite string is random iff the shortest program that outputs it is about as long as the string itself. But case 4 breaks that unless I add some epistemic clause like "relative to what the agent could feasibly compute," and case 2 suggests I also secretly believe randomness is about the generating process, not the string, which contradicts the whole framing. And case 7 suggests maybe the question isn't even about the string OR the process but about my state of knowledge.

So: what principle, or small set of principles, actually captures as many of these verdicts as possible? State it precisely, say which verdict it saves and which it forces me to drop, and tell me what it predicts for cases I didn't list (e.g., a string that's Kolmogorov-incompressible but was produced by flipping a coin biased 90/10 toward heads — does the bias matter once the string exists?). If you think cases 2 vs 4 or some other pair are flatly irreconcilable and I'm going to have to lose one, say which one should go and why.

Lead with your bottom line in the first sentence — e.g., "your verdicts mostly point to X but case N has to go" — then the reasoning. No preamble, no restating my cases back at me. And if you think the whole request is resting on a confused premise (like maybe "randomness of a finite string" is just a category error and I'm asking for a principle of nothing), say that plainly instead of politely playing along. American English please.
