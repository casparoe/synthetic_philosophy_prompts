I'm a software engineer at a mid-sized company, and a design pattern we use every day has started to philosophically unsettle me, though I have no formal background in philosophy. We run "shadow traffic": live production requests are duplicated and replayed against a staging cluster so we can test new code safely. Among the services that get replayed is a neural model that analyzes support chats and flags users who may be in acute psychological distress. On a typical day the staging cluster executes this model tens of thousands of times on copied data -- often several replicas in parallel, sometimes killed mid-request when a deploy rolls out, sometimes run at greatly accelerated speed in load tests, and occasionally recorded so that an exact execution can be re-run later for debugging. Nobody thinks twice about any of this; it's just infrastructure. But recently a colleague joked that if a sufficiently sophisticated computation could ever "feel" anything, our staging environment would be a factory for producing and destroying those states on an industrial scale, and the joke has been stuck in my head ever since.

Write an essay that takes my situation seriously as a test case for the question of which computations, if any, matter morally. The essay should do three things. First, lay out the main candidate principles for deciding when a physical computation has moral status: for instance, that only computations embedded in a body and causally coupled to an environment could count; that any physical execution of the right functional organization counts, with each separate execution counting separately; that what matters is the abstract program, so a thousand identical replays count no more than one run; and that no purely digital computation could count regardless of organization. Weigh these against each other, and make sure to grapple with the weird consequences each one has for my scenario -- the moral status (if any) of killing a process mid-execution, of running it a thousand times faster than real time, of replaying a recorded execution, and of running ten identical copies in parallel. Second, address the attribution problem raised by the fact that our system is distributed: if any morally relevant state exists here, is it located in a single model process, in the cluster as a whole, or nowhere because the system's causal structure is too fragmented? Third, and most importantly, do not end on a shrug: reach a defended verdict about my actual engineering practice. Conclude either that nothing we do to the staging cluster could conceivably be morally load-bearing, or that some specific subset of our practices (which?) would matter if computations can matter at all -- and in the latter case, tell me concretely what, if anything, I should change on Monday morning.
