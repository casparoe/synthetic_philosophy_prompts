I'm a software engineer with about a decade of experience, mostly backend systems and some dabbling in ML infrastructure. I have no formal philosophy background, but over the past year I've been reading about interpretability research on neural networks, and I've been drafting an essay for my personal blog arguing that the field is careless with the word "representation." Before I publish, I'd like your comments on the draft below — both on its factual accuracy and on whether the argument actually works.

Here is the draft, slightly condensed but structurally complete:

---

**Does the model know what it's saying? When does a direction in activation space earn the name "representation"?**

**1. The situation.** Interpretability researchers routinely report "finding" concepts inside trained networks. A linear probe trained on a model's activations can tell you whether the input concerns, say, a factual claim versus an opinion. Adding a scaled vector to the residual stream can make a model output text that is more sycophantic, more honest, or — in one widely discussed demonstration — obsessively focused on the Golden Gate Bridge. The researchers describing these results often speak of the model "having a representation" of the concept. My question: what, exactly, justifies that word, as opposed to the weaker claim that we have found a useful handle on the model?

**2. Three claims that get run together.** As far as I can tell, the literature trades on three distinct findings:

- (A) *Decoding.* A probe trained on activations recovers some property of the input above chance.
- (B) *Control.* Intervening on activations along some direction reliably changes behavior in a concept-consistent way.
- (C) *Mechanism.* The direction in question is one the network itself uses — it figures causally in the downstream computation, not just in our experiments on the network.

(A) is cheap: information can be decodable from a system without the system representing anything, the way tree rings let you decode past rainfall. (B) is stronger but still ambiguous: I can control a television's volume with a remote, but the remote frequency is not a representation of volume inside the TV. Only (C), I claim, licenses the word "representation," and most published results establish only (A) or (B).

**3. An analogy from my day job.** Suppose I'm reverse-engineering a stripped binary with no debug symbols. I find a memory address whose contents correlate perfectly with the player's score. That's decoding. I patch the address and the displayed score changes. That's control. But am I entitled to call the address "the score variable"? Not yet. An optimizing compiler may have split one source-level variable across several registers, or reused one register for three variables in different execution phases. Calling the address "the score" is warranted only once I can show the program's own logic reads it as the score — and even then, my claim is hostage to the compiler's decisions, which I can only partly reconstruct. Sparse coding results in interpretability (the superposition hypothesis; the fact that sparse autoencoders seem to recover more features than the network has dimensions) suggest networks face exactly this compression problem, except that unlike the compiler, the network was never working from source code anyone wrote.

**4. My proposed criterion.** We should say a network "represents X" only when we can identify the internal consumer: some downstream computation that treats the putative feature as being about X. Nothing represents simpliciter; something represents X *for* a use the system makes of it. This is meant to be a functional-role criterion, and I take it to imply that "the model represents deception" is, as usually asserted, underdetermined — what the experiments show is that *we* can read deception off the activations and push the model around with them.

**5. Where I know the argument is shaky.** Three worries I haven't resolved. First, the "consumer" of a mid-layer feature is arguably the entire rest of the network, which threatens to make my criterion trivial — everything is consumed by everything. Second, if interventions reliably produce concept-consistent behavior at scale, refusing to say "representation" might be scrupulosity rather than rigor; in engineering, if a handle works predictably, we don't usually withhold the name. Third, my binary analogy may smuggle in a false premise: binaries have ground truth (the source), networks don't, so perhaps the very demand for a mechanism-level fact of the matter is misplaced.

**6. Tentative conclusion.** Realism about interpretability findings should be local and consumer-relative. Global claims that a model "has a representation of X" outrun what probing and steering experiments establish.
