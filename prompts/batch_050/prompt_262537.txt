I've been working through the literature on program equilibrium — the idea, due to Tennenholtz, that two agents in a one-shot Prisoner's Dilemma can rationally cooperate if each can read the other's source code and condition on it. The classic construction is a program that cooperates if and only if the opponent's program is (in the relevant sense) identical or provably cooperative toward it. I think I understand the basic mechanism: reading source code lets an agent move before it moves, so to speak, collapsing the one-shot game into something where mutual cooperation can be an equilibrium. What I find much less clear is how fragile this result is, and I'd like a careful conceptual explanation of its foundations and failure modes.

To make this concrete, consider a variant I've been calling "noisy program equilibrium": each agent receives not the opponent's actual source code but only an imperfect summary of it — say, a compressed description produced by a lossy procedure, or the source code with a small probability of random corruption in any given token. Two agents might both be running genuinely cooperative programs, yet each one's summary of the other comes back garbled. Intuitively, the "cooperate iff we match" construction falls apart immediately, since exact syntactic comparison is hopeless under noise. But it seems like there should be more robust constructions — programs that cooperate with anything that is "close enough" to cooperative, or that reason about the opponent's behavior rather than its syntax — and I suspect those constructions reintroduce exploitable wiggle room: an agent that defects while being just similar enough to pass the fuzzy test.

Please explain, at a conceptual rather than fully formal level: (1) why the standard program equilibrium construction achieves cooperation where ordinary game theory says defection is dominant, and what exactly the source-code access is doing epistemically; (2) whether the fragility to noise I've described is a superficial implementation detail or points to something deep — for instance, whether any robust notion of "similar enough to cooperate with" must open the door to defection by sufficiently cleverly disguised defectors; and (3) how this bears on the broader question of whether program equilibrium is a genuine solution to one-shot cooperation problems or merely a relabeling of the coordination problem. Where relevant, connect this to related ideas like Löbian cooperation and the difficulties bounded agents face in verifying proofs about one another, but keep the focus on the noisy variant and what it reveals.
