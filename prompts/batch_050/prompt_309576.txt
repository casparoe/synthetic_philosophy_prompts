I write a magazine column on science and ideas, and last month I attended a small interdisciplinary workshop on cooperation among AI systems, where I listened to two researchers — a game theorist I'll call Anna and a computer scientist I'll call Bruno — argue about "program equilibrium." For readers I need to explain this idea and take a position on whether it matters, and I found I genuinely couldn't referee the exchange. The setup, for context: in the program-equilibrium framework (introduced in the game-theory literature in the mid-2000s), two players in a one-shot prisoner's dilemma don't submit a move; they each submit a computer program, each program gets to read the other's source code, and the programs' outputs determine the moves. A striking result is that mutual cooperation is sustainable in equilibrium — for instance, each player submits a program that cooperates if and only if the opponent's program is identical to itself, and defects otherwise. Here is roughly how the argument went. (1) Anna opened by saying the whole construction is a bait-and-switch: in the prisoner's dilemma, defection strictly dominates, and if your "solution" requires agents who can inspect and condition on each other's code, you have changed the strategy space and therefore changed the game — you haven't solved the dilemma, you've declined to play it. (2) Bruno replied that every celebrated resolution embeds the game in a richer structure: the iterated prisoner's dilemma "solves" the problem only by adding repetition, reputation, and discounting, yet nobody calls tit-for-tat a bait-and-switch; program equilibrium is exactly as legitimate a transformation, and arguably the more relevant one now, since AI systems can literally be handed one another's source code in a way humans never could. (3) Anna countered that the analogy cuts against him, because the program setting has the same disease as the iterated one, only worse: a folk theorem holds, so virtually any individually rational outcome is an equilibrium, and nothing in the framework privileges the mutual-recognition program over the continuum of alternatives — a theory that permits everything predicts nothing, and the cute cooperative construction is doing normative work the mathematics doesn't license. (4) Bruno answered that the privileged status of cooperation comes from simplicity and epistemic robustness rather than from equilibrium existence: the mutual-recognition program is short, achieves cooperation in a single shot with no punishment machinery or repeated interaction, and the basic design generalizes — programs can reason about proofs regarding each other's behavior rather than demanding syntactic identity, so the construction is a template, not a trick. (5) Anna's final move was to grant the generality but deny the robustness: conditioning cooperation on what the opponent's code is or provably does is knife-edge — write the opponent's program slightly differently and cooperation collapses — whereas tit-for-tat tolerates noise and misperception, and a framework whose flagship equilibrium shatters under small perturbations is a poor foundation for designing real systems.

I'd like you to adjudicate this exchange move by move: for each of the five numbered moves, say whether it is clearly right, clearly mistaken, or partly right, and justify the verdict in a sentence or three. Then answer the larger question the two of them were circling: does program equilibrium solve the prisoner's dilemma, dissolve it, or merely relocate it? If you think both of them are missing something — for instance, about what the "game" even is once agents choose what code to run, or about which parts of Bruno's case survive Anna's folk-theorem objection — please identify that too. I will quote the winning arguments (anonymized) in my column, so accuracy matters more to me than diplomacy.
