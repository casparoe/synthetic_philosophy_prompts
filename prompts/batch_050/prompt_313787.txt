I run the reading group for our local ACX-adjacent meetup and next month we're doing the old tool-vs-agent-AI debate, so I typed up my position ahead of time for people to poke holes in. Before I post it, I want a consistency check. Here's what I believe:

1. The tool/agent distinction is a real property of systems, not a marketing label or a deployment choice: some systems just map inputs to outputs, others steer the world toward outcomes, and which one you've built is what matters for safety.

2. Instrumental convergence is basically correct: any sufficiently capable system that strongly optimizes an objective will develop the standard drives (self-preservation, resource acquisition, resisting changes to its objective), whatever the objective happens to be.

3. LLMs are the existence proof that you can get massive capability without agency -- pure predictors, no goals of their own, superhuman at all kinds of tasks. Strongest evidence going for the tool path.

4. Given #2, the safe route is to keep building tools and just not build agents; the x-risk comes from deliberately wiring systems into long-horizon RL loops, not from tools themselves. This is roughly the conclusion of Gwern's "Why Tool AIs Want to Be Agent AIs", which is still my touchstone on all this.

5. When I actually need an agent I just wrap GPT-4 in a loop with memory and tool access and it works fine -- agency is a thin scaffolding layer on top of a tool.

Which of these pull against each other, which pairs only look like they clash, and what's the cheapest fix for each real tension? Rank the tensions by severity instead of treating them all as equal, and for each one say specifically what I'd have to give up. Fair warning: I don't know where the problem is, if there even is one, and I'd rather hear it from you than have the meetup folks definately find it first.
