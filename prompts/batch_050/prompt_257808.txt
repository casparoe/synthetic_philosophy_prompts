In mechanistic interpretability circles, people routinely describe their work as reverse engineering: a trained neural network is like a compiled binary for which the source code has been lost, and the interpretability researcher is like an engineer disassembling it back into legible functions and data structures. I'm a software engineer without a philosophy background, and I'd like this analogy audited. Start with the correspondence table: what plays the role of the machine code, the registers, the subroutines, the compiler, and the lost source? Then identify where the mapping breaks. The disanalogy that strikes me is that a binary was compiled from a human-authored program with intended semantics, so there is a determinate artifact the disassembler is trying to recover -- whereas a trained network has no source, and its "compiler" (gradient descent on a loss landscape) encodes no intentions at all. My worry is that the reverse-engineering framing presupposes that the network implements one particular algorithm, so that the analogy quietly assumes realism about neural representations -- that there is a fact of the matter about which decomposition into "circuits" and "features" is correct -- which is precisely what's in dispute when skeptics say interpretability findings are researcher-imposed decompositions rather than discoveries. Does that worry hold up, or is reverse engineering actually compatible with many equally legitimate disassemblies? And if the analogy fails at the point where it matters most, what would be a better one -- say, inferring the rules of an unfamiliar board game by watching it being played -- and does the case for treating interpretability results as objective survive the swap?
