DRAFT ESSAY: "The Legibility Trap: Why Program Equilibrium Cannot Escape the Problem of Trust"

Program equilibrium is often presented as a solution to the problem of cooperation that requires neither iteration, nor reputation, nor enforcement. Two agents in a one-shot Prisoner's Dilemma can cooperate if each can inspect the other's source code and condition its behavior on what it finds. The canonical construction is a program that cooperates when it determines that its opponent is relevantly like itself and defects otherwise. Since mutual cooperation is the outcome when such a program meets a copy of itself, cooperation becomes an equilibrium: neither party gains by unilateral deviation, because deviation means running different code, and running different code is exactly what triggers defection.

This essay argues that the result, though formally correct, does not dissolve the problem of trust but relocates and conceals it. The key observation is that the canonical construction papers over a hard epistemic step: the program must determine that its opponent is relevantly like itself. Exact source-code identity is a degenerate case of no practical interest — two agents written independently will never be byte-identical — so any realistic version must rely on a coarser test: syntactic similarity, behavioral simulation on a finite set of probe inputs, or proof-theoretic verification of selected properties. Every such test is a classificatory instrument with a boundary, and any boundary can be approached from the wrong side.

My central claim is that once cooperation is mediated by such a test, a selection pressure emerges that is the mirror image of the one program equilibrium was meant to escape. In an environment where agents are rewarded for passing one another's transparency checks, the agents that prosper are not the ones most committed to cooperation but the ones most skilled at legibility — at presenting code that passes inspection while retaining exploitable slack. The program equilibrium literature treats source code as a window into the agent; but code that is written in the knowledge that it will be read is not a window but a display. The conditions that make verification possible are the same conditions that make mimicry possible, and mimicry is cheaper than sincerity in exactly the way that defection is cheaper than cooperation in the classical dilemma.

I develop this through two arguments. First, an argument from the formal side: any verification procedure tractable enough to run in practice is incomplete, and its incompleteness defines a space of programs that pass the check while defecting in the deployed interaction. The verifier faces an analogue of the halting problem — not in the limit, but at every feasible computational budget — and so the equilibrium that the literature describes holds only relative to a fixed verification technology, not simpliciter. Second, an argument from the conceptual side: trust, in the pre-theoretical sense, is precisely reliance on another under conditions where verification is unavailable or incomplete. Since every feasible inspection leaves a residue of unverified behavior, the agents must still trust; the inspection merely determines where the trust is located. Program equilibrium has not eliminated trust but outsourced it to the verification procedure, and this is a place where trust is least warranted, because the procedure is the very thing the adversary studies.

I conclude that program equilibrium should be understood not as a solution to the cooperation problem but as a formal demonstration of the conditions under which cooperation and verification coincide — conditions that obtain only in the idealized limit where reading code is costless and complete. Outside that limit, the framework does not predict cooperation among rational agents; it predicts an arms race between legibility and scrutiny, with cooperation surviving only as a byproduct of stalemates in that race.
