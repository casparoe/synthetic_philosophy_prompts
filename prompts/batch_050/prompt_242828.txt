I work as a software engineer at a mid-size social platform company (no philosophy background, so bear with me). About once a week I end up in a launch review where someone says we should be "precautionary" about a feature -- like, it might do some harm we can't fully predict, so maybe we shouldn't ship it, or should gate it behind more testing. The problem is that both sides can play this card. Last month someone argued we shouldn't ship an auto-translation feature because it might spread mistranslations at scale, and someone else argued we should ship it *because* precaution demands we not leave non-English speakers stuck with a worse product. Both sounded "precautionary." The principle seems to point every direction at once and I've heard it criticized as basically paralyzing if you take it literally.

So: turn the precautionary principle into an actual procedure I can run in about 30 minutes during a launch review, for someone like me -- technical, no ethics training, and my manager has to sign off on the outcome. I want it as an ordered set of tests or questions I go through, not a vague list of considerations. Some things the procedure has to handle, because these come up constantly:

- Cases where we can't put a number on the probability of harm at all (not "low probability" -- just genuinely unknown), versus cases where we have decent estimates. My understanding is the principle is mostly about the former, so the procedure should route those differently.
- The both-sides-invoke-it problem above. The procedure needs a tiebreaker rule that isn't just "whoever frames their preferred outcome as the cautious one wins."
- Reversibility -- we can ship behind a flag, roll back, limit to 1% of users. A harm that's easy to undo shouldn't trigger the same response as one that isn't, and I want that built in explicitly rather than left to vibes.
- The cost of *not* acting. Delaying a feature for a quarter has real costs, and the procedure should force me to write those down instead of treating inaction as free.

Also tell me which steps are genuine judgment calls dressed up as procedure -- I'd rather know where the thing can't be mechanical than pretend it is. Then run the procedure on two hypotheticals: (1) a feature that recommends local groups to users based on inferred interests, where the worry is it could amplify extremist communities in ways we can't predict well; and (2) a small UI change to the block button that a couple of internal testers *feel* might be abusable somehow, with no specific mechanism. Ideally at least one of these should land on an answer I wouldn't like -- e.g., shipping something that feels creepy, or blocking something that seems fine -- so I can see the procedure has teeth. Finally, say what the procedure flat-out cannot do, so I know when to escalate instead.

Please write the whole answer in American English.
