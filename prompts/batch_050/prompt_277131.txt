The topic is program equilibrium -- the setup where agents in a game can read each other's source code before playing, which famously lets cooperation be an equilibrium in one-shot prisoner's dilemma via programs that basically say "cooperate iff the other guy's code cooperates with me." My worry: every version of this I've seen assumes each program gets *perfect, free* access to the other's full source. That's a wild assumption. Real agents would see compiled blobs, obfuscated code, or a limited sandbox, and verifying anything about the other program might itself be undecidable or just expensive. My hunch is that the cooperation result degrades gracefully or collapses entirely depending on how you model partial code access, and nobody has mapped out which. I want to study program equilibrium where inspection is noisy/costly -- e.g., players get a bounded number of test executions of the opponent's program, or a checksum that collides with some probability.

- What's Missing (about half a page): why the existing program equilibrium results and the obvious objections don't already answer this -- e.g., why you can't just wave your hands and say robustness follows from folk-theorem-style arguments.
- The Plan (about half a page): what I'd actually do, broken down roughly month by month. Be concrete -- is this pen-and-paper game theory, simulation, both?
- What Could Go Wrong (about a quarter page): what would count as the project failing, and which failure mode would still be a publishable negative result vs. just a dead end.
- Scope (2-3 sentences): why this is doable in 3 months and what I'm explicitly NOT trying to do.
