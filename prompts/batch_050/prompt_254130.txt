So I just reread Godel Escher Bach (yes, I know, most cliche book a programmer can reread) and the MU-puzzle is stuck in my head again. Recap so we're on the same page: in the MIU system you start from the string MI, and the rules are: if a string ends in I you can append a U, you can double everything after the M, any III can be rewritten as U, and any UU can be deleted. Can you derive MU? No — and the proof comes from OUTSIDE the system: the number of I's is never divisible by 3 (doubling a non-multiple-of-3 keeps it a non-multiple, deleting three at a time doesn't change divisibility), but MU has zero I's, which is divisible by 3. That's Hofstadter's whole jumping-out-of-the-system bit.

Thing is, every JOOTSing example I can find works basicly the same way: find a numeric invariant the rules can't break, show the target violates it, done. I want to see what it looks like when that trick is unavailable.

So build me a formal system, MU-puzzle style — one start string, 3 to 5 string-rewriting rules, an alphabet of 4 or 5 symbols max, and a target string — meeting this spec:

1. The target is provably NOT derivable from the start string. Not "I searched for a while and couldn't find a derivation" — provably not derivable.
2. The usual counting trick is genuinely useless here. Concretely: there must exist at least one derivable string with exactly the same letter-counts and the same total length as the target. So no mod-n argument on any character's count, and no length argument, can rule the target out.
3. The target is still underivable, but only because of a structural invariant — something about order, arrangement, adjacency, nesting, whatever — that the start string has, every rule preserves, and the target lacks.
4. Keep it small enough that I could check derivations with pencil and paper. No embedding a Turing machine in the rules, no diagonalization, no "derivability here is undecidable in general." This particular target has to have a decidable answer and the answer has to be no.

Deliverables:

- State the rules precisely, as rewrite rules (xI -> xIU style).
- Prove underivability: name the invariant, show the start string has it, check that each rule preserves it (all cases, including the awkward ones where a rule fires at the start or end of the string), and show the target fails it.
- Prove point 2 by actually exhibiting the derivable string that matches the target on counts and length, with its derivation.
- Tell me which specific rule is the one keeping the structural invariant alive — if I delete or weaken that rule, does the target become derivable? If yes, give the derivation. If no, explain what else is holding the line.

And one more thing: the classic failure mode for this kind of construction is convincing yourself a rule preserves your invariant when it actually breaks it on some edge case. So tell me which rule/invariant pair in your system you're least confident about, and exactly what counterexample string would sink it — i.e. what would have to be true for your whole answer to be wrong. If you think the spec itself is contradictory and nothing can satisfy all four points, that's a legitimate answer too, but then prove that instead of hand-waving it.
