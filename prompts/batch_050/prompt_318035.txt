I work on monitoring deployed language models, and I keep hitting a conceptual problem I can't get straight. The pitch for "mechanistic" anomaly detection — as opposed to ordinary outlier detection — is that we shouldn't flag outputs that look statistically unusual; we should flag outputs produced by a *different mechanism* than the one responsible for normal behavior. The two come apart in both directions: a backdoored model can produce perfectly typical-looking text when its trigger fires (the output distribution barely moves, but the internal causal story is different), and a well-behaved model given a weird input can produce statistical outliers via exactly its usual machinery. So far so good. But the entire approach rests on a notion I can't define: what makes two forward passes instances of the *same* mechanism?

Any two passes differ in some respect and agree under some description, so "same mechanism" has to mean "same under the relevant description" — but which description is relevant? I have three candidate criteria and they seem to give different verdicts:

1. Causal-graph identity: same mechanism iff the same internal variables mediate the output with the same functional dependencies, up to some tolerance.
2. Intervention equivalence: same mechanism iff the two passes respond identically to a fixed battery of counterfactual probes — ablations, activation patches, resamplings — even if their unperturbed activation patterns differ.
3. Task-solution identity: same mechanism iff both passes implement the same *solution* to the task (both genuinely computing, say, versus both retrieving from memory), however differently implemented.

Please explain, at a gut level, why individuating mechanisms is hard in the first place — why "same mechanism" can mean neither "same weights participated" nor "same input-output function" — and then apply all three criteria to one hard case: a model that usually does arithmetic via a learned algorithm but on some inputs answers correctly by consulting what is effectively a memorized lookup table. Under which criteria is the lookup-table pass anomalous? Where the criteria disagree, does that show that "mechanism" is interest-relative — definable only against a specific monitoring purpose — or that some of my criteria are simply mistaken? If it's interest-relative, I'd like to know whether that's a fatal problem for the whole approach or just a design parameter I should set deliberately.
