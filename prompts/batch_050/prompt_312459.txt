I'm a software engineer with no formal philosophy background, and I stumbled into this while trying to add a simple truth predicate to a toy logic engine I was building. Here is an argument that seems to prove something absurd, and I can't find the exit. Let K be the sentence "If K is true, then P," where P is any claim you like — say, that my codebase has no bugs. (1) A sentence is true if and only if what it says is the case. (2) K says that if K is true, then P; so K is true if and only if: if K is true, then P. (3) Assume K is true. Then by (2), if K is true, then P. (4) By modus ponens on the assumption and (3), P follows. (5) Since assuming K led to P, discharge the assumption: if K is true, then P. (6) By (2) again, K is true. (7) By modus ponens on (5) and (6), P. Since P was arbitrary, everything is true — which I refuse to accept. Two things make this worse for me. First, my naive fix was to ban self-reference outright, but I've since learned about Yablo's construction — an infinite list of sentences, each one saying only that every later sentence in the list is untrue — which apparently yields the same kind of contradiction with no self-reference anywhere, so that fix looks dead on arrival. Second, every individual step looks like inference I rely on daily when reasoning about programs. Which step should I reject, why did it look innocent, and what does rejecting it cost for ordinary reasoning?
