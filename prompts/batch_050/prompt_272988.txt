I'm a database engineer (15 yrs of Postgres, some query planner work), no philosophy training. I keep running into references to Nāgārjuna and his "tetralemma" thing, where for some claim -- say, "the self exists" -- he rejects all four options: it exists, it doesn't exist, it both exists and doesn't, it neither exists nor doesn't. And apparently this connects to the doctrine of emptiness, roughly the idea that nothing has its own intrinsic nature, and even emptiness is supposed to be empty somehow.

Here's what I want: restate this whole thing in vocabulary I actually think in -- SQL NULL and three-valued logic, IEEE 754 NaN, maybe Option/Maybe types if you need them. My gut says the mapping is trivially easy. In SQL, WHERE x = 5 drops NULL rows, but so does WHERE NOT (x = 5). So both p and not-p fail to come out TRUE, which looks a lot like the "neither" horn. And NaN is even spicier: NaN = NaN is false, every comparison with NaN is false, so NaN isn't even identical to itself, which sounds like "no self-nature" if I squint hard enough.

But I suspect the mapping is broken in interesting ways, and the part I actually care about is the residue report: what translates cleanly, what only translates with fudging, and what has no counterpart at all in this vocabulary. Concretely, the things I'm suspicious about:

1. SQL NULL (as Codd defined it) means "value unknown" -- it's epistemic, the value exists out there, we just don't have it. Is the tetralemma's rejection of all four options an epistemic claim (we can't settle it), or is it the stronger claim that the question itself is malformed? If it's the stronger one, isn't the closer analog a type error -- comparing an integer to a timestamp, which the engine refuses rather than answers -- rather than NULL?

2. In three-valued logic, if the self's existence is NULL, that's just a stable third truth value and the system chugs along fine. But from what little I've read, Nāgārjuna doesn't want you to settle on some third or fifth value either. Three-valued logic reifies the gap and makes it a first-class citizen. If Madhyamaka refuses to reify it, then no logic with a fixed set of truth values can express the position, right? If that's right, say it plainly.

3. The NaN self-inequality thing: genuine structural analog of lacking own-being, or am I just pattern-matching on general weirdness?

Bonus question: I know Codd at some point proposed splitting NULL into two markers, one for "missing" and one for "not applicable." If the not-applicable marker had survived into modern SQL, would it have been the better translation target than plain NULL?

And if your verdict ends up being "the tetralemma is really about rejecting the presupposition baked into the question," then tell me what in programming actually does that -- rejecting a query as ill-typed at compile time rather than returning NULL at runtime -- and whether that reframing demystifies the whole thing or just moves the mystery somewhere else.
