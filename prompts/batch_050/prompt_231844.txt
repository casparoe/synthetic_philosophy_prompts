I run a small recommendation API and hit a weird incident that feels like one of those conditional-probability traps, but I dont have the vocab for it.

Setup: two backend shards, A and B, get equal traffic. For requests served by A, failures are 90% timeouts and 10% crashes. For B, failures are 10% timeouts and 90% crashes. Overnight a complaint bot learns only this conditional: if the bad request came from shard A, it was almost certainly a timeout; if it came from B, almost certainly a crash. It does NOT learn which shard was hit. Then we observe exactly one failed request and get a ping saying teh conditional held for that request, but the payload got truncated before saying A or B.

Before the ping I had P(A)=.5, P(B)=.5. A teammate says conditionals never move priors, so keep shards at .5/.5 and only update timeout-vs-crash inside each branch. Another says use some minimum-entropy / Jeffrey-ish update with the new conditional probabilities, which also seems to leave shards at .5/.5 if traffic was equal. A third says we should image on the conditional: temporarily suppose A, recompute, suppose B, recompute, then mix by how unsurprising the ping would be under each shard.

Rank these rules best-to-worst for this incident, and score each /10 for: (a) not double-counting the conditional, (b) respecting that we did not learn the shard, (c) giving sane numbers if later we DO learn shard=A, (d) not exploding when base rates are not 50/50.

1 plain Bayes treating the ping as the material implication A -> timeout and B -> crash  
2 constrain posterior so P(timeout | A)=.9 and P(crash | B)=.9 while staying as close as possible to the prior  
3 imaging / suppositional update: compute under A and under B, then weight by how expected the conditional ping was under each  
4 ignore the conditional until a hard shard label arrives  
5 update P(A) by the likelihood ratio of receiving this kind of conditional ping under A vs B

Give a tier list, one worked posterior for the .5/.5 case and one for P(A)=.2,P(B)=.8, then say which rule you would ship in a monitoring system and which one is secretly equivalent to pretending the ping also leaked shard info. No textbook names needed, just concrete math and tradeoffs.
