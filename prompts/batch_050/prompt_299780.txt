I work as a backend engineer and recently attended a talk at a local rationality-adjacent meetup on decision theory and AI. The speaker introduced the idea of acausal trade -- two agents that can never communicate or causally influence each other nonetheless "trading," because each can reason about what the other is likely to do and act accordingly. To make it land for a technical audience, he used an analogy I've since heard repeated in my circles: an acausal trade is like two forks of the same codebase cooperating without a network connection. If I fork a repository and a colleague forks the same repository, the argument went, we can each predict the other's behavior because we share the same source; we can even "coordinate" -- I merge a patch assuming she'll merge the complementary one -- with zero communication. The speaker leaned on this to support a fairly strong conclusion: that a future AI could strike genuine bargains with alien civilizations it will never contact, or with simulated agents, because mutual predictability is all that trade requires. Something about the analogy feels off to me, but I can't articulate precisely where, and my formal-philosophy background is nil.

Could you audit the analogy for me? I'd like the correspondence made explicit -- a table is fine: what plays the role of the shared source code, the commit history, deterministic execution, the diff between forks, the merge, the "no network connection" -- and then an assessment of where the mapping breaks. A few suspected trouble spots I'd like addressed, though feel free to push back on them: first, forks diverge immediately after the fork point, so the shared code guarantees similarity only about the past, not about the future behavior the trade depends on; second, in the codebase case the correlation between the two forks is fully explained by their common causal origin, which seems to make it an ordinary causal explanation rather than anything "acausal," and I can't tell whether that undermines the analogy or actually vindicates it; third, with real code I can in principle read my colleague's fork, whereas the whole point of the acausal case is that nothing about the other agent is directly inspectable.

Finally, does the strong conclusion -- real bargains between causally isolated agents -- survive once the disanalogies are on the table, or was the fork analogy quietly importing exactly the features (shared origin, legibility, verifiable similarity) that do all the work? And if the fork picture is misleading, is there a better everyday analogy for what acausal trade actually requires -- I've seen Newcomb-style thought experiments and Schelling points mentioned in the same breath, but I'm not sure whether either is closer to the mark or just differently misleading.
