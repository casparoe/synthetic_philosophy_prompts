So here's my half-baked idea. We've been doing Frankfurt cases and the principle of alternative possibilities (PAP: you're morally responsible only if you could have done otherwise). The standard setup is that Black will force Jones to kill Smith if Jones shows any sign of not doing it on his own, but the sign never comes, so Black never acts, and Jones kills Smith anyway. Everyone in class either went for the "flicker of freedom" thing (Jones still had some tiny alternative, like the sign itself) or the "sourcehood" thing (responsibility is about where the action actually came from, alternatives are irrelevant).

My angle is different and it comes from my day job. When someone asks me whether a program "could have" behaved differently, that question is literally meaningless until you specify what you're allowed to vary: the inputs? the config? the network conditions? the code itself? Same program, same run, totally different answers depending on the test setup. We even do "chaos engineering" where we inject failures on purpose to check robustness, and Black's device is basically a fault that is prepared but never injected. So my suspicion: "could have done otherwise" is an underspecified counterfactual, and PAP only looks obviously true (or obviously false) because nobody says which variables get held fixed. Once you force people to write down the "test harness," maybe the Frankfurt case loses its bite, or maybe it survives under some specifications and not others, and the interesting question becomes which specification is the morally relevant one and why.
