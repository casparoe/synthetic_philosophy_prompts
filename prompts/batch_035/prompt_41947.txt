I'm a software engineer with no formal philosophy background, but I read code for a living and think in terms of modules, interfaces, call graphs, and refactorings. I've recently gotten interested in what philosophers call biological function — specifically the disagreement between etiological accounts, on which the function of a trait is whatever past selection kept the trait around to do (the heart's function is pumping blood, not making thumping sounds, because pumping blood is what hearts were selected for), and causal-role accounts, on which the function of a part is the contribution it makes to some capacity of the containing system, worked out by decomposing the system and seeing what the part contributes to the whole.

Restate each account, and the disagreement between them, in my vocabulary. Here is the rough mapping I have in mind, which you should use, correct, or replace as needed: an organism is a huge legacy codebase that nobody designed all at once and that has been shaped only by what got kept; a trait is a module or routine; etiological functions look like the reasons a routine is still in the codebase — the calls it was selected to answer, recorded in its history — while causal-role functions look like what the routine currently does for some system-level capability, read off the runtime call graph with no reference to history. If that mapping is doing smuggled work — for instance, if "recorded in its history" quietly encodes intentional design or an intelligent logger in a way that natural selection does not — say so plainly; I want an honest translation, not a flattering one.

Then give me the residue report. I'd like you to go through at least the following four points, and add others if they matter:

1. Malfunction. A defective heart still has the function of pumping blood even while it fails to perform it. In my world this looks like a routine whose contract says what it is for while its implementation fails the tests. Does the etiological account handle dysfunction as cleanly as contracts-plus-failing-tests suggests, and what does the causal-role account do with a broken part — is there anything in a purely runtime, call-graph view that says what a routine is supposed to do when it is currently broken and nobody wrote a contract?

2. The "also does" problem. The heart also makes sounds and contributes weight to the body; in code, a module's side effects sometimes turn out to stabilize things elsewhere in the system, and the system can come to depend on them even though nobody declared them. Which account draws the line between function and side effect, and does that line have a clean counterpart in the difference between a documented contract and behavior the rest of the system has silently come to rely on?

3. Vestigial code. Some code is dead but not deleted, and organs like wisdom teeth look like dead code retained because deleting it costs more than keeping it. Which account, once translated, handles "present but functionless," and what does the difficulty (or ease) of that case show about the translation?

4. The causal-role account seems to need a system-level capacity chosen in advance — the organism's survival and reproduction, or whatever target the analysis is aimed at — before anything in the system can have a function. Is that like having to decide which system-level feature you care about before you can say what any module is for? And does the etiological account avoid that choice, or does it just make the same choice earlier, under the name of "what selection was acting on"?

Finally, tell me what did not survive the translation. Is there anything the philosophers are arguing about that has no counterpart in a codebase whose only "designer" is selection pressure? If so, is that because my vocabulary is missing something, or because the disagreement is less substantive than it looks? I want a view, not a survey: if you think one of the two accounts is closer to right, say which, and argue for it in my terms.
