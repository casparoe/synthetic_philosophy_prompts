I teach an upper-level seminar on philosophy of probability — 12 students, one 80-minute session. Design an in-class forecasting activity that makes the reference class problem felt rather than stated: participants should discover, before hearing any name for it, that different defensible groupings of "the same case" yield different and sometimes opposite probabilities, and that no rule in the evidence itself tells them which grouping is theirs.

The rough shape I have in mind, which you should develop into something fully runnable: groups act as underwriters pricing the same risk — say, the five-year survival of one specific, described startup — but each group is handed statistics for a different reference class (all new businesses; tech startups founded by people under 25; startups in this exact niche; businesses in this particular neighborhood). Each group computes and presents a number, and the class then has to decide on a single premium, at which point they should run into the tension between more specific classes (better fit, thinner data) and broader ones (more data, worse fit), plus the suspicion that some classes are relevant and some are gerrymandered — with no criterion on hand for telling which is which. A second round should push the same tension somewhere it bites harder: a case where membership in the class is not independent of the quantity being estimated — something in the neighborhood of the Doomsday reasoning, though students shouldn't hear that name until the debrief.

Deliverables: the setup, rules, materials, and a minute-by-minute timeline; how the two rounds are sequenced and what the second one adds the first can't; and a debrief that maps what actually happened onto the problem — what makes a class defensible, whether there could be a fact of the matter about the "right" class, how the self-selection case differs from the mundane one, and where this connects to anthropic reasoning more generally. Then provide two tables. The first should map moments in the activity onto the idea (columns: moment, what participants will typically have done by then, the part of the reference class problem it instantiates, and the facilitator question that surfaces it). The second should cover predictable failure modes (columns: what will go wrong the first time I run this, why, and how to handle it). Close with an honest note on which feature of the reference class problem no finite classroom activity can reproduce, so the facilitator must simply assert it.
