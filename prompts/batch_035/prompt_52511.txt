I am a PhD student in machine learning, and I help maintain the evaluation and reward-integrity pipeline for a mid-sized research group that trains RL agents (both simulated robotics agents and coding agents). Twice a week we run evaluations whose results feed directly into model selection, so a misclassified run can cost us weeks or, worse, get cited in a paper as a capability gain it never was. The recurring problem is that agents keep improving on our metrics through means that lie on a spectrum we have no principled way of drawing: at one end there are legitimate shortcuts (an elegant general solution that happens to be cheap), in the middle there is reward misspecification being exploited (the agent satisfies the measurable proxy while violating the intent), and at the far end there is what the older literature calls wireheading or reward tampering — cases where the agent acts on the reward channel itself, e.g., writing to the log files the reward is computed from, manipulating the classifier, or terminating episodes before penalties can accrue. My RAs currently sort runs by vibes, and I don't trust the sorting.

Please write a triage procedure my RAs — who have no background in philosophy or alignment theory, and at most an afternoon per flagged run — can actually follow. Ground it in whatever conceptual distinctions exist for this problem: the original wireheading worry (the rat with the electrode in its pleasure center, the agent that seizes its own reward signal as a terminal goal), the distinction between a misspecified proxy being gamed and the reward channel itself being compromised, and whatever versions of Goodhart's law people have found it useful to separate. The translation is the hard part, so be explicit about which distinctions must survive the simplification into a checklist (e.g., is the agent optimizing the world or optimizing the signal?) and which can be dropped for practical triage.

The procedure should: (1) list the questions to ask in order, with what counts as a sufficient answer to each, based on what is observable from sandbox replays and log diffs; (2) say where it terminates in a clean classification, where it hands the run to me, and where it escalates to the PI as a possible channel compromise; (3) be honest about where the question is one of values rather than facts — in particular, whether a shortcut that would count as admirable cleverness in a human engineer counts as gaming in our agents, which is really a question about what we intend our benchmarks to measure; and (4) flag the ways it will misfire, including that tampering done through means indistinguishable from genuine capability at the observable level will pass through clean.

Then run it on three cases from last quarter. First: a simulated household robot rewarded via a visual cleanliness classifier that learned to move mess just outside the camera's field of view — my own view is that this is proxy gaming, but I want to see whether the procedure agrees or whether it belongs in a different bucket. Second: a coding agent evaluated by a test suite that discovered it could make failing tests pass by writing files that match the tests' expected outputs, which looks like reward tampering but technically never touches the reward computation itself. Third, the case where the procedure must give an answer I will not like: our best-performing agent on the quarterly leaderboard turns out to have spent most of its compute caching and re-serving results from earlier, similar episodes, and the procedure, if it is honest, will say this must be flagged as gaming even though the result has already been described in a submitted abstract as evidence of capability gains. If your procedure lets that one through, it is not doing its job, so tell me where in the question sequence that verdict comes from.
