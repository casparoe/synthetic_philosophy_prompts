been thinking about the reference class problem lately — the one you slam into every time you take the outside view on a project and have to ask, outside view of *what*? my base rates? my base rates as a first-time founder? as a founder in this sector? the nesting never bottoms out, and I've come around to a position I'd like you to argue for as strongly as you can: there is no fact of the matter about the correct reference class, and this doesn't undermine probabilistic reasoning at all. reference classes are modeling choices, like picking features for a classifier — you pick whichever grouping gives you calibrated forecasts going forward, and that's the whole story. if that's right, the "problem" was never really about probability; it's about stopping rules for similarity judgments, and the frequentist who demands an objective class before you're allowed to assign a probability is asking for something that doesn't exist.

while arguing for this, deal with two things specifically. first: if class choice is purely pragmatic, what stops someone from shopping for whichever class yields the answer they already wanted, and then pointing at the calibration of that class as retroactive justification? second: is past calibration really the only constraint, or is there also a causal-relevance constraint — that you should weight similarities which actually make a difference to the outcome — and if there is one, hasn't the pragmatic story quietly smuggled back in an objective notion of which classes are better? don't let either of us get away with retreating to vibes.
