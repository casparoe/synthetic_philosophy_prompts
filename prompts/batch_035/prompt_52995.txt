So I'm a software engineer, ML background, no philosophy training at all, and I got sucked into bayesian stuff through the usual route (learning about calibration, betting, that kind of thing). I like the picture where a rational agent is just a box that holds credences and shifts them by conditionalization when evidence comes in. Clean, implementable, I've literally written toy versions of it.

But then I hit something people call the "problem of old evidence" and it's been bugging me. The classic example: when general relativity came along, the weird wobble in Mercury's orbit was already known and had been known for decades. Everybody agrees GR got big points for explaining it. But conditionalization says you only update when you learn something new, and the agent already knew about Mercury. So where do the points come from? If there's no update event, a strict Bayesian seems to have to say old known evidence can't confirm anything, which is crazy, and yet the obvious patch -- "just imagine you didn't know it and update counterfactually" -- has its own problems (which counterfactual? what if I can't unlearn things coherently?).

I've half-collected a bunch of requirements that any fix to this should meet, but I don't trust my list and I want someone to do it properly. Write the desiderata: what an adequate account of confirmation-by-old-evidence has to deliver, with the case behind each one. Some things I suspect belong on the list, but push back on any that are wrong or missing:

- it has to handle the case where the NEW thing learned is a theory, not a piece of evidence (this seems different and harder -- when I first hear about GR, what's the event I'm conditioning on, exactly? my algebra of events didn't have "GR" in it before)
- it can't let the agent manufacture confirmation out of nothing -- if I can always "discover" a hypothesis after the fact that I know fits the data, and then cash in the data as confirmaton, everything confirms everything and the account is broken
- it should not depend on the agent being logically omniscient (I'm a programmer, I know all about systems that don't know all the consequences of what they know -- honestly this failure mode feels like the whole problem in disguise)
- it should say something about the difference, if any, between explaining data you already had vs predicting data you don't have yet (people keep insisting these are different but bayesians keep saying they shouldn't be, I want to know if that's a real requirement or a prejudice)
- it should be implementable, or at least idealizable -- I care whether a bounded agent with finite memory could actually run the account, not just whether an idealized angel could

For each requirement say what case or consideration motivates it, then flag which ones you think are non-negotiable versus which are wants of one camp, and importantly: tell me if any subset of them can't all be satisfied together, because I have a growing suspicion that "no confirmation manufacturing" plus "handle newly learned theories" plus "no logical omniscience" is jointly impossible, and if the whole list is unsatisfiable that's actually the answer I want, not a failure.

Then, briefly, run the two fixes I've heard of against the list: the counterfactual one (pretend you forgot the evidence, condition, then re-learn it) and the one where you expand your event space so that "learning the theory" itself becomes an event you can condition on. Don't do a big literature survey, I'll find the names myself -- I mostly want to know where each one breaks against the requirements.
