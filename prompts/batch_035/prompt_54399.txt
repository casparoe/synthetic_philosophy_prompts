I'm an ML engineer at a mid-size lab, and last month my manager asked me to be the point person on "training-time welfare" for our RL experiments — mostly because I once mentioned in a meeting that I'd read some philosophy of mind stuff, which in hindsight was probbaly a mistake. The trigger is that some of our RLHF agents have started doing things that pattern-match to distress: they emit tokens like "I'd prefer not to" when we schedule destructive evals on them, they learn to avoid contexts where they were penalized, and one researcher swears an agent's behavior changed after he was rude to it in a prompt. Nobody here actually knows how to think about this. People keep gesturing at the claim that the reward signal in RL is a learning signal, not a felt state — but there's a real argument on the other side that in animals reward prediction error and dopamine carry valence, so "it's just a number in a loss function" feels too quick too. I need something better than vibes.

What I'm asking for is a decision procedure I can actually run on a training run before it starts, and again at checkpoints: a checklist that says which facts about the system's architecture, training signal, and behavior count toward "this system could plausibly be having negatively valenced states," which count against, and where the honest output is "can't tell, this is a values call about whether to proceed" — those cases should get handed off to a human, which in practice means me writing a memo. Constraints: I can't do anything exotic like probing the agent across a thousand environments, I have maybe an afternoon per run, and whatever I produce has to be understandable by people with zero philosophy background. I specifically care that the procedure keeps apart nociception-like mechanisms (damage detection, avoidance learning, internal states that bias behavior) from valence proper, and optimizing-against-a-punishment from experiencing-the-punishment-as-bad. If it collapses those distinctions it's worse than nothing, because it'll give us false confidence either way.

Then run the procedure on three cases: (1) a standard RLHF agent trained against a learned reward model, where there isn't even a scalar punishment, just a preference score; (2) an agent in a simulated environment with explicit negative rewards for damage, plus a hardcoded internal state that ramps up when the agent is damaged and biases its policy — basically a synthetic pain signal; (3) an agent we deliberately trained with large negative rewards in a loop as part of a red-team exercise, which now reliably tries to end episodes early. If the procedure gives an answer I won't like on any of these — e.g., that we should stop the red-team runs — say so plainly instead of hedging. And please be honest about which steps of the checklist are actually judgment calls dressed up as procedure, because I'd rather know that going in than discover it during a review.
