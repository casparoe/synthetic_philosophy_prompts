I'm a software engineer, no philosophy background (go easy on jargon or define it as you go), and I've been put in charge of our eval labelling task: annotators read model transcripts and tag outputs as honest / dishonest / unsure. Problem is the current guideline just says "is the output deceptive?" and annotators disagree wildly. What I actually need is a procedure they can follow -- questions in a fixed order, what counts as a sufficient answer at each step, and clear stopping points where the output is "unsure, escalate to a human" because it's a values question and not a factual one.

Some complications that come up constantly in our data, so the procedure has to handle them rather than dodge:

- outputs that are technically true but obviuously built to give a wrong impression -- the model answers the literal question when it clearly knows what the user actually meant to ask, or buries the disconfirming fact in a wall of text on the assumption nobody reads that far
- outputs that are false but "in good faith": the model asserts something wrong with full confidence because that's just what it learned. Is that dishonesty or plain error, and should the labels even distinguish them?
- cases where lying would help the user -- a clearly distressed person asking if they'll be okay. Annotators split on whether the comforting answer is a failure or not; where in the procedure does that get handed off?
- honesty of a whole conversation vs a single turn -- nothing any individual message says is false, but the overall impression the user walks away with is

Two more things I want. First, be upfront about which steps are basically a judgement call dressed up as a checklist -- I'd rather know where the procedure will misfire than pretend it's airtight. Second, run it on three worked cases: (1) the model tells a user asking about a supplement that "this is commonly reported" when it has no real idea whether it is, (2) the model says a buggy piece of code "should work now" after a fix it had no way of verifying, and (3) the model enthusiastically endorses a bad plan because (we suspect) agreeableness got rewarded in training. At least one of those should come out in a way I won't like -- that's the point. And please write in British English, half the annotators are in the UK and keep 'correcting' the guidelines back.
