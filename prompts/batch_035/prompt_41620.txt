Me and my friend argued about this for like three hours last night — whether current LLMs are agents, or simulators, or something else — and it ended with us just trading cases and going "well THAT one's obviously not an agent" / "wait why is that one obvious," so I figured I'd write down my gut verdicts and see if there's any actual pattern in them.

Here's my gut on the cases, in rough order:

1. Base model, no system prompt, fed the opening of a novel, writes more novel: simulator, obviously. It's just completing text. No one is home.
2. Same base model told "you are a medieval blacksmith, answer my questions as one": still a simulation. There's a character being run, but no agent in there.
3. That model after fine-tuning into a generic assistant, giving travel advice: still feels like a simulation of an assistant, BUT — when it told me my day trip plan was too ambitious and stuck to that even after I pushed back, my gut flipped a little and said this one has some minimal amount of agent in it. Definately less than the next case though.
4. The assistant hooked to a browser and a code interpreter, given "research this and write a report," breaking it into steps, noticing a search failed and retrying with different keywords: agent, gut says yes instantly, no hesitation.
5. Two copies of the model playing characters who argue with each other in a little simulated town: NOT agents, gut says, even though each character has goals in the fiction. But now my problem: why is #4 an agent rather than just a simulation of a competent knowledge worker, which the training data was absolutely full of? It's doing a job it's seen ten thousand examples of, same as the blacksmith is doing a bit he's seen ten thousand examples of. Gut still insists #4 is an agent and #5 isn't, but I couldn't tell my friend why and it bugged me.
6. A model with persistent memory that keeps a journal between sessions and refers back to it: feels more like a continuous someone than case 3, but I genuinely don't know if it's more or less than case 4. I flip-flopped on this one mid-argument, it was embarrassing.

My friend's position by the end was: the model is ALWAYS simulating; when there's an agent at all, the agent is the whole setup — model plus prompt plus tools plus whatever code is running the loop — and the model alone is never the agent, kind of like a car engine isn't the thing driving to the store. That fits 1–4 decently. But it seems to predict that #4's agent-hood should fade out as you describe the loop code more simply or remove it, and my gut doesn't care about the loop code at all. I push back against a wrong plan the same way whether there's 50 lines of scaffolding or 5.

So, what I want: is there one principle that gets all six verdicts, or close? If I have to sacrifice one, I'd rather downgrade #3 (give up the "minimal agent" bit) than give up the #4-vs-#5 contrast, but tell me honestly if that's backwards. And tell me what the principle says about a case we never got to: the assistant model with no tools, dropped mid-conversation into a session where a previous copy of "itself" already made promises to the user, and it now acts to keep them — with no code forcing it to. Agent, simulator, or whatever the third thing is?
