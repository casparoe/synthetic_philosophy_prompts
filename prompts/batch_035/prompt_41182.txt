I teach an upper-level seminar on minds, machines, and computability — fourteen students, one 90-minute session — and next week we reach the Gödelian anti-mechanist argument: the thought, associated with Lucas and Penrose, that for any consistent formal system whose axioms and rules we can survey, we can construct a sentence the system cannot prove but which we can see to be true, so our mathematical understanding cannot be any such system. I want them to run into the argument as a lived experience before it is named. Design the activity accordingly: no lecture up front, and Lucas's and Penrose's names should not come up until the debrief.

The core mechanic should be a confrontation between two roles. Some students (say, three rotating groups) play formal systems: each receives an explicit axiom sheet and derivation rules, and its only permitted public behavior is to emit strings derived stepwise from those rules, with a referee checking each derivation against the sheet. The other students play mathematicians, whose task is to decide, for each machine output and each machine specification, whether they themselves can endorse the sentence as true — but crucially, the mathematicians may not use any argument they cannot articulate; anything they assert must be articulable in principle, though not necessarily derivable from any machine's sheet. The pivotal round should exploit the fact that whenever a machine's specification is public, the mathematicians can form the sentence that says of that very machine that it never proves falsehoods, or a diagonal sentence targeting it, and see that if the machine is trustworthy then this new sentence is true while being beyond the machine's reach. Later rounds should complicate the picture: a black-box machine whose specification the mathematicians are never shown, a machine that turns out to be inconsistent and emits a contradiction, and a machine that asserts its own soundness in some form. Devise a scoring system that makes these complications matter — for instance, machines gain points for outputs the mathematicians endorse, mathematicians gain points for endorsing truths, and lose points for endorsing falsehoods, so that inspecting versus trusting a specification carries real stakes. No real money.

Then the debrief: map each round onto a component of the argument and onto the standard mechanist replies — that the machine may be unsound, that the human mathematicians might themselves be inconsistent, and that the diagonal move requires the human to know which machine it is aimed at. Identify which round most nearly forces each reply. Tell me what will predictably go wrong the first time I run this (my guesses include students playing machines drifting into informal reasoning to win, and mathematicians overreaching on the black-box round, but I want your diagnosis and remedies). Finally, be frank about the feature of the actual dialectic that no staging can reproduce — that if mechanism is true, the mathematicians' own diagonal insight is itself the output of some system, so the felt asymmetry between surveying a specification from outside and generating insight from inside is exactly what a game must manufacture artificially — and explain what I, as facilitator, must supply in its place and how to flag that supplementation honestly in the debrief.
