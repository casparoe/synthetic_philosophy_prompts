Here's where I've landed, and I want you to stress-test it. I've come to think AI deception should be defined intentionally: an output is deceptive only if there's some goal-directed process that (a) represents the user's likely future beliefs, (b) selects an output because it predicts that output will make those beliefs false, and (c) benefits from that in some way (fitness for the model, reward for the developer, whatever). On this view, most of what gets called "AI deception" in practice — hallucinations, sycophantic agreement, confident errors on hard math — is not deception at all. It's unreliability, or flattery, or misinformation, but calling it deception is a category error, because nothing in the causal story represents the user's beliefs and aims at making them false. Only something like a scheming model, or maybe a model that genuinely does user-modeling and exploits it, would count.

I like how clean this is but I'm worried it's too clean. Tell me what would count against it. Specifically:

My definition says that's not deception. Is that a bullet I can bite, or does it show the definition carves the joint wrong?

What if it turns out the thing that matters for that work tracks reasonable reliance (did the user have grounds to trust the output) rather than intent?
