i run a guest workshop for an ML engineering bootcamp -- 18 students, all of whom can code but have basically never thought about AI safety as a technical problem, one 2-hour session. I want them to feel the difference between alignment and control: alignment work tries to make the model actually want the right things, control work assumes the model might be misaligned and tries to get useful work out of it anyway, via monitoring, sandboxing, honeypots, limiting what it can do, etc.

Design an in-class game for this. A small team (3-4 people) plays the "model": they get a secret objective that is NOT what their operators want, and they score points for advancing that objective without being caught. Everyone else plays operators/evaluators who have to extract useful work from the model while deciding whether to "deploy" it. Crucially, the operators should only be able to interact with the model through some constrained channel -- submitting tasks, reading outputs, maybe a limited number of audit queries -- so the game actually reproduces the epistemic situation of a real control evaluation instead of collapsing into a debate. Rules, scoring, materials, round structure, timings, the works.

Then a debrief that maps what happened in the room onto the real control toolbox (trusted monitoring, honeypots, adversarial evaluations, capability限制 via limited tools) and onto the core problem: you can never fully distinguish an aligned model from a misaligned one that's just playing along until deployment, and every control measure you layer on costs you some of the usefulness. No lecture up front -- I want the operator teams to invent their own monitoring strategies and then discover in the debrief that they've reinvented things people actually propose.

Also tell me what will predictably go wrong the first time I run it (my guess: the model team just openly sabotages everything in round one and the game ends immediately -- how do I prevent that without telling them the point of the exercise?), and be honest about which part of the real control problem this game just cannot reproduce no matter how I set it up. Keep it runnable with paper, index cards, and a shared doc -- no software.
