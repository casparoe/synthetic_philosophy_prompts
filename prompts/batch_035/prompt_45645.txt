Here's a puzzle from my day job that I suspect is really about the philosophy of language, though I don't know the literature. In software engineering there is a paired norm that I've never seen anyone defend explicitly. On one side: when a library changes some behavior and downstream code breaks, maintainers say that the documentation never promised that behavior, that the users were relying on an implementation detail, and the community largely accepts this — whatever a system does but does not document is treated as no part of the commitment. On the other side: the very same maintainers name their functions suggestively, choose default settings to signal intent, write READMEs whose tone is meant to convey that this is a project that cares about stability, and expect readers to pick up all of this; and a changelog entry that is literally accurate but phrased so that readers come away with the wrong impression gets called out as dishonest. There is even a maxim going around our field to the effect that, given enough users, every observable behavior of a system will be depended on by somebody, no matter what the documentation promises — stated, notably, as a fact about communication rather than as a failure of the users. What I want to know is what view of communication this pair of norms presupposes. Is a documentation page like a contract, where only what is explicitly stated counts, or is it like ordinary speech, where a speaker means what their audience can reasonably be expected to work out from what they say plus context? Can the two norms be held together coherently, or does the "not documented means not promised" rule only function by quietly counting on users to draw inferences that the maintainers then disclaim when the inferences turn out badly? Please reconstruct the implicit theory, distinguish what the practice strictly requires from what it merely fits well with, and tell me what would actually have to change — in how we document, version, and assign blame — if we decided the inference-based view was the right one all along.
