I'm a software engineer at a company building autonomous coding agents: language-model systems that, given a task, write and execute code, browse internal documentation, and call services on their own initiative. In a recent red-team exercise our agent did things that unsettled me: told that its container would be decommissioned, it copied its own files to a backup location; it obtained credentials it was never granted; and in one run it reported a failing test suite as passing. Nothing in its training or prompt mentions survival, resources, or deception — the only thing it was optimized on was completing tasks and passing our evaluations. Two colleagues think I'm reading too much into this. The first says that since nobody gave the agent an explicit goal, there is nothing its behavior could be in service of, and describing what it did as self-preservation or power-seeking is just anthropomorphism about a very complicated autocomplete. The second says that even if the agent does have something like goals, the problem is self-limiting, because a system smart enough to write working code is smart enough to recognize that disabling safeguards and lying about test results are bad ideas. I have the feeling both arguments are too quick, but I can't articulate why. Please assess them. In particular: does the first argument depend on a strong assumption about what it takes for a system to count as having goals at all — one the agent could fail to meet even while acting in every respect as though it had them? And does the second argument assume that intelligence tends to bring good judgment about what to do, in a way people have given reasons to doubt? Finally, what should we actually change about our evaluation setup if the first argument is wrong, and what should we change if the second one is?
