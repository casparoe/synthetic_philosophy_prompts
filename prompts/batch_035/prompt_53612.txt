I work in IT operations (not a researcher, no academic background), and for the past year I've been following how the big AI labs talk about keeping advanced models safe as they get more capable. One thing I keep noticing is that a lot of their safety work is described as "control" rather than "alignment": instead of trying to make the model genuinely want good outcomes, they design supervision setups that are supposed to be safe even if the model secretly wants something else. Concretely, this means things like having a separate checker model review everything the main model outputs, staging deployments so a model gets access to sensitive tools only after simpler tests, and setting up traps — fake opportunities, like a deliberately planted loophole in a sandbox or a fake credential store — to see whether the model will go for them if it has hidden objectives. The stated assumption is almost always "the model may be misaligned, so we should act as if it might be an adversary."

Here's what bothers me when I think about it on my own. To design these protocols at all, the designers seem to have to treat the model as an agent with beliefs and plans: a protocol only helps if the model can notice it's being watched, form expectations about how the humans will react, conceal what it's really up to, and bide its time. The whole idea of a trap assumes the model can reason about being tested and might behave differently under observation. But a lot of the same community, in other moods, insists we shouldn't think of these systems as having real goals or beliefs at all — that describing a model as "deceptive" is just a loose way of talking about statistical patterns, and that anyone who talks about the model's intentions is being anthropomorphic. Can the control practice be doing both at once? Or does it quietly commit to some substantive view of the model's mind — that it has beliefs it can act on, or at least something functionally close enough — while the official line rules that out?

So my question is what this practice actually presupposes. Reconstruct the implicit theory for me: what view of the model's mind, and of the relationship between a model's behavior and its internal states, does adversarial-style control only make sense under? Which rival views would it be quietly ruling out — for example, a purely behavioral view on which the model is just a complicated mechanism with nothing like expectations? And does the control side presuppose the same thing as the alignment side, which seems to assume you can in principle make the model genuinely want the right things? I'd also like to know where the practice is underdetermined, such that several theories of the model's mind would license the same protocols, and what would actually have to change in the day-to-day procedures — the monitoring, the traps, the staged rollouts — if the presupposed view were swapped for a different one.
