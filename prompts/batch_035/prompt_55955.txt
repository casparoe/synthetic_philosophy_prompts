I teach an upper-level philosophy of mind seminar on whether the brain is a computer — 14 students, one 90-minute session. Design an in-class activity that makes them run into the implementation problem before they can name it: the worry that if computation is just a mapping from physical states to computational states, such mappings are so cheap to produce that either every open physical system implements every program (making computationalism vacuous), or the computation exists only relative to an interpreter (making it not something in the system itself).

The core of the activity should be a sequence of at least four staged physical systems, presented one at a time, on which the class must issue verdicts about whether the system computes a specific function (XOR, say). You may extend or vary this list: a silicon circuit computing XOR; the same function built from valves, water, and floats; a person in a room following a lookup table and handing back outputs without seeing what passes through; a dripping faucet or drifting cloud whose pattern someone — an outside party with a mapping table — claims encodes a run of the same program. Split the class into juries with a fixed verdict form (computes / doesn't compute / computes only relative to an observer), a scoring scheme that rewards consistency across cases rather than any particular answer, and rules for how evidence may be inspected. Include a timeline, and a debrief that maps their verdicts onto the dilemma — showing that treating the last two cases as genuine computation collapses the distinction the first two cases were meant to draw, while refusing them forces a criterion the juries must then state explicitly and defend. Tell me what will predictably go wrong the first time I run it, and be honest about which feature of the implementation debate a staged activity cannot reproduce and I will have to supply in the debrief.
