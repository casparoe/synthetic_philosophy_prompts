me and a coworker keep having the same argument over slack about what counts as an "alignment failure" vs just a bad product / bad operator situation, and I want to settle it with a decision tree I can paste into our team wiki. The tree should take a description of a bad outcome involving an AI system and sort it into: alignment failure or not, and if yes, which kind. We're both software engineers with no philosophy background, so every branch node has to be a question you can actually answer from the case description itself ("did the system do what the operator literally asked for?"), never a question that presupposes you already know the terminology. Build the logical space first and then locate the leaves in it: one axis should be roughly what the intent is being aligned *to* (the operator's literal request, what the operator actually wanted, what they'd endorse on reflection), another axis should be whether the badness traces back to the operator's own values or to something the system did on its own. Leaves should include at least: system did exactly what was asked and the request itself was the problem; system did what was meant but not what was said; system was pursuing some proxy and neither; and the case where everything worked exactly as intended and the world is still worse off — that last one is the core of our argument, since on the narrow definition of alignment that leaf maybe isn't an alignment failure at all and belongs on some other tree (politics? deployment policy?). Flag any pair of leaves you can't really seperate from a case description alone, and note if there are combinations in your space that no one defends and whether thats because they're incoherent or just unexplored. If it helps, aim for something like 8-12 leaves so it fits on one page.
