I work on large legacy software systems, and I've noticed a configuration I can't find a proper word for. Some objects in a system seem to exist only relative to a particular way of predicting the system — but once you adopt that way of predicting, they behave exactly like ordinary objects: they persist through changes, they have locations, you can intervene on them and the intervention works. Two examples. In a flocking simulation, no line of code mentions a flock; every agent follows purely local rules. Yet the flock — its centroid, its habit of splitting when startled — is by far the most compact way to describe what the screen will look like in ten seconds, and if I drop an obstacle into the flock's path, the flock responds in the flock-level description just as an object of that shape would. In the codebase I maintain, nothing anywhere stores the user's intentions, but treating the input-handling subsystem as if it believes the user wants a certain outcome and is trying to bring it about predicts that subsystem's behavior far better than any specification or trace I can write down. In both cases the pattern is not written into the system; it is a compression you can find in the system, and it beats the literal description.

Two features make me suspect this is not just what people loosely call emergence. First, whether the pattern is present seems to depend on the observer's budget: an observer with unlimited time and memory could simply run the micro-level forward and would never need to posit the flock at all, so the pattern's existence appears to be indexed to observers who, like me, are in a hurry. Does that make the flock real, or merely real-for-us, and is there a principled distinction between those? Second, the boundaries wobble: two different predictive shortcuts over the same codebase pick out slightly different subsystems — one includes the retry logic, one doesn't — and both compress well, so which of them is the real object? Is there an established concept or literature for patterns that exist by out-competing the literal description of a system, together with the observer-dependence and boundary problems that follow? I would also like to know how the answer distinguishes these from merely useful fictions, since the patterns support interventions and counterfactuals in a way ordinary fictions do not; and if there is no established concept, I would settle for a careful definition and some boundary cases.
