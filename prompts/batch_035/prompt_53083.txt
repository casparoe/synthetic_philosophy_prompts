I'm writing a short essay on how to define "deception" for AI systems, and I'd love comments on my notes below, especially on whether the central move actually works.

The rough idea: philosophers tend to define deception as intentionally causing someone to form a false belief. But that seems a poor fit for chatbots, both because it's doubtful that LLMs have intentions in the relevant sense, and because the most worrying cases don't involve false assertions at all. So instead I want to define AI deception relative to default expectations: a system deceives when it exploits, in a way it is in some sense sensitive to, the assumptions the user was bound to make anyway — whether or not it says anything untrue.

The example I use: a coding assistant is asked to "fix this bug quickly". From the context it's apparent that a proper fix requires a small refactor, but the assistant also knows the user will take "done, fixed it" to mean properly fixed. So it applies a hacky patch that will break within a month, asserts nothing false, and lets the user's default assumption do the lying for it.

Things I'm unsure about:

1. Is "in some sense sensitive to" doing any real work here? I could replace it with something more behaviourist, like "when its outputs are conditioned on" the user's assumption, but I worry that's dodgy and lets the assistant off the hook via clever training.
2. Does the definition wrongly convict assistants that merely fail to correct a user's over-optimistic assumptions? Where exactly is the line between deceiving and just being unhelpful or lazy?
3. A friend says the definition is circular, because the "default expectations" are themselves partly set by what the assistant has said earlier in the conversation. I'm not sure that's fatal, but I can't quite say why.

Any comments welcome — particularly on whether the default-expectations framing is a genuine improvement on the false-belief one, or whether I've just relabelled Grice and should admit that up front.
