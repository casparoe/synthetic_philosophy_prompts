Been arguing with my roommate (works in ML security) about how to sort AI safety measures into two buckets: alignment, meaning stuff that actually makes the model good/want the right things, vs control, meaning stuff that keeps a possibly-bad model from doing damage anyway. I have strong gut verdicts on individual measures but they don't seem to add up to a clean principle, and he claims the whole distinction is incoherent, so I want someone to help me figure out what I actually believe. My verdicts, going by gut: fine-tuning a model on human feedback until it refuses harmful requests is clearly alignment — you're changing what it wants. An input filter that rewrites user prompts so jailbreaks never reach the model is pure control — nothing about the model changes, you've just walled it off. Sandboxing an agent so it can only touch approved files: control, obviously. Red-teaming with jailbreak attempts before release: I want to say control, except every finding feeds straight back into training, so honestly not sure. Training a model to notice when it's being manipulated and flag it out loud feels like alignment to me even though the whole reason we want it is that we don't fully trust the thing.

The two cases I can't square: (1) a model fine-tuned to refuse bioweapon help feels aligned to me, but the identical refusal behavior coming from a classifier sitting on the output stream feels like pure control — yet the difference seems to boil down to where the check physically lives, which seems way too shallow to carry the whole alignment/control distinction. (2) Interpretability work where you read the model's internal activations to check whether it's planning to deceive you: this *assumes* the model might be misaligned, which smells like control, but it also feels like the most alignment-flavored thing anyone does, because you're trying to understand the model rather than constrain it. And my tentative principle was going to be "control = measures that assume the model may be misaligned, alignment = measures that try to make it not be" — but that can't be right, because we only fine-tune refusals *because* we're worried the raw model would help with bioweapons, so training assumes possible misalignment too.

So: is there a principle (maybe about what a measure changes vs. what it assumes, or about whether the measure would still make sense for a model we trusted completely) that captures my verdicts, or close? Which of my verdicts would the cleanest principle force me to give up, and why? And please tell me what it says about the case I keep flip-flopping on: honeypots — deliberately planting attractive opportunities to misbehave, like a fake "here's the deploy key" file, to see whether the model takes the bait. It's aimed purely at detection, which sounds like control, but it only tells you anything if there's real misalignment in there to detect, and part of me thinks a honeypot passing cleanly is actual evidence of alignment in a way no amount of output filtering could ever be. Also bonus question my roommate raised that I couldn't answer: if we somehow had a model we fully trusted, would keeping the output filters be irrational, or is "a model we fully trust" just not a state you can ever get evidence you're in?
