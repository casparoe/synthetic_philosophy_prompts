I'm a PhD student in database systems — query processing and view maintenance, specifically — with no philosophy background beyond scattered reading. I'd like you to restate the classic frame problem from AI and philosophy of mind in the vocabulary I actually use, as faithfully as you can: updates, transactions, materialized views, triggers, incremental maintenance versus recomputation from scratch, invalidation, and the analysis of which derived structures a given write can possibly affect. Then I want the residue report: which parts of the philosophical problem map cleanly onto that vocabulary, which you had to distort to make them fit, and which have no counterpart at all.

To be concrete about the mapping I suspect, so you can correct it: in my world, when a transaction modifies a base relation, we don't recompute every derived view from stored data; we have rules specifying which views each kind of write touches and how to patch them incrementally. The narrow frame problem, as I understand it, was about an agent updating its beliefs after an action without re-deriving every unaffected fact — writing out the "nothing else changed" axioms for all of them blows up. My analogue is that an update to an inventory table leaves a view over customer addresses untouched, and we know that statically from the query structure, not by checking anything at runtime. The naive version of the worry — how do you know the wall behind the robot didn't change color when it picked up a block, without checking? — looks to me like an engineering discipline we solved: dependencies between base data and derived data are analyzable up front.

But I gather philosophers think something important is left over, and I want to know exactly what. I've run into two candidates. One is the qualification problem, the endless exceptions to an action's preconditions, which seems to map onto trigger conditions that can never be made exhaustive. The other is the broader reading, associated with Dennett among others, on which the real problem is how an intelligent agent decides which of the unboundedly many potentially relevant considerations are worth attending to, without enumerating them — which in my terms looks like asking which views to maintain when the schema is not fixed in advance and the future query workload is unknown. Our discipline quietly assumes both away: relevance analysis is always relative to registered queries. For each of these three — the narrow persistence problem, the qualification problem, and the relevance version — please say what it becomes in my vocabulary, what gets distorted, and whether the translation failure is a defect of my vocabulary (we offload open-endedness to schema design and workload evolution, which are somebody's job) or evidence that the frame problem was never a well-defined technical problem in the first place. And tell me whether the split between "solved engineering" and "unsolved philosophy" tracks a real boundary or is an artifact of which parts of the problem my field was able to formalize.
