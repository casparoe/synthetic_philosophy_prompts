You're a veteran AI-policy researcher who's spent years mediating adversarial collaborations between technical camps that argue past each other. I need your help drafting one.

Setting: my lab has two factions that have been fighting for like two years about tool AI vs agent AI. The "tools" camp: we should build systems that answer questions, draft artifacts, and hand control back to a human who decides and executes — because error compounds over long action chains, accountability blurs when a system acts on its own, and keeping a human at the decision point is both safer and respects human agency. The "agents" camp: tool-only is a fantasy — lots of the actually-valuable tasks (a week-long codebase refactor, running experiments, managing infrastructure) just aren't decomposable into one-shot tool calls, and anyway the "human in the loop" is a rubber stamp once reliability gets high enough; moreover "tools" quietly become agents the moment you stack an orchestration layer on top.

They finally agreed to a proper adversarial collaboration and I'm supposed to write up the joint statement. Please do it for me.

Start with a short brainstorm/outline (bullet points, doesn't need to be pretty), then produce the final document. The doc should contain:

1. A numbered section of claims both camps can sign. This should include things they genuinely agree on — about capability, about incentives, and importantly about the fact that "tool vs agent" is a spectrum rather than a binary (they actually already agree on that last one, which is part of why the shouting has been so unproductive).

2. A disagreements table. Each residual disagreement must be worded so that its own side would read it and say "yes, that's our position, fairly put." No strawmen, no hedging into vacuity — if a phrasing is so watered down that neither side would object, it belongs in section 1, not here.

3. The cruxes — the sub-questions such that settling one would actually move at least one camp. I suspect one is what we've been calling the verification asymmetry: whether agent outputs are intrinsically harder to verify than tool outputs (you see the artifact but not the process, and over long horizons the artifact is all you get), or whether that's just a current-engineering artifact that better logging, process transparency, or evaluation methods would erase. Another candidate crux is automation-bias transfer: the tools camp thinks a human with a tool genuinely decides, while the agents camp thinks the human rubber-stamps either way once reliability is high enough, so the "human decides" benefit is illusory and the camps are pricing the same thing differently. A third: the competitive-erosion argument — whether a lab that stays tool-only is a stable position or just gets outcompeted by whoever ships agents first, and whether that's an argument about the world or about what we should do given the world. Feel free to add or drop cruxes if you see better ones, but justify briefly.

4. For each crux, specify the argument, test, or observable development both camps agree would bear on it, and record each side's prediction in advance — this is the part they'll be graded on later, so the predictions need to be specific enough to be checkable.

5. Both camps have privately admitted to me that some chunk of this fight might be verbal — e.g. whether an orchestrated pipeline of tools on a scheduler already counts as an agent, or whether "the human decides" means decides-each-step vs decides-the-goal. If you conclude part of the dispute is verbal, say which part, why, and give the reformulation that dissolves it.

Think carefully and take your time with the wording of the disagreement rows — the whole value of an adversarial collaboration is making the residual disagreement exact, not papering over it. No citations, no reading lists, this is an internal doc for a model without web access anyway. Final statement should be ~1000-1200 words (the brainstorm doesn't count toward that).
