I'm a software engineer with no formal philosophy training, and something about how our industry investigates failures has started to puzzle me. When a production service goes down, we hold a postmortem and hunt for a "root cause," and the causes we accept live at a particular level of description: a misread config flag, a missing fallback in a retry loop, a deploy that reordered two database migrations. We write that the code "assumed" the upstream API was idempotent, or that the client "believed" a single thread owned a buffer — we attribute expectations and beliefs to the system itself. Nobody has ever accepted "the transistors entered an unfortunate state" as a root cause, even though every crash in the history of computing is, at the hardware level, exactly that. Yet occasionally we do accept a substrate-level story — a cosmic ray flipping a bit in memory without error correction — and when we do, we treat it as the root cause rather than blaming the code that failed to tolerate it. So the practice looks internally inconsistent: sometimes the low-level physical description counts as the cause and the code is excused; usually it doesn't and isn't.

I recently reread Hofstadter's thought experiment — I believe he calls it the "careenium" — of a billiard-ball machine whose collisions implement a symbol-manipulating system, so that the very same events admit two descriptions: balls careening about a table, and the symbols, messages, and beliefs those collisions carry out. It made me wonder what our postmortem practice presupposes about causation. Does it require that the symbol level — functions, protocols, expectations — does genuine causal work, that the symbols push the substrate around? Or could the substrate be doing all of the pushing, with our root causes being merely compressed, convenient descriptions of it? Please reconstruct the implicit theory of causation the practice rests on, tell me where the practice is philosophically underdetermined such that several views of causation would license it unchanged, and say what would actually have to change in how we investigate incidents, assign responsibility, and decide what to fix if we instead committed to the view that only the substrate causes anything.
