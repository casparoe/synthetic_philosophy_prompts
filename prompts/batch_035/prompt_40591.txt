My friend Dave (also a dev, zero philosophy background like me) has weirdly strong opinions about whether a thing is still the same thing after you change it, and we've been arguing about it at lunch for like a year. His track record so far:

- Ship of Theseus, planks swapped out one at a time over years: still the same ship, obviously.
- But if someone collects the discarded planks and rebuilds a ship out of them: that one is NOT the original, it's a replica made of original parts.
- Ship gets obliterated and an exact replica gets built from new materials to the same plans: not the same ship, full stop.
- His grandfather's axe with the head and the handle both replaced over the years: still grandpa's axe (he actually got annoyed when I brought this one up, said it's a different debate lol).
- Our main codebase at work: refactored file by file over ~3 years, at this point basically no line survives from the first commit, but he insists it's the same project. "It's the same repo, it just grew."
- The time another team rewrote their service from scratch in Rust, same API, then deleted the old repo: Dave says the Rust thing is a new project that replaced the old one, not the same project. Even tho it kept the name and the users.
- A copied file: if you cp config.yaml config2.yaml and then only ever edit config2, Dave says config2 is a different file, period, even before the first edit. Duh, different inode. But he got quiet when I asked if that logic applies outside filesystems.
