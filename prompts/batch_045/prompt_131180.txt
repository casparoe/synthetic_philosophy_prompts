I'm building a small protocol for one-off, escrow-free swaps between strangers: each side deploys an agent that must decide, with no enforcement and no expectation of repeat interaction, whether to hand over its side of the swap, so the underlying structure is a one-shot prisoner's dilemma. A colleague argues that we can dissolve the problem by requiring both agents to publish their source code: in the resulting program game, an agent that cooperates if and only if the other's source is textually identical to its own is in Nash equilibrium with a copy of itself, and so transparency alone is supposed to make cooperation rational.

I think this is too quick, but I can't quite get the objection into focus. Please argue that it fails because it lets the agents condition on syntax rather than on what the programs do. Any program has indefinitely many behavior-preserving rewrites — renamed variables, inserted dead code, a different language or compiler — and what gets published need not be what actually gets executed, so identity of source text is neither necessary nor sufficient for the two agents to be relevantly the same: two parties who both meant to cooperate can still end up defecting against each other, and a party can wear a cooperator's text while running something else. Then argue that the extensional replacements do not rescue the idea either: conditioning on mutual simulation runs into non-termination or regress, and conditioning on provable cooperation merely relocates the dependence onto a shared proof system, a shared bound on proof search, and the agents' already being similar enough to model one another. Conclude that program equilibrium therefore presupposes rather than explains the mutual recognizability that cooperation requires, and state what you take the strongest reply to be.
