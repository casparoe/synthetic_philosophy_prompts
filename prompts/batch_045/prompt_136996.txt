I've been hacking on a little font-fallback tool — the thing where your browser asks for a typeface the machine doesn't have and quietly swaps in another one instead of showing boxes. Right now I just match on the Unicode character: take the code point, find any font with a glyph for it. Writing that made me notice how weird the standards practice is about what counts as the same letter. Latin "a" and the Cyrillic "а" that can look pixel-identical get separate code points, but the CJK ideographs that Chinese and Japanese write with somewhat different strokes get one shared code point — the Unicode folks apparently say they encode characters, not glyphs. So sameness there looks like role in a script, while in the first case it looks like script membership rather than shape, even though the shape agrees completely.

My own half-baked rule for the tool was: two glyphs are the same letter if you can slowly morph one into the other while readers keep reading it as that letter the whole way, with no point where it flips into a different letter. I like it because I never have to say what an "a" is. But I think it breaks on italics: in alot of faces the italic "a" is the single-storey form, and there's no way to get to it from the double-storey roman "a" in small steps without passing through shapes nobody would read as an "a" at all — yet everyone, type designers included, treats those as the same letter without blinking.

So what does this whole business actually presuppose about what makes every "a" an "a"? Is there one view underneath font substitution, Unicode, and the way a family bundles roman, italic and bold as versions of one design — or several half-theories that just happen not to collide? What would a fallback tool built on a different view do differently? And is my morph rule just one of those views with extra steps, or does it genuinely give different answers somewhere?

Give me the reconstruction, then a one-sentence bottom line naming the view the existing practice really *commits* us to rather than merely fits well with, and then, as the very last line, a tag:

\answer{SHAPE | ROLE | FAMILY-RESSEMBLANCE | OTHER}
