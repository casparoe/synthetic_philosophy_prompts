The situation that prompted this. My team runs an inference platform for a large mixture-of-experts model: sixty-four experts per layer, of which two are routed to per token, so on any given token sixty-two of them sit in memory and do not compute. Our serving tier does speculative decoding, where a small draft model proposes several tokens and the larger model verifies them in one batched pass; the draft model's activations are computed, and the ones for rejected tokens are then thrown away with nothing downstream ever reading them. We run a prefix cache keyed by a hash of the prompt: when a customer resends a prompt that shares a prefix with one already served, we reuse the stored activations rather than recomputing them, so the arithmetic that produced them happens once but the values are consulted many times. We hedge about three percent of requests against tail latency by sending the same request to two replicas and discarding whichever result arrives second; the losing replica still did all the work. Our fleet is heterogeneous: some replicas run in bf16, some on newer accelerators in fp8 with a different reduction order, so the two are formally implementing slightly different functions whose outputs agree to a few decimal places but not bit for bit. For incident review we have a record-and-replay harness that re-executes a captured inference deterministically, step by step, so that a run which happened once at 03:00 can happen again the next morning in a debugger. We also fork serving processes with copy-on-write memory, so two logically separate sessions are physically the same pages until their states diverge. And one legacy model we still serve now runs under an emulator on hardware it was never written for, with the host burning something like an order of magnitude more arithmetic than the guest's own description would suggest.

Our policy team wants a number to put in an internal register: how much morally relevant computation did we perform last quarter.
