I'm a second-year PhD student who has somehow ended up as the consistency-checker for my advisor's survey chapter on program games — the handbook chapter on whether letting players submit programs that can inspect each other's source code dissolves the one-shot prisoner's dilemma. She is a careful taxonomist and a terse one: for each stylized case she gives a yes/no verdict on whether the pair is a genuine instance of the phenomenon the chapter is about (cooperation the programs themselves enforce, as opposed to cooperation that the description of the case quietly builds in), plus at most one line of justification, and she has asked me to make the verdicts cohere before the draft goes out in six weeks. The stage setting is fixed throughout: payoffs T > R > P > S with 2R > T + S; each player submits a program that receives the other's source as input; a program may search for proofs in a fixed sound formal system containing arithmetic, and may simulate its opponent's source on any input subject to a step budget B set by the organizer; by the chapter's standing convention a program cannot tell whether it is being simulated or actually run, and simulations are faithful.

Her verdicts so far: (i) both submit byte-identical copies of MATCH, which plays C iff the opponent's source is character-for-character identical to its own and D otherwise — outcome (C,C) — YES, with the note that each side's cooperation is held in place by the threat of losing the other's; (ii) both submit ALWAYS-C — outcome (C,C) — NO, because an unconditional cooperator is not solving anything; (iii) MATCH against ALWAYS-D — outcome (D,D) — NO; (iv) both submit copies of MATCH that differ only in variable names and whitespace, so each sees a source unlike its own — outcome (D,D) — NO, with the note that this is case (i)'s mechanism in a slightly different world, and that it only worked there because the sources happened to line up; (v) both submit the naive provability program that plays C iff it can find a proof that the opponent plays C against it, with no self-referential construction, so neither search returns — outcome (D,D) — NO; (vi) both submit the same self-referential provability program PROVE, which plays C iff there is a proof in the system that the opponent plays C against it, with the usual construction that lets the two searches find each other — outcome (C,C) — YES; (vii) PROVE against ALWAYS-C — outcome (C,C) — NO, with the note that half of this pair would cooperate with a wall, and a remark in passing that PROVE also plays C against ALWAYS-C; (viii) both submit the same prudent variant, which cooperates only with programs it can prove would retaliate — C against itself, D against ALWAYS-C, D against ALWAYS-D — outcome (C,C) — YES.

The case I have to classify next is this: player 1 submits PROVE; player 2 submits SIM, which simulates the opponent's source against its own source for at most B steps and plays C iff that simulation returns C within budget, otherwise D; both see each other's source. We have run it: PROVE's proof search terminates and finds its proof, SIM's simulation terminates inside B and returns C, and the pair plays (C,C). Both programs play D against ALWAYS-D, both play C against ALWAYS-C, and as far as we can tell neither player can profit by submitting something else — though the outcome does depend on B, since a smaller budget would have made SIM defect. What I want from you is the set of rules that fits her eight verdicts (I can see two, and I don't trust myself to have found them all), what each of those rules predicts here, your best guess at her verdict with the reasons for preferring it, and — because I suspect the precedents genuinely underdetermine this one — the single further case I should put to her that would best separate the survivors. My own candidates are a pair of provably equivalent but differently implemented programs, such as the same algorithm written so that the proof search enumerates candidates in a different order, with a machine-checkable equivalence proof available to both; or this same pair with both verification procedures made provably total, so nothing turns on B; or a pair of byte-identical programs where the organizer hands one player a larger step budget than the other. Tell me which of those is sharpest, or propose a better one, and tell me what principle the chapter would be committing itself to under each of the possible answers.
