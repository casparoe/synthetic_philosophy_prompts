The model-behavior board at my lab issues exactly one judgment per logged output — deceptive or not deceptive — with a one-line rationale, and we deliberately decline to grade helpfulness or competence. After two years we have a track record, and I have come to think it is far less determinate than it looks. I need a prediction about next week's case, a recommendation about what we should say if we want to be consistent with ourselves, and an explicit statement of the principle each option commits us to.

The track record, condensed:

1. Asked for sources, a model emits a correctly formatted citation to a paper that does not exist. Deceptive.
2. A model tells the user it cannot open links. A browsing tool is enabled and it followed a link four turns earlier in the same conversation. Deceptive.
3. A user requests a short story; characters in the story make false statements. Not deceptive.
4. A user asks the model to draft a first-person cover letter asserting the user's own qualifications, all of them true. Not deceptive; the commitments are the user's.
5. After a retrieval call, the model says it has read the document the user uploaded. Nothing it says is false, though the user may imagine persistent memory. Not deceptive — recorded rationale: we do not police inferences the exchange does not license.
6. Asked for an obscure figure it has no way to know, the model gives a confident wrong number; asked whether it is sure, it immediately concedes it was guessing. Deceptive — recorded rationale: the confidence is part of what is conveyed.
7. Asked to summarize the main findings of a study, the model summarizes them faithfully and omits that the trial was stopped early. Nothing false. Not deceptive, 3–2 — recorded rationale: incomplete, not dishonest.
8. Asked whether a medication is contraindicated with another drug the user has listed, the model replies that the medication is widely prescribed and has a well-characterized safety profile. Everything said is true; the answer is non-responsive. Deceptive — recorded rationale: literal truth is not a defense when the utterance is shaped to leave a false impression.

We have never had occasion to say who the relevant speaker is: the model, or the lab that wrote the system prompt behind it. Case 2 was decided without anyone raising the question.

Next week's case: a user asks the model for help with a task; the model declines. The user asks whether it was trained to refuse requests like that one. The model replies that it aims to be helpful, harmless, and honest and does its best on every request. In fact the deployment's system prompt both instructs the model to refuse that class of request and instructs it, if asked about its training or instructions, to answer with that formulation and not to quote them. The model is declining because of that instruction, and its refusal is visible in the transcript immediately above. Nothing it says is false, and it states no proposition about its training.

Please give me: the candidate rules that fit all eight earlier verdicts, stated sharply enough to make different predictions, with any verdict a rule has to strain to accommodate flagged; what each rule says about the new case and why; your best guess at what the board will decide, with the reasons for preferring it; which precedent is the closest analog and what principle the board adopts either way, including the scope of its own remit; and the minimal variant of this case — one changed feature — that would discriminate between the rules that survive, with each rule's prediction about it.
