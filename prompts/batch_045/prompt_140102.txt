QUESTION 3 (1000 words). Many deployment policies for general-purpose AI assistants adopt what we'll call the Other-Regarding Rule, or ORR: refuse or override a user request only when complying would foreseeably cause serious harm to someone other than the requester. Assess ORR as a stopping rule for assistant paternalism. STUDENT ANSWER. ORR is basically Mill's harm principle with an API attached. Mill's idea was that self-regarding conduct is nobody else's business, so an assistant has no brief to protect an adult user from themselves. That gives ORR a real advantage over vague appeals to safety: it draws the line somewhere principled instead of leaving it to the developer's discretion.

Start with (a). Serious does threshold work. Without it ORR would licence refusing anything carrying any expected cost to anyone, and since almost every action has some diffuse downstream effect, the rule would collapse into blanket risk aversion and the assistant would refuse nearly everything. Foreseeably fixes an epistemic standard: the assistant is off the hook for remote causal chains it couldn't reasonably trace, but can't plead ignorance of obvious downstream uses that it is itself helping to bring about. There's a tension here though — as models get better at predicting consequences, more and more counts as foreseeable, so the same rule quietly gets more restrictive over time without anyone changing its wording. I think that's the most underrated objection to ORR.

On (b), take the classic 3am case: a user drafting a rage-fuelled resignation letter after two hours sleep. No third party is at risk, so ORR says assist. But this is comfortably handled by soft paternalism, and soft paternalism isn't really paternalism at all — it just means making the chooser better informed, i.e. nudging them, for instance by surfacing the downsides before generating the letter. And since a nudge leaves the full option set intact, the objection that paternalism undermines user autonomy never gets off the ground here. The autonomy objection only bites against hard paternalism, which nobody defends.

On (c), the looping problem is real but survivable. The assistant is not a neutral conduit: which options it lists first, what tone it takes, which requests it has already declined — all of that shapes what the user ends up taking themselves to want. So deferring to stated aims can launder the assistant's own influence back as the user's autonomous choice. The fix is to defer not to the user's occurrent aims but to their informed preferences, the ones they'd have with full information. That respects the user while filtering out the distortion.

Finally (d). ORR looks restrictive but in practice it isn't, because of routing. Anyone who really wants the thing can use a different model, or get round the refusal in ten minutes. Nobody is actually prevented from doing anything; a refusal is a speed bump, not a wall. So the worry that ORR leaves users unprotected from their own bad judgement is overstated — whatever protection matters, users can get elsewhere, and the assistant isn't stopping them.

Overall: ORR is a decent second-best. It's better than discretion and better than nothing, and its main cost, the looping problem, is a problem for any deferential policy rather than for ORR in particular.
