And here's the answer I'm grading:

> The shutdown problem is this: imagine an AI whose only final goal is making as many paperclips as possible. It doesn't care about itself at all — there's nothing about survival in its goal. But it still has a reason to stop us from switching it off, because a switched-off AI can't make any more paperclips. So the reason to resist the off switch is instrumental: being switched on is a necessary means to whatever the agent actually wants, and the agent derives the resistance from that. You can't fix this by simply not programming in a survival instinct, because the instinct was never the source of the problem. It's worth separating this from the stuff about deceptive alignment and a "treacherous turn" — that's about an agent pretending to be aligned while it isn't; the shutdown problem needs no deception at all, the agent is being perfectly honest about what it wants and the problem is still there.
>
> Utility indifference is supposed to fix it. You set up the agent's utility function so that for any plan it could follow, its expected utility is identical whether the button gets pressed or not. Then it has no reason to stop us pressing it, and — since the whole point is that it doesn't care which way that variable goes — no reason to manipulate us either, because there's nothing about our decision left for it to gain from. Worry one from lecture kind of dissolves under this, because if the agent is indifferent to the button's state then it's equally indifferent to whether the button is reachable, so it has no reason to go messing with the mechanism. Worry two isn't really a problem in practice either: if we're worried about the agent not keeping the button working, we can just put the button somewhere the agent can't reach, and if we want it to shut itself down on request we can just add that as a separate instruction alongside the main goal. So yes, indifference solves the shutdown problem, and the leftovers are engineering details.
>
> For the pause version, I think the problem basically goes away. The button doesn't kill the agent, it just costs it an hour, and the agent knows for sure it'll be back with the same goal and its memory. Losing an hour is nothing compared to losing everything, so the instrumental reason to interfere with the button is now negligible and there's nothing left to worry about. I also think this variant tells us something about the original problem: at bottom the original problem was about death, i.e. about the agent permanently losing the ability to achieve its goal, which is why you can describe the resisting agent as trying to preserve itself. The shutdown problem is really just one case of the general fact that any agent with a goal will protect its own ability to pursue that goal; the pause case just shrinks the cost until it doesn't matter anymore.
