I'm putting together a short internal guidance doc for our team: when, if ever, are we allowed to write in a public transparency note that a model understood a document it summarised? What I want is a decision tree, not an essay.

Build it from the logical space rather than from a list of -isms: each branch node a question someone could answer without already knowing which view it leads to, each leaf a named position (six to eight leaves; call one "unnamed" if nobody really defends it). Make the questions tiny concrete cases — a model that summarises the lease correctly but falls apart when the key clause is moved to the last page, one trained almost only on code that still handles a metaphor task, one that explains a joke correctly but cant say why a slightly altered version isn't funny. No node may just ask "does it understand?"

Two things I care about. First, include a node for what I've been calling the shape-of-failure test: does it matter whether the mistakes are the mistakes a genuine misunderstanding would produce, rather than errors with no such shape at all? Second, these leaves at least: the hard parrot skeptic, a grounding-first view (understanding needs real causal contact with the world), a threshold-competence view, a degrees/gradualist view, and the deflationary one that says we should just retire the word. Flag any pair of leaves your tree can't really seperate, and for combinations of answers nobody occupies, say whether that's incoherent, merely unattractive, or just untried.

Commit to something: give me the tree you actually think is right, say which leaf you'd land on yourself and why, and don't hedge into a menu. No citations, I don't care who argued what.
