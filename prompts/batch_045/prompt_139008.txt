I think I've got a fix for the Pasadena game and I dont understand why nobody uses it. As I understand the problem, the expected value is undefined because the terms 1, −1/2, 1/3, ... only converge conditionally, so rearranging them gives you any total you like — but that seems like an artifact of summing in the order the coin tosses happen. So: sum in order of payout size instead, biggest absolute payoff first, then the next biggest, and so on, and take the limit of the partial sums. That ordering isn't me choosing a description, it's read off the game itself, so the value comes out as one number (about 69 cents?) and the rearrangement objection dies. My friend says that's just a "summation method" and not an expectation, but I don't see what turns on the difference — I get a number, and it matches the ordinary expected value in every case where the ordinary one exists. So what actually breaks if I do it this way: can I use that number to rank gambles the usual way, say Pasadena vs. Pasadena-plus-a-dollar, or two independent Pasadenas taken together? And wouldn't the same rule settle any game whose expectation is undefined?
