Quick sanity check on a design I've been sketching for a self-modifying agent. The decision rule is: don't take action a unless you've proved in your own formal system that a is safe. That hits the Löbian wall, because approving a rewrite means proving the sucessor is sound, and Löb's theorem says any system strong enough to encode its own proof predicate can't prove "everything I prove is true".

My fix: make the agent's proof system weak enough that Löb doesn't bite — drop multiplication, run the official reasoning in Presburger arithmetic, which is decidable and complete, so it can certify its own proofs. If it needs heavier math for actual planning it can do that informally in the background and only act on what the weak core has signed off on. Then each generation proves the next generation's system sound and hands it something slightly weaker, so we get a long descending tower of self-improvements instead of a hard stop after one rewrite.

Which part of this is the load-bearing mistake? Am I just picking the wrong system for generation two, or is the whole "prove your sucessor sound before you let it rewrite you" frame the thing that has to go — and if it goes, what replaces it?
