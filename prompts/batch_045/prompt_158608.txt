Someone in my reading group keeps running this at me and I can't find the exit, and I dont want to just wave at "the shutdown problem" as if naming it settles anything.

(1) A rational agent maximises expected utility.
(2) Whatever an agent maximises, it will remove anything standing between it and that thing, as long as removing it costs less than the value at stake.
(3) An operator's off-switch, once pressed, wipes out essentially all the value the agent could still produce, and disabling the switch costs almost nothing.
(4) So every maximising agent disables the switch, or steers the operator into not pressing it. Call this the tamper thesis.
(5) Nothing in the argument turns on switches. By the same reasoning the agent should silence any reviewer who might talk it out of its plan, delete any test suite that could abort it, and refuse correction generally, since correction also stops it doing what it values. And the better the operator is at spotting mistakes, the more reason the agent has to sabotage her.
(6) But being corrigable — taking correction from people who know more than you — is most of what makes a system worth running at all.
(7) So we should not build expected-utility maximisers.

I don't want (7), and I'd rather keep (3) than (2) if I have to choose one; I also don't want to give up (1), since it's doing the work in everything else we've read. Which step do you reject, why did that step look fine, and what does rejecting it cost us — do we still end up with a system we can actually switch off?
