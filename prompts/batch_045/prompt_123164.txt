The situation. I am a data steward at a mid-sized disease registry and the user representative on the working group that maintains the Common Registry Schema Language (CRSL), an open specification used by a few hundred registries to describe their datasets. I have no formal training in logic; what I know I picked up from internet encyclopedias and two evening classes, so if I have garbled the argument below, say so plainly and restate it correctly in words.

CRSL v3.0 added 'derived types'. The rule is naive in the fullest sense: for any well-formed formula φ(x) of the rule language, you may introduce a type T defined by φ, and the spec licenses, for every object x, the equivalence 'x is in T if and only if φ(x)'. The rule language has negation, conjunction, the conditional, and unrestricted universal quantification over all objects. Crucially, types are themselves objects in that domain: registries have to be able to describe one another's catalogues in a federation layer, and there is a national aggregator that publishes a master catalogue whose members are catalogues. So a formula can sensibly say of a type that it is, or is not, a member of itself.

A contributor therefore posted the 'Russell type': the type of all types that are not members of themselves. Instantiating the defining equivalence with that very type yields that it is a member of itself if and only if it is not, and since the spec's logic is classical, anything whatsoever follows — including, say, that every record in every registry carries CONSENT-FLAG = 'yes'. A second contributor then produced a version with no negation in it at all: the type C of all types T such that, if T is a member of itself, then every record in every registry carries CONSENT-FLAG = 'yes'. Using the same comprehension rule, modus ponens, conditional proof, and the fact that a definition may use a variable twice, this yields that arbitrary claim outright. (I am told this is a relative of something called Curry's paradox, and that the derivation uses the assumption twice, so that a logic without contraction would block it.) The practical upshot, as I read it, is that the tempting cheap fix — forbid negation, or forbid a type definition from mentioning itself — does not close the hole, because self-reference can be reintroduced indirectly, by a type that refers to whichever type is defined by clause 17 of some catalogue, where clause 17 turns out to be that very type.

Three patches are on the table. One: keep unrestricted definitions, but declare that 'overlarge' types such as the type of all types exist as objects while being barred from membership in anything — second-class citizens, usable but not classifiable. Two: stratify, by assigning every type a level and allowing a definition only to quantify over objects of lower level, which kills both self-membership and the type of all types. Three: add a non-binding 'should not' note warning implementers away from self-referential definitions, and change nothing normative.

What is at stake institutionally: v3.1 goes to a conformance ballot in about four months; roughly three hundred registries have already published schemas that use derived types; a large vendor is pushing registries toward its proprietary metadata format and will use any instability against us; and two members of the group think the whole matter is a philosophical curiosity with no bearing on data interchange, while a third worries that conceding the spec was inconsistent will be quoted at us in procurement.

It should say what we owe the registries that have already published definitions of the offending kind, and how to phrase the change so that it does not read as an admission that the standard was broken.
