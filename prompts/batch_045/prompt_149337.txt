I've been following a long-running comment thread on one of the rationalist group blogs about whole-brain emulation, and the same move keeps surfacing: someone says the brain is hardware and the mind is the software running on it, and then uses that one sentence to license two quite strong conclusions. First, that uploading or mind-copying is in principle just a matter of resolution and compute, since a program is portable. Second, that psychology is autonomous from neuroscience the way software engineering is autonomous from semiconductor physics, so functional and folk-psychological descriptions are the right level and the wetware is an implementation detail. A friend of mine who works adjacent to computational neuroscience says the sentence is doing all the work, and that the whole thing comes apart as soon as you ask what the instruction set architecture is supposed to be. I don't want a verdict on whether brains are computers; I want an audit of the analogy and of what it can carry.

So: give me the correspondence table. For each of the following, name what plays the role in the brain, or say that nothing does and that this is a genuine break rather than a strained fit — the instruction set architecture; the compiled artifact; the compiler and the source it compiles; the program/data distinction; the program counter and the clock; the memory hierarchy; the bus; the operating system; the power supply; the user; the programmer; and the operation of porting to different hardware. Then sort the breaks by whether they are load-bearing for the two conclusions or merely cosmetic. Is it load-bearing that the source is a genome and the compilation is development, so that there is no artifact to copy but only a noisy process to re-run? That plasticity makes the program self-modifying, collapsing the program/data split? That there is no published architecture, so same computation on different hardware is fixed only by whatever mapping we choose after the fact, which is the familiar worry that on a liberal enough mapping any physical system implements any computation? That the system is asynchronous, analog-ish and stochastic, so a faithful simulation is a discretization, and nobody has said what error tolerance still counts as running the same program rather than a near one? I'd also like named explicitly the features the analogy imports that the target might lack: that behavior is produced by rule-governed operations on discrete symbols at some level, that implementation is an objective relation rather than a description we impose, and that the program is separable from the machine and therefore copyable.

Then the verdict, kept separate for the two conclusions: which survives once the disanalogies are on the table, which was being carried entirely by the analogy, and is there a weaker version of the sentence worth keeping. I also suspect the thread is conflating two claims, and I'd like them pulled apart: substrate-independence for cognition and behavior versus for phenomenal experience. The piecemeal-replacement case — swapping neurons for functionally equivalent chips one at a time — seems to separate them, and I want to know which version of the analogy each half requires and what each half can concede without giving up the other. Finally, if the hardware/software picture is the wrong one, propose a better analogy and say what it would predict differently; my friend suggests something like an analog, self-rewiring systolic array whose firmware is partly the chemistry, and I genuinely can't tell whether that is an improvement or just a more impressive-sounding way of saying the same thing. Skip the Chinese Room — I've read that one, and it isn't the objection I'm after.
