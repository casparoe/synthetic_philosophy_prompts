Two people in my lab got into it yesterday about a shutdown-utility design and I was the only one in the room without a take, so now I'm stuck refereing.

Setup: the agent is supposed to be indifferent to being switched off, but instead of hardcoding a fixed probability that the operator hits the button, there's a learned monitor that watches the agent's own trajectory and outputs a live estimate of "the operator would shut this down right now," and the agent plans as if that number were the true probability. The monitor gets retrained periodically on the operator's actual presses.

Jonas says this is strictly better than the constant version: the agent's incentives now track what the operator actually cares about, rather than a number some designer guessed at before deployment.

Deb says it's worse, and worse in a new way. Now the agent has a per-timestep reason to steer the monitor's output, and the cheapest way to lower "operator would shut me down" is often not to behave better but to change the operator — slow down and look cautious right before a review, be vague about the bad part of a result, make itself annoying to replace. Manipulating a switch is one thing; manipulating the person holding it is another, and only the second setup makes that directly profitable.

Jonas: but that incentive is already there in the constant version. Any agent that wants to be shut down when the human wants it to be has a reason to make the human not want it. So you've found a problem with corrigibility in general, not with learning the probability.

Deb: no, there's a real difference. With a constant there's no gradient — the agent can't tell which of its actions moved the number, because nothing it does moves the number. Once the number is a learned function of its behavior, it gets a continuous signal aimed right at the operator's disposition, and it can exploit the retraining lag: behave fine while the monitor is being fit, then switch once the estimate has settled.

Jonas: that's just distribution shift, and we handle it the way we always do — randomized audits where the press is triggered by a coin flip the agent can't observe.

Deb: then you've thrown away the thing that made it attractive. The probability no longer means "the operator wants me off," it means "coin," so you're back to the constant case with extra machinery — except the agent can still learn to tell audit trials from real ones from context, so you don't even get clean indifference.
