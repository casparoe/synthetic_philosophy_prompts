I work in formal methods and, in what spare time I have, I have been playing with a small hobby setup that has turned into something I cannot name. I would be grateful for help with the carving rather than the labelling: I do not want a reading list or a set of references, and I would rather you argue the distinctions out than point me at where they are written down.

Here is the setup. Two machines play a single-shot prisoner's dilemma, but not by choosing actions directly. Each submits a program to a referee; the referee hands each program the other program's source text as input; each program must halt and print either COOPERATE or DEFECT. The point of the detour is that a program can inspect its counterpart and condition on what the counterpart will do. Call this the code-swap game.

Three things I observed, and one additional case that I suspect is the same thing in another costume.

First, the obvious strategy does not work. If each program tries to simulate the other, the two simulations call each other and nothing halts. I did not find this surprising; it looks like an ordinary vicious circle, and it is easy to describe.

Second, replacing simulation with proof fixes it, in a way I did find surprising. Let both sides run this:

    search over all proofs in a fixed formal system (Peano arithmetic, say)
    if a proof is found that the other program prints COOPERATE, print COOPERATE
    otherwise print DEFECT

Two copies of this program both cooperate, and the argument that they do appears to turn on a theorem about self-reference of exactly the kind I was taught to think of as purely negative. So the same-looking machinery that blocks a system from certifying itself is what lets these two programs find each other.

Third, the cooperation is sensitive to the proof bound in a way I cannot explain to myself. If I let each program search only over proofs shorter than some modest length, both defect; if I raise the bound past a threshold, both cooperate. The bound is not concealing the other program from me. The other program is twenty lines long and I can read it; I can also, in many cases, work out by hand what it will do. What the bound conceals is a proof.

The additional case is this. Suppose a program is in the business of building a successor and handing control to it, and its rule is that it may hand over control only if it can prove, in its own formal system, that the successor's behaviour will be acceptable. Then it cannot certify a successor that reasons exactly as well as it does, even when the successor's source code is available in full and even when the successor is, to all appearances, a copy of itself with a better search routine. Worse: if I try to let the builder help itself to the general rule that whatever it can prove is true, the builder's proof system stops discriminating at all and proves every sentence. If instead I let each generation use a strictly weaker formal system than its parent, I seem to have bought only a descending chain that either runs out or was never really a solution.

What I want, concretely:

Is there an established name for this pattern, and are the code-swap case and the successor case one phenomenon or two? I am not interested in being told the name if the name comes without the boundaries, so please also say which nearby things it is most often confused with and how it differs from each. In particular, I have had four diagnoses offered to me and none of them feels right, but I cannot say precisely why:

that this is just the undecidability of program behaviour, or a version of the theorem that no nontrivial property of a program's behaviour is decidable;

that this is just incompleteness in the usual textbook sense;

that this is just the banality that a system cannot be expected to predict what a more capable system will do;

that this is just a coordination failure of the sort that any game with multiple equilibria exhibits, and has nothing specifically to do with reasoning.

Then the boundary cases, which matter most to me. Does the pattern depend essentially on each side's reasoning appearing inside the statement it has to evaluate, so that it would vanish if the two agents could inspect only each other's behaviour and not each other's reasoning? Does it survive if the agents are allowed to be probabilistic, or if the requirement is weakened from proving optimality to proving that a successor is no worse than inaction? Does it survive if the two sides share correlated randomness, or a common random seed, ahead of time? Does anything change if the self-trust rule is restricted to statements of some restricted syntactic shape rather than adopted in full generality?

And if there turns out to be no established concept that fits, say so plainly, and give me a name and a definition instead, together with the cases that should count as instances, the cases that should not, and the nearest miss that I am most likely to conflate it with in future.
