We are evaluating a bounded approximation to Solomonoff induction on an in-house binary forecasting benchmark, and we cannot reconcile what we observe with the convergence result for the universal mixture. I would be grateful for a diagnosis before we spend more compute.

The agent. We fixed a reference universal prefix machine U₀ and equipped the agent with an exact oracle for K relative to U₀, deliberately setting approximation error aside, because we first want to know whether the procedure we implemented is the procedure the bound is about. Call it the razor agent: at each step t it takes the data seen so far, finds the lexicographically first shortest U₀-program consistent with that data, and predicts with that program's next output bit. We chose this over the full mixture because, as we understand the construction, the mixture only weights each candidate program by 2 to the minus its length; the shortest consistent program carries strictly more weight than any single rival, so the mixture is the shortest-program predictor plus a tail correction, and the dominance result is best read as Occam's razor in measure-theoretic dress — prefer the shortest description that fits, discount longer ones in proportion, and the expected total error against a generating measure μ is at most K(μ) times ln 2. Our benchmark scores by counting wrong predictions, so that is what we record.

The test. We built the environment ourselves, so it is computable by construction: for the first hundred thousand steps it emits a Bernoulli sequence with bias 0.6; thereafter it settles into a period-seven cycle forever. Bias, switch point, and cycle come to roughly forty bits on U₀, giving a budget of K(μ)·ln 2 of about twenty-eight. Even allowing generously for the invariance theorem's additive constant — say another twenty bits — and a factor of two for the tail correction, we expected the run to finish with something on the order of a hundred wrong predictions. As a sanity check: twenty-eight nats of slack at the coin's 0.673 nats per step cannot fund more than about forty bad steps, so that estimate felt conservative if anything.

What we observe is roughly forty thousand wrong predictions inside the first hundred thousand steps. A trivial forecaster that always predicts the majority bit is wrong on exactly forty percent of those same steps, i.e. our agent at best matches a constant predictor, and depending on how we break ties in the oracle it does somewhat worse. Its guess also oscillates between 0 and 1 from step to step in a way that tracks nothing we built into the environment.

The question. Two diagnoses are on the table and they point in opposite directions. (A) The reference machine is at fault: the additive constant is doing more work than we budgeted for, K(μ) is effectively well above forty bits, and we should re-derive the bound on a machine better adapted to the domain, or move to a domain-specific prior, after which the certified budget should line up with the observed counts. (B) The oracle step is fine but the razor agent is not the object the theorem is about, and we should implement the full mixture over all consistent programs.

Which is right? And concretely: for the first hundred thousand steps of this environment, what number of wrong predictions should we adopt as the pass/fail threshold implied by the bound, so that we can tell whether whichever fix we apply has worked? If there is a standard conversion from the K(μ)·ln 2 figure to an error-count budget, please state it explicitly, together with the loss function it assumes.
