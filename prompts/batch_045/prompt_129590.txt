I keep going in cirlces on the whole tool AI vs. agent AI thing. As far as I can tell, the safety case for tool AI just comes down to: build instruments, not agents — things that do what a human operator wants, under that operator's control, rather than things that go off and pursue their own ends. That seems easy to make precise, so I came up with what I call the tracking test: a system is a tool just in case its behavior counterfactually tracks the operator's will — if the user had wanted something different in that situation, the system would have done something different, and it does what it does *because* the user wants it, not because it wants anything.

If that's the right test, then capability looks like pure upside. A more capable system reads your intentions better, takes correction more gracefully, and can be pointed at harder problems without ever developing a project of it's own. So my actual question: given that the tracking condition is this easy to state, why do people keep saying that *keeping* systems in tool-land is the hard part, and that rising capability makes it harder, not easier? Isn't the whole strategy just: make the systems as capable as you like, and keep them deferential?

Two things people say to me that I don't buy, if you want to take them on directly. First, that a perfectly deferential assistant would still count as an agent — that sounds like word games to me, since if it has no ends of its own, what's left for "agency" to mean? Second, that whether something is a tool or an agent isn't a fact about the system at all but about how it's deployed, which sure sounds like changing the subject from a technical question to a sociological one.
