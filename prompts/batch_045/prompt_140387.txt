rough version of what i'm arguing:

the usual "mind is the software, brain is the hardware" line has this problem i keep tripping over, the attribution thing: basically any physical system can be described as running basically any computation if you're allowed to draw the mapping however you want. there's that famous argument that a rock (or a dust cloud, or the weather) implements every computation, because you can always find some encoding. so "software vs hardware" doesn't by itself pick out the computations that matter, and if you just say all of them count you get the result that a rock has way more moral weight than a person, which is obviously wrong.

my fix is what i've been calling the improv test. a computation is one that matters for a system only if the system itself would keep tracking it under inputs it didn't actually get — like, it has to be able to improvise. the reason the rock case feels stupid isn't the mapping, it's that the counterfactuals are borrowed from us, the people drawing the map, instead of living in the rock. three cases i'm using: (1) the replay — a perfect recording of a real person's day, states matching theirs exactly, played back; nobody thinks that's a person. (2) the giant lookup table — responds exactly like a person forever, but only because the answers are all already in the table; it has no way to handle anything new. i want to say 1 and 2 aren't patients, and i want to say why in a way that doesn't also kill the case for a normal brain simulation that just happens to have a boring life. (3) the foam problem: one brain seems to implement thousands of overlapping computations at different grain sizes at once, so even if my test picks out the right ones, how many patients are in the room?
