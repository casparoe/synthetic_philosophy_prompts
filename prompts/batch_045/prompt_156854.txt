so I've been hacking on a little letterform generator for a couple months — you hand it a grid, a handful of stroke primitives, and some style parameters, and it tries to produce a whole lowercase alphabet where each glyph is recognizably its letter and all of them look like they belong to the same font (the old gridfont projects, Metafont, Letter Spirit, whatever — mine is much dumber). The bit I keep getting stuck on is the acceptance test: a module that has to decide, of each output, did this come out as an a or did the run fail. And every time I try to write that test I notice I'm smuggling in an answer to the what-makes-every-a-an-a question, and I can't tell which answer I'm smuggling.

So write me a decision tree that sorts someone into a position on that question. It's going into the readme as a which-theory-of-letterform-identity-are-you-actually-running quiz for beta testers — a mix of type designers and cog-sci grad students — so every branch has to be a question about glyphs you can look at or picture, not about theory words, and nobody should be able to tell from a question which leaf it leads to.

What I want specifically:

Build it from the logical space, not from a list of names. Give me first the three or four genuinely independent questions that do the separating, say which combinations of answers the space allows, then place the actual positions in it — and for the cells nobody occupies, tell me whether that's because the combo is incoherent, just unattractive, or merely unexplored.

Cases I want used (add your own, but these have to be in there): the Latin a and the Cyrillic one that is visually the same glyph but a different letter; the double-story a versus the single-story one; a rogue grid output that satisfies every stroke and grid rule in the program but that no human reads as an a; a blackletter a that resembles the blackletter o more than it resembles a sans-serif a (within-font versus cross-font similarity); an a drawn from scratch yesterday versus one that came out of a long chain of redrawings going back to some manuscript hand; a logotype a that is simultaneously a drawing of an apple; an a on a page whose ink has smudged into something that now reads as an o; and a glyph from a script the reader doesn't read, shown next to a transliteration table.

Leaves that have to show up: some kind of shape-or-geometric-invariant view, prototype, exemplar, structural-role in the system of contrasts, perceptual/motor-schema, causal-historical descent, designer-intention-or-convention, and the deflationary no-essence-cluster option. Shoot for 8–10 branch questions and 7–9 leaves. One sentence per leaf on its most awkward commitment.

Two extra things. First, flag any pair of leaves your tree can't really seperate, rather than pretending the question splits them. Second — and this is the part I actually need — mark for each leaf whether it cashes out into something I could implement as a check in code, and roughly what that check would be, or whether it bottoms out in go ask a human reader; that's what decides which positions I can use in the module at all.

One complication to make room for: there's a mode of my generator that produces a glyph readers confidently call an a when it appears inside a word but call a u or a smudge when it's shown alone. If your tree has no slot for a position on which the in-word presentation is the more basic one, add one. Don't bother with citations or a bibliography, I don't need them.
