A blog post I came across on proof assistants invokes Lewis Carroll's 1895 piece "What the Tortoise Said to Achilles" to argue something about trusting checkers, and it summarizes the fable roughly as follows:

Carroll showed that modus ponens can never be proved. The Tortoise is perfectly willing to grant P, and to grant that if P then Q, but still declines to accept Q; so Achilles writes down a third premise saying that if P and if-P-then-Q are both true, then Q is true, and the Tortoise grants that too and still declines Q. The same move can be repeated forever, which means every deductive argument secretly depends on an extra premise no one has justified, and the only way to justify that premise is to use the very rule you were trying to justify. So deduction cannot be justified at all: it is circular, and calling an inference "valid" just means it plays by rules our community happens to have settled on. By the same token, no proof checker can give you a reason to trust a proof — the rules are compiled into the checker, so the machine can only report that a proof is well-formed by standards it was built with, never that those standards are worth accepting.

I write infrastructure code and have no philosophy training, so I can tell that "it's circular" is doing more work in that paragraph than it should, and the leap to proof checkers feels like a different point wearing the fable's clothes — but I can't say where the summary stops being fair.
