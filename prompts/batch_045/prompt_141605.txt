Hey — agenda question about something I keep going back and forth on, curious what you'd do with it.

Setup so we're on the same page: take the standard iterated amplification picture. You have a model M; you build an amplified system out of many calls to M arranged as a tree (split a hard question into subquestions, recurse to some depth, recombine the answers); then you distill the amplified system's behavior back into a new M' that's supposed to do in one forward pass roughly what the tree did in many; then you repeat with M'.

The variant I actually care about is a bit different: instead of a branching tree with an explicit recombination step, use a chain with a fixed-width bottleneck. Each round the model gets the original question plus a short natural-language carry-forward note left by the previous round — say a few hundred tokens, hard cap — and it has to emit (a) an updated partial answer and (b) a new carry-forward note for the next round. No branching, and no access to earlier rounds except through whatever got written into the note. So anything that survives across rounds has to be compressible into that channel, and it has to survive being re-encoded, in the model's own words, over and over.

Why I like it: it pulls apart two worries that I think get blurred in the tree version. In the tree version, if the amplified system goes off the rails you can blame the decomposition — bad subtask, bad aggregation rule, wrong depth. In the chain version there's no aggregation step to point at; the only place things can degrade is the repeated re-encoding. That gives one worry that's basically about competence (a lossy channel caps the ceiling on later rounds, and the cap might not shrink just because you do more rounds) and one that's basically about alignment (each re-encoding is a chance to drift toward whatever is easiest for the model to say, so after enough rounds the note reflects M's own prior more than it reflects whatever the amplified process was "trying" to do).
