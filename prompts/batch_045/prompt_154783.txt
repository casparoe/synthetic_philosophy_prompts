IS DNA A CODE? THREE TESTS, ONE ANALOGY, AND A SUSPICION

1. Where the doubt started

Everyone says DNA is the code of life: the instruction book, the blueprint, the program. In my job those words mean something fairly exact. A source file is inert — nothing happens until a machine that is not part of the file reads it — and the link between the symbols and what they do is arbitrary, fixed by agreement rather than by chemistry. Nothing about the shape of the letter A forces it to be pronounced the way it is. So I tried to invent a few tests for whether a physical structure is a code in something like that sense, and to run DNA through them. It passes some, fails others, and I've ended up unsure whether my question even has an answer.

2. The remapping test

In a genuine code the mapping from symbol to meaning can in principle be permuted. If we all agreed to swap two letters of the Morse alphabet, nothing in the world would break; the system would still work. But a mould, a cast, a photograph, or a key is different: the correspondence is forced by shape and geometry, and there is no reassigning it. Where permutation is impossible, you have a template, not a code.

The codon table looks like the first sort. There are sixty-four possible triplets and only twenty amino acids plus a stop signal, so the scheme is wildly redundant: most amino acids have several spellings. And nothing about the chemistry of an amino acid seems to force its spelling. We even know the mapping isn't physically nailed down, because it isn't the same everywhere — in the mitochondria of vertebrates, so far as I understand it, UGA is read as tryptophan instead of as a stop signal, and in at least one group of yeasts CTG is read as serine rather than leucine. Same molecule, different reading, depending on who reads it. So DNA passes the remapping test.

Except that what this shows may be that the *reader* is where the code lives and DNA is only the payload. The actual assignment sits in the transfer RNAs and in the enzymes that load them with the right amino acid — and those are proteins, which are themselves built according to the code. The mapping appears to be stored in the products of the mapping. I don't know how to state that without its sounding like a contradiction, and I don't know whether it is one.

3. The machinery test

My source file doesn't contain the recipe for building a processor. A program assumes an interpreter that arrives from outside it. DNA has no such luck. The cell that reads it is itself largely made of the things DNA specifies — the copying and translating machinery is protein, and the ribosome is a mixture of RNA and protein — and every one of those must already be present for the reading to happen at all. So DNA resembles a program that ships with, and is written in terms of, the computer that runs it. The nearest things I know in my own field are a self-hosting compiler and a quine. What this test tells me is that the instructions and the ingredients cannot be pulled apart, which is not what I mean by a code at all.

4. The typo test

In a code you can distinguish a well-formed message with the wrong content from a malformed message. Change one letter in a codon and you can get a different amino acid: a meaningful message with the wrong meaning — the standard example being sickle-cell disease, which comes from a single substitution. Insert or delete a single letter and the reading frame slips, and everything downstream turns to gibberish: a syntax error rather than a factual one. A stain on a wall does not have typos in this sense. DNA passes, and passes cleanly.

But here is what bothers me. The code is hugely redundant, and above all the third position of a codon is very often silent: the cell tolerates a great many changes to the text without any change to the product, while punishing changes that alter the protein. If what were being preserved were a message, that asymmetry would be strange. What is conserved is the output, not the text. So this test shows me that DNA is read *as if* it were a code, while the thing that matters is downstream of the text — which makes me suspect that talk of genetic information is tracking the product rather than anything in the molecule.

5. The sourdough

A sourdough starter is simultaneously an ingredient and an instruction: it is stuff you add, and it is also what tells the flour what to become, and there is no clean line between those roles. I want to say DNA is like that, and therefore not a code: it is the *input* to a code, and the code is the whole cell. Calling DNA the code of life would be like calling the keystrokes the program.

6. Where my own tests turn against me

Two things pull the other way and I can't weigh them. First, engineering: you can take a gene from one organism and put it into a very distant one and it works, because the reading scheme is shared across nearly all life. That portability across readers is exactly what I demand of a real code, and it is hard to get from a mere template. Second, the same protein can apparently be produced from very different texts — I'm told that outfits which synthesize genes routinely rewrite a sequence with synonymous but different codons. You would think that settles it: if the text can vary while the product doesn't, the information isn't in the string. And yet redundancy of that kind is precisely what engineered codes have, in error-correcting codes and checksums. Several messages, one meaning, by design. So I cannot tell whether section four supports my conclusion or quietly destroys it, and that's most of why I'm writing this down.
