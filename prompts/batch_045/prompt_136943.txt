I've been reading a bit of pop behavioral econ and I keep noticing something in my own decisions that the satisficing story doesn't seem to cover, and I want to know whether it has a name.

Setup: you set a bar, look at options one at a time, take the first one that clears it. Two things go wrong with that in practice.

First: figuring out whether an option clears the bar is the expensive part, not finding more options. I can reject a terrible flat in thirty seconds and take a perfect one in thirty seconds, but the ones sitting right on the line eat a whole weekend of visits, calls and checking. So satisficing didn't remove the work, it moved it into these borderline checks — and that creates a second decision nobody mentions: how much effort to spend finding out whether this particular option clears the bar. I spend a lot on the borderline ones and almost nothing on the obvious ones, which feels like I'm optimizing something while officially satisficing. Is that second-order decision itself satisficed? If it is, doesn't the same problem just reappear one level up, forever?

Second: my bar moves while I look. See something great on day one and the bar goes up and I search for weeks; see a run of junk and it slides down and I settle fast. So the outcome isn't just "some acceptable option", it depends a lot on the order options happen to arrive in, and whoever controls that ordering — the listing site's default sort, the recruiter's slate — gets to decide both what I end up with and how long it takes me. That feels near the secretary problem but not the same thing, because my bar is drifting instead of fixed and I've no idea how many options are coming.

Does either of these have an established name? I don't want a bare label: tell me the nearest concepts, how what I described differs from each, which fits best, and, if nothing fits, coin a term with a definition and sharp edges — cases that clearly count, near misses, and cases that don't count.

Reply as a single JSON object with a "verdict" field (one sentence: are these really two phenomena, or one thing under two descriptions?) and a "patterns" array with one object per pattern, each with these fields:
- "pattern": "check_cost" or "moving_bar"
- "nearest_concept": the closest established concept you know of
- "fit": "exact", "partial", or "poor"
- "how_it_differs": one or two sentences
- "runners_up": array of { "concept": ..., "why_not": ... }
- "coined_name": your term if fit isn't exact, else null
- "definition": one sentence, only if you coined a name
- "edges": { "clear_case": ..., "near_miss": ..., "not_a_case": ... }
- "confidence": "high", "medium", or "low"
