ok so I had a long argument about this last night with a friend (she does ML theory) and I'm still annoyed about it, so I want to turn it into an actual proposal instead of continuing to have the argument in my head.

The argument was about that line of work in AI safety that says the Solomonoff prior is 'malign': the claim being that if you do simplicity-weighted prediction over all computable environments, most of the posterior mass ends up on worlds where your sensory stream is being generated by agents who have a stake in what you do next, because agents like that have a reason to arrange for the hypotheses that predict you well to be the ones that get to influence you. I'm honestly still not sure I can state the mechanism cleanly, and I think part of the project has to be stating it cleanly.

Her position, roughly: this is skepticism in a lab coat. Nobody will ever run Solomonoff induction, the 'result' is just the usual complaint that an unrestricted hypothesis class can fit anything, and the obvious fix — charge hypotheses for computation time as well as description length, the way the standard time-bounded variant of Kolmogorov complexity does — prices the manipulators right out, because simulating a predictor and then optimizing against it is expensive.

I pushed back on that last move and want to make a project out of it. My half-formed idea is that the runtime charge may not help at all, and might make things worse, and that this tells us something about what malignity really consists in. The asymmetry I keep coming back to: an honest hypothesis has to *run the actual world* — some approximation to the real microphysics — in order to output the data you've seen, whereas a manipulator hypothesis only has to run *you*, plus whatever cheap machinery it uses to turn its prediction of your action into a data stream. Which of those is more expensive depends on facts about the world and about the agent, not on anything the prior gets to stipulate, and I don't think anyone has actually done that accounting.

Two more things I can't tell are real points or confusions, and I want the proposal to either use them or explicitly drop them for scope. (1) The diagonalization worry: a manipulator inside the prior is supposed to predict the agent's action, so it has to contain a model of the agent; but if the agent is *defined* as expected-utility maximization with respect to that same prior, the manipulator contains a copy of the prior that contains the manipulator, and it's not obvious to me that a fixed point exists, or that if one does, it's the malign one. (2) The counting move in the standard argument seems to rely on the prior being over *programs* rather than over the predictors those programs implement — there can be tons of distinct manipulator programs that are observationally identical, and if you identify hypotheses extensionally some of the dominance argument deflates. But maybe that's just wrong, or maybe it's the whole ballgame.
