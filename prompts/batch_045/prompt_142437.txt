so i've been messing around with a dumb little side project in the spirit of that old grid-font thing (Letter Spirit, roughly): you hand the program two or three letters of an alphabet drawn on a coarse grid in some made-up style -- blocky, or spiky, or like a shaky hand -- and it's supposed to produce the rest of the alphabet in that same style, including letters it has never once seen an example of in that style. and separately it should be able to look at a glyph and say which letter it is, and which style it's in.

and i keep hitting the same wall: i can't tell what i'm even asking for. is an 'a' an 'a' because of its topology, because it has the right strokes/parts, because it's near a prototype in some similarity space, because a competent reader would call it one, or because it plays the right role inside the alphabet (distinct enough from the other letters, combinable with them)? everyone i ask answers a different one of these and then argues past everyone else, which makes me think the fight is about the spec and not the theories.

so before i write more code i want the spec. write me the desiderata: what does a theory of letterform identity-and-style have to deliver to count as adequate for building something like this and for settling the argument in my head? i mean which cases it has to get right, which distinctions it isn't allowed to collapse (letter-type vs allograph vs individual handwritten token, say; or is-a-letter-at-all vs which-letter; or having-a-style vs how-much-of-it), and which facts about actual writing systems it can't contradict -- e.g. scripts where a letter's shape depends on where it sits in the word, scripts with no uppercase/lowercase distinction, scripts where letters get packed into blocks, and the annoying case where basically the same shape is one letter in one system and a different letter in another.

the parts i actually care about, pls don't skip them:

- the case or consideration behind each requirement, not just the requirement. i want to know why it's on the list.
- mark which are non-negotiable and which are just preferences of one camp (explicit rules vs learned, must be learnable without supervision, must work on a grid vs in continuous space, must be human-readable/explainable, must scale to scripts nobody has seen, must be neurally plausible, whatever else you think belongs here).
- tell me which pair of requirements you suspect can't be jointly satisfied. my own guess is that factoring a glyph cleanly into letter-identity + style is one of those things that everybody demands and that can't actually be done, because in some styles what makes an a an a partly *is* the style. but say so if you think the real tension is somewhere else and i'm chasing the wrong one.
- which single requirement does the most work ruling candidates out? is it one-shot style transfer into unseen letters? is it the alien-script test (here's a pile of glyphs from a writing system you've never seen: say which are the same letter as which, and which aren't letters at all)? is it the in-between glyph that's clearly well-formed but sits exactly between two letters? broken or half-erased letters? a letter written by a kid that a human still reads fine? argue for which one is load-bearing.
- does recognition and generation even need the same theory? my hunch is that a purely discriminative account could clear requirements that a generative one fails, and i want the requirements that specifically separate them. add whatever only makes sense on the generative side -- e.g. a test where the system has to invent a plausible 27th letter for the alphabet in a given style, one a reader would accept as belonging there even though no such letter exists.
- at the very end, super short: how do the usual suspects do against your own list? template/pixel similarity, stroke-and-part features, prototype plus deformation, structural analogy / role-in-the-system, embedding-space neighbourhood. a table, a few words per cell, no essays.

no reading recs and i don't care who proposed what first -- i want the list, with the reason each item earned its place. aim for somewhere around a dozen to eighteen requirements; fewer is fine if each one is doing real work, more is fine if you can defend them.
