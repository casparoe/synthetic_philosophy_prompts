I work at a small interpretability-ish lab and our own writeups have started to bug me. The practice: take a language model, train a sparse autoencoder on the activations at some layer so each activation is reconstructed as a weighted sum of a big set of learned directions, look at what inputs maximally fire each direction, give it a name (this one is Golden Gate Bridge, this one is code errors, this one is sycophantic praise), check that turning that direction up or down shifts the model's behaviour the way the name predicts, and then publish a post saying the model "represents" X or "has a feature for" X. But when we train a wider dictionary on the same layer the bridge feature splits into three, and a different random seed gives a different-looking set that reconstructs just as well — and we still talk as if one of these is the model's real decomposition.

So: what does that pipeline actually presuppose about representation? Not whether nets have representations in the abstract — I mean what the train-a-dictionary-name-it-intervene-on-it routine has to assume for its outputs to be the kind of claim our posts make, which rival views it quietly rules out (a purely instrumental "useful fiction" view? a view where only the whole network state represents and the parts don't? something about representations needing to be causally efficacious versus merely correlating with the input?), and whether the splitting and seed-dependence actually threaten it or sit fine with several theories. And if someone on the team insisted the features are just useful summaries with no fact of the matter about which decomposition is correct, what exactly would we have to stop saying and stop doing?
