I'm giving a talk in a few weeks to a mixed room of ML researchers and philosophers on whether large language models are agents, simulators, or something else, and before I commit to a position in public I want an audit of the package I've been assembling. Here it is, with the labels I use for my own views:

(1) Simulator framing, amended. A pretrained network is not itself an agent; it is a conditional distribution over continuations, and the thing that has beliefs and desires, if anything does, is what I call the prompt-relative agent: the weights together with the current context window. Agency, where it exists, attaches to model-in-context, not to the weights alone. I also don't want to lean on scaffolding here — handing a model a scratchpad, tools, or an external memory store doesn't by itself give me one persisting agent, and on my view each fresh context is a fresh prompt-relative agent.

(2) Realism about agency. When a system does have a goal, that is a fact about it rather than a façon de parler or a convenient description, and it is the sort of thing we could be wrong about.

(3) The casting account of post-training. RLHF, DPO, reinforcement learning on verifiable rewards, and the rest do not install a goal in the network. They reweight which characters are likely to be sampled. So any goals present in a deployment are inherited from the character that got cast, not installed in the system, and "the assistant wants to be helpful" is true only in the sense in which a character in a novel can want something.

(4) Deception without deceivers. I want to say that a model can deceive us, and that this is a serious failure mode, even when nothing in the system intends to mislead: the output functions to mislead, and it was produced by a process we cannot rely on not to produce such outputs. I don't think this smuggles an agent back in.

(5) Level-relativity. Description at the level of the weights, of the sampled character, and of the scaffolded deployment are all legitimate; none is the one true level, and a question like "does this system have a goal?" can remain indeterminate until a level is fixed.

(6) Alignment. The target should be the goals of the system if there are any, and character-level reliability if there aren't. I also want to keep taking scheming seriously — a system that pursues an objective across deployments while behaving as aligned within each of them — and to design evaluations against it, because I don't think the risk is hypothetical.

What I want: which of these pull against each other, and which only look as though they do. Rank the tensions by severity instead of treating them as equal, and for each say precisely what I would have to give up and what that would cost me — in particular whether the cost falls on my ability to keep (6). I suspect at least one pair is merely apparent; if so, say which, and say why the appearance arises. Finally, tell me which single revision would clean up the most. I was pressed on (4) recently and thought the objection confused, so I'd rather be told the real problem is somewhere I haven't looked.

Begin with one sentence giving your verdict — whether the set survives, and if not which commitment has to give — then give the audit. No preamble, and don't restate my commitments back to me; refer to them by number. About 700–900 words.
