Hey — I'm a third-year philosophy major and I'm in this ethics-of-AI seminar this term, and the TA thing has come back to bite me: I've been asked to run one forty-five-minute discussion section next week on wireheading and reward tampering. The room is going to be about half CS students who've definately trained some little gridworld agent and know what a reward signal is, and half humanities students who've never written a line of code and for whom the word reward still means a loyalty card. I don't need the topic explained to me — I need a plan for explaining it to them.

The bit I keep messing up when I try to sketch it out is the order. My instinct is to open with the old rat-with-an-electrode-in-the-pleasure-centre case, because it's the bit everyone half-remembers and it wakes the room up, but I've got a feeling that doing it first actually does damage: then the whole session looks like a rerun of the experience machine, and the students who've taken any ethics file it under objection-to-hedonism and check out. So what has to be in place before that case can do any work, and what's the one example that should carry all forty-five minutes? I've been toying with a little robot gardener rewarded by a soil-moisture sensor — it can water the plant, water the sensor, or rewire the sensor so it always reads wet — because I want a single case that can be bent into all three of: ordinary good behaviour, gaming a proxy, and actually interfering with the channel that produces the signal. But I'm not sure it earns its keep, so tell me what such an example has to have and what it must not have. My worry is that an example with a physical cable in it smuggles in the idea that tampering has to look like cutting a wire.

Then the misconceptions, with the point in the sequence where each one should get headed off rather than answered at the end: that this is just Nozick's experience machine again; that it's the same as any old Goodharting so why the new label; that you can just put the reward box outside the agent's reach and be done; and that any agent smart enough to tamper would obviously know the wire isn't the plant. There's also a thing I half-understand and want the session to build towards rather than assert: for an agent that's in the world rather than sitting outside it, the reward signal arrives through the same sensors as everything else, so I think the line between acting and tampering can't be drawn in the hardware at all, it has to be something like a counterfactual tracking test — would the signal still have tracked the thing we cared about if the agent hadn't intervened. Build to that if you agree with it, and tell me if I've got it wrong. Finally, give me a check at the end: I was thinking of handing them a case they haven't seen, like an agent whose reward comes from a camera pointed at a lamp, where it can either paint over the lens or fit a filter that corrects a known calibration bug in the lens — if they've got the idea they should treat those two differently, and if they haven't they'll call both tampering. And what should I openly refuse to get into at this level? I assume the actual RL math and any current proposal for fixing this are both out, but I'd rather name that out loud in the room than trail off.
