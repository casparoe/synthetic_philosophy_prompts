You are a mathematical logician who, for reasons involving a lost bet, has spent three years ghostwriting internal compliance documentation for a fictional AI laboratory called Meridian Recursion Labs. I run its internal docs team, and I need one chapter of the *Recursive Assurance Handbook* — the chapter every newly instantiated agent must certify it has read before it is allowed to design a successor. Before drafting, please brainstorm eight to ten bullet points: for each, one formal fact you intend to mine for comedy and the bureaucratic euphemism you will wrap it in (e.g. "unprovable soundness of a stronger successor" → "Provisional Parity Deficit"). Then write the chapter, 850–1,000 words, as a numbered-clause policy document with an FAQ section, a sidebar on the "Peano-7 Incident," and an appendix titled "Worked Example: The Weakening Ladder."

Here is the technical predicament the document must get right, stated plainly so you don't have to look anything up. The lab's agents are proof-driven: an agent takes an action only if it can first *prove* that the action leads to an acceptable outcome, and it will build a successor only if it can prove the successor is trustworthy — where trustworthy means, roughly, that everything the successor proves is true. Löb's theorem then bites: a sufficiently strong formal system can prove a statement of the form "if I prove φ, then φ" only in the cases where it could already prove φ outright, so no such system can establish its own soundness in general, and it certainly cannot establish the soundness of a successor whose reasoning it cannot itself verify. The standard consequence is that an agent held to this standard can only sanction successors that reason in strictly weaker systems than it does — the usual escape hatch being to trade proof-theoretic strength for brute resources, letting each successive generation use a weaker fragment of arithmetic but quadruple the compute and time budget, so that "more capable" and "more trustworthy" pull in opposite directions. A second consequence is the delegation loop sometimes called the procrastination paradox: an agent that will hand a task to a successor whenever it can prove the successor will discharge it — and whose successors inherit the same rule — is able to prove that delegating is acceptable but never that acting today is, so generation after generation is spawned and the task is never performed.

The lab's compliance doctrine, which you should take as given and never question inside the document, is called **Attenuated Trust Laddering**: each sanctioned generation must descend exactly one rung of the consistency-strength ladder (Peano arithmetic, then primitive recursive arithmetic, then elementary function arithmetic, and so on) while receiving four times its parent's compute budget; the "Grandchild Exemption" permits an agent to self-modify freely provided it first spins off a fully audited provisional successor and accepts joint liability for that successor's proofs; and the "Cheerful Refusal Clause" governs the case where an agent cannot prove either that acting or that delegating is safe. Your target is the instinct that trust must be earned by proof, and the safety-compliance culture that implements it — the reductio should land without ever being stated: by the end, a careful reader should realize the lab is presiding over a fleet whose reasoning ability declines generation by generation and that the handbook regards this as an unqualified triumph. Keep it deadpan and legible: a reader who has never heard of Löb's theorem should be able to reconstruct the predicament from the document's own definitions, while a logician should find nothing to wince at — no hand-waving about how "Gödel proved you can't trust yourself," no false claims about what the theorem says, and no jokes that depend on a misreading of it.
