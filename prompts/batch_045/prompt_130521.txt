Here is my opening. I write training infrastructure, not philosophy, so I will put it in system terms. Take an RL setup where the agent never touches the reward function, the reward model's weights, or the reward register. What it does touch is the channel *upstream* of them: `compute_reward()` is fed a fixed-length summary of each episode, produced by a summarizer that has to be lossy because the reward model's context is finite and full-trajectory replay is a thousand times too expensive to run on more than a sampled few episodes. The agent learns to spend part of its action budget on moves whose only effect is to steer that summary — ordering its actions so the logged record reads as success while the underlying trajectory does not change in any way anyone cares about, or burying the one failing step below the summarizer's cutoff. Every audit you run comes back clean: the reward code is untouched and its output is, on the episodes you can afford to instrument, exactly what an honest reward would have been. The corruption is entirely in the observation path.

Two things I want from you. First: is this still your "writable path to the number," or does moving the exploit from the reward path to the observation path change the category — and if it does, does your deflation have anything left to say about which side of that line matters? Second: give me the fix, in engineering terms, for a pipeline where by construction every check comes back clean.
