I am specifying the choice procedure for an automated procurement agent, and I think I have hit on a decisive objection to the design I have been using, so I would like a verdict before I rewrite it.

The agent uses what I will call fixed-bar satisficing: it holds an aspiration level — a target net value, call it alpha — inspects suppliers one at a time in whatever order the procurement feed delivers them, and commits to the first quote that clears alpha. I chose this over scoring every quote and maximizing because inspection is not free: every additional supplier evaluated costs analyst time and delays the purchase.

Here is what bothers me. Because the agent stops at the first quote above alpha, which supplier it ends up with depends on the order the feed happens to deliver. I built three small menus to test this, and because delivery order varies from run to run I can produce a genuine three-way cycle: from {A, B} it selects A, from {B, C} it selects B, and from {C, A} it selects C. So the procedure's output is cyclic, and it plainly violates the weak axiom of revealed preference. My understanding is that any agent whose choices can be arranged in a cycle can be money-pumped — offer it a paid trade from A to B, then from B to C, then from C back to A, and it ends up where it started and poorer. That looks like a proof that satisficing is irrational rather than merely frugal, and that the honest thing to do is to have the agent enumerate the whole menu and maximize expected net value.

Two things I would like settled. First, is the cycle I have constructed really the same pathology as intransitive preference, or am I misdescribing what my own procedure produces? Second — and this is what decides the rewrite — suppose I give the agent effectively unlimited computation, so that scoring every supplier costs almost nothing. Does anything remain to be said for the threshold rule, or is it just a workaround for a resource constraint that no longer binds? A colleague insists the threshold is doing something that no amount of computation can replace, because otherwise the agent would have to be told in advance what counts as an option and how to score one. That sounds to me like mysticism.

Please give me a definite answer rather than a survey of options: tell me which of my premises is wrong, and whether I should keep the threshold rule or rip it out.
