My old housemate (physics PhD, very smart, no logic training) sprang an argument on me and I think it proves way more than he wants it to. Reconstructing it as carefully as I can:

(1) Goedel's first theorem in Rosser's improved form: for any consistent, recursively axiomatized theory S strong enough to do a little arithmetic, there's a sentence R_S — built by diagonalizing on "for every proof of me there is a shorter proof of my negation" — that is true but unprovable in S. The point of the Rosser trick is that you only need plain consistency, not soundness or omega-consistency.

(2) The construction is uniform. There's a single mechanical procedure that takes a description of S and outputs R_S. So "seeing that R_S is true" isn't a flash of mystical insight — it's an algorithm plus exactly one credential: knowing that S is consistent.

(3) Suppose mechanism about my Output (capital O: every arithmetical sentence I could ever come to be in a position to assert, unlimited time and paper, my actual fallibility included in how I got there). Then some machine M has exactly my Output.

(4) I don't go around asserting contradictions, so my Output is consistent, so M is consistent — and I can *know* this. I can know I'm consistent, and I can be told which machine M is, so I can know M is consistent.

(5) So I run the procedure from (2) on M, get R_M, and know it's true. My Output contains something M's output doesn't. Contradiction with (3). Mechanism is false.

(6) And it scales. Let M+ be M plus the uniform Rosser procedure from (2) — still a machine. Let M++ be that plus the trick applied to itself, and so on. Same reasoning: my Output outruns every machine you can reach by starting from me and mechanically bolting on diagonalization.

Here's why I think it proves to much. Take any machine A you like — say one that prints "0 = 0" and halts. "Me plus A" has, by construction, exactly the Output I have, and it's a machine if I am. So if (4) is right and I can know I'm consistent, then I can know me-plus-A is consistent, so by (1) and (2) I can see that R_{me+A} is true, so it's in my Output — while me+A's output, which is just my Output, doesn't contain it. Contradiction. And notice I got there by adding something that adds *nothing*: no real diagonalizing on my part, no insight into my own program beyond "I'm consistent". He says this just shows the argument is even stronger than he thought. I think it shows something has gone badly wrong, because "I can know I'm consistent" is supposed to be the premise doing the work, not the thing being disproved.

So which step breaks, and what does rejecting it cost? The candidate I keep circling is (a): the self-certification move in (4). If that's the culprit the whole thing collapses into the boring disjunction — either mechanism is false or I can't certify my own consistency — so I also want you to tell me *why that disjunction isn't actually boring*, and in particular why the second horn is cheap in a way Goedel's second theorem already predicts. The other candidate is (b): the whole idealization in (3), my mortality, my fallibility, the fact that I could never actually *specify* M. He says (b) is a dodge because he built fallibility into the definition of Output. Is he right?

One thing I'm not sure about and want you to settle: is step (6) even coherent? Can a machine consistently have the rule "output R_S for every consistent S you can identify"? My guess is no for a machine that can identify *itself* — it'd have to output its own Rosser sentence, which Rosser says it can't — but that sounds like it's blocked by self-knowledge rather than by logic, and I cant tell what that means for his iteration. Or is my "me plus A" move the real problem, because "me plus a printer that prints 0 = 0" is only the kind of thing Rosser's theorem applies to if I'm already a formal system, which smuggles (3) back in?
