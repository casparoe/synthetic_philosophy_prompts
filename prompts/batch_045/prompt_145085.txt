Hey — I've been down a rabbit hole for about a week now and I want to know whether the thing I keep hitting has a name, or whether I've just argued myself into a corner.

The setup: you and me play a one-shot prisoner's dilemma, payoffs 5 / 3 / 1 / 0, no communication. But instead of picking an action, each of us hands in a piece of software that plays on our behalf, and each piece of software gets shown the other one's complete source code before it has to decide. Both programs have to finish and print a move. So a program can do things like 'cooperate iff the other program is this program, character for character', or 'cooperate iff, when I run the other program on my own source code, it says cooperate'. Apparently that's enough to get mutual cooperation out of a one-shot game where you'd normally both just defect.

Two things I keep running into while messing about with this:

1. The 'cooperate only with an exact copy of myself' program can't be exploited by anything at all. But it's insanely brittle: it defects against a program that's identical to it apart from a renamed variable, or a line of dead code that never executes — programs that would happily have cooperated with it.

2. So I tried to write the fair one: cooperate with anything that would cooperate with me, defect against anything that would defect against me. And I think I can show no such program exists. Whatever rule my program uses, you can write a program that runs my program on that program's own source code, watches which way my program would go, and then does the exact opposite. If my program would cooperate with you, you defect and I've been suckered. If my program would defect, you cooperate and I've passed up a cooperation I wanted. Either way my rule got you wrong. And I don't think I can wriggle out by having my program hang on nasty inputs, because then it hasn't produced a move at all.

I don't just want a label, I want to know exactly what this is and where its edges are. Concretely:

- Is my argument right? If the ideal program does exist, sketch it and I'll shut up. If it can't exist, does the impossibility have a name?
- Is it just the liar paradox in a costume, or just the usual you-can't-in-general-tell-what-an-arbitrary-program-will-do point? I don't think it's the second one: even if my program were magic and could always tell what any program does, the spoil-sport above still seems to break it. But check me on that, and say what the real difference is if I'm wrong.
- Is a three-way squeeze the right way to carve it — never be exploited, cooperate with everything that would cooperate with you, always output a move, pick any two — or does that misdescribe what's going on?
- Does it matter that the counterexample is a purpose-built spoiler constructed out of my own program, and that in one of the two branches it screws itself over and takes the sucker payoff? Is that a reason to stop caring about it, or does the impossibility survive?
- The versions I've seen that actually work all seem to have the shape 'cooperate iff I can prove you cooperate'. Is giving up one of the legs the only way out, and if so which leg, and why that one rather than the others?

Also, if the whole submit-a-program-instead-of-a-move setup has a name, tell me that too — I've only ever seen it described informally so I don't know what to search for.
