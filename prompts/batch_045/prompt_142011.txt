That respect is the one I want you to take seriously: for some data streams, the shortest program that fits the data so far runs vastly slower than a slightly longer program that fits it equally well, and this gap in running time can be arbitrarily large. Call it the speed gap.

Given that the speed gap is real, allocate 100 points of explanatory weight across the five considerations below — weight meaning: how much each should move a designer who is deciding whether to rank hypotheses by simplicity at all. Give the resulting ranking, one sentence of justification per item, and say plainly which item is doing the least real work. Dominance without structural assumptions: mixing over all computable measures with weights decreasing in complexity dominates each computable measure up to a constant fixed by that measure's own complexity, so cumulative expected error is bounded in terms of the complexity of the true source, with no extra assumption that the world is simple in some further sense.

2. The symmetry objection: across the space of all computable sources, any prior that concentrates on simple ones is made to look foolish by some source; simplicity pays only if the actual source happens to be simple, and the framework itself offers no a priori reason to expect that.

3. The additive-constant worry: verdicts of "simpler" are stable only up to a constant set by the reference machine, so for short data streams the ordering reflects the machine rather than the stream.

4. Track record: in the actual history of science, preferring the simpler theory has often singled out theories that later survived harder tests.

5. The speed gap itself: the shortest fitting program can be arbitrarily slow, so a simplicity-weighted predictor may be correct in the limit while being useless at every horizon anyone cares about — which suggests that what should be ranked is some trade-off of brevity against speed, not brevity alone.
