I've finaly written my position on shutdown and corrigibility into something like a doc for my research group, and before I send it round I want somebody to check whether the package actually holds together. I've been going back and forth on this for like a year and I can't tell any more which bits are load-bearing.

The setup I'm working with: there's an off-switch, but there's also what I've started calling a *dimmer* — the operators can at any point cut the agent to 10% of its resources, or route its outputs through an approval queue, instead of killing it outright. I think the dimmer matters because in practice that's what operators would actually do, and my worry is that a lot of the tidy off-switch results come apart once the switch has settings on it.

Where I've landed:

1. Corrigibility should be a property of what the agent wants (or of how it decides), not of what it doesn't know about the world. I don't want a design that's corrigible only because the agent is still uncertain about the facts — it should stay corrigible after it's learned everything there is to learn.

2. In the plain off-switch setup I'm on board with the indifference approach: make the button press a free event for the agent, so it neither fights being turned off nor angles for it, and it goes on working normally in the branch where it's still running.

3. But not the useless version of that. An agent that's just as happy being switched off as doing the job is not worth building. Whatever the fix is, it has to leave the agent actually trying.

4. It shouldn't work the humans: no spinning its reports, no burying bad news, no nudging us into leaving the switch alone. But it should still deliver the bad news, including in the cases where it can see perfectly well that the news is exactly what will make us reach for the switch.

5. It should let us rewrite it, and it shouldn't try to smuggle it's current objective into whatever replaces it. But I also don't want a total pushover — I think it should be allowed to make the case against being changed, and we might sometimes listen to it.

6. And I want its corrigibility to be self-endorsing rather than bolted on: the kind of thing that survives the agent asking itself whether deference is really the right policy, not a rule that holds only as long as it never thinks about it.

The one thing I keep going in circles on is (2) against (3) — indifference to being switched off sure sounds like not caring about the job, and my office mate says that's a non-issue and I half believe her. Everything else feels fine to me, but I've stopped trusting that feeling.

So: go through these and tell me which pairs are genuinely in tension and which only look like it, ordered by how bad the tension actually is, and for each one say what would have to give and what giving it up costs. I don't have a favourite among them, so don't assume which one I'd drop. Also flag anywhere that a fix for one tension quietly makes a different one worse — including with the dimmer, which nobody in my group has wanted to talk about. And please be explicit about which things you're saying are boring and standard in this area versus which are genuinely fought over; I really don't want to walk into a room of people who know this stuff and present somebody's contested take as the consensus.
