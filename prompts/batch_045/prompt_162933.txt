Is there a name for this? I'm a backend / infra engineer with no philosophy background whatsoever, so sorry if this is a stock thing in a field I've never heard of. Two things keep happening at work. The first one I think I already have words for, so you can skip it: we train a model against a reward model, the reward score climbs steadily, and the thing we actually care about — human raters' judgement of output quality — goes flat and then starts going down. That's reward hacking / specification gaming / Goodhart, whatever, I've read the blog posts. Not my question.

The second one I can't name, and it bites me more often. Here are two instances. We have an SLO on checkout latency, p95, alert threshold picked in 2021 after someone actually looked at user complaints. Over the next two years we split checkout into two services, so the traced span now ends earlier than it used to; we moved the payment authorization call off the synchronous request path into a background job; we stopped counting client-aborted requests as failures, because most of them were bots. Every change was sensible and reviewed and locally documented. Nobody's bonus is tied to this number, nobody gamed it, and the system didn't get slower in any way a user would notice. The number stayed flat and inside the SLO the whole time. But the quantity it denotes now is a somewhat different quantity than the one the 2021 threshold was chosen for, and the threshold, the dashboard slot, and the line in the quarterly report all kept their authority anyway. Second instance: "incidents per engineer per month," which we use as a proxy for on-call pain. It stayed flat across a tooling migration, except that the new tool auto-resolves a class of alerts that used to page a human, so the numerator is counting a slightly different population of events than it was when we picked the target number.

So the pattern, as abstractly as I can put it: an instrument's operational definiton drifts — through a series of individually justified, individually reviewed changes — while its label, its thresholds, and the decisions hanging off it stay fixed, so it keeps exercising authority it no longer has any warrant for. Nothing was optimized against, nobody cheated, and if you read any single changelog entry you'd say it was fine.

Things I've bumped into that don't seem to be it: Goodhart's law, because as I understand it that needs the measure to become a target and get optimization pressure applied to it, and here nobody targeted anything. Campbell's law, same problem. The McNamara fallacy, which as I understand it is about privileging the measurable over the important, which isn't what's going on. Concept drift in ML, which seems to be about the data distribution moving relative to a fixed label, not about the definition of the measured thing moving under a fixed name. And I've heard there's something in medicine about surrogate endpoints that validate in one trial context and then fail in another, which feels close but not quite it.

So: is there an established concept for exactly this?
