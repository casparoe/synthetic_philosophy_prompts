I am leading next week's session in an upper-level seminar on ethics and public policy — 18 students, 90 minutes, the topic is paternalism and nudging. Everyone will have already read the standard material, including the libertarian-paternalist reply that a nudge is permissible when it leaves the options open and makes the chooser better off as judged by themselves. I want to run an activity rather than lecture, and I would like your help designing it.

The angle I want them to feel is something I have been calling an orphaned default. Real choice architecture is sticky: pension auto-enrolment rates, organ-donation registries, app privacy settings, and default enrolments in this university's own systems were each set for one population, justified by that population's own judgments, and then inherited by later cohorts whose ends differ. Because a default is largely invisible to the people it governs, nobody complains and nobody re-audits it, so the as-judged-by-themselves test quietly detaches from any actual person. There is also an auditing asymmetry: setting a default is a single deliberate act by someone with the job, whereas noticing that an inherited default needs revisiting requires someone to see a choice that no longer looks like one.

Here is what I want. A runnable activity in which participants first experience a default as a genuine benefit — say, the familiar two-selves setup, where the default rescues them from something they themselves would later regret — and then find themselves still governed by the same default after their own preferences have changed, with the default never revisited and with no one on the choice-architecture side assigned to check it. Stakes should be small but real: something about how the remaining class time is spent, or a comparable token good. The invisibility has to be something they run into and only afterwards see, not something I announce in advance.

Please give me the setup and materials, the rounds with what participants are and are not told at each stage, the stake structure, and a debrief that maps specific moments onto (a) the as-judged-by-themselves defence, (b) the orphaned-default problem, and (c) the auditing asymmetry. Then tell me what will predictably go wrong the first time I run it, and be frank about which part of the idea the activity cannot produce on its own and which I will have to state outright. My own sketches keep collapsing into either a lecture with props or a set-up where the nudge looks bad from the start; I need the defence to actually land before it is put under pressure.
