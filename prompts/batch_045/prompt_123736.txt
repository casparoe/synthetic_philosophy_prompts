Working through the Löbian obstacle on my own and I think I've built an argument that proves way more than I'm willing to accept, so I want someone to tell me which step to throw out.

Setup, so we're using the same words. An agent A is a reasoner over some theory T (consistent, strong enough to do arithmetic, Godel applies). A is verificationist: before it executes a plan or a new version of itself, it wants a T-proof that executing it leads to a good outcome. Call that prove-then-act. Self-improvement means building a successor A' that's a strictly better reasoner, i.e. A' runs on a theory T' that properly extends T, so it proves things A can't.

1. Prove-then-act: A may execute a plan (including "build and run A'") only if A has a T-proof that executing it brings about a good outcome.
2. Improvement: a real successor proves strictly more than A does; T' properly extends T.
3. What step 1 requires for self-modification: the outcome of running A' depends on what A' concludes about the effects of its actions, so A's proof that executing A' is good has to contain a proof that A' is reliable about that stuff — a proof, in T, that for the relevant claims, if A' proves it then it's true.
4. A' extends A, so every T-proof is a T'-proof, and A can prove that. So if A could prove the soundness of T', A could derive the soundness of T — its own uniform reflection principle, the schema "for all φ, if T proves φ then φ".
5. Lob's theorem: if T proves (if T proves φ then φ), then T already proves φ. So no consistent T of that strength proves the schema for all φ; take φ to be a contradiction and T would be proving its own consistency, which Godel says it can't. So step 4's target is unreachable.
6. So A never gets step 3, and no verificationist agent can self-improve. That's the obstacle, and so far I believe it.

Then I tried to patch it and the patch failed, which is what worries me.

7. Maybe A doesn't need A' to be sound in general, only right about the decision-relevant claims: bounded, checkable, empirical things of roughly the form "action a brings about outcome o inside horizon h". Call that class C. Weaken step 3 to: prove A'-soundness restricted to C.
8. The narrowing doesn't help, because reflection restricted to a class like that is still unprovable: even proving T's soundness for just the Sigma-1 style claims would already amount to proving T's consistency, which T can't do. And C is exactly the class that decides whether the outcome is good, so shrinking it doesn't lower the bar.
9. And the one direction verification does work in is the wrong one: A can certify strictly weaker systems (that's the normal Godelian asymmetry, you can prove things about weaker theories, never your own or stronger), but improvement goes up, not down. So the obstacle survives narrowing: the only successor you could ever certify is a dumber one.

Here's where it goes off the rails for me. Run the same argument with A' = A itself at a later time, or A with a longer time limit, or A with a better search heuristic but the same axioms. The theory hasn't changed, but by 4 and 5 A still can't prove that its own later outputs are sound, since "my proofs are sound" is precisely what it can't prove. So the argument seems to say an agent shouldn't plan to run its own reasoning longer, or rely on a proof it found yesterday, or adopt any new method — which is just... all reasoning. And humans obviously do learn, change methods, and get smarter without proving in advance that post-change-them is reliable. So the argument isn't really about self-improvement at all; it seems to show that verificationism plus any reliance on your own cognition is impossible, which I can't accept.

So: which step do I reject, and what does rejecting it cost? I'd most like to keep the mathematical core (that T can't prove its own reflection principles, so you can't just tile a chain of stronger-and-stronger trusted successors) and I'd like to keep that self-improvement is possible in principle. But I also don't want to just delete step 1, because I want something to say to the person who says safety-critical systems should prove their behaviour before they run. If there's a reading where the argument is valid and the obstacle is real but narrower than I stated — something like "no gain in logical strength under verification, but gains in search or heuristics are fine" — I want that, and I want to know what it costs. (Also, the bit I can't articulate: re-checking a proof myself feels completely different from trusting a stronger successor, and I can't say why. If that's the crack, say so and say what it costs.)

Don't hand me a contested view dressed up as the consensus, and say how confident you are in the diagnosis versus the pricing.
