I'm in a seminar on formal epistemology and we're doing a reading on logical uncertainty, the whole "what credence should I assign to the 10^100th digit of pi before I've actually computed it" problem. For our next session I want to make a handout that sorts the main positions into a decision tree, and I'd rather it be built up from the logical space than from a list of names, so could you do that for me?

Here's what I need. Start with the branch questions, not the labels. The first question should seperate the views that take logical uncertainty seriously from the ones that dissolve it, i.e. say there's no fact of the matter about the "right" credence before you can finish the computation. Then, for the views that take it seriously, branch on whether the target is a single point credence or a credal set / range. Then branch on whether the ideal reasoner is supposed to be logically omniscient or explicitly computationally bounded. Among the bounded views I want a split between diachronic views (credences are supposed to converge over time to some "logical limit") and synchronic fixed-point views (the credences are a fixed point of the agent's own reasoning). And I'd like one more branch on whether Dutch-book-freeness is a hard normative requirement or something that gets relaxed or replaced.

The leaves that have to show up: logical omniscience (the standard Bayesian ideal where credences are closed under logical consequence); the logical induction approach (convergence to the logical limit, with Dutch books avoided in the limit); the deflationary view that there's no objective logical probability before you can compute it; the imprecise / credal-set view; a synchronic fixed-point or reflection view; and a computationally bounded algorithmic view where the agent's credence is just whatever its own internal state encodes. If there's a seventh position you think belongs (maybe something modal, where you treat logical uncertainty as uncertainty about which logical world you're in), add it, but don't pad it.

To keep it from turning into an encyclopedia entry, here are the cases the tree has to actually come apart on, and each branch question should be answerable by looking at one of these: (1) the 10^100th digit of pi, which is definite but infeasible to compute; (2) a long program whose output is fixed but the agent can't run it in time; (3) a statement that's true but unprovable in Peano arithmetic, so no proof will ever turn up, which raises the question of whether the "logical limit" even definately exists for that; (4) the agent trying to predict what a weaker version of itself would conclude, i.e. reasoning about its own reasoning; (5) a set of bets on logical statements that would Dutch-book the agent if its credences are inconsistent.

Two more constraints. Build the tree from the questions and the answer combinations they allow first, then locate the actual positions in that space, and note any unoccupied combinations with a one-line diagnosis of why nobody's there (incoherent, unattractive, or just unexplored). And flag any pair of leaves your tree genuinely can't separate rather than papering over it. Keep it to six to eight leaves, and make each branch question concrete enough that a student could answer it without already knowing which position they're landing on.
