I work in software engineering, not philosophy, so I'll state the use case directly: I'm building a decision-support module for an engineering team. Given a pending decision (ship or hold a feature, buy or build a component, run the migration this quarter or next) and a candidate information-gathering action (an A/B test, a user survey, a load test, a vendor quote), the module should estimate the value of the information and compare it against the cost of acquiring it, so we can decide whether to run the test before we make the call. I keep running into a result usually attributed to I. J. Good — that under standard expected utility the expected value of free information is never negative — and before I read further I want the specification: what must a theory of the value of information deliver to count as adequate for backing a decision rule of the form "acquire this information at cost c only if its value exceeds c"?

Write the desiderata list. For each requirement, give the case or consideration that motivates it, and mark which are non-negotiable (a theory that fails one is simply wrong) and which are preferences of a particular modeling camp. Below are the requirements I expect to see in the neighborhood; add the ones I haven't listed, and drop any of these that are actually prejudices rather than genuine desiderata, saying so.

- It must derive the non-negativity result rather than assume it, and must say exactly which assumptions do the work — whether the agent is free to ignore the signal, whether preferences are fixed, whether processing the information is costless — because I need to know which of those my team actually satisfies.
- It must separate value ex ante, before the result is seen, from value ex post, after it; the module reports a number before the test runs, and "the test came back bad" must not get logged as "information can have negative value."
- It must handle information that changes what the agent wants, not just what the agent believes — a trial that reveals we actually hate the new UI — since the non-negativity result is usually stated for belief-only updates.
- It must handle information about the agent's own preferences, and say whether self-discovery is the same channel as preference change in general or a different one.
- It must treat value as defined relative to a decision problem rather than as an intrinsic property of the information, and say what happens when the same measurement is worth more to one decision than to another.
- It must accommodate the value of information about information — the option value of learning now partly because it tells us whether to buy more information later — and say whether the non-negativity result survives that recursion.
- It must handle information whose acquisition has side effects on what is being measured (the survey changes the users, the experiment changes the system), i.e., information that is not a passive observation.
- It must be consistent with the fact that people and teams actually avoid information — skip the doctor's appointment, don't open the survey results — without either declaring the avoiders irrational or quietly giving up the non-negativity result; it should say where the negative-value cases live: cost, preference change, disutility of knowing, or a violation of one of the theorem's assumptions.

Then two closing items. First, identify any subset of the requirements you think is jointly unsatisfiable — in particular, whether "preserve the non-negativity theorem as a core result" and "treat rational information avoidance as a first-class case" can both be met, and if so at the price of which assumption. That part matters most to me. Second, a brief scorecard: how do vanilla expected-utility decision theory, models that let information change preferences, and models of costly attention or information avoidance each do against the list? Keep the scorecard short; the requirements and the joint-satisfiability question are the point.
