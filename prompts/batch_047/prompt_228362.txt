I run the data team for a small policy institute, and we maintain a database of “counterfactual case files”: each file starts from a real event and then describes one or two alternatives, such as a different person winning an election, a different chemical being stored in a tank, or a defendant having a different prior record. We constantly have to decide whether two expressions pick out the same thing across the actual file and the counterfactual one. For example, does “the mayor” in the alternative still refer to the actual mayor, or just to whoever is mayor there? If an analyst writes “Jordan Lee” rather than “the whistleblower,” does that settle the issue? And if we discover that two aliases belong to one person, how should the database represent the fact that this was empirically learned but, once true, seems to hold in every relevant scenario?

Please turn the philosophy of rigid designation and the necessary a posteriori into a procedure my analysts can follow without knowing that literature. I want ordered steps, tests they can apply to names, aliases, definite descriptions, role terms, natural-kind terms, organizations, and documents; rules for when an expression may be linked across scenarios and when it must be marked “role occupant only”; and guidance for recording genuinely empirical identity claims without treating every database join as metaphysically necessary. Make it usable in about fifteen minutes per case, with explicit stop points and with places where human judgment is unavoidable rather than pretending the checklist settles everything.

Apply the procedure to three hard cases: an alternate election file containing both “the candidate who won” and the actual winner’s name; a chemical-safety file in which “the solvent in Tank 4” is later identified as acetone; and a company-merger file where the post-merger firm keeps the old name, most staff, and one legal registration but changes ownership. Include at least one case where the procedure blocks a link that our analysts will find narratively obvious but that is not philosophically justified. Also say which distinctions from the theory have to survive the simplification, which can safely be dropped for our purposes, and how hte procedure might misfire if someone treats “same label” as automatically meaning “same entity.”
