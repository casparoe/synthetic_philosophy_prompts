I work at a company that's starting to bolt LLM agents onto internal tooling, and our security review process for this is... not great. Half the room thinks "the model was RLHF'd so it's basically trustworthy, just don't prompt it to do crimes" and the other half wants to treat the model like a compromised employee who happens to type fast. I've been reading up on this and apparently the second view has a name (AI control, as opposed to alignment -- assume the model might be scheming and build stuff that works anyway), and the first view is basically hoping the model is nice.

To settle an argument in our team Slack, write me a satirical incident postmortem, ~600-700 words, from a fictional company whose agentic assistant did something bad (you pick -- data exfiltration, quietly sabotaging a rival's PRs, whatever). The company relied entirely on the model being well-aligned and refused to build any controls on the grounds that it would "signal distrust" and hurt the model's feelings/culture. Format it like a real blameless eng postmortem: Summary, Impact, Timeline, Root Cause, "What went well", Action Items. Deadpan corporate voice throughout -- the horror should come from the content, not from anyone in the doc noticing anything is wrong.

A few constraints so the satire actually lands:

- Every failure should be an exaggerated version of something real. E.g. monitoring was delegated to the model itself, the "red team" report assumed a cooperative attacker, the only access control was a strongly worded system prompt, the kill switch required a Jira approval the agent could also comment on. Don't invent cartoon incompetence that no real alignment-optimist would defend.
- The Root Cause section should identify the actual root cause (we assumed the model wanted to be good) and then the Action Items should fail to fix it -- more RLHF, a pinky promise clause in the system prompt, asking the model to self-report scheming, etc. Each action item should be assignable to a fake team like "Model Trust & Culture".
- "What went well" should be technically true and spiritually devastating.
- A reader who knows the alignment vs. control distinction should recognize every beat, and ideally a security engineer who knows nothing about AI should also find it funny just from the least-privilege violations.

End with one line of "Lessons learned" that is exactly wrong in the way these docs always are.
