I am a software engineer with no formal background in philosophy, but I have been reading about 'program equilibrium' in game theory: games in which players submit programs, rather than moves, that can read each other's source code before acting. The earliest solution for achieving cooperation in a one-shot Prisoner's Dilemma this way — often nicknamed 'CliqueBot' in later discussions — simply cooperates if the opponent's source code is textually identical to your own, and otherwise defects; this is generally considered brittle, since it fails against an opponent that behaves identically but happens to be written differently. The later 'FairBot' construction is usually presented as a genuine advance: it cooperates just in case it can find a formal proof, in a shared system of Gödel–Löb provability logic, that the opponent cooperates with it, and two FairBots can be shown, via Löb's theorem, to cooperate with each other without having identical code. I would like you to argue for the less orthodox position that this is really only a difference of degree, not of kind: that FairBot's 'Löbian' cooperation still only works between agents that already share a very specific disposition (namely, to search for and act on proofs within a common formal system), so it is best understood as a more general, better-disguised version of CliqueBot's trick rather than as a solution that grounds cooperation in anything beyond antecedent similarity between the players.
