I'm a software engineer, and the fraud-detection model my team maintains outputs a statement such as "this transaction has an 87% probability of being fraudulent" for individual transactions. While trying to understand what such a number actually means, I came across the reference class problem for the frequentist interpretation of probability: a single transaction belongs to indefinitely many reference classes — all transactions of this size, all transactions from this merchant, all transactions from this merchant at this hour, and so on — each with its own long-run fraud frequency, and there seems to be no principled way to determine which one fixes the "real" probability of this particular transaction. Please describe the most important implications of this problem for how I should interpret and act on the model's single-case outputs. In particular, does reading the 87% as a frequency, as the model's subjective credence, or as an objective propensity of this transaction change what I am actually entitled to conclude from it, and does any of these three interpretations genuinely escape the reference class problem, or does it merely resurface in a different form under each one?
