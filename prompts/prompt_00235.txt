I've been digging into program equilibrium -- the idea, following Tennenholtz, that letting players in a game submit source code (rather than actions) that can inspect and respond to each other's code can sustain cooperation in one-shot games like the Prisoner's Dilemma. This is often framed as an advance on the classical trick of using trigger strategies to sustain cooperation via the folk theorem in infinitely repeated games. I'd like to understand precisely what program equilibrium adds. Both approaches seem to rest on making defection conditionally costly; is program equilibrium doing something genuinely new, or does it just relocate the same commitment and equilibrium-selection problems from the space of repeated-game strategies into the space of programs?
