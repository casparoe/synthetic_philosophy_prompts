His fix for corrigibility is basically: build the agent so it has a preferential gap between any two trajectories that end in shutdown at different times, so it never has a reason to shift probability toward an earlier or later button-press. The fix I've seen for this involves some dynamic/resolute choice rule that only lets the agent pick plans that aren't dominated by some other available plan at the time of choosing.
