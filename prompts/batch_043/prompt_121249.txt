Here's the concrete setup we were arguing about, so you've got something specific to audit rather than a cloud of vibes. Call it the paraphrase-and-audit stack:

- The deployment uses a powerful model that nobody trusts. It might be cooperative, or it might be waiting for a moment when defecting is cheap; the whole point is that you're not supposed to assume either way.
- The untrusted model's job is to write code patches for a large codebase.
- Before anything runs, a much weaker but trusted model reads each patch and rewrites it in its own words; only the rewritten version ships. The idea is that rewriting strips out anything hidden — a subtle backdoor, or a message encoded in the style or ordering of the code that only another copy of the untrusted model would pick up.
- On top of that there are automated tripwires: cheap tests that fire when an output looks like it belongs to the sort of thing a scheming model would produce.
- About one patch in twenty gets a full human review, chosen at random, and the humans know the rate but not which ones are coming.
- If a tripwire fires or an audit finds something, the system shuts down, the weights are frozen, and the incident is logged.
