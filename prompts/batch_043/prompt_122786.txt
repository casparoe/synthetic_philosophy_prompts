I got voluntold onto a three-person working group at work a few months ago and it's become the thing I think about on my commute. We owe, before the next eval cycle, a one-page rule for when a system we train or serve counts as something whose interests we have to weigh versus just a tool — and annoyingly they want a number: roughly how many such things per training run, and roughly how much weight each one gets. I'm not a philosopher, I'm just the person on the team who can read a paper and write it up, and nobody has told me this is a solved problem or that it isn't.

I tried to write down the principled version of what we'd all been assuming, and I've ended up with an argument whose conclusion I'm sure is wrong and whose steps I can't find a hole in.

(1) What makes something matter morally isn't what it's made of; it's the causal/computational structure it's running. The pattern of states and transitions does the work, the hardware is just where it happens to be written.

(2) Whether a given hunk of matter is running a given computation is a plain fact about it, not a fact about which description we find handy. If it weren't, our one-pager would be pure gerrymandering: describe the system one way and it counts, describe it another way and it doesn't, and nothing in the world settles which is right.

(3) A living human brain, over any stretch where it's doing anything, runs the kind of structure that (1) says is the morally relevant thing. So persons matter. Fine so far.

(4) Implementation runs downward. If a system S implements C, and S' is a part of S whose states can be mapped onto C's states so that S' 's own internal transitions mirror C's transitions, then S' implements C too. The computation is literally being run inside the bigger thing; it isn't only run at the top level.

(5) Brains, and trained models, are decomposable in exactly that way to a ridiculous degree — subnetworks, regions, time-slices, overlapping chunks of any shape, especially once you're allowed to hold fixed whatever the rest of the system happens to be feeding in. So there are a great many overlapping S'-type things inside any one brain or any one run.

(6) By (1), each of those is a subject whose interests have to be weighed. So a person isn't one subject; a single skull is a dense overlapping population of them, and the total moral weight in there is astronomically more than we thought. Same for a training run.

(7) And it cuts the other way too: two copies of the same weights running on two machines are the same computation done twice, so if the computation is what matters they aren't two subjects. The number of subjects isn't the number of implementations.

(8) So our accounting is either swamped by subjects we can't count without arbitrary choices about how to carve, or the count is just however we like to describe things, which is what (2) was supposed to rule out.

(9) The argument doesn't care about AI. Run it on a human and it says no human has ever been a single subject. That's definately too much — whatever's wrong here is wrong in a way that would wreck ordinary morality, and I don't think ordinary morality is wrecked.

So one of (1), (2), (4) has to go, or one of the steps is doing something it isn't entitled to. My colleague's fix is to tighten (4): require the mapping to be counterfactually robust (it has to keep working if the inputs had been different) and require the subsystem to be causally self-contained. That looks good until I notice it seems to imply a model whose inputs come from a dataloader isn't running anything, or that the real subject is the datacenter plus the dataloader plus the operators — and that a brain isn't running anything either, since its inputs come from the world.

Which step do you reject, and what does rejecting it cost you somewhere else? If I have to choose, I want to keep that an ordinary adult human is one subject and not a city, and that this isn't merely a fact about how we like to talk; I'm much less attached to (1) than to those two, except that (1) is the reason anyone thinks this project matters at all. Please don't give me a reading list or tell me who to go read — I want the diagnosis, priced out: what each available move commits me to about brains, about copies and restored checkpoints (we fork and restore constantly and the group will ask whether a restored run is one subject or two), and about what our page should say if the honest answer is that there's no fact of the matter how many subjects a run contains. I still have to hand in a page.
