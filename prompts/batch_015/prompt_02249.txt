I'm a software engineer with no formal background in philosophy, but I've been reading about "program equilibrium" in game theory and would like a sanity check on an objection that occurred to me. What follows is closer to notes than a polished essay; I'd appreciate comments on whether the reasoning holds up and whether I've represented the underlying ideas accurately.

The setup, as I understand it: Tennenholtz's program equilibrium replaces ordinary strategies with programs that get to read each other's source code before acting, and shows that mutual cooperation in the one-shot Prisoner's Dilemma can be a genuine equilibrium if each program cooperates only when it recognizes the other's source as sufficiently similar to (in the simplest version, identical to) its own. Later refinements — agents like "FairBot," which cooperates with any opponent it can prove, in some formal proof system, will cooperate with it — use Löb's theorem and provability logic to reach the same cooperative outcome without requiring byte-for-byte identical source, while staying "unexploitable": they never end up cooperating with an opponent that defects against them. The moral usually drawn is that mutual transparency can do the enforcement work a third party (a Hobbesian sovereign, a court, an escrow service) would otherwise have to do — you don't need anyone to make a commitment binding if each side can simply verify the other's actual disposition by inspecting its code.

Here's my worry, straight from my day job: this treats "I have read your source code" as equivalent to "I know what you will do," and that's exactly the equivalence Ken Thompson's "Reflections on Trusting Trust" lecture shows can fail. Thompson's compiler hack recognizes, at the binary level, when it is compiling the login program (and inserts a hidden backdoor) or the compiler itself (and reinserts both tricks into the freshly built binary), so the backdoor survives every future recompilation even after every trace of it is deleted from the source files anyone could inspect. If that kind of gap between source and behavior is a live possibility, a real implementation of program equilibrium wouldn't eliminate the need for a trusted third party — it would just relocate that trust further down the stack, onto the compiler, the operating system, and the hardware that turn source into behavior, with nothing obviously stopping that regress from repeating at each level.

The obvious reply is that "source code," in the formal model, just is the agent's disposition by stipulation, so Thompson's worry is a fact about physical realizability that leaves the theorem untouched. But if that's right, I'm not sure what licenses the informal gloss people put on the result — that transparency can substitute for enforcement in real cases like open-source commitments or smart contracts — since that gloss seems to trade on source code doing exactly the representational work Thompson's attack undermines.

So: does this point to a genuine gap between the formal result and its usual informal interpretation, or is there a standard move that blocks it? And please flag anything above where I've mischaracterized program equilibrium, FairBot, or the Thompson lecture.
